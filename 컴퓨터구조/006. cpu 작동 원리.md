## 1. 인터럽트(Interrupt)

### 1.1 인터럽트의 개념

**인터럽트**는 CPU의 작업 흐름을 중단시키고 즉시 처리해야 할 작업을 알리는 신호입니다. CPU가 프린터에 출력 명령을 보내고 다른 작업을 하다가, 프린터 작업이 완료되면 인터럽트를 통해 CPU에 알립니다.

### 1.2 인터럽트의 종류

### 1.2.1 동기적 인터럽트 (예외)

- **특징** : 입출력장치에 의한 발생하는 인터럽트
- **비동기** : 주로 입출력장치에 의해 발생
- **처리 과정** :
- CPU가 프린터에 작업을 맡김
- 다른 작업 수행
- 프린터 작업 완료 시 인터럽트 발생
- CPU는 하던 작업 중단하고 프린터 관련 처리

### 1.2.2 비동기적 인터럽트 (하드웨어 인터럽트)

- **특징** : CPU 작업 중간에 발생
- **발생 원인** : 예상치 못한 상황 (오류 등)

### 1.3 하드웨어 인터럽트 처리 순서

| 단계 | 내용                 | 설명                                                                                    |
| ---- | -------------------- | --------------------------------------------------------------------------------------- |
| ①    | 인터럽트 요청 신호   | CPU의 작업을 방해하는 인터럽트 요청 발생                                                |
| ②    | CPU 실행 사이클 완료 | 현재 실행 중인 명령어까지 완료하고 멈춤                                                 |
| ③    | 인터럽트 여부 확인   | 인터럽트 요청을 확인하고 인터럽트 플래그를 통해 현재 인터럽트를 받아들일 수 있는지 확인 |
| ④    | 인터럽트 받아들임    | CPU는 지금까지의 작업 내역을 백업                                                       |
| ⑤    | 인터럽트 벡터 참조   | 인터럽트 서비스 루틴 실행                                                               |
| ⑥    | 인터럽트 서비스 루틴 | 실제 인터럽트를 처리하는 프로그램 실행                                                  |

### 1.4 인터럽트 관련 주요 개념

### 1.4.1 인터럽트 요청 신호

CPU에 인터럽트가 있음을 알리는 신호

### 1.4.2 인터럽트 플래그

- **역할** : 인터럽트 요청을 받아들일지 무시할지 결정
- **처리** : 모든 인터럽트 요청을 인터럽트 플래그로 막을 수 있는 것은 아님
- **예외** : 정전이나 하드웨어 고장 등 반드시 처리해야 하는 인터럽트는 차단 불가

### 1.4.3 인터럽트 벡터

- **정의** : 인터럽트 서비스 루틴의 시작 주소를 포함하는 인터럽트 서비스 루틴의 식별 정보
- **기능** : CPU가 어떤 인터럽트를 처리하는지 파악

### 1.4.4 인터럽트 서비스 루틴 (ISR: Interrupt Service Routine)

- **별칭** : 인터럽트 핸들러(Interrupt Handler)
- **역할** : 인터럽트를 처리하기 위한 프로그램
- **저장 위치** : 메모리에 저장

### 1.5 인터럽트 서비스 루틴의 작동 원리

CPU가 인터럽트를 처리하는 방법은 **'인터럽트 서비스 루틴'**이라는 프로그램을 실행하는 것입니다.

**처리 과정:**

1. CPU는 작업 중 다른 인터럽트를 받아들일 수 있고 받아들여진 인터럽트는 인터럽트 요청 신호를 받아들이고 인터럽트를 처리
2. 인터럽트를 처리하는 방법은 여러 가지이며, 대표적인 것이 더 큰 인터럽트 서비스 루틴을 가지고 있는 인터럽트를 선택
3. 그렇다면 CPU는 각각 다른 인터럽트 서비스 루틴을 구분하기 위해 인터럽트 벡터를 사용
4. 프로그램의 위치를 파악
5. 프로그램 실행 중 다른 인터럽트 서비스 루틴의 시작 주소가 위치한 것을 인터럽트 서비스 루틴이라고 함

**1500의 10으로 나누는 것과 관련된 예시:**
그림의 예시에서 작업이 1500이라는 메모리 공간에 10으로 나눈 값을 산출하는 경우, CPU는 인터럽트 요청 신호를 받아들이고 다음과 같은 일들을 처리합니다:

- 프로그램 카운터의 값을 백업(스택에 저장)
- 인터럽트 서비스 루틴의 시작 주소가 위치
- 프로그램 실행

## 2. 예외(Exception)

### 2.1 예외의 정의

**예외**는 CPU가 명령어를 처리하다가 예상치 못한 상황에 마주쳤을 때 발생하는 것입니다.

### 2.2 예외의 종류

| 예외 종류               | 설명                                                       | 비고                |
| ----------------------- | ---------------------------------------------------------- | ------------------- |
| **폴트(Fault)**         | 예외를 처리한 직후 예외가 발생한 명령어부터 실행           | 대표적: 페이지 폴트 |
| **트랩(Trap)**          | 예외를 처리한 직후 예외가 발생한 명령어의 다음 명령어 실행 | 디버깅에 주로 사용  |
| **중단(Abort)**         | CPU가 실행 중인 프로그램을 강제 중단                       | 회복 불가능         |
| **소프트웨어 인터럽트** | 시스템 호출이 발생했을 때 나타남                           | -                   |

### 2.3 주요 예외 상세 설명

### 2.3.1 트랩(Trap)

- **용도** : 주로 디버깅에 사용
- **동작** : 프로그램의 실행을 추적
- **예시** : 소프트웨어 인터럽트와 같은 개념으로 동작

### 2.3.2 중단(Abort)

- **특징** : CPU가 실행 중인 프로그램을 강제로 중단시킴
- **사용 시기** : 회복 불가능한 치명적인 오류 발생 시

### 2.3.3 소프트웨어 인터럽트

- **정의** : 시스템 호출 발생 시 나타나는 인터럽트
- **특징** : 사용자가 프로그램 실행 과정에서 다른 레지스터에 접근하거나 자원에 접근 시 발생

## 3. CPU 설계 기법

### 3.1 클럭 (Clock)

### 3.1.1 클럭의 개념

**클럭**은 컴퓨터 부품들이 일을 할 수 있는 박자를 만들어주는 것입니다.

### 3.1.2 클럭 속도

- **단위** : Hz (헤르츠)
- **의미** : 1Hz = 1초에 클럭이 1번 반복
- **예시** :
- 1초에 클럭이 100번 반복: 100Hz
- 1초에 클럭이 100Hz인 CPU: 클럭 속도가 100Hz

### 3.1.3 클럭 속도와 CPU 성능

**클럭 속도 표현:**

```
클럭 속도 = 헤르츠(Hz)
1GHz = 1,000,000,000 Hz (10^9)

```

| 용어                  | 설명                           | 예시                  |
| --------------------- | ------------------------------ | --------------------- |
| **베이스 클럭(Base)** | CPU 기본 클럭 속도             | 2.5GHz                |
| **최대 클럭(Max)**    | CPU가 발휘할 수 있는 최대 속도 | 4.9GHz (= 2.5 × 1.96) |

**실제 제품 예시:**

- Intel Core i7-11700 Processor
- Base: 2.5GHz
- Max: 4.9GHz

### 3.2 코어(Core)와 멀티코어

### 3.2.1 코어의 정의

**코어**는 명령어를 실행하는 부품입니다. 현대 CPU는 여러 개의 코어를 가지고 있습니다.

### 3.2.2 멀티코어 프로세서

- **의미** : 코어를 여러 개 포함하고 있는 CPU
- **장점** : 처리 속도 향상

**멀티코어 종류:**

| 코어 수 | 프로세서 명칭           |
| ------- | ----------------------- |
| 1       | 싱글코어(single-core)   |
| 2       | 듀얼코어(dual-core)     |
| 3       | 트리플코어(triple-core) |
| 4       | 쿼드코어(quad-core)     |
| 6       | 헥사코어(hexa-core)     |
| 8       | 옥타코어(octa-core)     |
| 10      | 데카코어(deca-core)     |
| 12      | 도데카코어(dodeca-core) |

### 3.2.3 코어 vs 스레드

**코어:**

- 물리적인 명령어를 처리하는 부품
- CPU 내에서 실질적 연산을 처리

**스레드:**

- 하나의 코어가 동시에 처리할 수 있는 명령어 단위
- 하드웨어 스레드 = 하나의 코어로 여러 개의 명령어를 동시에 처리
- 소프트웨어 스레드 = 프로그램의 일의 단위

### 3.3 하드웨어 스레드 (하이퍼스레딩)

### 3.3.1 스레드의 구분

```
스레드 ─┬─ 하드웨어 스레드 (하이퍼스레딩)
        └─ 소프트웨어 스레드

```

### 3.3.2 하드웨어 스레드 작동 원리

- CPU 내부에 레지스터 세트 추가
- 하나의 코어로 여러 명령어를 동시에 처리
- 1코어 1스레드 CPU는 한 번에 1개의 명령어 처리
- 1코어 2스레드 CPU는 한 번에 2개의 명령어 처리

**예시:**

- 2코어 4스레드 CPU = 명령어를 실행하는 부품이 2개, 한 번에 4개의 명령어를 처리할 수 있는 CPU

### 3.4 스레드와 멀티스레드

### 3.4.1 스레드의 종류

- **하드웨어적 스레드** : 하나의 코어가 동시에 처리하는 명령어 단위
- **소프트웨어적 스레드** : 하나의 프로그램에서 독립적으로 실행되는 단위

### 3.4.2 멀티스레드 프로세서

- **정의** : 하나의 코어로 여러 명령어를 동시에 처리하는 CPU
- **장점** :
- 프로그램의 여러 부분을 동시에 실행 가능
- 레지스터 세트를 여러 개 사용

**2코어 4스레드 CPU 구조:**

```
코어 1 ─┬─ ALU + 레지스터 세트 A
        └─ 레지스터 세트 B

코어 2 ─┬─ ALU + 레지스터 세트 A
        └─ 레지스터 세트 B

```

### 3.4.3 멀티스레드 프로세서의 장점

하나의 코어로도 여러 명령어를 동시에 처리할 수 있어 다중 명령어 효율을 프로그램 입장에서 맴돌 때 하나의 명령어를 처리하는 CPU가 여러 있는 것처럼 보이고 프로세서라고 불립니다.

## 4. 명령어 병렬 처리

### 4.1 명령어 파이프라인

### 4.1.1 파이프라인의 개념

**명령어 파이프라인**은 여러 개의 명령어를 동시에 처리하기 위해 CPU를 한시도 쉬지 않고 작동시키는 기법입니다.

### 4.1.2 명령어 처리 과정

**전통적인 방식 (순차 처리):**

```
명령어 1: 인출 → 해석 → 실행 → 결과 저장
명령어 2: 인출 → 해석 → 실행 → 결과 저장
명령어 3: 인출 → 해석 → 실행 → 결과 저장

```

**파이프라인 방식:**

| 시간     | t₁   | t₂   | t₃   | t₄   | t₅   | t₆   | t₇  |
| -------- | ---- | ---- | ---- | ---- | ---- | ---- | --- |
| 명령어 1 | 인출 | 해석 | 실행 | 저장 |      |      |     |
| 명령어 2 |      | 인출 | 해석 | 실행 | 저장 |      |     |
| 명령어 3 |      |      | 인출 | 해석 | 실행 | 저장 |     |

### 4.1.3 명령어 파이프라인의 4단계

| 단계 | 영문명              | 설명        |
| ---- | ------------------- | ----------- |
| ①    | Instruction Fetch   | 명령어 인출 |
| ②    | Instruction Decode  | 명령어 해석 |
| ③    | Execute Instruction | 명령어 실행 |
| ④    | Write Back          | 결과 저장   |

### 4.2 파이프라인 위험 (Pipeline Hazard)

### 4.2.1 데이터 위험 (Data Hazard)

- **정의** : 명령어 간 데이터 의존성이 있을 때 발생
- **문제** : 이전 명령어를 끝내야 다음 명령어를 실행 가능

**예시:**

```
명령어 1: R1 ← R2 + R3  // R2와 R3를 더한 값을 R1에 저장
명령어 2: R4 ← R1 + R5  // R1과 R5를 더한 값을 R4에 저장

```

명령어 2는 명령어 1의 결과인 R1 값이 필요하므로 순서를 바꿀 수 없습니다.

### 4.2.2 제어 위험 (Control Hazard)

- **정의** : 분기 등으로 프로그램 카운터 값의 갑작스러운 변화로 인한 위험
- **발생 원인** : 조건문, 반복문 등으로 인한 프로그램 실행 순서 변경

**분기 예측(Branch Prediction) 기법:**

- 프로그램이 어디로 분기할지 미리 예측
- 예측이 맞으면 성능 향상
- 예측이 틀리면 파이프라인의 앞 단계부터 다시 시작

### 4.2.3 구조적 위험 (Structural Hazard)

- **정의** : 명령어들을 겹쳐 실행하는 과정에서 서로 다른 명령어가 동시에 ALU, 레지스터 등 같은 CPU 부품을 사용하려고 할 때 발생
- **해결** : 자원 위험(resource hazard)이라고도 부름

### 4.3 슈퍼스칼라

### 4.3.1 슈퍼스칼라의 개념

**슈퍼스칼라**는 단일 파이프라인으로도 CPU 내부에 여러 개의 명령어 파이프라인을 포함한 구조입니다.

### 4.3.2 슈퍼스칼라의 특징

- 멀티스레드 프로세서와 비교 테이블:

| 구분             | 슈퍼스칼라                         | 멀티스레드 프로세서            |
| ---------------- | ---------------------------------- | ------------------------------ |
| 파이프라인 수    | 여러 개                            | 1개                            |
| 동시 처리 명령어 | 여러 개                            | 하나의 코어로 여러 명령어 처리 |
| 프로그램 처리    | 파이프라인 개수만큼 처리 속도 향상 | 동시에 여러 명령어를 동시 처리 |

### 4.3.3 슈퍼스칼라 프로세서 vs 멀티스레드 프로세서

**차이점:**

- 슈퍼스칼라 프로세서: 인위적으로 파이프라인 개수를 늘려 프로그램 처리 속도 향상
- 멀티스레드 프로세서: 한 번에 여러 명령어를 동시 처리

**공통점:**

- 이론적으로는 양쪽 모두 처리 속도 향상
- 실제로는 데이터 위험, 제어 위험, 구조적 위험으로 파이프라인이 항상 작동하기 어려워 고도로 설계되어야 함

### 4.4 비순차적 명령어 처리 (OoOE)

### 4.4.1 OoOE의 개념

- \*Out-of-Order Execution (비순차적 명령어 처리)\*\*는 파이프라인의 중단을 방지하기 위해 명령어를 순차적으로 처리하지 않는 기법입니다.

### 4.4.2 비순차적 처리 예시

**순차적 처리 시:**

```
① M(100) ← 1
② M(101) ← 2
③ M(102) ← M(100) + M(101)
④ M(150) ← 1
⑤ M(151) ← 2
⑥ M(152) ← 3

```

③번 명령어가 ①번과 ②번 명령어의 순서를 바꿀 수 없으므로, ①번 명령어를 토대로 ③번 명령어가 수행되고, ③번 명령어를 토대로 ④번이 수행됩니다.

**비순차적 처리:**
①번과 ②번 명령어와 ⑤번 명령어는 순서를 바꿔도 실행할 수 있습니다.

```
비순차적 명령어 처리 기법은 파이프라인의 중단을 방지하기 위해
명령어를 순차적으로 처리하지 않는 명령어 병렬 처리 기법입니다.

```

## 5. CISC와 RISC

### 5.1 ISA (Instruction Set Architecture)

### 5.1.1 ISA의 정의

- \*ISA(명령어 집합 구조)\*\*는 CPU의 언어이자 하드웨어가 소프트웨어를 어떻게 이해할지에 대한 약속입니다.

### 5.1.2 ISA의 특징

- CPU가 이해할 수 있는 명령어의 모음
- 명령어 집합 또는 명령어 집합 구조
- CPU마다 ISA가 다름

### 5.2 CISC (Complex Instruction Set Computer)

### 5.2.1 CISC의 개념

- **정의** : 복잡한 명령어 집합을 활용하는 컴퓨터
- **특징** : 다양하고 강력한 명령어 활용

### 5.2.2 CISC의 특징

| 특징             | 설명                                    |
| ---------------- | --------------------------------------- |
| 명령어 형태      | 다양하고 강력한 기능 수행               |
| 명령어 길이      | 가변 길이 명령어 (명령어 길이가 다양함) |
| 명령어 수행 시간 | 명령어마다 실행 시간이 다름             |
| 사용 분야        | 주로 x86, x86-64 ISA에 활용             |

### 5.2.3 CISC의 장단점

**장점:**

- 적은 수의 명령어로 프로그램 실행 가능
- 컴파일러가 복잡한 명령어를 사용하여 효율적

**단점:**

- 명령어 파이프라인 구현이 어려움
- 명령어 하나를 실행하는 데 여러 클럭 주기 필요
- 복잡성으로 인한 설계의 어려움

### 5.3 RISC (Reduced Instruction Set Computer)

### 5.3.1 RISC의 개념

- **정의** : 명령어의 종류가 적고 짧고 규격화된 명령어 사용
- **철학** : 자주 쓰이는 명령어를 작고 빠르게

### 5.3.2 RISC의 특징

| 특징             | 설명                                         |
| ---------------- | -------------------------------------------- |
| 명령어 형태      | 단순하고 적은 수의 고정 길이 명령어          |
| 명령어 길이      | 고정 길이                                    |
| 명령어 수행 시간 | 1클럭 내외로 실행                            |
| 레지스터 활용    | 메모리 접근 최소화, 레지스터 적극 활용       |
| 사용 분야        | ARM ISA (대부분의 스마트폰, 임베디드 시스템) |

### 5.3.3 RISC의 장단점

**장점:**

- 파이프라이닝에 최적화
- 빠른 명령어 처리
- 낮은 전력 소비

**단점:**

- 복잡한 작업을 처리하기 위해 더 많은 명령어 필요

### 5.4 CISC vs RISC 비교

### 5.4.1 컴파일 결과 비교

**예시 코드:**

```c
int main(void) {
    int a = 1;
    int b = 2;
    int c = a + b;
    return 0;
}

```

**x86-64 (CISC) 컴파일 결과:**

```
main:
    push    rbp
    mov     rbp, rsp
    mov     DWORD PTR [rbp-4], 1
    mov     DWORD PTR [rbp-8], 2
    mov     edx, DWORD PTR [rbp-4]
    mov     eax, DWORD PTR [rbp-8]
    add     eax, edx
    mov     DWORD PTR [rbp-12], eax
    mov     eax, 0
    pop     rbp
    ret

```

**ARM (RISC) 컴파일 결과:**

```
main:
    push    {r7}
    sub     sp, sp, #20
    add     r7, sp, #0
    movs    r3, #1
    str     r3, [r7, #12]
    movs    r3, #2
    str     r3, [r7, #8]
    ldr     r2, [r7, #12]
    ldr     r3, [r7, #8]
    add     r3, r3, r2
    str     r3, [r7, #4]
    movs    r3, #0
    movs    r0, r3
    adds    r7, r7, #20
    mov     sp, r7
    ldr     r7, [sp], #4
    bx      lr

```

### 5.4.2 ISA별 특징 요약

| 구분         | CISC (x86-64)  | RISC (ARM)       |
| ------------ | -------------- | ---------------- |
| 대표 ISA     | x86, x86-64    | ARM              |
| 명령어 특징  | 복잡하고 다양  | 단순하고 규격화  |
| 명령어 수    | 적음           | 많음             |
| 명령어 길이  | 가변           | 고정             |
| 파이프라이닝 | 어려움         | 쉬움             |
| 소비 전력    | 높음           | 낮음             |
| 주 사용처    | 데스크톱, 서버 | 모바일, 임베디드 |

## 📋 핵심 요약본

### 🎯 인터럽트

- CPU 작업을 중단시키고 즉시 처리할 작업을 알리는 신호
- 동기적(예외), 비동기적(하드웨어) 인터럽트로 구분
- 인터럽트 벡터 → 인터럽트 서비스 루틴(ISR) 실행

### ⚡ CPU 설계 기법

- **클럭** : CPU의 작업 속도 결정 (Hz 단위)
- **코어** : 실제 명령어 처리 부품
- **멀티코어** : 여러 코어로 병렬 처리
- **스레드** : 코어가 동시에 처리하는 명령어 단위

### 🔄 명령어 병렬 처리

- **파이프라인** : 명령어를 중첩하여 동시 처리
- **파이프라인 위험** : 데이터/제어/구조적 위험
- **슈퍼스칼라** : 여러 파이프라인 동시 운영
- **비순차적 처리(OoOE)** : 의존성 없는 명령어 먼저 실행

### 💻 CISC vs RISC

- **CISC** : 복잡하고 강력한 명령어 (x86)
- **RISC** : 단순하고 빠른 명령어 (ARM)
- CISC는 명령어 수 적지만 복잡, RISC는 명령어 많지만 단순

### Q1. 다음 중 인터럽트 서비스 루틴(ISR)에 대한 설명으로 올바른 것은?

① ISR은 항상 인터럽트 플래그에 의해 차단될 수 있다
② ISR의 시작 주소는 인터럽트 벡터에 저장되어 있다
③ ISR은 CPU 내부의 하드웨어 회로로만 구성되어 있다
④ ISR은 인터럽트가 발생하면 무조건 즉시 실행된다

**정답: ②**

**해설** :
인터럽트 서비스 루틴(ISR)의 시작 주소는 인터럽트 벡터에 저장되어 있습니다. CPU는 인터럽트를 받으면 인터럽트 벡터를 참조하여 해당 ISR의 위치를 파악하고 실행합니다. ①은 틀렸습니다. 정전이나 하드웨어 고장 같은 치명적인 인터럽트는 플래그로 차단할 수 없습니다. ③은 틀렸습니다. ISR은 메모리에 저장된 프로그램입니다. ④는 틀렸습니다. 현재 실행 중인 명령어를 완료한 후 인터럽트 플래그를 확인하는 과정을 거칩니다.

### Q2. 파이프라인 위험(Pipeline Hazard) 중 '데이터 위험'이 발생하는 상황은?

① CPU 내부에 ALU가 하나밖에 없어 두 명령어가 동시에 사용하려 할 때
② 조건문으로 인해 프로그램 카운터 값이 갑자기 변경될 때
③ 이전 명령어의 결과값을 다음 명령어가 사용해야 할 때
④ 여러 명령어가 동시에 메모리 접근을 시도할 때

**정답: ③**

**해설** :
데이터 위험은 명령어 간 데이터 의존성이 있을 때 발생합니다. 예를 들어 R1 ← R2 + R3 명령어 다음에 R4 ← R1 + R5 명령어가 있다면, 두 번째 명령어는 첫 번째 명령어의 결과인 R1 값이 필요하므로 데이터 위험이 발생합니다. ①은 구조적 위험, ②는 제어 위험에 해당합니다. ④는 구조적 위험의 일종이지만 데이터 위험의 정의와는 맞지 않습니다.

### Q3. 다음 중 RISC 아키텍처의 특징으로 올바르지 않은 것은?

① 고정 길이 명령어를 사용한다
② 대부분의 명령어가 1클럭 내외로 실행된다
③ 복잡한 연산을 하나의 명령어로 처리할 수 있다
④ 레지스터를 적극적으로 활용하여 메모리 접근을 최소화한다

**정답: ③**

**해설** :
③번은 CISC의 특징입니다. RISC는 '단순화된 명령어 집합'을 의미하며, 복잡한 연산을 여러 개의 단순한 명령어로 나누어 처리합니다. ①, ②, ④는 모두 RISC의 대표적인 특징입니다. RISC는 고정 길이 명령어를 사용하여 파이프라이닝을 쉽게 하고, 대부분의 명령어를 1클럭에 처리하며, 레지스터를 적극 활용하여 메모리 접근을 줄입니다.

### Q4. 2코어 4스레드 CPU에 대한 설명으로 올바른 것은?

① 물리적인 코어가 4개 있다는 의미이다
② 한 번에 최대 2개의 명령어만 처리할 수 있다
③ 각 코어는 2개의 레지스터 세트를 가지고 있다
④ 멀티스레딩을 지원하지 않는 구조이다

**정답: ③**

**해설** :
2코어 4스레드는 물리적 코어가 2개이고, 각 코어가 하드웨어 스레드를 2개씩 지원한다는 의미입니다. 이를 위해 각 코어는 2개의 레지스터 세트를 가지고 있어, 한 번에 2개의 명령어를 동시에 처리할 수 있습니다. ①은 틀렸습니다(물리적 코어는 2개). ②는 틀렸습니다(한 번에 최대 4개 명령어 처리 가능). ④는 틀렸습니다(멀티스레딩을 지원하는 구조).

### Q5. 클럭 속도가 2.5GHz인 CPU가 최대 4.9GHz로 작동한다는 것의 의미는?

① CPU가 항상 4.9GHz로 작동한다
② 2.5GHz는 오버클럭킹 전 속도이고, 4.9GHz는 오버클럭킹 후 속도이다
③ 2.5GHz는 베이스 클럭이고, 4.9GHz는 터보 부스트 시 최대 속도이다
④ 두 속도는 서로 다른 코어의 클럭 속도를 나타낸다

**정답: ③**

**해설** :
2.5GHz(베이스 클럭)는 CPU의 기본 작동 속도이며, 4.9GHz(최대 클럭)는 터보 부스트나 유사 기술을 통해 일시적으로 도달할 수 있는 최대 속도입니다. CPU는 필요에 따라 베이스 클럭과 최대 클럭 사이에서 동적으로 속도를 조절합니다. ①은 틀렸습니다(상황에 따라 변동). ②는 틀렸습니다(오버클럭킹과는 다른 개념). ④는 틀렸습니다(모든 코어에 적용되는 사양).

### Q6. 비순차적 명령어 처리(OoOE)가 사용되는 주된 이유는?

① CPU의 클럭 속도를 높이기 위해
② 파이프라인의 중단을 방지하기 위해
③ 메모리 용량을 절약하기 위해
④ 전력 소비를 줄이기 위해

**정답: ②**

**해설** :
비순차적 명령어 처리(Out-of-Order Execution)는 파이프라인의 중단을 방지하기 위한 기법입니다. 명령어 간 의존성이 없다면 순서를 바꿔 실행함으로써 파이프라인을 계속 가동시킬 수 있습니다. 예를 들어, M(100)←1, M(101)←2, M(102)←M(100)+M(101) 순서의 명령어가 있을 때, 세 번째 명령어가 첫 두 명령어를 기다리는 동안 의존성이 없는 다른 명령어를 먼저 실행할 수 있습니다.

### Q7. 슈퍼스칼라 프로세서의 특징으로 올바른 것은?

① 하나의 명령어 파이프라인만 가지고 있다
② 여러 개의 명령어 파이프라인을 동시에 운영한다
③ 멀티코어 프로세서와 동일한 개념이다
④ 클럭 속도를 높이는 것이 주된 목적이다

**정답: ②**

**해설** :
슈퍼스칼라 프로세서는 CPU 내부에 여러 개의 명령어 파이프라인을 포함하여, 한 번에 여러 명령어를 동시에 처리할 수 있는 구조입니다. 이는 파이프라인의 개수만큼 이론적으로 처리 속도가 향상될 수 있습니다. ①은 틀렸습니다(여러 파이프라인 보유). ③은 틀렸습니다(멀티코어는 물리적 코어가 여러 개, 슈퍼스칼라는 파이프라인이 여러 개). ④는 틀렸습니다(파이프라인 증가가 목적).

### Q8. 다음 중 예외(Exception)의 종류가 아닌 것은?

① 폴트(Fault)
② 트랩(Trap)
③ 중단(Abort)
④ 인터럽트 벡터(Interrupt Vector)

**정답: ④**

**해설** :
인터럽트 벡터는 예외의 종류가 아니라 인터럽트 서비스 루틴의 시작 주소를 저장하는 공간입니다. 예외의 종류에는 폴트(예외 처리 후 예외 발생 명령어부터 재실행), 트랩(예외 처리 후 다음 명령어 실행, 디버깅에 사용), 중단(회복 불가능한 치명적 오류로 프로그램 강제 종료), 소프트웨어 인터럽트(시스템 호출) 등이 있습니다.
