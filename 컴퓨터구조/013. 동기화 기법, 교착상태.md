## 1. 뮤텍스 락 (Mutex Lock)

### 📌 핵심 요약

뮤텍스 락은 한 번에 하나의 프로세스만 임계 구역에 진입하도록 보장하는 가장 기본적인 동기화 도구입니다.

---

### 1.1 뮤텍스 락의 개념

**출처**: 운영체제 교재 Chapter 12-2 동기화 기법

**정의**

- Mutex = Mutual Exclusion Lock (상호 배제 락)
- 임계 구역 문제를 해결하기 위한 동기화 메커니즘
- 공유 자원에 대한 접근을 '자물쇠'처럼 제어

**비유로 이해하기**
화장실(임계 구역)을 생각해보세요.

- 한 사람이 화장실에 들어가면 문을 잠급니다 (lock)
- 다른 사람은 문이 열릴 때까지 기다립니다
- 사용이 끝나면 문을 열고 나옵니다 (unlock)

---

### 1.2 뮤텍스 락의 구성 요소

**1) lock 변수**

```
전역 변수로 잠금 상태를 표현
- true: 임계 구역이 잠겨있음 (사용 중)
- false: 임계 구역이 열려있음 (사용 가능)

```

**2) acquire() 함수**

```
역할: 임계 구역에 진입하기 전 잠금 획득
동작: 잠금이 풀릴 때까지 대기 → 잠금 설정

```

**3) release() 함수**

```
역할: 임계 구역 작업 완료 후 잠금 해제
동작: lock을 false로 설정

```

---

### 1.3 뮤텍스 락 구현 코드

**acquire() 함수 구현**

```c
acquire() {
    while (lock == true)    // 잠겨있는지 확인
        ;                    // 잠겨있으면 계속 대기
    lock = true;            // 잠겨있지 않으면 잠금 설정
}

```

**release() 함수 구현**

```c
release() {
    lock = false;           // 잠금 해제
}

```

**사용 예시**

```c
acquire();              // 잠금 획득
// 임계 구역 (중요한 작업)
release();              // 잠금 해제

```

---

### 1.4 뮤텍스 락의 문제점

**Busy Waiting (바쁜 대기)**

**문제 상황**

```
acquire() 함수는 lock이 false가 될 때까지
while 루프를 반복하며 계속 확인합니다.
→ CPU 자원을 낭비하는 문제 발생

```

**비유**
화장실 문이 잠겨있는지 1초마다 계속 확인하는 것과 같습니다.

**해결 방법**
실제 프로그래밍 언어(C/C++, Python 등)의 뮤텍스 구현은 busy waiting을 사용하지 않고, 대기 중인 프로세스를 잠재우는 방식으로 개선되어 있습니다.

---

### 1.5 뮤텍스 락 사용 시기

**적합한 경우**

- 단일 공유 자원을 보호할 때
- 간단한 임계 구역 제어가 필요할 때
- 짧은 시간 동안만 잠금이 유지될 때

**부적합한 경우**

- 여러 개의 공유 자원을 관리해야 할 때 → 세마포어 사용
- 복잡한 동기화 로직이 필요할 때 → 모니터 사용

## 2. 세마포어 (Semaphore)

### 📌 핵심 요약

세마포어는 여러 개의 공유 자원을 관리할 수 있는 일반화된 동기화 도구입니다.

---

### 2.1 세마포어의 개념

**출처**: 운영체제 교재 Chapter 12-2 동기화 기법

**정의**

- 뮤텍스 락의 확장된 개념
- 여러 개의 자원에 대한 접근을 제어
- 정수 변수 S로 사용 가능한 자원의 개수를 관리

**뮤텍스와의 차이**

```
뮤텍스: 화장실 1개 (0 또는 1)
세마포어: 화장실 N개 (0, 1, 2, ..., N)

```

**실생활 예시**
탈의실이 3개 있는 수영장을 생각해보세요.

- 3명까지는 동시에 탈의실 사용 가능
- 4번째 사람은 대기
- 누군가 나오면 다음 사람이 들어갈 수 있음

---

### 2.2 세마포어의 종류

**1) 이진 세마포어 (Binary Semaphore)**

```
S = 0 또는 1
뮤텍스 락과 동일한 동작

```

**2) 카운팅 세마포어 (Counting Semaphore)**

```
S = 0, 1, 2, 3, ...
여러 개의 자원 관리

```

---

### 2.3 세마포어의 핵심 함수

**wait() 함수 (= P 연산, down)**

**코드 구현**

```c
wait() {
    while (S <= 0)      // 자원이 없으면
        ;                // 대기
    S--;                // 자원이 있으면 1 감소
}

```

**동작 설명**

```
1. 사용 가능한 자원이 있는지 확인 (S > 0?)
2. 없으면 대기
3. 있으면 자원을 하나 사용 (S--)

```

---

**signal() 함수 (= V 연산, up)**

**코드 구현**

```c
signal() {
    S++;                // 자원 반환 (1 증가)
}

```

**동작 설명**

```
임계 구역 작업이 끝나면 자원을 반환
S를 1 증가시켜 대기 중인 프로세스가 사용 가능하도록 함

```

---

### 2.4 세마포어 사용 예시

**예시 1: 프린터 3대 관리**

**초기 설정**

```c
S = 3;  // 프린터 3대

```

**프로세스 A, B, C, D가 프린터 사용**

```
시간    프로세스    동작         S 값
----    --------    -------     ----
T1      A          wait()       2
T2      B          wait()       1
T3      C          wait()       0
T4      D          wait()       0 (대기!)
T5      A          signal()     1
T6      D          wait()       0 (진입 가능)

```

---

**예시 2: 실행 순서 제어**

**문제 상황**

```
프로세스 P1이 먼저 실행된 후
프로세스 P2가 실행되어야 함

```

**해결 방법**

```c
// 초기값: S = 0

// P1 코드
P1_작업();
signal();       // P2에게 신호

// P2 코드
wait();         // P1의 신호 대기
P2_작업();

```

**동작 과정**

```
1. P2가 먼저 실행되면 wait()에서 대기 (S = 0이므로)
2. P1이 실행되고 signal() 호출 (S = 1)
3. P2가 wait() 통과하고 실행

```

---

### 2.5 세마포어 활용 패턴

**패턴 1: 자원 관리**

```c
S = 자원의 개수;

// 사용할 때
wait();
// 자원 사용
signal();

```

**패턴 2: 실행 순서 제어**

```c
S = 0;

// 먼저 실행할 프로세스
작업();
signal();

// 나중에 실행할 프로세스
wait();
작업();

```

## 3. 모니터 (Monitor)

### 📌 핵심 요약

모니터는 세마포어의 복잡성을 개선하고, 교착 상태를 시각적으로 분석할 수 있는 도구를 제공합니다.

---

### 3.1 모니터의 필요성

**출처**: 운영체제 교재 Chapter 12-2 동기화 기법

**세마포어의 문제점**

**1) 사용의 복잡성**

```
개발자가 매번 wait()와 signal()을
정확한 위치에 배치해야 함
→ 실수 가능성 높음

```

**2) 교착 상태 발생 위험**

```c
// 프로세스 A
lock1 = true;
while (lock2 == true);  // lock2 대기
// 작업
lock1 = false;

// 프로세스 B
lock2 = true;
while (lock1 == true);  // lock1 대기
// 작업
lock2 = false;

```

**문제 상황**

```
A가 lock1을 잡고 lock2를 기다림
B가 lock2를 잡고 lock1을 기다림
→ 서로 기다리는 교착 상태 발생!

```

---

### 3.2 자원 할당 그래프

**개념**
교착 상태를 시각적으로 표현하는 도구

**구성 요소**

**1) 프로세스 (원으로 표현)**

```
○ 프로세스 A
○ 프로세스 B

```

**2) 자원 (사각형으로 표현)**

```
□ 자원 D
내부의 점: 사용 가능한 자원 개수

```

**3) 화살표**

```
자원 → 프로세스: 자원이 프로세스에 할당됨
프로세스 → 자원: 프로세스가 자원을 요청함

```

---

### 3.3 자원 할당 그래프 예시

**정상 상태**

```
   [자원 D]
      ↓
   (프로세스 A)
      ↓
   [자원 E]

```

해석: 자원 D가 프로세스 A에 할당되고, A는 자원 E를 요청

---

**교착 상태**

```
   [자원 A] ← (프로세스 1)
      ↓              ↑
   (프로세스 2) → [자원 B]

```

해석: 순환 구조 형성! → 교착 상태

**교착 상태 판별**

```
화살표가 원(순환)을 이루면 교착 상태!

```

---

## 4. 교착 상태 (Deadlock)

### 📌 핵심 요약

교착 상태는 프로세스들이 서로가 가진 자원을 기다리며 무한정 대기하는 상태입니다.

---

### 4.1 식사하는 철학자 문제

**출처**: 운영체제 교재 Chapter 13-1 교착 상태

**문제 설정**

**상황**

```
- 원탁에 5명의 철학자
- 각 철학자 사이에 포크 1개 (총 5개)
- 식사하려면 양쪽 포크 2개 필요

```

**철학자의 행동 순서**

```
1. 왼쪽 포크를 집는다
2. 오른쪽 포크를 집는다
3. 식사한다
4. 오른쪽 포크를 내려놓는다
5. 왼쪽 포크를 내려놓는다
6. 다시 생각한다

```

---

**교착 상태 발생**

**문제 시나리오**

```
시간    철학자들의 행동
----    ----------------
T1      모든 철학자가 동시에 왼쪽 포크를 집음
T2      모든 철학자가 오른쪽 포크를 기다림
...     영원히 대기 → 교착 상태!

```

**왜 교착 상태인가?**

```
철학자 1: 포크1 보유, 포크2 대기
철학자 2: 포크2 보유, 포크3 대기
철학자 3: 포크3 보유, 포크4 대기
철학자 4: 포크4 보유, 포크5 대기
철학자 5: 포크5 보유, 포크1 대기
→ 순환 대기 구조!

```

---

### 4.2 교착 상태 발생의 4가지 조건

교착 상태는 다음 **4가지 조건이 모두 충족**될 때 발생합니다.

---

**조건 1: 상호 배제 (Mutual Exclusion)**

**정의**

```
한 번에 하나의 프로세스만
자원을 사용할 수 있음

```

**철학자 문제 적용**

```
한 포크는 한 철학자만 사용 가능

```

**일반적 예시**

```
프린터: 한 번에 한 작업만 출력
파일 쓰기: 한 프로세스만 수정 가능

```

---

**조건 2: 점유와 대기 (Hold and Wait)**

**정의**

```
자원을 보유한 상태에서
다른 자원을 기다림

```

**철학자 문제 적용**

```
왼쪽 포크를 쥔 채로
오른쪽 포크를 기다림

```

**일반적 예시**

```
프로세스 A: 메모리 보유 + CPU 대기
프로세스 B: CPU 보유 + 메모리 대기

```

---

**조건 3: 비선점 (No Preemption)**

**정의**

```
다른 프로세스의 자원을
강제로 빼앗을 수 없음

```

**철학자 문제 적용**

```
다른 철학자의 포크를
강제로 뺏을 수 없음

```

**일반적 예시**

```
프로세스가 자발적으로 반납하기 전까지
운영체제도 자원을 빼앗을 수 없음

```

---

**조건 4: 원형 대기 (Circular Wait)**

**정의**

```
프로세스들이 순환 구조로
서로의 자원을 기다림

```

**철학자 문제 적용**

```
철학자 1 → 포크2 → 철학자 2 → 포크3
→ 철학자 3 → ... → 포크1 → 철학자 1
(순환!)

```

**일반적 예시**

```
P1 → R2 → P2 → R3 → P3 → R1 → P1

```

---

### 4.3 교착 상태 조건 정리표

| 조건 | 설명 | 철학자 문제 예시 |
| --- | --- | --- |
| **상호 배제** | 한 번에 하나만 사용 | 포크는 한 명만 사용 |
| **점유와 대기** | 보유 + 대기 | 왼쪽 포크 보유 + 오른쪽 대기 |
| **비선점** | 강제로 빼앗기 불가 | 다른 철학자 포크 빼앗기 불가 |
| **원형 대기** | 순환 구조 | 1→2→3→4→5→1 |

---

### 4.4 교착 상태 해결 전략 (개요)

교착 상태는 다음 방법으로 해결할 수 있습니다.

**1) 예방 (Prevention)**

```
4가지 조건 중 하나라도
발생하지 않도록 사전 차단

```

**2) 회피 (Avoidance)**

```
안전한 상태를 유지하며
자원 할당

```

**3) 탐지 및 복구 (Detection & Recovery)**

```
교착 상태 발생 후
탐지하고 복구

```

**4) 무시 (Ignorance)**

```
발생 빈도가 낮다면
무시하고 재시작

```

## 5. 최종 핵심 요약

### 🔐 뮤텍스 락 (Mutex Lock)

**핵심 개념**

```
한 번에 하나의 프로세스만 임계 구역 진입

```

**주요 구성**

```
- lock 변수: 잠금 상태 (true/false)
- acquire(): 잠금 획득
- release(): 잠금 해제

```

**장점**

```
- 간단하고 이해하기 쉬움
- 단일 자원 보호에 효과적

```

**단점**

```
- busy waiting으로 CPU 낭비
- 여러 자원 관리 불가

```

---

### 🚦 세마포어 (Semaphore)

**핵심 개념**

```
여러 개의 공유 자원 관리 가능

```

**주요 구성**

```
- S 변수: 사용 가능한 자원 개수
- wait(): 자원 요청 (S--)
- signal(): 자원 반환 (S++)

```

**활용**

```
1. 자원 관리: S = 자원 개수
2. 실행 순서 제어: S = 0으로 시작

```

**장점**

```
- 뮤텍스보다 유연함
- 다양한 동기화 문제 해결

```

**단점**

```
- 사용이 복잡함
- 실수 시 교착 상태 발생 가능

```

---

### 📊 모니터 (Monitor)

**핵심 개념**

```
교착 상태를 그래프로 시각화

```

**자원 할당 그래프**

```
- 프로세스: 원(○)
- 자원: 사각형(□)
- 할당: 자원 → 프로세스
- 요청: 프로세스 → 자원

```

**교착 상태 판별**

```
화살표가 순환 구조 → 교착 상태!

```

---

### 🔒 교착 상태 (Deadlock)

**핵심 개념**

```
프로세스들이 서로 기다리며 무한 대기

```

**4가지 필수 조건 (모두 충족 시 발생)**

```
1. 상호 배제: 한 번에 하나만 사용
2. 점유와 대기: 보유 + 대기
3. 비선점: 강제 빼앗기 불가
4. 원형 대기: 순환 구조

```

**대표 예시**

```
식사하는 철학자 문제
- 5명의 철학자, 5개의 포크
- 모두 왼쪽 포크 집음 → 교착!

```

## 6. 복습 퀴즈

### Q1. 뮤텍스 락의 동작

다음 중 뮤텍스 락의 acquire() 함수가 하는 역할은?

A) 임계 구역의 작업이 끝났음을 알림

B) 임계 구역이 잠겨있는지 확인하고, 잠겨있지 않으면 잠금

C) 다른 프로세스에게 자원을 강제로 양보

D) 여러 프로세스가 동시에 임계 구역에 진입하도록 허용

E) 프로세스의 우선순위를 조정

---

정답: B) 임계 구역이 잠겨있는지 확인하고, 잠겨있지 않으면 잠금

해설: acquire() 함수는 while (lock == true) 루프를 통해 임계 구역이 잠겨있는지 반복적으로 확인하고, 잠겨있지 않으면 lock을 true로 설정하여 임계 구역을 잠그는 역할을 합니다. 이를 통해 한 번에 하나의 프로세스만 임계 구역에 진입할 수 있도록 보장합니다. release() 함수가 작업 종료를 알리며, 뮤텍스는 한 번에 하나의 프로세스만 허용합니다.

---

### Q2. 세마포어와 뮤텍스의 차이

세마포어가 뮤텍스 락과 다른 점은?

A) 세마포어는 busy waiting 문제가 없다

B) 세마포어는 여러 개의 공유 자원을 관리할 수 있다

C) 세마포어는 임계 구역 보호 기능이 없다

D) 세마포어는 자동으로 잠금을 해제한다

E) 세마포어는 하드웨어 수준에서만 동작한다

---

정답: B) 세마포어는 여러 개의 공유 자원을 관리할 수 있다

해설: 세마포어는 뮤텍스 락보다 일반화된 동기화 도구로, 카운팅 변수 S를 사용하여 여러 개의 공유 자원을 관리할 수 있습니다. 예를 들어, 탈의실이 3개 있다면 S=3으로 설정하여 3개의 프로세스가 동시에 자원을 사용할 수 있습니다. 반면 뮤텍스 락은 단일 자원만 관리합니다. 세마포어도 busy waiting 문제가 있을 수 있고, 임계 구역 보호 기능이 있으며, 명시적으로 signal()을 호출해야 합니다.

---

### Q3. wait()와 signal() 함수

다음 중 세마포어의 wait() 함수에 대한 설명으로 옳은 것은?

A) 자원을 반환하고 S 값을 증가시킨다

B) S 값이 0보다 클 때까지 대기하고, S를 1 감소시킨다

C) 모든 프로세스의 작업을 중단시킨다

D) 임계 구역의 크기를 동적으로 조정한다

E) 프로세스 간 메시지를 전달한다

---

정답: B) S 값이 0보다 클 때까지 대기하고, S를 1 감소시킨다

해설: wait() 함수는 while (S <= 0) 루프를 통해 사용 가능한 자원이 있을 때까지 반복적으로 확인하고, 자원이 있으면 S--를 실행하여 S를 1 감소시킨 후 임계 구역에 진입합니다. 이는 자원을 요청하고 획득하는 과정입니다. 반면 signal() 함수가 S++를 실행하여 자원을 반환하고 S를 증가시킵니다.

---

### Q4. 자원 할당 그래프

자원 할당 그래프에서 교착 상태를 나타내는 특징은?

A) 프로세스에서 자원으로 향하는 화살표만 존재

B) 자원에서 프로세스로 향하는 화살표만 존재

C) 화살표들이 순환 구조를 형성

D) 모든 자원이 사용 가능한 상태

E) 프로세스 수가 자원 수보다 적음

---

정답: C) 화살표들이 순환 구조를 형성

해설: 자원 할당 그래프에서 교착 상태는 화살표들이 원형(순환) 구조를 이룰 때 발생합니다. 예를 들어, 프로세스 A가 자원1을 보유하고 자원2를 요청하는데, 프로세스 B가 자원2를 보유하고 자원1을 요청하면 순환 대기 상태가 형성됩니다. 프로세스에서 자원으로 향하는 화살표는 자원 요청을, 자원에서 프로세스로 향하는 화살표는 자원 할당을 의미하며, 이 둘이 순환 구조를 이루면 교착 상태입니다.

---

### Q5. 식사하는 철학자 문제

식사하는 철학자 문제에서 교착 상태가 발생하는 주요 원인은?

A) 철학자들이 무한정 식사를 계속함

B) 포크가 너무 많아서

C) 모든 철학자가 동시에 왼쪽 포크를 집음

D) 식사 시간이 너무 길어서

E) 철학자 수가 홀수여서

---

정답: C) 모든 철학자가 동시에 왼쪽 포크를 집음

해설: 식사하는 철학자 문제에서 교착 상태는 모든 철학자가 동시에 왼쪽 포크를 집고, 오른쪽 포크를 기다리는 상황에서 발생합니다. 이는 점유와 대기(자원을 보유한 상태에서 다른 자원을 대기) 및 원형 대기(순환 구조로 서로를 기다림) 조건을 만족합니다. 각 철학자는 왼쪽 포크를 놓지 않고 오른쪽 포크를 기다리므로, 아무도 식사를 진행할 수 없는 교착 상태에 빠집니다.

### Q6. 교착 상태 발생 조건

다음 중 교착 상태 발생의 필수 조건이 아닌 것은?

A) 상호 배제 (Mutual Exclusion)

B) 점유와 대기 (Hold and Wait)

C) 비선점 (No Preemption)

D) 원형 대기 (Circular Wait)

E) 높은 우선순위 (High Priority)

---

정답: E) 높은 우선순위 (High Priority)

해설: 교착 상태가 발생하기 위한 네 가지 필수 조건은 상호 배제, 점유와 대기, 비선점, 원형 대기입니다. 이 네 가지 조건이 모두 동시에 만족될 때 교착 상태가 발생합니다. 상호 배제는 한 번에 하나의 프로세스만 자원 사용, 점유와 대기는 자원을 보유한 채 다른 자원 대기, 비선점은 강제로 자원을 빼앗을 수 없음, 원형 대기는 프로세스들이 순환 구조로 자원을 대기하는 것을 의미합니다. 우선순위는 스케줄링과 관련된 개념으로 교착 상태의 필수 조건이 아닙니다.
