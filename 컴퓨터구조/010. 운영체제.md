# 운영체제(Operating System) 핵심 요약

## 1. 운영체제를 알아야 하는 이유

### 1.1 운영체제의 정의와 역할

**운영체제**는 프로그램이 필요로 하는 자원을 할당하고, 여러 프로그램이 하드웨어를 효율적으로 사용할 수 있도록 관리하는 시스템 소프트웨어입니다.

### 주요 역할

- **컴퓨터 부품들의 구조적 관리** : 컴퓨터를 사용하는 모든 사람과 프로그램을 위해 작동
- **프로그램 실행 환경 제공** : 사용자가 다양한 프로그램을 효율적으로 실행할 수 있도록 지원
- **자원 할당 및 관리** : CPU, 메모리, 하드디스크 등의 자원을 여러 프로그램에 적절히 분배

### 1.2 시작하기 전에

### 운영체제의 필요성

여러분의 효율적 사용하는 대표적 운영체제로는 Windows, macOS, Linux, Android, iOS 등이 있습니다.

```
사용자 → 프로그램 → 운영체제 → 하드웨어(CPU, 메모리, 보조기억장치)

```

컴퓨터 부품들은 전기적 신호에 의해 작동하는데, 운영체제는 이러한 전기적 신호를 관리하고 여러분이 개발한 프로그램이 올바르게 실행될 수 있도록 돕습니다.

### 1.3 운영체제의 계층 구조

```
[애플리케이션]
      ↓
[운영체제(OS)]
      ↓
[하드웨어]

```

운영체제는 **하드웨어와 소프트웨어 사이의 중재자** 역할을 수행합니다. 모든 프로그램이 직접 하드웨어를 조작하는 것이 아니라, 운영체제가 제공하는 서비스를 통해 하드웨어 자원에 접근합니다.

## 2. 운영체제의 큰 그림

### 2.1 운영체제의 핵심 구성요소

### 2.1.1 커널 (Kernel)

운영체제의 핵심 부분으로, 다음과 같은 주요 기능을 담당합니다:

- **프로그램 관리** : 여러 프로그램의 실행을 관리
- **자원 할당** : 하드웨어 자원을 프로그램에 적절히 배분
- **모드와 시스템 호출** : 사용자 프로그램과 하드웨어 간의 안전한 인터페이스 제공

### 2.1.2 인터페이스

사용자가 운영체제와 상호작용하는 방법에는 두 가지가 있습니다:

**1. 그래픽 유저 인터페이스 (GUI - Graphical User Interface)**

- 마우스와 아이콘을 사용한 직관적인 조작
- Windows, macOS 등 대부분의 현대 운영체제가 제공
- 사용자 친화적이지만 자원을 더 많이 소비

**2. 커맨드 라인 인터페이스 (CLI - Command Line Interface)**

- 텍스트 명령어를 입력하여 작업 수행
- 개발자와 시스템 관리자가 선호
- 효율적이고 강력한 제어가 가능

### 2.2 운영체제의 실장과 커널

### 커널의 중요성

커널은 운영체제 서비스를 제공할 수 있는 **실행 모드**입니다. 사용자가 실행하는 응용 프로그램이 하드웨어 자원에 직접 접근하는 것은 위험하므로, 운영체제가 대신하여 처리합니다.

```
응용 프로그램 → 시스템 호출 → 커널 → 하드웨어

```

### 커널 모드 vs 사용자 모드

| 구분 | 커널 모드 (Kernel Mode)       | 사용자 모드 (User Mode)       |
| ---- | ----------------------------- | ----------------------------- |
| 정의 | CPU가 명령어를 제한 없이 실행 | CPU 사용과 자원 접근이 제한됨 |
| 권한 | 하드웨어 직접 제어 가능       | 운영체제를 통해서만 자원 접근 |
| 사용 | 운영체제의 핵심 코드 실행     | 일반 응용 프로그램 실행       |
| 목적 | 시스템 안정성 및 보안 유지    | 프로그램 간 충돌 방지         |

### 이중 모드와 시스템 호출의 작동 원리

```jsx
// 파일 읽기 예시 (JavaScript 유사 코드)
function readFile(filename) {
  // 1. 사용자 모드에서 실행 중
  // 2. 파일 접근을 위해 시스템 호출
  const systemCall = requestFileRead(filename);

  // 3. 커널 모드로 전환
  // 4. 운영체제가 하드 디스크에 접근하여 데이터 읽기
  // 5. 데이터를 사용자 프로그램에 전달
  // 6. 다시 사용자 모드로 전환

  return systemCall.getData();
}
```

### 2.3 운영체제의 핵심 서비스

### 2.3.1 프로세스 관리

운영체제는 여러 프로그램이 동시에 실행될 수 있도록 관리합니다.

```
[프로그램1] [프로그램2] [프로그램3] ...
       ↓         ↓         ↓
    [운영체제 - 프로세스 스케줄러]
              ↓
           [CPU]

```

**주요 개념:**

- **프로세스** : 실행 중인 프로그램
- **스케줄링** : CPU 시간을 프로세스들에게 할당
- **컨텍스트 스위칭** : 프로세스 간 전환

### 2.3.2 시스템 호출 (System Call)

응용 프로그램이 운영체제 서비스를 요청하는 메커니즘입니다.

**주요 시스템 호출 종류:**

| 분류             | 시스템 호출 | 설명                                                           | 사용 예시           |
| ---------------- | ----------- | -------------------------------------------------------------- | ------------------- |
| 프로세스 관리    | `fork()`    | 새 자식 프로세스 생성                                          | 프로그램 복제       |
|                  | `execve()`  | 프로세스 실행(메모리 공간을 새로운 프로그램의 내용으로 덮어씀) | 새 프로그램 실행    |
|                  | `exit()`    | 프로세스 종료                                                  | 프로그램 종료 처리  |
|                  | `waitpid()` | 자식 프로세스가 종료할 때까지 대기                             | 프로세스 동기화     |
| 파일 관리        | `open()`    | 파일 열기                                                      | 파일 읽기/쓰기 준비 |
|                  | `close()`   | 파일 닫기                                                      | 파일 리소스 해제    |
|                  | `read()`    | 파일 읽기                                                      | 데이터 입력         |
|                  | `write()`   | 파일 쓰기                                                      | 데이터 출력         |
|                  | `stat()`    | 파일 정보 확인                                                 | 파일 속성 조회      |
| 디렉터리 관리    | `chdir()`   | 작업 디렉터리 변경                                             | 폴더 이동           |
|                  | `mkdir()`   | 디렉터리 생성                                                  | 새 폴더 만들기      |
|                  | `rmdir()`   | 비어 있는 디렉터리 삭제                                        | 폴더 제거           |
| 파일 시스템 관리 | `mount()`   | 파일 시스템 마운트                                             | 드라이브 연결       |
|                  | `umount()`  | 파일 시스템 마운트 해제                                        | 드라이브 해제       |

```jsx
// Node.js에서의 시스템 호출 예시
const fs = require("fs");

// open(), read() 시스템 호출을 내부적으로 사용
fs.readFile("/path/to/file.txt", "utf8", (err, data) => {
  if (err) {
    console.error("파일 읽기 실패:", err);
    return;
  }
  console.log("파일 내용:", data);
});

// write() 시스템 호출을 내부적으로 사용
fs.writeFile("/path/to/output.txt", "안녕하세요", (err) => {
  if (err) {
    console.error("파일 쓰기 실패:", err);
    return;
  }
  console.log("파일 작성 완료");
});
```

### 2.3.3 메모리 관리

운영체제는 각 프로그램에 메모리를 할당하고 관리합니다.

**주요 기능:**

- 프로그램별 메모리 공간 할당
- 메모리 보호 (다른 프로그램의 메모리 침범 방지)
- 가상 메모리 관리

```
[메모리 구조]
┌─────────────┐
│ 운영체제    │
├─────────────┤
│ 프로그램A   │
├─────────────┤
│ 프로그램B   │
├─────────────┤
│ 프로그램C   │
└─────────────┘

```

### 2.3.4 입출력(I/O) 모드와 시스템 호출

하드웨어와 상호작용하기 위한 두 가지 접근 방식:

**1. 이중 모드 시스템 호출**

```
사용자 프로그램 → 시스템 호출 → 커널 모드 → 하드웨어 제어 → 사용자 모드로 복귀

```

**2. 사용자 모드 실행**

```jsx
// 디스크 읽기 요청 예시
async function readFromDisk(blockNumber) {
  // 사용자 모드에서 실행
  const data = await systemCall.readDiskBlock(blockNumber);
  // 커널이 디스크 작업 완료 후 데이터 반환
  return data;
}
```

## 3. 운영체제의 핵심 서비스 상세

### 3.1 프로세스 관리

### 3.1.1 프로세스 스케줄링

운영체제는 한정된 CPU 자원을 여러 프로세스에 공정하게 분배합니다.

**스케줄링 알고리즘:**

| 알고리즘                       | 설명                       | 장점                  | 단점                |
| ------------------------------ | -------------------------- | --------------------- | ------------------- |
| FCFS (First Come First Served) | 도착 순서대로 처리         | 구현 간단             | 대기 시간 증가 가능 |
| SJF (Shortest Job First)       | 실행 시간이 짧은 작업 우선 | 평균 대기 시간 최소화 | 긴 작업 기아 현상   |
| Round Robin                    | 시간 할당량 단위로 순환    | 공정한 분배           | 문맥 교환 오버헤드  |
| Priority Scheduling            | 우선순위 기반 실행         | 중요 작업 신속 처리   | 낮은 우선순위 기아  |

### 3.1.2 시스템 호출의 종류

POSIX 운영체제(Unix, Linux 등)에서 사용하는 대표적인 시스템 호출:

```jsx
// 프로세스 생성 예시 (Node.js child_process)
const { spawn } = require("child_process");

// fork() 시스템 호출과 유사
const child = spawn("ls", ["-la"]);

child.stdout.on("data", (data) => {
  console.log(`출력: ${data}`);
});

child.on("close", (code) => {
  console.log(`프로세스 종료 코드: ${code}`);
});
```

### 3.2 메모리 누수와 보안

### 3.2.1 메모리 누수 (Memory Leak)

프로그램이 할당받은 메모리를 제대로 해제하지 못해 시스템 자원이 낭비되는 현상입니다.

**메모리 누수 예시:**

```jsx
// 잘못된 코드 - 메모리 누수 발생
let leakyArray = [];
setInterval(() => {
  // 계속해서 메모리에 데이터 추가
  leakyArray.push(new Array(1000000).fill("데이터"));
  // 해제하지 않아 메모리 계속 증가
}, 1000);

// 올바른 코드 - 메모리 관리
let managedArray = [];
setInterval(() => {
  managedArray.push(new Array(1000000).fill("데이터"));

  // 오래된 데이터 제거
  if (managedArray.length > 10) {
    managedArray.shift(); // 가장 오래된 요소 제거
  }
}, 1000);
```

### 3.2.2 잘못된 주소 참조

프로그램이 운영체제 지시 없이 잘못된 메모리를 참조하면 심각한 오류가 발생합니다.

**오류 유형:**

- **Segmentation Fault** : 허가되지 않은 메모리 영역 접근
- **Program Critical Error** : 메모리 주소 오류로 인한 프로그램 종료

### 3.3 가상 머신 (Virtual Machine)

### 3.3.1 가상 머신의 개념

가상 머신은 소프트웨어로 구현한 컴퓨터로, 하나의 물리적 하드웨어에서 여러 운영체제를 동시에 실행할 수 있게 합니다.

```
[물리적 하드웨어]
      ↓
[호스트 운영체제]
      ↓
[가상화 소프트웨어 (하이퍼바이저)]
      ↓
[가상 머신1] [가상 머신2] [가상 머신3]
   (Linux)    (Windows)   (macOS)

```

### 3.3.2 가상 머신의 종류

**1. 가상 머신 (Virtual Machine)**

- 하드웨어를 완전히 에뮬레이션
- 게스트 OS가 독립적으로 실행
- 예: VMware, VirtualBox

**2. 가상 머신 관리자 (Hypervisor)**

```
Type 1 (Bare-metal):
하드웨어 → 하이퍼바이저 → VM들
예: VMware ESXi, Hyper-V

Type 2 (Hosted):
하드웨어 → 호스트 OS → 하이퍼바이저 → VM들
예: VirtualBox, VMware Workstation

```

## 핵심 요약

### 운영체제의 기본 개념

1. **정의** : 하드웨어 자원을 관리하고 프로그램 실행 환경을 제공하는 시스템 소프트웨어
2. **주요 역할** : 자원 할당, 프로세스 관리, 메모리 관리, 입출력 제어
3. **구성** : 커널(핵심) + 인터페이스(GUI/CLI)

### 커널과 시스템 호출

1. **커널** : 운영체제의 핵심 기능을 담당하는 부분
2. **이중 모드** : 커널 모드(제한 없음)와 사용자 모드(제한됨)로 시스템 보안 유지
3. **시스템 호출** : 응용 프로그램이 운영체제 서비스를 요청하는 인터페이스

### 주요 서비스

1. **프로세스 관리** : 여러 프로그램의 동시 실행 관리 (스케줄링)
2. **메모리 관리** : 프로그램별 메모리 할당 및 보호
3. **파일 관리** : 파일 시스템을 통한 데이터 저장 및 접근
4. **입출력 관리** : 하드웨어 장치와의 통신 제어

### 핵심 개념

- **프로세스** : 실행 중인 프로그램
- **시스템 호출** : fork(), exec(), open(), read(), write() 등
- **메모리 누수** : 할당된 메모리를 해제하지 않아 발생하는 문제
- **가상 머신** : 소프트웨어로 구현한 가상의 컴퓨터 환경

## 복습용 퀴즈

### 문제 1

운영체제에서 커널(Kernel)의 주요 역할이 아닌 것은?

1. 프로그램 실행 관리
2. 하드웨어 자원 할당
3. 그래픽 사용자 인터페이스 제공
4. 시스템 호출 처리

**정답: 3번**

**해설** : 커널은 운영체제의 핵심 부분으로 프로그램 관리, 자원 할당, 시스템 호출 처리 등을 담당합니다. 그래픽 사용자 인터페이스(GUI)는 커널 위에서 동작하는 별도의 계층으로, 커널의 핵심 기능은 아닙니다. 커널은 주로 하드웨어와 직접 통신하며 시스템의 안정성과 보안을 유지하는 역할을 합니다.

### 문제 2

다음 중 시스템 호출(System Call)에 대한 설명으로 올바른 것은?

1. 응용 프로그램이 하드웨어를 직접 제어하는 방법이다
2. 사용자 모드에서 커널 모드로 전환하여 운영체제 서비스를 요청하는 메커니즘이다
3. GUI 환경에서만 사용할 수 있는 기능이다
4. CPU의 성능을 향상시키기 위한 하드웨어 기술이다

**정답: 2번**

**해설** : 시스템 호출은 응용 프로그램이 운영체제의 서비스를 요청하기 위한 인터페이스입니다. 프로그램이 사용자 모드에서 실행되다가 파일 읽기, 메모리 할당 등의 작업이 필요할 때 시스템 호출을 통해 커널 모드로 전환됩니다. 이는 시스템의 안정성과 보안을 유지하기 위한 중요한 메커니즘으로, GUI/CLI 환경과 무관하게 모든 프로그램에서 사용됩니다.

### 문제 3

운영체제가 이중 모드(커널 모드/사용자 모드)를 사용하는 주된 이유는?

1. 프로그램 실행 속도를 높이기 위해
2. 메모리 용량을 절약하기 위해
3. 시스템의 안정성과 보안을 유지하기 위해
4. 여러 프로그램을 동시에 실행하기 위해

**정답: 3번**

**해설** : 이중 모드는 시스템의 안정성과 보안을 위한 핵심 메커니즘입니다. 만약 모든 프로그램이 하드웨어를 직접 제어할 수 있다면, 악의적인 프로그램이나 버그가 있는 프로그램이 시스템 전체를 손상시킬 수 있습니다. 사용자 모드에서는 제한된 명령어만 실행할 수 있고, 중요한 시스템 자원 접근은 커널 모드를 통해서만 가능하게 하여 시스템을 보호합니다.

### 문제 4

다음 중 메모리 누수(Memory Leak)가 발생하는 상황은?

1. CPU가 과열되어 시스템이 느려지는 경우
2. 프로그램이 할당받은 메모리를 해제하지 않고 계속 새로운 메모리를 할당하는 경우
3. 하드 디스크의 공간이 부족한 경우
4. 네트워크 연결이 끊어지는 경우

**정답: 2번**

**해설** : 메모리 누수는 프로그램이 동적으로 할당받은 메모리를 사용 후 적절히 해제하지 않아 시스템의 가용 메모리가 점점 줄어드는 현상입니다. JavaScript에서 불필요한 객체 참조를 계속 유지하거나, 이벤트 리스너를 제거하지 않는 경우 등이 대표적인 예입니다. 시간이 지날수록 시스템 성능이 저하되고, 심한 경우 시스템이 응답하지 않거나 충돌할 수 있습니다.

### 문제 5

fork() 시스템 호출의 역할은?

1. 파일을 열어서 읽기
2. 새로운 자식 프로세스를 생성
3. 프로세스를 종료
4. 메모리를 할당

**정답: 2번**

**해설** : fork()는 프로세스 관리를 위한 시스템 호출로, 현재 실행 중인 프로세스를 복제하여 새로운 자식 프로세스를 생성합니다. 부모 프로세스와 자식 프로세스는 동일한 코드를 실행하지만 서로 다른 프로세스 ID를 가지며 독립적으로 동작합니다. 이는 Unix/Linux 시스템에서 새로운 프로그램을 실행하기 위한 기본적인 메커니즘이며, 일반적으로 fork() 이후 exec() 계열 함수를 호출하여 자식 프로세스에서 다른 프로그램을 실행합니다.

### 문제 6

다음 중 CLI(Command Line Interface)의 장점이 아닌 것은?

1. 시스템 자원을 적게 사용한다
2. 강력하고 세밀한 제어가 가능하다
3. 초보자가 사용하기 쉽다
4. 자동화 스크립트 작성이 용이하다

**정답: 3번**

**해설** : CLI는 텍스트 기반 명령어를 입력하여 시스템을 제어하는 인터페이스로, 시스템 자원을 적게 사용하고 강력한 제어가 가능하며 자동화에 유리합니다. 하지만 명령어를 외우고 정확한 문법으로 입력해야 하므로 초보자에게는 진입 장벽이 높습니다. 반면 GUI는 직관적인 아이콘과 메뉴를 제공하여 초보자도 쉽게 사용할 수 있지만, 더 많은 시스템 자원을 소비합니다.
