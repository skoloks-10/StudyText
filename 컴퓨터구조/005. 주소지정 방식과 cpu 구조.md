## 1. 주소 지정 방식 (Addressing Mode)

### 1.1 주소 지정 방식의 필요성

### 개념 설명

주소 지정 방식은 **명령어의 오퍼랜드 필드에서 유효 주소(effective address)를 찾는 방법**입니다. 오퍼랜드 필드에 데이터를 직접 저장하지 않고 주소를 저장하는 이유는 명령어의 길이 제약 때문입니다.

### 왜 주소를 사용하는가?

명령어가 16비트이고 연산 코드가 4비트인 경우:

- **2-주소 명령어** : 각 오퍼랜드 필드는 6비트 → 2^6 = 64가지만 표현 가능
- **3-주소 명령어** : 각 오퍼랜드 필드는 4비트 → 2^4 = 16가지만 표현 가능

하지만 오퍼랜드 필드에 **메모리 주소**를 저장하면:

- 16비트 메모리 주소 사용 시 → 2^16 = 65,536개의 데이터 접근 가능

### 유효 주소 (Effective Address)

**연산에 사용할 데이터가 실제로 저장된 위치**를 의미합니다.

---

### 1.2 즉시 주소 지정 방식 (Immediate Addressing Mode)

### 개념

오퍼랜드 필드에 **연산에 사용할 데이터를 직접 명시**하는 방식입니다.

### 구조

```
[연산 코드] [실제 데이터]

```

### 특징 비교표

| 항목          | 내용                                                                                    |
| ------------- | --------------------------------------------------------------------------------------- |
| **장점**      | • 메모리나 레지스터 접근이 불필요하여 가장 빠름`<br>`• 데이터를 즉시 사용 가능          |
| **단점**      | • 표현할 수 있는 데이터 크기가 제한적`<br>`• 오퍼랜드 필드 크기에 따라 데이터 범위 제한 |
| **사용 상황** | • 상수값을 사용하는 연산`<br>`• 작은 크기의 데이터 처리`<br>`• 빠른 응답이 필요한 경우  |
| **예시 코드** | `MOV R1, #5`(R1 레지스터에 5를 직접 저장)                                               |

---

### 1.3 직접 주소 지정 방식 (Direct Addressing Mode)

### 개념

오퍼랜드 필드에 **유효 주소(메모리 주소)를 직접 명시**하는 방식입니다.

### 구조

```
[연산 코드] [메모리 주소]
     ↓
[메모리의 해당 주소]
     ↓
[실제 데이터]

```

### 특징 비교표

| 항목          | 내용                                                                                                      |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| **장점**      | • 즉시 주소 지정 방식보다 큰 데이터 표현 가능`<br>`• 구현이 비교적 간단                                   |
| **단점**      | • 오퍼랜드 필드 길이만큼만 주소 표현 가능`<br>`• 표현 가능한 메모리 범위 제한`<br>`• 메모리 접근 1회 필요 |
| **사용 상황** | • 고정된 메모리 위치의 데이터 접근`<br>`• 전역 변수 접근`<br>`• 절대 주소 참조가 필요한 경우              |
| **예시 코드** | `LOAD R1, [1000]`(메모리 1000번지의 데이터를 R1에 로드)                                                   |

---

### 1.4 간접 주소 지정 방식 (Indirect Addressing Mode)

### 개념

오퍼랜드 필드에 **유효 주소가 저장된 메모리 주소**를 명시하는 방식입니다. 즉, 주소의 주소를 저장합니다.

### 구조

```
[연산 코드] [주소 A]
     ↓
[메모리 주소 A]
     ↓
[유효 주소 B] → [메모리 주소 B]
                      ↓
                 [실제 데이터]

```

### 특징 비교표

| 항목          | 내용                                                                                     |
| ------------- | ---------------------------------------------------------------------------------------- |
| **장점**      | • 표현 가능한 유효 주소 범위가 넓음`<br>`• 포인터 구현 가능`<br>`• 동적 메모리 접근 용이 |
| **단점**      | • 메모리 접근 2회 필요 (가장 느림)`<br>`• 구현이 복잡함                                  |
| **사용 상황** | • 포인터를 사용하는 경우`<br>`• 배열이나 연결 리스트 접근`<br>`• 동적 메모리 할당        |
| **예시 코드** | `LOAD R1, @[500]`(메모리 500번지에 저장된 주소가 가리키는 데이터를 R1에 로드)            |

---

### 1.5 레지스터 주소 지정 방식 (Register Addressing Mode)

### 개념

오퍼랜드 필드에 **데이터가 저장된 레지스터를 직접 명시**하는 방식입니다.

### 구조

```
[연산 코드] [레지스터 이름]
     ↓
CPU 내부 [레지스터]
     ↓
[실제 데이터]

```

### 특징 비교표

| 항목          | 내용                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| **장점**      | • CPU 내부 레지스터 접근으로 매우 빠름`<br>`• 메모리 접근 불필요`<br>`• 직접 주소 지정보다 빠른 처리 |
| **단점**      | • 레지스터 개수 제한으로 표현 범위 제한`<br>`• 레지스터 크기에 따른 데이터 크기 제한                 |
| **사용 상황** | • 빈번하게 사용되는 데이터 처리`<br>`• 임시 계산 결과 저장`<br>`• 고속 연산이 필요한 경우            |
| **예시 코드** | `ADD R1, R2`(R1과 R2의 값을 더하여 결과 저장)                                                        |

---

### 1.6 레지스터 간접 주소 지정 방식 (Register Indirect Addressing Mode)

### 개념

오퍼랜드 필드에 **유효 주소가 저장된 레지스터**를 명시하는 방식입니다.

### 구조

```
[연산 코드] [레지스터 이름]
     ↓
CPU 내부 [레지스터]
     ↓
[메모리 주소] → [메모리]
                  ↓
             [실제 데이터]

```

### 특징 비교표

| 항목          | 내용                                                                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------------------ |
| **장점**      | • 간접 주소 지정보다 빠름 (메모리 접근 1회)`<br>`• 레지스터 접근이 메모리보다 빠름`<br>`• 넓은 주소 범위 표현 가능 |
| **단점**      | • 직접 방식보다는 느림`<br>`• 레지스터와 메모리 모두 접근 필요                                                     |
| **사용 상황** | • 배열 순회 (인덱스 레지스터 사용)`<br>`• 포인터 기반 데이터 구조`<br>`• 간접 주소 지정의 성능 개선이 필요한 경우  |
| **예시 코드** | `LOAD R1, [R2]`(R2에 저장된 주소가 가리키는 메모리의 데이터를 R1에 로드)                                           |

---

### 주소 지정 방식 종합 비교표

| 방식          | 오퍼랜드 필드 내용 | 메모리 접근 횟수 | 속도      | 주소 범위   |
| ------------- | ------------------ | ---------------- | --------- | ----------- |
| 즉시          | 실제 데이터        | 0회              | 가장 빠름 | 매우 제한적 |
| 직접          | 메모리 주소        | 1회              | 빠름      | 제한적      |
| 간접          | 주소의 주소        | 2회              | 느림      | 넓음        |
| 레지스터      | 레지스터 이름      | 0회              | 매우 빠름 | 제한적      |
| 레지스터 간접 | 레지스터 이름      | 1회              | 빠름      | 넓음        |

## 2. 스택과 큐

### 2.1 스택 (Stack)

### 개념

**한쪽 끝이 막혀 있는 통 형태의 자료구조**로, 후입선출(LIFO: Last In First Out) 방식으로 데이터를 관리합니다.

### 동작 원리

```
PUSH (삽입)          POP (제거)
    ↓                   ↑
[   5   ] ← Top     [       ]
[   4   ]           [   4   ] ← Top
[   3   ]           [   3   ]
[   2   ]           [   2   ]
[   1   ]           [   1   ]

```

### 스택 명령어 및 특징

| 항목          | 내용                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------- |
| **PUSH**      | 스택의 최상단(Top)에 데이터 삽입                                                                         |
| **POP**       | 스택의 최상단(Top)에서 데이터 제거 및 반환                                                               |
| **LIFO 특성** | 마지막에 들어온 데이터가 가장 먼저 나감                                                                  |
| **사용 예시** | • 함수 호출 시 복귀 주소 저장`<br>`• 지역 변수 저장`<br>`• 수식 계산 (후위 표기법)`<br>`• 재귀 함수 구현 |

### 스택 예시 코드

```
PUSH 1    ; 스택에 1 삽입
PUSH 2    ; 스택에 2 삽입
PUSH 3    ; 스택에 3 삽입
POP       ; 3이 반환됨
POP       ; 2가 반환됨

```

---

### 2.2 큐 (Queue)

### 개념

**양쪽 끝이 열려 있는 통 형태의 자료구조**로, 선입선출(FIFO: First In First Out) 방식으로 데이터를 관리합니다.

### 동작 원리

```
입력(Enqueue) →  [1][2][3][4][5]  → 출력(Dequeue)
               Front          Rear

```

### 큐 명령어 및 특징

| 항목          | 내용                                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------------------- |
| **Enqueue**   | 큐의 뒤쪽(Rear)에 데이터 삽입                                                                               |
| **Dequeue**   | 큐의 앞쪽(Front)에서 데이터 제거 및 반환                                                                    |
| **FIFO 특성** | 먼저 들어온 데이터가 먼저 나감                                                                              |
| **사용 예시** | • 프로세스 스케줄링`<br>`• 프린터 작업 대기열`<br>`• 네트워크 패킷 전송`<br>`• BFS(너비 우선 탐색) 알고리즘 |

### 큐 예시 코드

```
Enqueue 1    ; 큐에 1 삽입
Enqueue 2    ; 큐에 2 삽입
Enqueue 3    ; 큐에 3 삽입
Dequeue      ; 1이 반환됨 (먼저 들어온 것)
Dequeue      ; 2가 반환됨

```

## 3. ALU와 제어장치

### 3.1 ALU (Arithmetic Logic Unit, 산술논리연산장치)

### 개념

**CPU 내에서 실제 연산을 수행하는 핵심 부품**으로, 산술 연산과 논리 연산을 담당합니다.

### ALU의 입출력 구조

```
입력:
- 레지스터 → 피연산자1
- 레지스터 → 피연산자2
- 제어장치 → 제어 신호 (어떤 연산을 할지)

     ↓
   [ALU]
     ↓

출력:
- 결과값 → 레지스터
- 플래그 → 플래그 레지스터

```

### ALU 입출력 상세 설명

| 구분     | 항목         | 설명                                                                        |
| -------- | ------------ | --------------------------------------------------------------------------- |
| **입력** | 피연산자     | • 레지스터로부터 받음`<br>`• 연산에 사용될 실제 데이터                      |
|          | 제어 신호    | • 제어장치로부터 받음`<br>`• 수행할 연산 종류 지정 (덧셈, 뺄셈, AND, OR 등) |
| **출력** | 연산 결과값  | • 레지스터에 일시 저장`<br>`• 메모리보다 레지스터가 빠르므로                |
|          | 플래그(Flag) | • 연산 결과의 추가 정보`<br>`• 플래그 레지스터에 저장                       |

---

### 플래그(Flag)의 종류와 의미

플래그는 **연산 결과에 대한 추가적인 상태 정보**를 나타냅니다.

| 플래그 종류           | 설명                                | 사용 예시                       |
| --------------------- | ----------------------------------- | ------------------------------- |
| **부호 플래그**       | 연산 결과의 부호를 나타냄           | 결과가 1이면 음수, 0이면 양수   |
| **제로 플래그**       | 연산 결과가 0인지 나타냄            | 결과가 1이면 0, 0이면 0이 아님  |
| **캐리 플래그**       | 연산 결과 올림수나 빌림수 발생 여부 | 덧셈에서 자리 올림 발생 시 1    |
| **오버플로우 플래그** | 연산 결과가 표현 범위를 초과했는지  | 부호 있는 정수의 범위 초과 시 1 |
| **인터럽트 플래그**   | 인터럽트 가능 여부                  | 1이면 인터럽트 발생 가능        |
| **슈퍼바이저 플래그** | 커널 모드/사용자 모드 구분          | 1이면 커널 모드 실행 중         |

### 플래그 사용 예시

```
; 두 수의 비교
CMP R1, R2      ; R1 - R2 연산 수행 (결과는 저장 안 함)
                ; 제로 플래그 확인
JE EQUAL        ; 제로 플래그가 1이면 (같으면) EQUAL로 점프

```

### 3.2 제어장치 (Control Unit)

### 개념

**CPU 내에서 명령어를 해석하고 각 부품에게 제어 신호를 보내는 지휘자** 역할을 합니다.

### 제어장치의 입출력 구조

```
입력:
- 명령어 레지스터 → 명령어 (해석할 명령어)
- 플래그 레지스터 → 플래그 (현재 상태)
- 클럭 신호 → 타이밍 신호

     ↓
 [제어장치]
     ↓

출력:
- 제어 신호 → CPU 내부 각 부품
- 제어 신호 → 메모리
- 제어 신호 → 입출력 장치

```

### 제어장치 입출력 상세 설명

| 구분     | 항목              | 설명                                                                                           |
| -------- | ----------------- | ---------------------------------------------------------------------------------------------- |
| **입력** | 명령어(클럭 신호) | • 명령어 레지스터로부터`<br>`• 현재 실행할 명령어                                              |
|          | 플래그            | • 플래그 레지스터로부터`<br>`• 현재 CPU 상태 정보                                              |
|          | 클럭              | • 시스템 클럭`<br>`• 제어 신호 타이밍 동기화                                                   |
| **출력** | 제어 신호         | • CPU 내부: ALU, 레지스터에 신호`<br>`• 메모리: 읽기/쓰기 신호`<br>`• 입출력: 입출력 장치 제어 |

---

### 3.3 레지스터의 종류

### 개념

**CPU 내부의 작고 빠른 임시 저장 공간**으로, 다양한 용도로 사용됩니다.

### 주요 레지스터 종류

| 레지스터                 | 영문명                        | 역할                                                                     | 사용 예시                                                   |
| ------------------------ | ----------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------- |
| **프로그램 카운터**      | PC (Program Counter)          | • 다음에 실행할 명령어 주소 저장`<br>`• 명령어 인출 시 자동 증가         | CPU가 1000번지 명령 실행 후 PC는 자동으로 1001번지를 가리킴 |
| **명령어 레지스터**      | IR (Instruction Register)     | • 현재 실행 중인 명령어 저장`<br>`• 제어장치가 해석                      | LOAD R1, [500] 명령어 전체가 저장됨                         |
| **메모리 주소 레지스터** | MAR (Memory Address Register) | • 메모리 접근 시 읽거나 쓸 주소 저장                                     | 1000번지를 읽으려면 MAR에 1000 저장                         |
| **메모리 버퍼 레지스터** | MBR (Memory Buffer Register)  | • 메모리에서 읽어온 데이터 임시 저장`<br>`• 메모리에 쓸 데이터 임시 저장 | MAR의 주소에서 읽은 데이터 저장                             |
| **범용 레지스터**        | General Purpose Register      | • 다양한 용도로 사용`<br>`• 데이터, 주소 모두 저장 가능                  | R1, R2, R3 등 프로그래머가 자유롭게 사용                    |
| **플래그 레지스터**      | Flag Register                 | • 연산 결과 상태 정보 저장`<br>`• 조건 분기에 사용                       | 부호, 제로, 캐리, 오버플로우 플래그 등                      |
| **스택 포인터**          | SP (Stack Pointer)            | • 스택의 최상단 주소 저장`<br>`• PUSH/POP 시 자동 조정                   | 함수 호출 시 복귀 주소를 스택에 저장                        |
| **베이스 레지스터**      | Base Register                 | • 기준 주소 저장`<br>`• 상대 주소 계산에 사용                            | 베이스 + 오프셋 = 실제 주소                                 |

---

### 레지스터 동작 예시

**프로그램 카운터(PC) 동작:**

```
01. CPU가 1000번지 명령어 실행
02. 프로그램 카운터가 자동으로 1001번지로 증가
03. 1000번지 명령어가 1500번지로 점프(JUMP)하라는 명령이면
    PC는 1500번지로 변경됨

```

**메모리 주소/버퍼 레지스터 동작:**

```
메모리 읽기 과정:
1. MAR에 1000번지 저장 (읽을 주소)
2. 메모리에서 1000번지 데이터를 읽음
3. MBR에 읽은 데이터 임시 저장
4. MBR의 데이터를 목적 레지스터로 전송

```

## 4. 명령어 사이클과 인터럽트

### 4.1 명령어 사이클 (Instruction Cycle)

### 개념

**CPU가 하나의 명령어를 처리하는 과정**을 의미하며, 여러 단계로 구성됩니다.

### 명령어 사이클의 단계

| 단계            | 영문명          | 설명                                               | 동작 내용                                                                                                                                             |
| --------------- | --------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **인출 사이클** | Fetch Cycle     | 명령어를 메모리에서 CPU로 가져오는 단계            | 1. PC가 가리키는 메모리 주소를 MAR에 저장`<br>`2. 메모리에서 명령어를 읽어 MBR에 저장`<br>`3. MBR의 내용을 IR(명령어 레지스터)로 전송`<br>`4. PC 증가 |
| **실행 사이클** | Execution Cycle | 가져온 명령어를 실행하는 단계                      | 1. IR의 명령어를 제어장치가 해석`<br>`2. 필요한 제어 신호 생성`<br>`3. ALU 또는 메모리 접근 수행`<br>`4. 결과를 레지스터나 메모리에 저장              |
| **간접 사이클** | Indirect Cycle  | 간접 주소 지정 시 실제 주소를 구하는 단계 (선택적) | 1. 오퍼랜드가 간접 주소인 경우`<br>`2. 메모리 접근하여 실제 유효 주소 획득                                                                            |

---

### 명령어 사이클 상세 흐름도

```
[시작]
  ↓
[인출 사이클]
- PC → MAR (다음 명령어 주소)
- 메모리 읽기
- 메모리 → MBR → IR
- PC = PC + 1
  ↓
[간접 사이클] (필요시)
- 간접 주소인 경우
- 실제 유효 주소 계산
  ↓
[실행 사이클]
- 명령어 해석
- 제어 신호 생성
- 연산 수행
- 결과 저장
  ↓
[인터럽트 확인]
- 인터럽트 발생했는가?
  ↓
[처음으로 또는 인터럽트 처리]

```

---

### 4.2 인터럽트 (Interrupt)

### 개념

**CPU가 프로그램 실행 중 예외 상황이나 입출력 요청 등으로 인해 현재 작업을 중단하고 다른 작업을 수행해야 할 때 발생하는 신호**입니다.

### 인터럽트의 종류

| 종류                                           | 설명                                                                                 | 발생 예시                                                                             |
| ---------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| **동기적 인터럽트`<br>`(예외, Exception)**     | • CPU 내부에서 발생`<br>`• 프로그램 실행 중 예측 가능`<br>`• 명령어 실행과 직접 관련 | • 0으로 나누기`<br>`• 잘못된 메모리 접근`<br>`• 오버플로우`<br>`• 명령어 실행 중 오류 |
| **비동기적 인터럽트`<br>`(하드웨어 인터럽트)** | • CPU 외부에서 발생`<br>`• 예측 불가능`<br>`• 하드웨어 장치가 신호 보냄              | • 키보드 입력`<br>`• 마우스 클릭`<br>`• 타이머`<br>`• 입출력 장치 완료 신호           |

---

### 인터럽트 처리 과정

```
1. [정상 프로그램 실행 중]
   ↓
2. [인터럽트 발생]
   ↓
3. [현재 작업 상태 저장]
   - PC, 레지스터 등을 스택에 PUSH
   ↓
4. [인터럽트 벡터 확인]
   - 어떤 인터럽트인지 확인
   ↓
5. [인터럽트 서비스 루틴(ISR) 실행]
   - 해당 인터럽트 처리 코드 실행
   ↓
6. [저장된 상태 복원]
   - 스택에서 POP하여 복원
   ↓
7. [원래 프로그램으로 복귀]

```

---

### 인터럽트 관련 용어 정리

| 용어                          | 설명                                                                                |
| ----------------------------- | ----------------------------------------------------------------------------------- |
| **인터럽트 서비스 루틴(ISR)** | 인터럽트가 발생했을 때 실행되는 프로그램`<br>`= 인터럽트 핸들러                     |
| **인터럽트 벡터**             | 각 인터럽트 서비스 루틴의 시작 주소를 저장한 테이블                                 |
| **인터럽트 플래그**           | 인터럽트 발생 가능 여부를 나타내는 플래그`<br>`1: 인터럽트 가능, 0: 인터럽트 불가능 |
| **인터럽트 비활성화**         | 중요한 작업 중 인터럽트를 일시적으로 막음`<br>`= Masking                            |

---

### 인터럽트 우선순위

여러 인터럽트가 동시에 발생하면 **우선순위**에 따라 처리됩니다.

```
우선순위 (높음 → 낮음):

1. 전원 이상 (Power Fail)
2. 기계 착오 (Machine Check)
3. 외부 신호 (External)
4. 입출력 (I/O)
5. 명령어 오류 (Illegal Instruction)
6. 프로그램 검사 (Program Check)
7. SVC (Supervisor Call)

```

### 인터럽트 예시 상황

| 상황                           | 인터럽트 종류       | 처리 방법                              |
| ------------------------------ | ------------------- | -------------------------------------- |
| 프로그램 실행 중 키보드 입력   | 비동기적 (하드웨어) | 현재 작업 저장 → 입력 처리 → 복귀      |
| 배열 범위를 벗어난 접근        | 동기적 (예외)       | 예외 처리 루틴 실행 또는 프로그램 종료 |
| 타이머가 정해진 시간 경과 알림 | 비동기적 (하드웨어) | 스케줄러 호출하여 다른 프로세스 실행   |
| 잘못된 명령어 코드 실행        | 동기적 (예외)       | 오류 메시지 출력 후 종료               |


### 퀴즈 1: 주소 지정 방식

**문제** : 다음 중 메모리 접근이 **2회** 발생하는 주소 지정 방식은?

① 즉시 주소 지정 방식

② 직접 주소 지정 방식

③ 간접 주소 지정 방식

④ 레지스터 주소 지정 방식

<details>
<summary><b>정답 및 해설 보기</b></summary>

**정답** : ③ 간접 주소 지정 방식

**해설** :
간접 주소 지정 방식은 오퍼랜드 필드에 저장된 주소(A)로 먼저 메모리에 접근하여 유효 주소(B)를 얻고, 다시 그 유효 주소(B)로 메모리에 접근하여 실제 데이터를 가져오므로 **총 2회의 메모리 접근**이 필요합니다. 이는 다른 방식보다 느리지만 표현 가능한 주소 범위가 가장 넓다는 장점이 있습니다.

- 즉시: 메모리 접근 0회 (데이터가 명령어에 포함)
- 직접: 메모리 접근 1회
- 레지스터: 메모리 접근 0회 (레지스터만 접근)
- 레지스터 간접: 메모리 접근 1회

</details>

### 퀴즈 2: 스택과 큐

**문제** : 스택에 1, 2, 3, 4, 5 순서로 PUSH한 후 POP을 2회 수행하면 나오는 값은?

① 1, 2

② 2, 1

③ 5, 4

④ 4, 5

<details>
<summary><b>정답 및 해설 보기</b></summary>

**정답** : ③ 5, 4

**해설** :
스택은 LIFO(Last In First Out) 구조이므로 가장 나중에 들어간 데이터가 먼저 나옵니다.

```
스택 상태:
PUSH 1 → [1]
PUSH 2 → [1][2]
PUSH 3 → [1][2][3]
PUSH 4 → [1][2][3][4]
PUSH 5 → [1][2][3][4][5] ← Top

POP 1회 → 5가 나옴, [1][2][3][4] ← Top
POP 2회 → 4가 나옴, [1][2][3] ← Top

```

만약 큐(FIFO)였다면 1, 2가 나왔을 것입니다.

</details>

### 퀴즈 3: ALU의 플래그

**문제** : 부호 있는 정수 연산에서 결과값이 표현 가능한 범위를 벗어났을 때 1로 설정되는 플래그는?

① 부호 플래그

② 제로 플래그

③ 캐리 플래그

④ 오버플로우 플래그

<details>
<summary>

<b>정답 및 해설 보기</b></summary>

**정답** : ④ 오버플로우 플래그

**해설** :
오버플로우 플래그는 **부호 있는 정수의 연산 결과가 표현 가능한 범위를 초과**했을 때 1로 설정됩니다.

**예시** :

- 8비트 부호 있는 정수 범위: -128 ~ +127
- 127 + 1 = 128이지만, 8비트로는 -128로 잘못 표현됨
- 이때 오버플로우 플래그 = 1

  **플래그 구분** :

- **캐리 플래그** : 부호 없는 정수의 자리 올림/빌림
- **오버플로우 플래그** : 부호 있는 정수의 범위 초과

</details>

### 퀴즈 4: 레지스터

**문제** : CPU가 다음에 실행할 명령어의 주소를 저장하는 레지스터는?

① 명령어 레지스터(IR)

② 프로그램 카운터(PC)

③ 메모리 주소 레지스터(MAR)

④ 메모리 버퍼 레지스터(MBR)

<details>
<summary><b>정답 및 해설 보기</b></summary>

**정답** : ② 프로그램 카운터(PC)

**해설** :
프로그램 카운터(PC)는 **다음에 실행할 명령어의 메모리 주소**를 저장합니다.

**레지스터별 역할** :

- **PC** : 다음 실행할 명령어 주소 (명령어 인출 후 자동 증가)
- **IR** : 현재 실행 중인 명령어 저장
- **MAR** : 메모리에 접근할 주소 저장
- **MBR** : 메모리에서 읽거나 쓸 데이터 임시 저장

  **동작 예시** :

```
1. PC = 1000 (1000번지 명령어 실행 예정)
2. 1000번지 명령어를 IR로 가져옴
3. PC = 1001 (자동 증가)
4. IR의 명령어 실행

```

</details>

### 퀴즈 5: 명령어 사이클

**문제** : 명령어 사이클에서 PC가 가리키는 메모리 주소의 명령어를 가져오는 단계는?

① 인출 사이클(Fetch Cycle)

② 간접 사이클(Indirect Cycle)

③ 실행 사이클(Execution Cycle)

④ 인터럽트 사이클(Interrupt Cycle)

<details>
<summary><b>정답 및 해설 보기</b></summary>

**정답** : ① 인출 사이클(Fetch Cycle)

**해설** :
인출 사이클은 **PC가 가리키는 메모리 주소에서 명령어를 읽어와 IR에 저장하는 단계**입니다.

**인출 사이클 상세 과정** :

```
1. PC → MAR (다음 명령어 주소를 MAR에 복사)
2. 메모리[MAR] → MBR (메모리에서 명령어 읽기)
3. MBR → IR (명령어를 IR에 저장)
4. PC = PC + 1 (PC 자동 증가)

```

**명령어 사이클 전체 흐름** :

- **인출** : 명령어를 메모리에서 가져옴
- **간접** : (선택적) 간접 주소 지정 시 유효 주소 계산
- **실행** : 명령어를 실제로 수행

</details>

### 퀴즈 9: 레지스터 종류

**문제** : 메모리에서 읽어온 데이터나 메모리에 쓸 데이터를 임시로 저장하는 레지스터는?

① 프로그램 카운터(PC)

② 명령어 레지스터(IR)

③ 메모리 주소 레지스터(MAR)

④ 메모리 버퍼 레지스터(MBR)

<details>
<summary><b>정답 및 해설 보기</b></summary>

**정답** : ④ 메모리 버퍼 레지스터(MBR)

**해설** :
메모리 버퍼 레지스터(MBR)는 **메모리와 CPU 사이의 데이터 교환 시 데이터를 임시 저장**하는 버퍼(완충) 역할을 합니다.

**메모리 접근 과정** :

**읽기 과정** :

```
1. MAR ← 읽을 주소 (예: 1000번지)
2. 메모리[1000] → MBR (데이터 임시 저장)
3. MBR → 목적지 레지스터

```

**쓰기 과정** :

```
1. MAR ← 쓸 주소 (예: 2000번지)
2. MBR ← 쓸 데이터 (데이터 임시 저장)
3. MBR → 메모리[2000]

```

**MAR vs MBR** :

- **MAR** : 주소 저장 (어디에 접근할지)
- **MBR** : 데이터 저장 (무엇을 읽고/쓸지)

</details>

### 퀴즈 10: 종합 문제

**문제** : 다음 중 옳지 **않은** 설명은?

① 스택은 함수 호출 시 복귀 주소를 저장하는 데 사용된다

② 큐는 FIFO 방식으로 동작하여 먼저 들어온 데이터가 먼저 나간다

③ ALU는 제어 신호를 생성하여 다른 부품들을 제어한다

④ 인터럽트가 발생하면 현재 작업 상태를 저장한 후 ISR을 실행한다

<details>
<summary><b>정답 및 해설 보기</b></summary>

**정답** : ③ ALU는 제어 신호를 생성하여 다른 부품들을 제어한다

**해설** :
**제어 신호를 생성하는 것은 제어장치의 역할**입니다. ALU는 연산을 수행하는 부품으로, 제어장치로부터 제어 신호를 **받아서** 어떤 연산을 수행할지 결정합니다.

**올바른 역할 구분** :

- **제어장치** : 명령어 해석 → 제어 신호 생성 → 각 부품에 전달
- **ALU** : 제어 신호 수신 → 연산 수행 → 결과 및 플래그 출력

  **나머지 선택지 검증** :

- ① **정답** : 함수 호출 시 복귀 주소를 스택에 PUSH, 함수 종료 시 POP
- ② **정답** : 큐는 선입선출(FIFO) 구조
- ④ **정답** : 인터럽트 처리 순서: 상태 저장 → ISR 실행 → 상태 복원 → 복귀

</details>
