## 1. CISC와 RISC

### 1-1. CISC (Complex Instruction Set Computer)

### 개념

CISC는 복잡하고 다양한 기능의 명령어 집합을 활용하는 컴퓨터 구조입니다. 대표적인 예로 x86, x86-64 계열의 ISA가 있으며, Intel과 AMD의 CPU가 이 방식을 채택하고 있습니다.

### 주요 특징

- **복잡한 명령어** : 하나의 명령어로 여러 작업을 동시에 처리 가능
- **가변 길이 명령어** : 명령어의 길이가 일정하지 않음
- **다양한 주소 지정 방식** : 프로그램이 메모리의 데이터를 참조하는 방법이 다양함
- **여러 클럭 사이클** : 하나의 명령어 실행에 여러 클럭이 필요
- **파이프라이닝 어려움** : 명령어 처리 과정의 병렬화가 복잡함

### 작동 방식

CISC는 메모리와 프로그램 간의 데이터 교환을 효율적으로 수행하기 위해 **매우 다양하고 복잡한 명령어**를 제공합니다. 예를 들어, 메모리에서 데이터를 읽고, 연산하고, 다시 저장하는 과정을 하나의 명령어로 처리할 수 있습니다.

```
# CISC 명령어 예시
ADD [메모리주소1], [메모리주소2]  # 메모리의 두 값을 더해서 저장

```

---

### 1-2. RISC (Reduced Instruction Set Computer)

### 개념

RISC는 단순하고 적은 수의 명령어로 구성된 컴퓨터 구조입니다. 명령어 실행 속도가 빠르고 효율적이며, 현대의 ARM 계열 프로세서가 대표적입니다.

### 주요 특징

- **단순하고 적은 명령어** : 기본적인 명령어만 제공
- **고정 길이 명령어** : 모든 명령어의 길이가 동일
- **적은 주소 지정 방식** : 명령어 구조가 단순함
- **1클럭 내외 실행** : 대부분의 명령어가 1개의 클럭 사이클에 실행
- **파이프라이닝 쉬움** : 명령어 처리 병렬화가 용이함

### Load-Store 구조

RISC는 **Load-Store 구조**를 사용합니다. 이는 메모리 접근은 `load`(읽기)와 `store`(쓰기) 명령어로만 수행하고, 연산은 레지스터에서만 처리하는 방식입니다.

```
# RISC 명령어 예시
LOAD R1, [메모리주소1]    # 메모리에서 레지스터로 값 로드
LOAD R2, [메모리주소2]    # 메모리에서 레지스터로 값 로드
ADD R3, R1, R2            # 레지스터 간 연산
STORE R3, [메모리주소3]   # 결과를 메모리에 저장

```

---

### 1-3. CISC vs RISC 비교표

| 구분                 | CISC                                 | RISC                                 |
| -------------------- | ------------------------------------ | ------------------------------------ |
| **명령어 복잡도**    | 복잡하고 다양한 명령어               | 단순하고 적은 명령어                 |
| **명령어 길이**      | 가변 길이                            | 고정 길이                            |
| **주소 지정 방식**   | 다양한 주소 지정 방식                | 적은 주소 지정 방식                  |
| **프로그램 크기**    | 프로그램을 이루는 명령어의 수가 적음 | 프로그램을 이루는 명령어의 수가 많음 |
| **명령어 실행 속도** | 여러 클럭에 걸쳐 실행                | 1클럭 내외로 실행                    |
| **파이프라이닝**     | 어려움                               | 쉬움                                 |
| **대표 사례**        | x86, x86-64 (Intel, AMD)             | ARM, RISC-V                          |

---

### 1-4. 사용 상황

### CISC 사용 사례

- 데스크톱 및 서버용 고성능 CPU
- 복잡한 연산이 많은 작업
- 기존 소프트웨어 호환성이 중요한 경우

### RISC 사용 사례

- 모바일 기기 (스마트폰, 태블릿)
- 임베디드 시스템
- 전력 효율이 중요한 IoT 기기
- 최신 서버 CPU (AWS Graviton 등)

## 2. RAM의 특징과 종류

### 2-1. RAM의 기본 개념

### RAM이란?

RAM (Random Access Memory)은 **휘발성 저장 장치**로, 프로그램과 데이터를 임시로 저장하는 메모리입니다. 컴퓨터가 작업을 수행하는 동안 CPU가 빠르게 접근할 수 있도록 데이터를 보관합니다.

### RAM의 특징

- **휘발성** : 전원이 꺼지면 저장된 데이터가 사라짐
- **빠른 속도** : 보조기억장치(HDD, SSD)보다 훨씬 빠름
- **임의 접근** : 어떤 위치의 데이터든 동일한 속도로 접근 가능
- **작업 공간** : CPU가 실행 중인 프로그램의 데이터를 일시적으로 저장

---

### 2-2. RAM의 용량과 성능

### 용량의 중요성

프로그램을 실행할 때 해당 프로그램의 데이터는 **보조기억장치(저장 공간)에서 RAM으로 이동**합니다. RAM 용량이 충분하면 여러 프로그램을 동시에 실행할 수 있지만, 부족하면 프로그램 실행 속도가 느려지거나 실행이 불가능합니다.

### RAM 용량 비유

- **작은 책상** : RAM 용량이 작으면 한 번에 펼칠 수 있는 자료가 적음
- **큰 책상** : RAM 용량이 크면 여러 자료를 동시에 펼쳐놓고 작업 가능

---

### 2-3. RAM의 종류

### DRAM (Dynamic RAM)

| 속성            | 설명                                                          |
| --------------- | ------------------------------------------------------------- |
| **의미**        | Dynamic (동적) RAM의 약자                                     |
| **재충전 필요** | 시간이 지나면 저장된 내용이 사라지므로 주기적으로 재충전 필요 |
| **속도**        | 상대적으로 느림                                               |
| **가격**        | 저렴함                                                        |
| **용량**        | 대용량                                                        |
| **사용 용도**   | 주기억장치(RAM)                                               |

**DRAM의 특징** :

- 시간이 지나면 자연스럽게 데이터가 사라지기 때문에 지속적으로 데이터를 다시 저장(재충전)해야 합니다
- 소비 전력이 크고 속도가 느리지만, 저렴하고 대용량 제작이 가능합니다

---

### SRAM (Static RAM)

| 속성            | 설명                                             |
| --------------- | ------------------------------------------------ |
| **의미**        | Static (정적) RAM의 약자                         |
| **재충전 필요** | 전원이 공급되는 동안 데이터 유지 (재충전 불필요) |
| **속도**        | 매우 빠름                                        |
| **가격**        | 비쌈                                             |
| **용량**        | 소용량                                           |
| **사용 용도**   | 캐시 메모리                                      |

**SRAM의 특징** :

- 전원이 공급되는 한 데이터가 유지되며 재충전이 필요 없음
- DRAM보다 훨씬 빠르지만 가격이 비싸고 집적도가 낮아 대용량 제작이 어려움
- CPU 내부의 캐시 메모리로 주로 사용됨

---

### SDRAM (Synchronous Dynamic RAM)

| 속성       | 설명                        |
| ---------- | --------------------------- |
| **의미**   | 클럭 신호와 동기화된 DRAM   |
| **동기화** | CPU와 클럭 신호를 맞춰 동작 |
| **속도**   | DRAM보다 빠름               |

**SDRAM의 발전** :

- **SDRAM → DDR SDRAM → DDR2 → DDR3 → DDR4 → DDR5**
- DDR (Double Data Rate): 대역폭(데이터 전송 속도)를 두 배로 늘린 SDRAM
- 숫자가 높을수록 더 빠른 속도와 낮은 전력 소비를 제공

---

### 2-4. RAM 종류 비교표

| 종류      | 재충전 | 속도          | 가격 | 용량     | 사용 용도       |
| --------- | ------ | ------------- | ---- | -------- | --------------- |
| **DRAM**  | 필요   | 느림          | 저렴 | 대용량   | 주기억장치(RAM) |
| **SRAM**  | 불필요 | 빠름          | 비쌈 | 소용량   | 캐시 메모리     |
| **SDRAM** | 필요   | DRAM보다 빠름 | 중간 | 중대용량 | 메인 메모리     |

## 3. 메모리의 주소 공간

### 3-1. 물리 주소와 논리 주소

### 물리 주소 (Physical Address)

- **정의** : 메모리 하드웨어가 사용하는 실제 메모리 주소
- **특징** : 메모리의 실제 위치를 나타냄
- **접근** : CPU와 메모리 사이에서 직접 사용

### 논리 주소 (Logical Address)

- **정의** : CPU가 실행 중인 프로그램이 사용하는 가상의 주소
- **특징** : 프로그램마다 독립적인 주소 공간을 가짐
- **변환** : MMU(Memory Management Unit)를 통해 물리 주소로 변환됨

---

### 3-2. 물리 주소와 논리 주소의 관계

### 주소 변환 과정

1. CPU가 논리 주소를 생성
2. MMU(Memory Management Unit)가 논리 주소를 물리 주소로 변환
3. 메모리에서 실제 데이터를 읽거나 씀

```
[CPU] → 논리 주소 → [MMU] → 물리 주소 → [메모리]

```

### MMU (Memory Management Unit)

- CPU와 메모리 사이에 위치한 하드웨어
- 논리 주소를 물리 주소로 변환하는 역할
- 메모리 보호 및 가상 메모리 지원

---

### 3-3. 베이스 레지스터 방식

### 개념

CPU가 발생시킨 논리 주소에 **베이스 레지스터 값을 더해** 물리 주소를 계산하는 방식입니다.

### 계산 공식

```
물리 주소 = 베이스 레지스터 값 + 논리 주소

```

### 예시

- 베이스 레지스터 값: 15000
- 논리 주소: 100
- **물리 주소 = 15000 + 100 = 15100**

### 작동 흐름

```
프로그램 C의 시작 주소: 15000

CPU → 논리 주소 100 → MMU (베이스 레지스터: 15000)
→ 물리 주소 15100 → 메모리의 15100번지 접근

```

---

### 3-4. 메모리 보호 기법

### 한계 레지스터 (Limit Register)

- **목적** : 프로그램이 다른 프로그램의 메모리 영역을 침범하지 못하도록 보호
- **작동 방식** : 논리 주소가 한계 레지스터 값을 초과하면 인터럽트 발생

### 예시

- 한계 레지스터 값: 1000
- CPU가 논리 주소 1100을 요청
- **결과** : 범위를 벗어났으므로 **인터럽트 발생** → 프로그램 강제 종료

### 보호 흐름

```
CPU → 논리 주소 → MMU
→ 논리 주소 < 한계 레지스터?
   → Yes: 베이스 레지스터 + 논리 주소 = 물리 주소
   → No: 인터럽트 발생

```

---

### 3-5. 메모리 주소 지정 방식 비교표

| 방식                | 설명                          | 장점                 | 단점                  |
| ------------------- | ----------------------------- | -------------------- | --------------------- |
| **물리 주소**       | 메모리의 실제 위치            | 빠른 접근            | 프로그램 간 충돌 가능 |
| **논리 주소**       | 프로그램이 사용하는 가상 주소 | 독립적인 메모리 공간 | 주소 변환 필요        |
| **베이스 레지스터** | 논리 주소 + 베이스 값         | 간단한 구현          | 연속된 메모리 필요    |
| **한계 레지스터**   | 논리 주소 범위 제한           | 메모리 보호          | 추가 하드웨어 필요    |

## 4. 캐시 메모리

### 4-1. 캐시 메모리의 개념

### 정의

캐시 메모리는 **CPU와 RAM 사이에 위치**하여 자주 사용되는 데이터를 임시로 저장하는 고속 메모리입니다. SRAM으로 구성되어 있으며, CPU가 메모리에 접근하는 시간을 단축시키는 역할을 합니다.

### 필요성

- CPU의 연산 속도는 매우 빠르지만, RAM의 속도는 상대적으로 느림
- CPU가 RAM에서 데이터를 가져오는 동안 대기 시간 발생
- 캐시 메모리를 사용하면 자주 사용하는 데이터를 빠르게 접근 가능

---

### 4-2. 저장 장치 계층 구조

### 계층 구조 피라미드

```
          ▲ 빠름, 비쌈, 작은 용량
          │
    ┌─────────┐
    │ 레지스터 │ ← CPU 내부
    ├─────────┤
    │  캐시   │ ← SRAM (L1, L2, L3)
    ├─────────┤
    │   RAM   │ ← DRAM (메인 메모리)
    ├─────────┤
    │보조기억장치│ ← HDD, SSD
    └─────────┘
          │
          ▼ 느림, 저렴, 큰 용량

```

### 각 계층의 특징

| 계층                  | 속도      | 용량      | 가격      | 위치           |
| --------------------- | --------- | --------- | --------- | -------------- |
| **레지스터**          | 가장 빠름 | 가장 작음 | 가장 비쌈 | CPU 내부       |
| **캐시 (L1, L2, L3)** | 매우 빠름 | 작음      | 비쌈      | CPU 내부/근처  |
| **RAM**               | 빠름      | 중간      | 보통      | 메인보드       |
| **보조기억장치**      | 느림      | 큼        | 저렴      | 외부 저장 장치 |

---

### 4-3. 저장 장치 계층 구조의 원리

### 1. CPU는 가까운 저장 장치부터 데이터를 찾음

- 레지스터 → 캐시 → RAM → 보조기억장치 순으로 탐색

### 2. 속도가 빠른 저장 장치는 용량이 작고, 가격이 비쌈

- 레지스터와 캐시는 용량은 작지만 속도가 매우 빠름

### 3. 자주 사용하는 데이터를 상위 계층에 저장

- 캐시 히트(Cache Hit): 캐시에서 데이터를 찾는 경우
- 캐시 미스(Cache Miss): 캐시에 데이터가 없어 RAM에서 가져오는 경우

---

### 4-4. 캐시 메모리의 계층 구조

### L1, L2, L3 캐시

```
   CPU 코어
      │
   ┌──┴──┐
   │ L1  │ ← 가장 빠르고 작음 (코어 내부)
   ├─────┤
   │ L2  │ ← 중간 속도와 용량 (코어 내부 또는 근처)
   ├─────┤
   │ L3  │ ← 상대적으로 느리고 큼 (여러 코어가 공유)
   └─────┘
      │
    RAM

```

### 캐시 계층별 특징

| 캐시 레벨   | 위치               | 속도            | 용량                   | 공유 여부             |
| ----------- | ------------------ | --------------- | ---------------------- | --------------------- |
| **L1 캐시** | CPU 코어 내부      | 가장 빠름       | 가장 작음 (수십 KB)    | 코어별 독립           |
| **L2 캐시** | CPU 코어 내부/근처 | 빠름            | 중간 (수백 KB ~ 수 MB) | 코어별 독립 또는 공유 |
| **L3 캐시** | CPU 칩 내부        | 상대적으로 느림 | 큼 (수 MB ~ 수십 MB)   | 여러 코어 공유        |

---

### 4-5. 캐시 메모리 작동 원리

### 참조 지역성의 원리 (Locality of Reference)

캐시 메모리는 **참조 지역성의 원리**에 기반하여 동작합니다.

### 1. 시간 지역성 (Temporal Locality)

- CPU가 최근에 접근한 메모리는 **가까운 시간 내에 다시 접근할 가능성이 높음**

  **예시** :

```c
int sum = 0;
for (int i = 0; i < 100; i++) {
    sum += i;  // sum 변수는 반복문 내에서 계속 사용됨
}

```

### 2. 공간 지역성 (Spatial Locality)

- CPU가 접근한 메모리 근처의 데이터도 **곧 접근할 가능성이 높음**

  **예시** :

```c
int arr[100];
for (int i = 0; i < 100; i++) {
    arr[i] = i;  // 배열의 연속된 요소에 순차적으로 접근
}

```

---

### 4-6. 캐시 히트와 캐시 미스

### 캐시 히트 (Cache Hit)

- CPU가 필요한 데이터를 캐시에서 찾은 경우
- 빠르게 데이터를 가져올 수 있음

### 캐시 미스 (Cache Miss)

- CPU가 필요한 데이터를 캐시에서 찾지 못한 경우
- RAM에서 데이터를 가져와 캐시에 저장

### 캐시 적중률 (Cache Hit Rate)

- 전체 메모리 접근 중 캐시 히트가 발생한 비율
- 일반적으로 85~95% 수준
- 적중률이 높을수록 CPU 성능 향상

```
캐시 적중률 = (캐시 히트 횟수) / (전체 메모리 접근 횟수) × 100

```

---

### 4-7. 캐시 메모리의 예시 코드

### 시간 지역성 예시

| 코드                                                    | 설명                                  | 시간 지역성 |
| ------------------------------------------------------- | ------------------------------------- | ----------- |
| `for (int i = 0; i < 9; i++) { printf("%d\\n", num); }` | `num`변수가 반복문 내에서 계속 사용됨 | **높음**    |

### 공간 지역성 예시

| 코드                                                          | 설명                           | 공간 지역성 |
| ------------------------------------------------------------- | ------------------------------ | ----------- |
| `int arr[100]; for (int i = 0; i < 100; i++) { arr[i] = i; }` | 배열의 연속된 요소에 순차 접근 | **높음**    |

---

### 4-8. 최종 지역성 원리

### 공간 지역성 적용

CPU가 워드 프로세서 프로그램을 실행할 때:

1. 프로그램의 **일부 공간 근처**에 있는 공간(근처 공간)을 집중적으로 참조
2. 사용자가 입력을 할 때 **업데이트 기능**이 모여 있는 메모리 위치를 반복 사용
3. 워드 프로세서의 코드 프로그램이 자동으로 열림 기능을 사용

캐시 메모리는 이렇듯 **참조 지역성의 원리**에 입각하여 CPU가 사용할 법한 데이터를 예측합니다.

## 📌 핵심 요약본

### ⚡ CISC vs RISC 핵심

- **CISC** : 복잡한 명령어, 가변 길이, 여러 클럭, 파이프라이닝 어려움 (Intel, AMD)
- **RISC** : 단순한 명령어, 고정 길이, 1클럭 실행, 파이프라이닝 쉬움 (ARM)

### 💾 RAM 핵심

- **DRAM** : 재충전 필요, 느림, 저렴, 대용량 → 메인 메모리
- **SRAM** : 재충전 불필요, 빠름, 비쌈, 소용량 → 캐시 메모리
- **SDRAM** : 클럭 동기화 DRAM (DDR, DDR2, DDR3, DDR4, DDR5)

### 🗺️ 메모리 주소 핵심

- **물리 주소** : 메모리의 실제 위치
- **논리 주소** : 프로그램이 사용하는 가상 주소
- **MMU** : 논리 주소 → 물리 주소 변환
- **베이스 레지스터** : 물리 주소 = 베이스 값 + 논리 주소
- **한계 레지스터** : 메모리 보호 (범위 초과 시 인터럽트)

### 🚀 캐시 메모리 핵심

- **역할** : CPU와 RAM 사이의 고속 버퍼
- **계층** : L1 (가장 빠름) → L2 → L3 → RAM
- **참조 지역성** : 시간 지역성 + 공간 지역성
- **캐시 히트** : 캐시에서 데이터 발견 (빠름)
- **캐시 미스** : 캐시에서 데이터 미발견 → RAM 접근 (느림)

## ✅ 복습용 퀴즈

### 문제 1: CISC와 RISC의 차이

**Q. 다음 중 RISC의 특징으로 올바른 것은?**

① 복잡하고 다양한 명령어를 사용한다

② 명령어의 길이가 가변적이다

③ 하나의 명령어가 여러 클럭 사이클에 걸쳐 실행된다

④ 모든 명령어의 길이가 동일하다

**정답: ④**

**해설** : RISC는 단순하고 적은 수의 명령어를 사용하며, 모든 명령어의 길이가 고정되어 있습니다. 이는 파이프라이닝을 쉽게 만들고, 대부분의 명령어가 1클럭 내외에 실행될 수 있도록 합니다. ①②③은 CISC의 특징입니다.

---

### 문제 2: RAM의 종류

**Q. SRAM의 특징으로 올바르지 않은 것은?**

① 전원이 공급되는 동안 데이터가 유지된다

② DRAM보다 속도가 빠르다

③ 저렴하고 대용량 제작이 가능하다

④ 주로 캐시 메모리로 사용된다

**정답: ③**

**해설** : SRAM은 빠르지만 가격이 비싸고 집적도가 낮아 대용량 제작이 어렵습니다. 저렴하고 대용량 제작이 가능한 것은 DRAM의 특징입니다. SRAM은 빠른 속도 덕분에 캐시 메모리로 주로 사용됩니다.

---

### 문제 3: 메모리 주소 지정

**Q. 베이스 레지스터 값이 20000이고, CPU가 논리 주소 500을 요청했을 때 물리 주소는?**

① 19500

② 20000

③ 20500

④ 25000

**정답: ③**

**해설** : 물리 주소는 "베이스 레지스터 값 + 논리 주소"로 계산됩니다. 따라서 20000 + 500 = 20500이 물리 주소가 됩니다.

---

### 문제 4: MMU의 역할

**Q. MMU(Memory Management Unit)의 주요 역할은?**

① 데이터를 압축하여 저장한다

② 논리 주소를 물리 주소로 변환한다

③ 프로그램을 컴파일한다

④ 네트워크 통신을 관리한다

**정답: ②**

**해설** : MMU는 CPU와 메모리 사이에 위치하여 논리 주소를 물리 주소로 변환하는 역할을 합니다. 이를 통해 프로그램마다 독립적인 메모리 공간을 제공하고, 메모리 보호 기능을 수행합니다.

---

### 문제 5: 한계 레지스터

**Q. 한계 레지스터의 역할은?**

① 프로그램의 실행 속도를 높인다

② 프로그램이 다른 프로그램의 메모리 영역을 침범하지 못하도록 보호한다

③ 논리 주소를 물리 주소로 변환한다

④ 캐시 메모리의 크기를 결정한다

**정답: ②**

**해설** : 한계 레지스터는 논리 주소의 최대 범위를 설정하여, 프로그램이 허용된 메모리 범위를 벗어나지 못하도록 보호하는 역할을 합니다. 범위를 초과하면 인터럽트가 발생하여 프로그램이 강제 종료됩니다.

---

### 문제 6: 캐시 메모리의 위치

**Q. 다음 중 캐시 메모리에 대한 설명으로 올바른 것은?**

① CPU와 보조기억장치 사이에 위치한다

② DRAM으로 구성되어 있다

③ CPU와 RAM 사이에 위치하며 SRAM으로 구성되어 있다

④ 전원이 꺼져도 데이터가 유지된다

**정답: ③**

**해설** : 캐시 메모리는 CPU와 RAM 사이에 위치하며, 빠른 속도의 SRAM으로 구성되어 있습니다. 자주 사용되는 데이터를 임시 저장하여 CPU의 메모리 접근 시간을 단축시킵니다.

---

### 문제 7: 저장 장치 계층 구조

**Q. 저장 장치 계층 구조에서 가장 빠르지만 용량이 작은 것은?**

① RAM

② 캐시 메모리

③ 레지스터

④ SSD

**정답: ③**

**해설** : 레지스터는 CPU 내부에 위치하여 가장 빠른 속도를 자랑하지만, 용량이 가장 작고 가격이 가장 비쌉니다. 계층 구조는 레지스터 → 캐시 → RAM → 보조기억장치 순입니다.

---

### 문제 8: 캐시 계층

**Q. CPU 코어 내부에 위치하며 가장 빠른 캐시는?**

① L1 캐시

② L2 캐시

③ L3 캐시

④ L4 캐시

**정답: ①**

**해설** : L1 캐시는 CPU 코어 내부에 위치하며 가장 빠른 속도를 제공합니다. 하지만 용량은 가장 작습니다. L2는 중간, L3는 여러 코어가 공유하며 상대적으로 느리지만 용량이 큽니다.

---

### 문제 9: 참조 지역성

**Q. 다음 중 시간 지역성(Temporal Locality)의 예시는?**

① 배열의 연속된 요소에 순차적으로 접근

② 반복문에서 동일한 변수를 계속 사용

③ 함수 호출 시 스택 메모리 사용

④ 랜덤하게 메모리에 접근

**정답: ②**

**해설** : 시간 지역성은 최근에 접근한 데이터가 가까운 시간 내에 다시 접근될 가능성이 높다는 원리입니다. 반복문에서 동일한 변수를 계속 사용하는 것이 대표적인 예시입니다. ①은 공간 지역성의 예시입니다.

---

### 문제 10: 캐시 히트

**Q. CPU가 필요한 데이터를 캐시에서 찾지 못한 경우를 무엇이라고 하는가?**

① 캐시 히트 (Cache Hit)

② 캐시 미스 (Cache Miss)

③ 캐시 오류 (Cache Error)

④ 캐시 충돌 (Cache Conflict)

**정답: ②**

**해설** : 캐시 미스는 CPU가 필요한 데이터를 캐시에서 찾지 못해 RAM에서 데이터를 가져와야 하는 상황입니다. 반대로 캐시에서 데이터를 찾은 경우를 캐시 히트라고 합니다.

---

### 문제 11: SDRAM의 발전

**Q. DDR SDRAM에서 DDR은 무엇을 의미하는가?**

① Dynamic Data RAM

② Double Data Rate

③ Direct Data Read

④ Dual Data Range

**정답: ②**

**해설** : DDR은 "Double Data Rate"의 약자로, 기존 SDRAM보다 대역폭(데이터 전송 속도)을 두 배로 늘린 기술입니다. DDR → DDR2 → DDR3 → DDR4 → DDR5로 발전하며 속도가 계속 향상되고 있습니다.

---

### 문제 12: 공간 지역성

**Q. 다음 코드에서 적용되는 참조 지역성의 원리는?**

```c
int arr[100];
for (int i = 0; i < 100; i++) {
    arr[i] = i * 2;
}

```

① 시간 지역성

② 공간 지역성

③ 순차 지역성

④ 랜덤 지역성

**정답: ②**

**해설** : 공간 지역성은 CPU가 접근한 메모리 근처의 데이터도 곧 접근할 가능성이 높다는 원리입니다. 배열의 연속된 요소에 순차적으로 접근하는 코드는 공간 지역성의 대표적인 예시입니다.
