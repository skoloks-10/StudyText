# 14-2. 페이징을 통한 가상 메모리 관리

## 1. 가상 메모리와 페이징 기본 개념

### 1.1 시작하기 전에

프로세스를 메모리에 연속적으로 할당하는 방식은 두 가지 문제를 내포하고 있습니다.

- 첫째, 외부 단편화가 발생합니다
- 둘째, 프로세스를 반드시 메모리에 연속적으로 할당해야 한다면 메모리보다 큰 프로그램은 적재할 수 없습니다

4GB 메모리가 설치된 컴퓨터로는 4GB 이상의 프로그램을 실행할 수 없게 됩니다.

### 1.2 가상 메모리(Virtual Memory)의 개념

**가상 메모리**는 실행하고자 하는 프로그램을 일부만 메모리에 적재하여 실제 물리 메모리 크기보다 큰 프로세스를 실행할 수 있게 하는 기술입니다.

이를 가능하게 하는 가상 메모리 관리 기법에는:

- **페이징(Paging)** : 가상 메모리와 실제 메모리를 일정한 크기의 작은 단위(페이지)로 나누어 관리
- **세그멘테이션(Segmentation)** : 프로세스를 논리적 단위(세그먼트)로 나누어 메모리에 배치

### 1.3 페이징의 이점

페이징을 사용할 경우:

- 연속된 메모리 할당 방식에 의한 단편화를 해결
- 프로세스 전체를 메모리에 올릴 필요가 없으므로 물리적 메모리보다 큰 프로세스 실행 가능
- 외부 단편화 문제 해결 (내부 단편화는 발생 가능)

---

## 2. 페이징 시스템의 구성 요소

### 2.1 프로세스와 페이지

**프로세스의 논리 주소 공간**은 페이지(Page)라는 일정한 단위로 나뉩니다.

- 프로세스 A가 30MB라면, 페이지 크기가 10MB일 경우 3개의 페이지로 나뉩니다
- 각 페이지는 페이지 1, 페이지 2, 페이지 3과 같이 번호가 매겨집니다

### 2.2 물리 메모리와 프레임

**물리 메모리의 물리 주소 공간**은 프레임(Frame)이라는 일정한 단위로 나뉩니다.

- 프레임의 크기는 페이지의 크기와 동일합니다
- 프로세스 A의 메모리를 프레임별로 나누면: 프로세스 A 프레임 1, 프로세스 A 프레임 2 등으로 구성

  **주의사항** :

- 논리 주소는 페이지 단위로 구성
- 물리 주소는 프레임 단위로 구성
- 페이지와 프레임은 크기가 같지만 서로 다른 개념

### 2.3 페이지와 프레임의 관계

프로세스를 이루는 페이지는 프로세스 실행 과정에서 메모리의 프레임에 적재됩니다.

**특징** :

- 페이지들이 메모리 프레임에 분산되어 적재 가능
- 논리적으로 연속된 페이지라도 물리 메모리상에서는 떨어져 있을 수 있음
- 스왑 공간(하드디스크의 일부 영역)에 있는 페이지도 존재 가능

## 3. 페이지 테이블(Page Table)

### 3.1 페이지 테이블의 역할

페이지 테이블은 페이지와 프레임을 대응시키는 자료구조입니다.

**구성** :

- 각 프로세스마다 고유한 페이지 테이블 보유
- CPU가 프로세스 내 페이지를 참조하면, 해당 페이지가 어느 프레임에 적재되어 있는지 페이지 테이블을 통해 확인
- 프로세스가 메모리에 불연속적으로 배치되어도 CPU가 올바른 위치 접근 가능

### 3.2 페이지 테이블의 저장 위치

페이지 테이블은 CPU 내부가 아니라 메모리에 저장됩니다.

**이유** :

- CPU 내의 공간은 한정적
- 프로세스 수가 많아질수록 페이지 테이블도 증가
- 메모리에 페이지 테이블을 저장하여 공간 효율성 확보

### 3.3 페이지 테이블 베이스 레지스터(PTBR)

**PTBR (Page Table Base Register)** :

- 프로세스별 페이지 테이블이 적재된 메모리 주소를 가리킴
- CPU 내부에 위치
- 각 프로세스의 페이지 테이블 시작 주소 저장

  **프로세스 문맥 교환 시** :

- CPU가 실행할 프로세스가 바뀌면 PTBR 값도 변경
- 이를 통해 각 프로세스의 페이지 테이블 위치 파악

### 3.4 페이지 테이블 항목(Page Table Entry)

페이지 테이블의 각 행을 **페이지 테이블 엔트리(PTE, Page Table Entry)**라고 합니다.

---

## 4. 페이지 테이블 엔트리의 구조

### 4.1 페이지 번호와 프레임 번호

가장 기본적인 페이지 테이블 엔트리 구성:

```
| 페이지 번호 | 프레임 번호 |

```

**동작 원리** :

- CPU는 논리 주소의 페이지 번호로 페이지 테이블 접근
- 해당 페이지가 적재된 물리 메모리의 프레임 번호 확인
- 프레임 번호를 통해 물리 주소 계산

### 4.2 페이지 테이블 엔트리의 추가 정보

실제 페이지 테이블 엔트리는 프레임 번호 외에도 여러 정보를 포함합니다:

```
| 페이지 번호 | 프레임 번호 | 유효 비트 | 보호 비트 | 참조 비트 | 수정 비트 |

```

### 4.2.1 유효 비트(Valid Bit)

**역할** :

- 페이지가 현재 메모리에 적재되어 있는지 여부 표시
- 1: 페이지가 메모리에 적재됨
- 0: 페이지가 스왑 영역에 있음

  **페이지 폴트(Page Fault)** :

- 유효 비트가 0인 페이지에 접근하려 할 때 발생하는 예외
- 스왑 영역의 페이지를 메모리로 적재하는 과정 필요

### 4.2.2 보호 비트(Protection Bit)

**역할** :

- 페이지 접근 권한 제어
- 읽기(Read), 쓰기(Write), 실행(Execute) 권한 표시

  **비트 구성 예시** :

```
| r | w | x |

```

- r=1, w=0, x=0: 읽기 전용
- r=1, w=1, x=1: 읽기, 쓰기, 실행 모두 가능

  **주의** :

- 보호 비트를 위반하면 CPU는 해당 페이지에 접근 불가
- 운영체제가 예외 처리

### 4.2.3 참조 비트(Reference Bit)

**역할** :

- 페이지 접근 여부 기록
- CPU가 페이지를 읽거나 실행하면 1로 설정
- 페이지 교체 알고리즘에서 활용

### 4.2.4 수정 비트(Modified Bit / Dirty Bit)

**역할** :

- 페이지 내용 변경 여부 기록
- 쓰기 작업이 발생하면 1로 설정
- 페이지를 스왑 아웃할 때:
  - 수정 비트가 0이면 메모리에서 삭제만 하면 됨
  - 수정 비트가 1이면 변경 내용을 스왑 영역에 기록 후 삭제

## 5. 페이징에서의 주소 변환

### 5.1 논리 주소의 구성

페이징 시스템에서 하나의 페이지 내 주소를 나타내는 방법:

**페이지 번호 + 변위(Offset)**

- 페이지 번호: 어떤 페이지인지 지정
- 변위: 페이지 내에서의 위치

  **예시** :

- CPU가 5번 페이지의 2번째 바이트 접근하려면
- 논리 주소: 페이지 번호(5) + 변위(2)

### 5.2 물리 주소의 구성

프레임 내 주소 표현 방법:

**프레임 번호 + 변위(Offset)**

- 프레임 번호: 어떤 프레임인지 지정
- 변위: 프레임 내에서의 위치

  **핵심** : 논리 주소의 변위와 물리 주소의 변위는 동일합니다.

### 5.3 주소 변환 과정

1. CPU가 페이지 번호와 변위를 포함한 논리 주소 생성
2. 페이지 테이블을 통해 페이지 번호를 프레임 번호로 변환
3. 프레임 번호와 동일한 변위를 결합하여 물리 주소 완성

---

## 6. 내부 단편화(Internal Fragmentation)

### 6.1 내부 단편화의 개념

**내부 단편화**는 페이징 시스템에서 프로세스에 할당된 페이지 내에서 사용되지 않고 남는 메모리 공간을 의미합니다.

**발생 원인** :

- 프로세스 크기가 페이지 크기의 정확한 배수가 아닌 경우 발생
- 마지막 페이지에서 사용하지 않는 공간이 낭비됨

### 6.2 내부 단편화 예시

프로세스 크기가 10KB이고 페이지 크기가 4KB인 경우:

- 필요한 페이지 수: 3개 (4KB + 4KB + 2KB)
- 할당된 메모리: 12KB (4KB × 3)
- 내부 단편화: 2KB (마지막 페이지에서 4KB 중 2KB만 사용)

  **일반 공식** :

```
프로세스 크기 = n개의 완전한 페이지 + r바이트
내부 단편화 크기 = 페이지 크기 - r바이트

```

### 6.3 내부 단편화와 외부 단편화 비교

**외부 단편화** :

- 메모리 공간이 여러 조각으로 나뉘어져 사용 불가능한 상태
- 연속 메모리 할당 방식에서 발생
- 페이징이 해결

  **내부 단편화** :

- 할당된 메모리 내부에서 사용되지 않는 공간
- 페이징 시스템에서 발생
- 페이지 크기를 작게 하면 감소하지만 페이지 테이블 크기 증가

### 6.4 내부 단편화 최소화 방법

1. **적절한 페이지 크기 선택** : 너무 크지도 작지도 않은 크기
2. **가변 페이지 크기** : 일부 시스템에서 여러 페이지 크기 지원
3. **trade-off 고려** : 페이지 크기 ↓ → 내부 단편화 ↓, 페이지 테이블 크기 ↑

## 7. TLB (Translation Lookaside Buffer)

### 7.1 페이징의 성능 문제

기본 페이징 시스템에서 주소 변환 시 **이중 메모리 접근** 문제가 발생합니다:

1. 페이지 테이블 접근을 위한 메모리 접근
2. 실제 데이터 접근을 위한 메모리 접근

**결과** : 메모리 접근 시간이 2배로 증가하여 성능 저하

### 7.2 TLB의 개념

- \*TLB (Translation Lookaside Buffer)\*\*는 페이지 테이블의 캐시 메모리입니다.

  **특징** :

- CPU 내부 또는 MMU(Memory Management Unit) 내에 위치
- 최근에 사용된 페이지 번호와 프레임 번호 쌍을 저장
- 매우 빠른 하드웨어로 구성
- 페이지 테이블의 일부만 저장 (전체 저장 불가)

### 7.3 TLB의 동작 원리

**주소 변환 과정** :

1. CPU가 논리 주소 생성
2. TLB에서 해당 페이지 번호 검색
3. **TLB 히트(Hit)** :

- TLB에 페이지 번호가 있으면 즉시 프레임 번호 획득
- 메모리 접근 1회만 필요 (실제 데이터 접근)

1. **TLB 미스(Miss)** :

- TLB에 페이지 번호가 없으면 페이지 테이블 접근
- 메모리 접근 2회 필요 (페이지 테이블 + 실제 데이터)
- 페이지 테이블에서 찾은 정보를 TLB에 저장

### 7.4 TLB의 구조

```
| 페이지 번호 | 프레임 번호 |
|------------|------------|
|     0      |     5      |
|     1      |     4      |
|     2      |     6      |
|    ...     |    ...     |

```

**참고** : TLB는 페이지 테이블 엔트리의 일부만 저장하므로 크기가 작습니다.

### 7.5 TLB 히트율(Hit Rate)

**TLB 히트율** : TLB에서 페이지 정보를 찾는 비율

```
히트율 = TLB에서 찾은 횟수 / 전체 메모리 참조 횟수 × 100%

```

**실효 메모리 접근 시간(EAT, Effective Access Time)** :

```
EAT = (TLB 히트율 × TLB 접근 시간 + 메모리 접근 시간)
    + (TLB 미스율 × TLB 접근 시간 + 페이지 테이블 접근 시간 + 메모리 접근 시간)

```

**예시** :

- TLB 접근 시간: 1ns
- 메모리 접근 시간: 100ns
- TLB 히트율: 99%

```
EAT = 0.99 × (1 + 100) + 0.01 × (1 + 100 + 100)
    = 99.99 + 2.01
    = 102ns

```

### 7.6 TLB 미스 처리

**TLB 미스 시 동작** :

1. 페이지 테이블에서 페이지 번호에 해당하는 프레임 번호 검색
2. 프레임 번호를 사용하여 물리 주소 계산
3. 해당 페이지 정보를 TLB에 저장 (지역성 원리 활용)
4. TLB가 가득 찬 경우 교체 알고리즘 사용 (LRU, FIFO 등)

### 7.7 TLB와 문맥 교환

**문맥 교환 시 TLB 처리** :

- 프로세스가 바뀌면 TLB 내용도 해당 프로세스의 것으로 변경 필요
- **방법 1** : TLB 플러시(Flush) - 모든 항목 삭제
- **방법 2** : ASID(Address Space Identifier) 사용 - 프로세스 식별자 추가

  **ASID를 사용한 TLB 구조** :

```
| ASID | 페이지 번호 | 프레임 번호 |
|------|------------|------------|
| P1   |     0      |     5      |
| P2   |     0      |     8      |
| P1   |     1      |     4      |

```

## 8. 페이징의 이점과 문제점

### 8.1 쓰기 시 복사(Copy on Write)

**개념** :

- 프로세스를 fork하여 부모 프로세스와 자식 프로세스 생성 시
- 처음에는 같은 프레임 공유
- 페이지 내용 수정이 발생할 때만 페이지 복사

  **장점** :

- 메모리 절약
- 프로세스 생성 시간 단축

### 8.2 계층적 페이징(Hierarchical Paging)

**문제 상황** :

- 프로세스 크기가 커질수록 페이지 테이블도 증가
- 모든 페이지 테이블을 항상 메모리에 유지하면 메모리 낭비

  **해결 방법** : 계층적 페이징

- 페이지 테이블을 여러 단계로 나눔
- Outer 페이지 테이블과 Inner 페이지 테이블로 구성
- 필요한 페이지 테이블만 메모리에 적재

  **동작** :

1. Outer 페이지 테이블의 페이지 테이블 엔트리 확인
2. 해당 Inner 페이지 테이블이 메모리에 있는지 유효 비트로 확인
3. Inner 페이지 테이블을 통해 최종 프레임 번호 획득

### 8.3 역 페이지 테이블(Inverted Page Table)

**기존 페이지 테이블의 문제** :

- 프로세스마다 페이지 테이블 존재
- 여러 프로세스 실행 시 메모리 공간 낭비

  **역 페이지 테이블 구조** :

```
| 프로세스 번호 | 페이지 번호 |

```

**특징** :

- 시스템 전체에 하나의 페이지 테이블만 존재
- 프레임 번호를 인덱스로 사용
- 각 엔트리는 해당 프레임에 적재된 프로세스와 페이지 정보 저장

  **바깥 페이지 번호와 안쪽 페이지 번호** :

- 바깥 페이지 번호: CPU가 접근한 페이지 번호 (논리 주소)
- 안쪽 페이지 번호: 프레임에 실제 적재된 페이지 번호

---

## 9. 스와핑과 페이지 교체

### 9.1 요구 페이징(Demand Paging)

**개념** :

- 처음부터 모든 페이지를 메모리에 적재하지 않음
- 필요한 페이지만 메모리에 적재
- 당장 실행에 필요한 페이지만 메모리에 올림

  **장점** :

- 메모리 공간 효율적 사용
- 프로세스 실행 속도 향상

### 9.2 페이지 교체 알고리즘

메모리가 가득 찬 상태에서 새로운 페이지를 적재해야 할 때, 어떤 페이지를 스왑 아웃할지 결정하는 알고리즘입니다.

---

## 핵심 요약

1. **가상 메모리**는 프로세스를 페이지 단위로 나누어 물리 메모리보다 큰 프로세스 실행 가능하게 함
2. **페이징**은 외부 단편화 문제를 해결하고 물리 메모리를 효율적으로 사용
3. **내부 단편화**는 페이지 내에서 사용되지 않는 공간으로, 페이징 시스템의 단점
4. **페이지 테이블**은 논리 주소의 페이지를 물리 주소의 프레임으로 변환
5. **PTBR**은 현재 실행 중인 프로세스의 페이지 테이블 위치를 가리킴
6. 페이지 테이블 엔트리는 **유효 비트, 보호 비트, 참조 비트, 수정 비트** 등을 포함
7. **TLB**는 페이지 테이블의 캐시로, 주소 변환 속도를 향상시킴
8. **TLB 히트**는 TLB에서 정보를 찾는 경우, **TLB 미스**는 페이지 테이블 접근이 필요한 경우
9. **논리 주소**는 페이지 번호와 변위로, **물리 주소**는 프레임 번호와 변위로 구성
10. **계층적 페이징**과 **역 페이지 테이블**은 페이지 테이블 크기 문제를 해결
11. **요구 페이징**은 필요한 페이지만 메모리에 적재하여 효율성 향상

### 문제 1

페이징 시스템에서 프로세스의 논리 주소 공간을 나누는 단위를 무엇이라고 하는가?

1. 세그먼트(Segment)
2. 페이지(Page)
3. 프레임(Frame)
4. 블록(Block)
5. 섹터(Sector)

**정답** : 2번
**해설** : 프로세스의 논리 주소 공간은 페이지라는 일정한 크기의 단위로 나뉩니다. 프레임은 물리 메모리를 나누는 단위이며, 페이지와 프레임은 크기가 같지만 서로 다른 개념입니다.

---

### 문제 2

페이지 테이블이 저장되는 위치는 어디인가?

1. CPU 레지스터
2. 캐시 메모리
3. 주 메모리(RAM)
4. 하드디스크
5. ROM

**정답** : 3번
**해설** : 페이지 테이블은 CPU 내부가 아니라 메모리에 저장됩니다. CPU의 공간은 한정적이고 프로세스가 많아질수록 페이지 테이블도 증가하기 때문입니다. CPU 내부에는 PTBR이라는 레지스터가 페이지 테이블의 시작 주소를 가리킵니다.

---

### 문제 3

페이지 폴트(Page Fault)가 발생하는 경우는?

1. 페이지 크기가 너무 클 때
2. 프레임 번호가 잘못되었을 때
3. 유효 비트가 0인 페이지에 접근할 때
4. 보호 비트가 설정되지 않았을 때
5. 페이지 테이블이 손상되었을 때

**정답** : 3번
**해설** : 페이지 폴트는 CPU가 접근하려는 페이지가 현재 메모리에 없을 때 발생합니다. 유효 비트가 0이면 해당 페이지는 스왑 영역에 있다는 의미이며, 이 페이지에 접근하려 하면 페이지 폴트 예외가 발생하여 운영체제가 해당 페이지를 메모리로 적재합니다.

---

### 문제 4

내부 단편화(Internal Fragmentation)에 대한 설명으로 올바른 것은?

1. 연속 메모리 할당 방식에서만 발생한다
2. 페이지 크기를 크게 하면 줄어든다
3. 페이지 내에서 사용되지 않고 남는 공간이다
4. 페이징 시스템에서는 전혀 발생하지 않는다
5. 외부 단편화와 같은 개념이다

**정답** : 3번
**해설** : 내부 단편화는 프로세스에 할당된 페이지 내에서 사용되지 않고 남는 메모리 공간을 의미합니다. 프로세스 크기가 페이지 크기의 정확한 배수가 아닐 때 마지막 페이지에서 발생합니다. 페이지 크기를 작게 하면 내부 단편화는 줄어들지만 페이지 테이블의 크기가 증가하는 trade-off가 있습니다.

---

### 문제 5

TLB(Translation Lookaside Buffer)의 역할로 올바른 것은?

1. 페이지 테이블 전체를 저장하는 메모리
2. 최근 사용된 페이지 정보를 캐싱하여 주소 변환 속도 향상
3. 프로세스의 논리 주소를 저장하는 레지스터
4. 스왑 공간을 관리하는 하드웨어
5. 페이지 교체 알고리즘을 실행하는 장치

**정답** : 2번
**해설** : TLB는 페이지 테이블의 캐시 메모리로, 최근에 사용된 페이지 번호와 프레임 번호 쌍을 저장합니다. TLB 히트 시 페이지 테이블 접근 없이 바로 프레임 번호를 얻을 수 있어 메모리 접근 횟수가 1회로 줄어들어 성능이 크게 향상됩니다.

---

### 문제 6

TLB 미스(Miss)가 발생했을 때의 처리 과정으로 올바른 것은?

1. 즉시 페이지 폴트가 발생한다
2. 페이지 테이블에서 정보를 찾고 TLB를 업데이트한다
3. 프로세스를 종료한다
4. 스왑 공간에서 페이지를 가져온다
5. 새로운 프레임을 할당한다

**정답** : 2번
**해설** : TLB 미스가 발생하면 메모리에 있는 페이지 테이블에 접근하여 해당 페이지의 프레임 번호를 찾습니다. 그 후 이 정보를 TLB에 저장하여 다음 번 접근 시 빠르게 사용할 수 있도록 합니다. TLB 미스는 페이지 폴트와 다른 개념으로, 페이지는 메모리에 있지만 TLB에만 없는 상태입니다.

---

### 문제 7

논리 주소를 물리 주소로 변환할 때, 변하지 않고 그대로 사용되는 값은?

1. 페이지 번호
2. 프레임 번호
3. 변위(Offset)
4. 프로세스 ID
5. 유효 비트

**정답** : 3번
**해설** : 논리 주소는 페이지 번호와 변위로 구성되고, 물리 주소는 프레임 번호와 변위로 구성됩니다. 주소 변환 시 페이지 번호만 프레임 번호로 바뀌고, 변위는 동일하게 유지됩니다. 이는 페이지와 프레임의 크기가 같고, 페이지 내에서의 상대적 위치는 변하지 않기 때문입니다.

---

### 문제 8

수정 비트(Dirty Bit)의 역할로 올바른 것은?

1. 페이지가 메모리에 있는지 확인
2. 페이지에 대한 접근 권한 제어
3. 페이지 내용이 변경되었는지 표시
4. 페이지가 최근에 참조되었는지 기록
5. 페이지의 우선순위 결정

**정답** : 3번
**해설** : 수정 비트는 페이지 내용이 변경되었는지를 나타냅니다. 쓰기 작업이 발생하면 1로 설정됩니다. 페이지를 스왑 아웃할 때, 수정 비트가 0이면 메모리에서 삭제만 하면 되지만, 1이면 변경된 내용을 스왑 영역에 기록한 후 삭제해야 합니다.

---

### 문제 9

계층적 페이징의 주요 목적은?

1. 페이지 접근 속도 향상
2. 외부 단편화 제거
3. 페이지 테이블 크기 감소 및 메모리 효율성 향상
4. CPU 사용률 증가
5. 프로세스 간 메모리 공유

**정답** : 3번
**해설** : 계층적 페이징은 페이지 테이블을 여러 단계로 나누어 필요한 부분만 메모리에 적재하는 방식입니다. 프로세스 크기가 커질수록 페이지 테이블도 커지는데, 모든 페이지 테이블을 항상 메모리에 유지하면 낭비가 발생합니다. 계층적 페이징을 통해 실제 사용하는 페이지 테이블만 메모리에 적재하여 메모리 효율성을 높입니다.

### 문제 10

역 페이지 테이블(Inverted Page Table)의 특징이 아닌 것은?

1. 시스템 전체에 하나의 페이지 테이블만 존재
2. 프레임 번호를 인덱스로 사용
3. 각 프로세스마다 별도의 페이지 테이블 생성
4. 페이지 테이블 크기가 물리 메모리 크기에 비례
5. 프로세스 번호와 페이지 번호를 함께 저장

**정답** : 3번
**해설** : 역 페이지 테이블은 기존 페이지 테이블과 달리 각 프로세스마다 별도의 페이지 테이블을 만들지 않습니다. 시스템 전체에 하나의 페이지 테이블만 존재하며, 이를 통해 여러 프로세스 실행 시 발생하는 메모리 공간 낭비 문제를 해결합니다.

### 문제 11

요구 페이징(Demand Paging)의 장점으로 올바르지 않은 것은?

1. 메모리 공간을 효율적으로 사용
2. 프로세스 실행 시간 단축
3. 모든 페이지를 처음부터 메모리에 적재
4. 당장 필요한 페이지만 적재
5. 불필요한 입출력 오버헤드 감소

**정답** : 3번
**해설** : 요구 페이징은 처음부터 모든 페이지를 메모리에 적재하지 않고, 필요한 페이지만 메모리에 적재하는 방식입니다. 이는 메모리 공간을 효율적으로 사용하고 프로세스 실행 속도를 향상시킵니다. "모든 페이지를 처음부터 메모리에 적재"하는 것은 요구 페이징과 반대되는 개념입니다.

### 문제 12

TLB 히트율이 95%이고, TLB 접근 시간이 1ns, 메모리 접근 시간이 100ns일 때, 실효 메모리 접근 시간(EAT)은?

1. 101ns
2. 106ns
3. 110.95ns
4. 195ns
5. 201ns

**정답** : 2번
**해설** :

```
EAT = (TLB 히트율 × (TLB 접근 + 메모리 접근))
    + (TLB 미스율 × (TLB 접근 + 페이지 테이블 접근 + 메모리 접근))
    = 0.95 × (1 + 100) + 0.05 × (1 + 100 + 100)
    = 95.95 + 10.05
    = 106ns

```

TLB 히트 시 메모리 접근이 1회, TLB 미스 시 메모리 접근이 2회(페이지 테이블 + 실제 데이터) 발생합니다.
