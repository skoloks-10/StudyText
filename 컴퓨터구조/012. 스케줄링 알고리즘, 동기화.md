## 1️⃣ CPU 스케줄링 알고리즘

### 1.1 스케줄링 알고리즘의 종류

CPU는 여러 프로세스를 효율적으로 관리하기 위해 다양한 스케줄링 알고리즘을 사용합니다. 각 알고리즘은 특정 상황과 목적에 최적화되어 있습니다.

---

### 1.2 선입 선처리 스케줄링 (FCFS)

**개념:**  
FCFS(First Come First Served Scheduling)는 가장 먼저 도착한 프로세스를 가장 먼저 처리하는 비선점형 스케줄링 방식입니다.

**특징:**
- 준비 큐에 삽입된 순서대로 CPU를 할당
- 단순하고 공정한 방식
- CPU 이용 시간이 긴 프로세스가 먼저 도착하면 뒤의 프로세스들이 오래 기다려야 함 (호위 효과 convoy effect)

**동작 방식:**
```
준비 큐: [프로세스 C (17ms), 프로세스 A (5ms), 프로세스 B (2ms)]

실행 순서: C → A → B
대기 시간: (22 + 17 + 0) / 3 = 13ms
```

**사용 상황:**
- 프로세스 실행 시간이 비슷한 경우
- 단순한 스케줄링이 필요한 시스템

---

### 1.3 최단 작업 우선 스케줄링 (SJF)

**개념:**  
SJF(Shortest Job First Scheduling)는 CPU 사용 시간이 가장 짧은 프로세스부터 실행하는 스케줄링 방식입니다.

**특징:**
- 평균 대기 시간을 최소화
- 비선점형과 선점형(SRTF) 두 가지 방식 존재
- CPU 사용 시간을 정확히 예측해야 하는 어려움

**예시:**
```
프로세스 A: 11ms
프로세스 B: 3ms  
프로세스 C: 7ms

실행 순서: B(3ms) → C(7ms) → A(11ms)
평균 대기 시간: 4ms
```

**사용 상황:**
- 짧은 작업을 우선 처리해야 하는 배치 시스템
- 응답 시간이 중요한 경우

---

### 1.4 라운드 로빈 스케줄링 (Round Robin)

**개념:**  
타임 슬라이스(time quantum)를 정하고, 각 프로세스가 정해진 시간만큼만 CPU를 사용하는 선점형 스케줄링입니다.

**특징:**
- 타임 슬라이스 단위로 CPU를 순환하며 할당
- 공평한 CPU 분배
- 타임 슬라이스가 너무 크면 FCFS와 유사해지고, 너무 작으면 context switching 오버헤드 증가

**예시 (타임 슬라이스: 4ms):**
```
프로세스 A: 11ms
프로세스 B: 3ms
프로세스 C: 7ms

실행 순서: A(4) → B(3) → C(4) → A(4) → C(3) → A(3)
```

**사용 상황:**
- 대화형 시스템
- 공정한 CPU 할당이 필요한 시분할 시스템

---

### 1.5 최소 잔여 시간 우선 스케줄링 (SRT)

**개념:**  
SRT(Shortest Remaining Time)는 SJF의 선점형 버전으로, 남은 실행 시간이 가장 짧은 프로세스에 CPU를 할당합니다.

**특징:**
- 새로운 프로세스가 도착하면 잔여 시간 비교
- 더 짧은 잔여 시간을 가진 프로세스로 선점 가능
- 잦은 context switching 발생 가능

**사용 상황:**
- 짧은 작업의 응답 시간을 최소화해야 하는 경우
- 실시간 시스템의 일부 시나리오

---

### 1.6 우선순위 스케줄링

**개념:**  
각 프로세스에 우선순위를 부여하고, 우선순위가 높은 프로세스부터 실행하는 방식입니다.

**특징:**
- 우선순위는 정적 또는 동적으로 결정
- 기아 현상(starvation) 발생 가능: 낮은 우선순위 프로세스가 무한정 대기
- 에이징(aging) 기법으로 기아 현상 해결 가능

**기아 현상 해결:**
```
에이징: 대기 시간이 길어질수록 우선순위를 점진적으로 상승
```

**사용 상황:**
- 중요도가 다른 작업들을 처리하는 시스템
- 실시간 시스템

---

### 1.7 다단계 큐 스케줄링

**개념:**  
우선순위별로 준비 큐를 여러 개 사용하고, 각 큐마다 다른 스케줄링 알고리즘을 적용하는 방식입니다.

**특징:**
- 우선순위가 가장 높은 큐의 프로세스부터 실행
- 큐 사이 이동이 불가능
- 고정적인 우선순위 체계

**구조:**
```
우선순위 0 (최고)
우선순위 1
우선순위 2
  ⋮
```

**사용 상황:**
- 프로세스 유형이 명확히 구분되는 시스템
- 시스템 프로세스와 사용자 프로세스를 분리 관리

---

### 1.8 다단계 피드백 큐 스케줄링

**개념:**  
다단계 큐 스케줄링의 발전된 형태로, 프로세스가 큐 사이를 이동할 수 있는 유연한 스케줄링입니다.

**특징:**
- CPU를 오래 사용한 프로세스는 우선순위가 낮은 큐로 이동
- 짧은 작업과 입출력 집중 프로세스에 유리
- 가장 일반적인 CPU 스케줄링 알고리즘

**동작 원리:**
```
우선순위 0 ⇄ (CPU 많이 사용)
우선순위 1 ⇄ (CPU 많이 사용)  
우선순위 2 ⇄ (CPU 많이 사용)
  ⋮
```

**사용 상황:**
- 대부분의 범용 운영체제
- 다양한 특성의 프로세스를 효율적으로 관리해야 하는 경우

---

## 2️⃣ 동기화 (Synchronization)

### 2.1 동기화의 의미

**개념:**  
동기화는 프로세스들이 공유 자원에 접근할 때 데이터의 일관성을 유지하고, 실행 순서를 조율하는 것을 의미합니다.

**필요성:**
- 실행 순서 제어: 프로세스들이 올바른 순서대로 실행되도록 보장
- 상호 배제: 동시에 접근하면 안 되는 자원에 대한 접근 제어
- 프로세스 동기화를 통해 Race Condition 방지

**동기화 종류:**

1. **실행 순서 제어를 위한 동기화**
   - Reader 프로세스와 Writer 프로세스가 있을 때
   - Writer가 Book.txt에 값을 쓴 후 Reader가 읽어야 함
   - 순서가 바뀌면 잘못된 데이터 읽기 발생

2. **상호 배제를 위한 동기화**  
   - 생산자와 소비자 문제
   - 동시에 같은 변수(총합)를 수정하면 안 됨
   - 한 번에 하나의 프로세스만 접근 허용

---

### 2.2 공유 자원과 임계 구역

**공유 자원 (Shared Resource):**
- 여러 프로세스가 공동으로 접근하는 자원
- 전역 변수, 파일, 입출력장치, 보조기억장치 등

**임계 구역 (Critical Section):**
- 공유 자원에 접근하는 코드 영역
- 두 개 이상의 프로세스가 동시에 실행하면 안 되는 영역
- Race Condition 발생 가능 구역

**예시:**
```javascript
// 생산자 프로세스
function producer() {
    // 버퍼에 데이터 삽입
    buffer.push(data); // ← 임계 구역
    count++; // ← 임계 구역
}

// 소비자 프로세스  
function consumer() {
    // 버퍼에서 데이터 꺼내기
    let data = buffer.pop(); // ← 임계 구역
    count--; // ← 임계 구역
}
```

**사용 상황:**
- 공유 메모리를 사용하는 멀티스레드 프로그래밍
- 데이터베이스 트랜잭션
- 파일 입출력 동시 제어

---

### 2.3 레이스 컨디션 (Race Condition)

**개념:**  
여러 프로세스가 동시에 공유 자원에 접근할 때, 실행 순서에 따라 결과가 달라지는 상황입니다.

**발생 원리:**
```javascript
// 초기 변수 1을 증가시키는 코드
let result = 1;

// 프로세스 A: 변수를 1 증가
r1 = result;    // r1 = 1
r1 = r1 + 1;    // r1 = 2  
result = r1;    // result = 2

// 프로세스 B: 변수를 1 감소
r2 = result;    // r2 = 1 (또는 2)
r2 = r2 - 1;    // r2 = 0 (또는 1)
result = r2;    // result = 0 (또는 1)

// 실행 순서에 따라 최종 result 값이 달라짐!
```

**문제점:**
- 실행 타이밍에 따라 예측 불가능한 결과
- 디버깅이 매우 어려움
- 시스템 불안정성 야기

**해결 방법:**
- 상호 배제 (Mutual Exclusion) 구현
- 임계 구역을 원자적으로 실행
- 동기화 기법 적용

---

### 2.4 동기화 기법의 조건

운영체제에서 안전한 동기화를 위해서는 다음 세 가지 조건을 만족해야 합니다:

1. **상호 배제 (Mutual Exclusion)**
   - 한 프로세스가 임계 구역에 진입했다면 다른 프로세스는 들어갈 수 없음

2. **진행 (Progress)**  
   - 임계 구역에 어떤 프로세스도 진입하지 않았다면 진입하고자 하는 프로세스는 들어갈 수 있어야 함

3. **유한 대기 (Bounded Waiting)**
   - 한 프로세스가 임계 구역에 진입하고 싶다면 그 프로세스는 언제가는 임계 구역에 들어갈 수 있어야 함 (무한정 대기하지 않음)

**잘못된 동기화 예시:**
```javascript
// 상호 배제만 보장하고 진행과 유한 대기를 보장하지 못하는 코드
// 이런 코드는 데드락이나 기아 현상을 발생시킬 수 있음
```

## 💡 최종 핵심 요약

### CPU 스케줄링
- **FCFS**: 선입선출, 단순하지만 호위 효과 발생 가능
- **SJF**: 최단 작업 우선, 평균 대기 시간 최소화
- **Round Robin**: 타임 슬라이스로 공평하게 분배, 대화형 시스템에 적합
- **SRT**: SJF의 선점형 버전, 남은 시간이 짧은 것 우선
- **우선순위**: 중요도 기반, 기아 현상 주의
- **다단계 큐**: 우선순위별 큐 분리, 고정적
- **다단계 피드백 큐**: 큐 간 이동 가능, 가장 일반적

### 동기화
- **목적**: 공유 자원의 일관성 유지 + 실행 순서 제어
- **임계 구역**: 공유 자원 접근 코드 영역
- **Race Condition**: 실행 순서에 따라 결과가 달라지는 문제
- **동기화 3대 조건**: 상호 배제, 진행, 유한 대기

## 📝 복습용 퀴즈

### Q1. FCFS 스케줄링의 단점으로 가장 적절한 것은?

**선택지:**
1. 구현이 매우 복잡하다
2. CPU 사용 시간이 긴 프로세스가 먼저 도착하면 뒤의 프로세스들이 오래 기다리게 된다
3. 우선순위를 고려하지 못한다
4. 타임 슬라이스 설정이 어렵다
5. 기아 현상이 자주 발생한다

**정답: 2번**

**해설:**  
FCFS는 가장 먼저 도착한 프로세스를 먼저 처리하는 방식입니다. CPU 사용 시간이 17ms인 프로세스 C가 먼저 도착하고, 그 뒤에 5ms, 2ms의 짧은 프로세스들이 도착하면, 짧은 프로세스들은 C가 끝날 때까지 긴 시간을 기다려야 합니다. 이를 **호위 효과(convoy effect)**라고 하며, FCFS의 가장 큰 단점입니다.

---

### Q2. 다음 중 선점형 스케줄링 방식은?

**선택지:**
1. FCFS
2. SJF
3. Round Robin
4. 비선점 우선순위 스케줄링
5. 단순 큐 스케줄링

**정답: 3번**

**해설:**  
Round Robin은 각 프로세스에 타임 슬라이스를 할당하고, 시간이 끝나면 강제로 CPU를 빼앗아 다음 프로세스에 할당하는 **선점형(preemptive)** 스케줄링입니다. 반면 FCFS와 기본 SJF는 비선점형입니다. SRT(Shortest Remaining Time)는 SJF의 선점형 버전입니다.

---

### Q3. Race Condition이 발생하는 주된 원인은?

**선택지:**
1. CPU 스케줄링 알고리즘의 잘못된 선택
2. 메모리 부족
3. 여러 프로세스가 공유 자원에 동시에 접근하여 실행 순서에 따라 결과가 달라짐
4. 프로세스의 우선순위가 너무 낮음
5. 타임 슬라이스가 너무 작음

**정답: 3번**

**해설:**  
Race Condition은 두 개 이상의 프로세스가 공유 자원(변수, 파일 등)에 **동시에 접근**할 때, 실행 타이밍과 순서에 따라 결과가 달라지는 현상입니다. 예를 들어, 프로세스 A가 `result++`를 실행하는 동안 프로세스 B가 `result--`를 실행하면, 두 작업의 순서에 따라 최종 값이 달라질 수 있습니다.

---

### Q4. SJF 스케줄링에서 프로세스 A(11ms), B(3ms), C(7ms)가 동시에 도착했을 때, 실행 순서는?

**선택지:**
1. A → B → C
2. C → B → A
3. B → C → A
4. B → A → C
5. A → C → B

**정답: 3번**

**해설:**  
SJF(Shortest Job First)는 CPU 사용 시간이 가장 짧은 프로세스부터 실행합니다. 주어진 프로세스들의 실행 시간은 B(3ms), C(7ms), A(11ms) 순서로 짧습니다. 따라서 실행 순서는 **B → C → A**가 됩니다. 이 방식은 평균 대기 시간을 최소화하는 장점이 있습니다.

---

### Q5. 동기화의 3대 조건에 해당하지 않는 것은?

**선택지:**
1. 상호 배제 (Mutual Exclusion)
2. 진행 (Progress)
3. 유한 대기 (Bounded Waiting)
4. 공정성 (Fairness)
5. 1, 2, 3번 모두 동기화 조건이다

**정답: 4번**

**해설:**  
동기화를 위해 반드시 만족해야 하는 3대 조건은 **상호 배제, 진행, 유한 대기**입니다. 

- **상호 배제**: 한 프로세스가 임계 구역에 있으면 다른 프로세스는 들어갈 수 없음
- **진행**: 임계 구역이 비어있으면 진입을 원하는 프로세스가 들어갈 수 있어야 함  
- **유한 대기**: 무한정 기다리지 않고 언젠가는 임계 구역에 진입할 수 있어야 함

공정성은 중요한 개념이지만 동기화의 필수 조건은 아닙니다.

### Q6. 다음 중 기아 현상(Starvation)이 발생할 수 있는 스케줄링은?

**선택지:**
1. FCFS
2. Round Robin
3. 우선순위 스케줄링
4. 다단계 피드백 큐 스케줄링
5. 모든 스케줄링에서 발생 가능

**정답: 3번**

**해설:**  
우선순위 스케줄링에서는 우선순위가 높은 프로세스들이 계속 도착하면, 우선순위가 낮은 프로세스는 무한정 대기하게 되는 **기아 현상(Starvation)**이 발생할 수 있습니다. 이를 해결하기 위해 **에이징(Aging)** 기법을 사용합니다. 에이징은 대기 시간이 길어질수록 프로세스의 우선순위를 점진적으로 높여주는 방법입니다.

### Q7. 임계 구역(Critical Section)에 대한 설명으로 옳은 것은?

**선택지:**
1. 여러 프로세스가 동시에 실행해도 안전한 코드 영역
2. CPU 스케줄링이 이루어지는 영역
3. 공유 자원에 접근하는 코드로, 동시에 실행되면 안 되는 영역
4. 프로세스가 생성되는 메모리 공간
5. 운영체제의 커널 영역

**정답: 3번**

**해설:**  
임계 구역은 **공유 자원에 접근하는 코드 영역**으로, 두 개 이상의 프로세스가 동시에 실행하면 Race Condition이 발생할 수 있어 위험합니다. 예를 들어, 생산자-소비자 문제에서 `count++`, `count--` 같은 코드가 임계 구역에 해당합니다. 안전한 동기화를 위해서는 임계 구역을 한 번에 하나의 프로세스만 실행할 수 있도록 보호해야 합니다.

### Q8. Round Robin 스케줄링에서 타임 슬라이스가 너무 작을 때 발생하는 문제는?

**선택지:**
1. 호위 효과 발생
2. 기아 현상 발생
3. Context Switching 오버헤드 증가
4. 평균 대기 시간 무한대로 증가
5. 우선순위 역전 발생

**정답: 3번**

**해설:**  
Round Robin에서 타임 슬라이스가 너무 작으면, 프로세스들이 빈번하게 교체되면서 **Context Switching(문맥 교환)**이 자주 발생합니다. Context Switching은 현재 실행 중인 프로세스의 상태를 저장하고 다음 프로세스의 상태를 복원하는 작업으로, 이 자체가 시간을 소비합니다. 따라서 타임 슬라이스가 너무 작으면 실제 작업보다 Context Switching에 더 많은 시간을 사용하게 되어 시스템 성능이 저하됩니다.
