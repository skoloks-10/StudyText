## 요구 페이징

### 개념

- \*요구 페이징(Demand Paging)\*\*은 프로세스 실행 시 필요한 페이지만 메모리에 적재하는 기법입니다.

### 작동 원리

1. CPU가 특정 페이지에 접근하는 명령어를 실행
2. 해당 페이지가 현재 메모리에 있을 경우 (유효 비트가 1인 경우): CPU는 페이지에 적재된 프레임에 접근
3. 해당 페이지가 현재 메모리에 없을 경우 (유효 비트가 0인 경우): 페이지 폴트가 발생
4. 페이지 폴트 처리 루틴은 해당 페이지를 메모리로 적재하고 유효 비트를 1로 설정
5. 1번으로 다시 돌아감

### 특징

- 프로세스의 모든 페이지를 메모리에 적재하지 않고 일부만 적재
- 순수한 요구 페이징 기법에서는 프로세스가 처음 실행될 때 어떤 페이지도 메모리에 적재하지 않음
- 실행 중에 필요한 페이지만 메모리에 적재하며 보조기억장치로 내보냄
- 프로세스를 구성하는 모든 페이지를 무조건 메모리에 적재하는 방법에 비해 효율적

## 페이지 교체 알고리즘

### 개념

페이지 교체 알고리즘은 프로세스가 사용할 메모리 공간이 부족할 때, 메모리에 적재된 어떤 페이지를 내보낼지 결정하는 방법입니다.

### 종류

- FIFO 페이지 교체 알고리즘
- 2차 기회 페이지 교체 알고리즘
- 최적 페이지 교체 알고리즘
- LRU 페이지 교체 알고리즘

---

### FIFO 페이지 교체 알고리즘

### 개념

**FIFO(First-In First-Out) 페이지 교체 알고리즘**은 가장 먼저 메모리에 들어온 페이지부터 내보내는 방식입니다.

### 작동 방식

- 가장 단순한 방식
- 메모리에 가장 먼저 올라온 페이지를 스택처럼 제거
- 페이지가 처음에 적재된 시간을 기준으로 교체

### 예시

페이지 참조열: `2 3 1 3 5 2 3 4 2 3`

프레임이 3개인 경우:

```
시간 →  2  3  1  3  5  2  3  4  2  3
─────────────────────────────────────
프레임1 │2  2  2  2  5  5  5  4  4  4
프레임2 │   3  3  3  3  2  2  2  2  2
프레임3 │      1  1  1  1  3  3  3  3

```

페이지 폴트 횟수: 7회

### 특징

- 구현이 간단
- CPU가 참조하는 페이지들 중 연속된 페이지를 생략
- 페이지 폴트가 자주 발생하지 않음
- 메모리에 먼저 올라온 순서로 페이지를 내보냄

---

### 2차 기회 페이지 교체 알고리즘

### 개념

- \*2차 기회 페이지 교체 알고리즘(Second Chance Page Replacement Algorithm)\*\*은 FIFO 방식에 참조 비트를 결합한 알고리즘입니다.

### 작동 방식

1. FIFO처럼 가장 오래된 페이지를 먼저 검사
2. 참조 비트가 1이면 0으로 바꾸고 한 번의 기회를 더 줌
3. 참조 비트가 0인 페이지를 만나면 해당 페이지를 교체

### 예시

페이지 참조열을 처리할 때:

**예전 차례(1번) 페이지 1**

- 참조 비트: 1 → 0
- 처음 비트: 0

**최근 차례(4번) 페이지 1**

- 참조 비트: 0
- 처음 비트: 0

가장 오래된 페이지 중에서도 참조 비트가 0인 페이지부터 교체합니다.

### 특징

- FIFO의 단점 보완
- 페이지가 3의 참조 비트를 보고, 1일 경우 참조 비트만 0으로 바꾸고 한 번 더 기회 부여
- 보조기억장치에서 가져온 오래된 페이지라도 참조될 가능성이 있다면 교체하지 않음

---

### 최적 페이지 교체 알고리즘

### 개념

**최적 페이지 교체 알고리즘**은 CPU에 의해 참조되는 횟수를 고려하는 페이지 교체 알고리즘입니다.

### 작동 방식

- 가장 앞으로 CPU에 의해 참조될 횟수를 고려
- 앞으로 가장 오랫동안 사용하지 않을 페이지를 교체
- 프로세스가 앞으로 메모리에 어느 순간에 어떤 페이지를 요구하는지 미리 알아야 함

### 특징

- 실생활에 보편적으로 적용 불가능
- 미래에 어떤 페이지가 참조될지 예측 필요
- 이론적으로 페이지 교체 알고리즘의 이상적 성능 제시
- 실제 사용보다는 다른 알고리즘 성능 평가를 위한 기준으로 사용
- 최소 임계값 개의 페이지를 참조하기 위해 사용되는 페이지 교체 알고리즘

---

### LRU 페이지 교체 알고리즘

### 개념

**LRU(Least Recently Used) 페이지 교체 알고리즘**은 가장 오랫동안 사용되지 않은 페이지를 교체하는 알고리즘입니다.

### 작동 방식

- 최근에 사용되지 않은 페이지는 앞으로도 사용되지 않을 가능성이 높다는 아이디어
- 가장 사용이 적었던 페이지를 교체

### 예시

페이지 참조열: `2 3 1 3 5 2 3 4 2 3`

```
시간 →  2  3  1  3  5  2  3  4  2  3
─────────────────────────────────────
프레임1 │2  2  2  2  5  5  5  4  4  4
프레임2 │   3  3  3  3  3  3  3  3  3
프레임3 │      1  1  1  2  2  2  2  2

```

### 특징

- 가장 오랫동안 사용하지 않은 페이지를 대상으로 사용
- 429족의 예시를 다시 한번 가져와 보겠습니다
- LRU 알고리즘은 다음과 같이 작동
- 이 예시에서는 페이지 폴트가 3회 발생

### 장점

- 최적 페이지 교체 알고리즘에 가까운 성능
- 실제 구현 가능

## 스래싱과 프레임 할당

### 스래싱 개념

### 정의

- \*스래싱(Thrashing)\*\*은 프로세스가 실제 작업을 수행하는 시간보다 페이징에 더 많은 시간을 소모하는 현상입니다.

### 발생 원인

1. 프로세스가 자주 사용하는 페이지들의 개수보다 적은 프레임이 할당
2. 페이지 폴트가 자주 발생하여 CPU 이용률이 낮아짐
3. 운영체제가 CPU 이용률을 높이려고 또 다른 프로세스를 실행
4. 새로운 프로세스 실행으로 각 프로세스들이 자여하는 프레임의 수가 감소
5. 페이지 폴트가 더욱 자주 발생하여 스래싱 심화

### 문제점

- CPU 이용률 감소
- 프로세스의 실제 작업시간 감소
- 페이지 교체에 많은 시간 소비
- 전체 시스템 성능 저하

### 작업 집합 모델

### 개념

- \*작업 집합(Working Set)\*\*은 프로세스가 일정 시간 동안 참조한 페이지의 집합입니다.

### 특징

- 프로세스가 원활히 실행되려면 작업 집합 내 페이지들이 모두 메모리에 유지되어야 함
- 프로세스의 작업 집합을 분석하여 적절한 프레임 수 결정

---

### 작업 집합 구하기

### 방법

프로세스가 일정 시간(윈도우) 동안 참조한 페이지들을 파악합니다.

### 예시

페이지 참조열: `2 3 1 3 5 2 3 4 2 3`

시간 t에서 110개의 작업 집합은 이와 같이 구합니다. 윈도우 크기가 다르면 작업 집합도 달라집니다.

```
시간 t(20개시)의 작업 집합은 이와 같이: {2, 4, 7}

```

### 활용

- 프로세스의 현재 작업 집합 크기를 파악
- 해당 크기만큼의 프레임 할당
- 작업 집합 내의 모든 페이지가 메모리에 있어야 효율적 실행 가능

## 파일과 디렉터리

### 파일

### 개념

- \*파일(File)\*\*은 컴퓨터 시스템이 관리하는 데이터 및 프로그램의 집합입니다.

### 특징

- 그러나 파일은 이름을 가지고 있어 정보의 위치를 쉽게 파악 가능
- 운영체제를 사용하려면 파일 속성을 잘 파악해야 함

### 시스템 호출

1. 파일 생성
2. 파일 삭제
3. 파일 열기
4. 파일 닫기
5. 파일 읽기
6. 파일 쓰기

### 디렉터리

### 개념

- \*디렉터리(Directory)\*\*는 파일을 일목요연하게 관리하기 위해 사용하는 폴더입니다.

### 구조

**트리 구조 디렉터리**

현대 운영체제에서는 하나의 디렉터리가 여러 디렉터리나 파일을 포함할 수 있는 트리 구조를 사용합니다.

```
        /
        │
    ┌───┼───┐
    │   │   │
  home bin etc
    │
  ┌─┴─┐
  │   │
minchul guest
  │     │
┌─┼─┐   │
│ │ │   │
a.sh b.c c.tar d.jpg

```

- 최상위 디렉터리: **루트 디렉터리(Root Directory)** - `/`로 표현
- 루트 디렉터리 아래 다른 서브 디렉터리들 존재
- 여러 계층 구조로 파일 관리 가능

### 디렉터리 엔트리

### 개념

**디렉터리 엔트리**는 디렉터리에 담기는 정보를 의미합니다.

### 구성 요소

많은 시스템은 정확을 동해 있는 것도 같은 디렉터리는 동일한 이름의 파일이 존재할 수 없습니다.

디렉터리도 파일의 한 종류이므로 minchul 디렉터리도 있고, etc 디렉터리도 있습니다. 디렉터리 경로에서 해당 디렉터리 정보는 /bin인 경우 파일 etc /home이라면 /home 디렉터리 아래에 있습니다.

**디렉터리 테이블 정보 예시**

| 파일 이름 | 위치를 추측할 수 있는 정보 |
| --------- | -------------------------- |
| ..        |                            |
| .         |                            |
| minchul   |                            |
| guest     |                            |

### 절대 경로와 상대 경로

### 절대 경로(Absolute Path)

루트 디렉터리에서 시작하여 현재 작업 디렉터리까지 이르는 고유한 경로입니다.

**예시**

```
/minchul/b.c

```

- 윈도우, 리눅스, 유닉스, macOS 등 대부분의 운영체제에서 `cd`(change directory) 명령을 통해 현재 작업 디렉터리를 이동할 수 있음

**경로 표현 구조**

```
/minchul/b.c
 └─ 루트 작업 디렉터리 아래
      └─ minchul 디렉터리 아래
           └─ b.c 파일

```

### 상대 경로(Relative Path)

현재 디렉터리부터 시작하는 경로를 나타냅니다.

**예시**

현재 작업 디렉터리 home에서:

- test 디렉터리로 이동: `cd C:\\test`
- test 디렉터리 내의 cd.C:\test 참조

현재 작업 디렉터리가 /home인 경우 상대 경로로 /minchul/b.c에 상대 경로는 `./minchul/b.c`로 나타냄

**특수 경로 기호**

- `.`: 현재 디렉터리
- `..`: 부모 디렉터리(한 단계 위)

## 최종 핵심 요약

### 메모리 관리

1. **요구 페이징** : 필요한 페이지만 메모리에 적재하여 효율성 향상
2. **페이지 교체 알고리즘** : 메모리가 부족할 때 어떤 페이지를 내보낼지 결정

- FIFO: 가장 먼저 들어온 페이지 교체
- 2차 기회: FIFO + 참조 비트 활용
- 최적: 이론적 이상, 가장 오래 사용하지 않을 페이지 교체
- LRU: 가장 최근에 사용하지 않은 페이지 교체

1. **스래싱** : 페이징이 실제 작업보다 많은 시간을 차지하는 현상
2. **작업 집합** : 프로세스가 원활히 실행되기 위한 페이지 집합

### 파일 시스템

1. **파일** : 이름을 가진 데이터 및 프로그램의 집합
2. **파일 속성** : 유형, 크기, 보호, 생성/수정 날짜, 위치 등
3. **디렉터리** : 트리 구조로 파일을 체계적으로 관리
4. **경로** : 절대 경로(루트부터)와 상대 경로(현재 위치부터)

## 복습 퀴즈

### 문제 1

요구 페이징에 대한 설명으로 옳지 않은 것은?

A) 프로세스 실행 시 필요한 페이지만 메모리에 적재한다
B) 모든 페이지를 항상 메모리에 유지해야 한다
C) 페이지 폴트가 발생하면 필요한 페이지를 메모리로 가져온다
D) 보조기억장치의 사용을 줄일 수 있다

정답: B

해설: 요구 페이징은 필요한 페이지만 메모리에 적재하는 기법으로, 모든 페이지를 항상 메모리에 유지하지 않습니다. 이는 오히려 일반적인 페이징 방식의 특징입니다. 요구 페이징은 실제로 필요할 때만 페이지를 적재하여 메모리 효율성을 높입니다.

---

### 문제 2

다음 중 LRU 페이지 교체 알고리즘에 대한 설명으로 옳은 것은?

A) 가장 먼저 들어온 페이지를 교체한다
B) 가장 오랫동안 사용되지 않은 페이지를 교체한다
C) 앞으로 가장 오래 사용하지 않을 페이지를 교체한다
D) 참조 비트가 0인 페이지를 교체한다

정답: B

해설: LRU(Least Recently Used)는 '가장 최근에 사용되지 않은'이라는 의미로, 가장 오랫동안 사용되지 않은 페이지를 교체합니다. A는 FIFO, C는 최적 알고리즘, D는 2차 기회 알고리즘의 특징입니다. LRU는 최근 사용 패턴을 기반으로 미래 사용을 예측하는 실용적인 알고리즘입니다.

---

### 문제 3

스래싱(Thrashing)에 대한 설명으로 옳은 것은?

A) CPU 이용률이 매우 높은 상태를 말한다
B) 페이지 폴트가 거의 발생하지 않는 상태이다
C) 실제 작업보다 페이징에 더 많은 시간을 소비하는 현상이다
D) 프로세스에 충분한 프레임이 할당된 상태이다

정답: C

해설: 스래싱은 프로세스가 실제 작업을 수행하는 시간보다 페이지 교체에 더 많은 시간을 소비하는 현상입니다. 프로세스에 할당된 프레임이 부족하여 페이지 폴트가 자주 발생하고, 결과적으로 CPU 이용률이 낮아지며 시스템 성능이 크게 저하됩니다.

---

### 문제 4

FIFO 페이지 교체 알고리즘의 특징으로 옳지 않은 것은?

A) 구현이 가장 간단하다
B) 메모리에 가장 먼저 들어온 페이지를 교체한다
C) 항상 최적의 성능을 보장한다
D) 페이지가 적재된 시간을 기준으로 교체한다

정답: C

해설: FIFO는 구현이 간단하지만 최적의 성능을 보장하지는 않습니다. 오래 전에 적재되었어도 자주 사용되는 페이지를 교체할 수 있어, 페이지 폴트가 더 많이 발생할 수 있습니다. 참조 패턴을 고려하지 않고 단순히 적재 순서만 고려하기 때문입니다.

### 문제 5

다음 중 절대 경로에 대한 설명으로 옳은 것은?

A) 현재 디렉터리를 기준으로 표현한다
B) 루트 디렉터리부터 시작하여 경로를 표현한다
C) `.`과 `..`을 자주 사용한다
D) 현재 위치에 따라 경로가 달라진다

정답: B

해설: 절대 경로는 루트 디렉터리(`/`)에서 시작하여 대상까지의 전체 경로를 표현합니다. 예를 들어 `/minchul/b.c`는 루트부터 시작하는 절대 경로입니다. A, C, D는 모두 상대 경로의 특징입니다. 절대 경로는 현재 위치와 무관하게 항상 동일한 파일을 가리킵니다.

### 문제 6

파일 시스템에서 디렉터리의 역할로 옳은 것은?

A) 데이터를 직접 저장한다
B) 파일을 체계적으로 관리하고 조직화한다
C) CPU 스케줄링을 담당한다
D) 메모리 할당을 관리한다

정답: B

해설: 디렉터리는 파일을 체계적으로 관리하고 조직화하는 역할을 합니다. 트리 구조를 통해 파일들을 계층적으로 관리하며, 파일의 위치 정보와 속성 정보를 담고 있습니다. 데이터 저장은 파일이, CPU 스케줄링과 메모리 할당은 운영체제의 다른 구성요소가 담당합니다.
