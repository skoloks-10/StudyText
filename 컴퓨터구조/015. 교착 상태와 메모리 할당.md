## 1. 교착 상태 (Deadlock)

### 1.1 교착 상태의 정의

**교착 상태(Deadlock)** 란 두 개 이상의 프로세스가 서로 다른 프로세스가 보유한 자원을 요청하면서, 각자 현재 보유한 자원을 놓지 않아 모든 프로세스가 무한정 대기하게 되는 상황을 의미합니다.

**실생활 비유:**
식당에서 두 사람이 식사를 하려고 하는데, A는 포크를 들고 나이프를 기다리고, B는 나이프를 들고 포크를 기다리는 상황과 같습니다. 서로 상대방이 가진 것을 놓을 때까지 기다리게 되어 식사를 시작할 수 없습니다.

**핵심 특징:**

- 각 프로세스는 현재 보유한 자원을 해제하지 않음
- 다른 프로세스가 보유한 자원을 계속 요청함
- 모든 프로세스가 영구적으로 대기 상태에 빠짐
- 외부 개입 없이는 자연적으로 해결 불가능

---

### 1.2 교착 상태의 발생 조건 (4가지 필요조건)

교착 상태는 다음 4가지 조건이 **모두 동시에 성립**할 때 발생합니다.

### 1) 상호 배제 (Mutual Exclusion)

한 번에 한 프로세스만 자원을 사용할 수 있는 조건

**예시:**

- 프린터는 한 번에 한 프로세스만 사용 가능
- 파일 쓰기는 동시에 여러 프로세스가 수행 불가

### 2) 점유와 대기 (Hold and Wait)

프로세스가 최소한 하나의 자원을 보유한 채로 다른 자원을 기다리는 조건

**예시:**

- 프로세스 A가 프린터를 점유한 상태에서 스캐너를 요청

### 3) 비선점 (No Preemption)

다른 프로세스가 사용 중인 자원을 강제로 빼앗을 수 없는 조건

**예시:**

- CPU는 선점 가능 (다른 프로세스에게 강제로 넘길 수 있음)
- 프린터는 비선점 (사용 중 강제로 빼앗으면 출력물 손상)

### 4) 원형 대기 (Circular Wait)

프로세스들이 순환 형태로 서로의 자원을 기다리는 조건

**예시:**

```
P1 → 자원 A 보유, 자원 B 요청
P2 → 자원 B 보유, 자원 C 요청
P3 → 자원 C 보유, 자원 A 요청
(P1 → P2 → P3 → P1 순환 구조)

```

---

### 1.3 교착 상태 해결 방법 개요

교착 상태를 다루는 방법은 크게 4가지로 분류됩니다:

1. **예방 (Prevention)**: 4가지 발생 조건 중 하나를 원천적으로 제거
2. **회피 (Avoidance)**: 안전한 상태를 유지하며 자원을 할당
3. **검출 및 회복 (Detection & Recovery)**: 교착 상태 발생을 감지하고 복구
4. **무시 (Ignore)**: 교착 상태를 무시하고 사용자가 처리 (타조 알고리즘)

---

## 2. 교착 상태 예방 (Prevention)

### 2.1 예방의 기본 원리

교착 상태의 4가지 발생 조건 중 **최소 하나를 제거**하여 교착 상태가 발생하지 않도록 하는 방법입니다.

---

### 2.2 상호 배제 조건 제거

### 우선 자원의 상호 배제를 없앨 수 있습니까?

**결론: 불가능합니다.**

자원의 상호 배제는 본질적으로 필요한 경우가 많아 제거가 현실적으로 불가능합니다.

**이유:**

- 프린터: 여러 프로세스가 동시에 출력하면 출력물이 섞임
- 파일 쓰기: 동시에 여러 프로세스가 쓰면 데이터 손상
- 임계 영역(Critical Section): 데이터 일관성을 위해 상호 배제 필수

**예외:**
읽기 전용 파일처럼 공유 가능한 자원도 있지만, 대부분의 자원은 상호 배제가 필요합니다.

---

### 2.3 점유와 대기 조건 제거

### 그렇다면 점유와 대기를 없애봅시다

**방법:** 프로세스가 실행 전에 **필요한 모든 자원을 한 번에 요청**하여 할당받도록 함

**구현 방식:**

1. 프로세스는 시작 전에 필요한 모든 자원을 선언
2. 모든 자원이 사용 가능할 때만 프로세스 실행
3. 하나라도 사용 불가능하면 대기

**장점:**

- 교착 상태 발생 원천 차단
- 구현이 비교적 단순

**단점:**

- **자원 활용도 저하**: 프로세스가 자원을 사용하지 않는 시간에도 계속 점유
- **기아(Starvation) 현상**: 많은 자원을 요구하는 프로세스는 영원히 실행 못할 수 있음
- **비효율성**: 실제로는 나중에 필요한 자원도 미리 할당받아야 함

**예시:**

```
프로세스가 파일 A, 프린터, 파일 B를 순차적으로 사용한다고 가정
- 실제로는 파일 B는 마지막에만 필요
- 하지만 처음부터 파일 B까지 할당받아야 함
→ 파일 B를 사용하지 않는 시간 동안 자원 낭비

```

---

### 2.4 비선점 조건 제거

### 비선점 조건을 없애봅시다

**방법:** 운영체제가 프로세스로부터 **자원을 강제로 회수(선점)** 할 수 있도록 함

**구현 방식:**

1. 프로세스 A가 자원을 보유 중
2. 프로세스 B가 해당 자원을 요청하면 운영체제가 A로부터 강제 회수
3. 자원을 B에게 할당
4. A는 나중에 자원을 다시 할당받음

**특징:**

- **CPU 자원**: 선점 가능 (컨텍스트 스위칭을 통해 다른 프로세스에게 넘김)
- **메모리 자원**: 선점 가능 (스왑 아웃을 통해 디스크로 이동)

**한계:**
일부 자원은 선점이 **불가능하거나 비효율적**입니다.

**선점 불가능한 자원 예시:**

- **프린터**: 출력 중간에 빼앗으면 출력물이 손상됨
- **데이터베이스 트랜잭션**: 중간에 중단하면 데이터 무결성 손상
- **테이프 드라이브**: 물리적 장치 특성상 선점 어려움

---

### 2.5 원형 대기 조건 제거

### 마지막으로 원형 대기 조건을 없애봅시다

**방법:** 모든 자원에 **고유 번호를 부여**하고, 프로세스는 **오름차순으로만** 자원을 요청하도록 제한

**구현 방식:**

```
자원 번호 체계:
프린터 = 1번
파일 A = 2번
파일 B = 3번
메모리 = 4번

규칙: 프로세스는 1 → 2 → 3 → 4 순서로만 요청 가능

```

**원리:**

- 순환 대기가 발생하려면 작은 번호에서 큰 번호로, 다시 작은 번호로 요청해야 함
- 오름차순 제한으로 순환 구조 자체가 불가능해짐

**예시:**

```
P1: 자원 1번 보유 → 자원 2번 요청 (가능)
P2: 자원 2번 보유 → 자원 3번 요청 (가능)
P3: 자원 3번 보유 → 자원 1번 요청 (불가능, 역순 금지)

→ 순환 대기 발생 불가

```

**장점:**

- 교착 상태 원천 방지
- 구현이 비교적 명확

**한계:**

- **실제 자원 사용 패턴과 맞지 않을 수 있음**: 프로세스가 자원을 사용하는 순서가 번호 순서와 다를 수 있음
- **자원 활용도 저하**: 나중에 필요한 자원도 순서상 먼저 할당받아야 할 수 있음
- **유연성 부족**: 동적으로 변하는 자원 요청 패턴에 대응 어려움

---

### 2.6 교착 상태 예방의 한계

교착 상태 예방은 **이론적으로는 완벽**하지만, **실용성이 떨어집니다**.

**주요 문제점:**

- 자원 활용도가 크게 저하됨
- 시스템 처리량(Throughput)이 감소
- 실제 시스템에서는 자원 요청 패턴이 복잡하고 동적임
- 프로세스의 실행 효율성이 떨어짐

**결론:**
실제 운영체제에서는 예방보다는 **회피(Avoidance)** 또는 **검출 및 회복(Detection & Recovery)** 방식을 더 많이 사용합니다.

---

## 3. 교착 상태 회피 (Avoidance)

### 3.1 회피의 기본 원리

**교착 상태 회피**는 교착 상태가 발생할 **가능성을 사전에 검사**하여, 안전한 경우에만 자원을 할당하는 방법입니다.

**핵심 아이디어:**

- 교착 상태 발생 조건을 제거하지 않음
- 대신 자원 할당 시 **안전성을 검사**
- 교착 상태로 이어질 수 있는 할당은 거부

**예방 vs 회피:**

- **예방**: 교착 상태 발생 조건 자체를 제거 (너무 보수적)
- **회피**: 교착 상태 가능성을 미리 파악하여 회피 (더 효율적)

---

### 3.2 안전 상태 (Safe State)

**안전 상태**란 시스템이 어떤 순서로든 **모든 프로세스에게 자원을 할당**하여 교착 상태 없이 **완료**시킬 수 있는 상태를 의미합니다.

**안전 순서열 (Safe Sequence):**
프로세스들이 교착 상태 없이 완료될 수 있는 실행 순서

**안전 상태의 조건:**

- 안전 순서열이 **최소 하나 이상** 존재
- 각 프로세스가 요청하는 자원을 순차적으로 할당 가능
- 모든 프로세스가 완료 가능

**불안전 상태 (Unsafe State):**

- 안전 순서열이 존재하지 않음
- 교착 상태가 **발생할 가능성**이 있음 (반드시 발생하는 것은 아님)

**중요 개념:**

```
안전 상태 ⊂ 불안전 상태 ⊂ 교착 상태

안전 상태: 교착 상태 발생 불가능
불안전 상태: 교착 상태 발생 가능성 있음
교착 상태: 실제로 교착 상태 발생

```

---

### 3.3 은행원 알고리즘 (Banker's Algorithm)

교착 상태 회피를 위한 대표적인 알고리즘으로, **은행의 대출 관리**와 유사한 방식입니다.

**알고리즘 명칭의 유래:**
은행이 고객에게 대출할 때, 모든 고객이 동시에 최대 대출액을 요구해도 대응할 수 있도록 자금을 관리하는 것과 유사합니다.

**필요한 정보:**

- **최대 요구량 (Max)**: 각 프로세스가 필요로 하는 최대 자원 개수
- **현재 할당량 (Allocation)**: 현재 프로세스에게 할당된 자원 개수
- **추가 요구량 (Need)**: 앞으로 추가로 필요한 자원 개수 (Max - Allocation)
- **가용 자원 (Available)**: 현재 시스템에서 사용 가능한 자원 개수

---

### 3.4 교착 상태 회피 실습 예제

### 초기 상황 설정

```
시스템 총 자원: 12개

프로세스 | 최대 요구량 | 현재 사용량 | 추가 필요량
  (Max)        (Allocation)  (Need)
--------|-----------|------------|----------
P1      |    10     |     5      |    5
P2      |     4     |     2      |    2
P3      |     9     |     2      |    7
--------|-----------|------------|----------

```

**현재 상태 계산:**

- 할당된 총 자원 = 5 + 2 + 2 = 9개
- 가용 자원(Available) = 12 - 9 = 3개

---

### 시나리오 1: P2가 자원 2개 추가 요청

**요청 처리 시뮬레이션:**

**1단계: P2에게 2개 할당 가정**

```
프로세스 | 최대 요구량 | 현재 사용량 | 추가 필요량
P1      |    10     |     5      |    5
P2      |     4     |     4      |    0  ← 완료 가능!
P3      |     9     |     2      |    7

가용 자원: 3 - 2 = 1개

```

**2단계: P2 완료 후 자원 반납**

```
P2가 사용하던 자원 4개 반납
가용 자원: 1 + 4 = 5개

```

**3단계: P1에게 5개 할당**

```
프로세스 | 최대 요구량 | 현재 사용량 | 추가 필요량
P1      |    10     |    10      |    0  ← 완료 가능!
P3      |     9     |     2      |    7

가용 자원: 5 - 5 = 0개

```

**4단계: P1 완료 후 자원 반납**

```
P1이 사용하던 자원 10개 반납
가용 자원: 0 + 10 = 10개

```

**5단계: P3에게 7개 할당**

```
프로세스 | 최대 요구량 | 현재 사용량 | 추가 필요량
P3      |     9     |     9      |    0  ← 완료 가능!

가용 자원: 10 - 7 = 3개

```

**결론:**

- **안전 순서열 발견**: P2 → P1 → P3
- **요청 승인**: P2에게 자원 2개 할당

---

### 시나리오 2: P2 요청 승인 후, P1이 자원 5개 추가 요청

**현재 상태 (P2 완료 후):**

```
프로세스 | 최대 요구량 | 현재 사용량 | 추가 필요량
P1      |    10     |     5      |    5
P3      |     9     |     2      |    7

가용 자원: 5개

```

**요청 처리 시뮬레이션:**

**1단계: P1에게 5개 할당 가정**

```
프로세스 | 최대 요구량 | 현재 사용량 | 추가 필요량
P1      |    10     |    10      |    0  ← 완료 가능!
P3      |     9     |     2      |    7

가용 자원: 5 - 5 = 0개

```

**2단계: P1 완료 후 자원 반납**

```
P1이 사용하던 자원 10개 반납
가용 자원: 0 + 10 = 10개

```

**3단계: P3에게 7개 할당**

```
프로세스 | 최대 요구량 | 현재 사용량 | 추가 필요량
P3      |     9     |     9      |    0  ← 완료 가능!

가용 자원: 10 - 7 = 3개

```

**결론:**

- **안전 순서열 발견**: P1 → P3
- **요청 승인**: P1에게 자원 5개 할당

---

### 시나리오 3: 초기 상태에서 P1이 먼저 자원 5개 요청

**초기 상태:**

```
프로세스 | 최대 요구량 | 현재 사용량 | 추가 필요량
P1      |    10     |     5      |    5
P2      |     4     |     2      |    2
P3      |     9     |     2      |    7

가용 자원: 3개

```

**요청 처리 시뮬레이션:**

**1단계: P1에게 5개 할당 가정**

```
P1에게 5개를 주려면 가용 자원 3개로는 부족
하지만 가정상 할당한다면:

프로세스 | 최대 요구량 | 현재 사용량 | 추가 필요량
P1      |    10     |    10      |    0  ← 완료 가능!
P2      |     4     |     2      |    2
P3      |     9     |     2      |    7

가용 자원: 3 - 5 = -2개 (불가능)

```

**실제로는 가용 자원이 3개뿐이므로:**

```
프로세스 | 최대 요구량 | 현재 사용량 | 추가 필요량
P1      |    10     |     8      |    2  ← 3개만 할당
P2      |     4     |     2      |    2
P3      |     9     |     2      |    7

가용 자원: 0개

```

**2단계: 안전 순서열 확인**

```
가용 자원 0개로는 P1(2개 필요), P2(2개 필요), P3(7개 필요) 모두 완료 불가
→ 어느 프로세스도 완료할 수 없음
→ 교착 상태 가능성!

```

**결론:**

- **안전 순서열 없음**: 불안전 상태
- **요청 거부**: P1의 요청을 거부하고 대기시킴

---

### 3.5 교착 상태 회피의 장단점

**장점:**

- 교착 상태 발생 조건을 제거하지 않아도 됨
- 예방보다 자원 활용도가 높음
- 시스템 처리량이 더 좋음

**단점:**

- 각 프로세스의 **최대 자원 요구량을 미리 알아야 함** (실제로는 예측 어려움)
- 자원 할당 요청마다 **안전성 검사** 필요 (오버헤드 발생)
- 프로세스 수와 자원 종류가 많으면 계산 복잡도 증가
- 시스템 자원이 동적으로 변하는 환경에서는 적용 어려움

**실제 사용:**

- 실시간 시스템, 임베디드 시스템 등 제한적인 환경에서 주로 사용
- 일반적인 범용 운영체제에서는 오버헤드로 인해 잘 사용하지 않음

---

## 4. 교착 상태 검출 및 회복 (Detection & Recovery)

### 4.1 검출 및 회복의 기본 원리

**방식:**

- 교착 상태 발생을 **허용**함
- 주기적으로 또는 특정 상황에서 교착 상태를 **검출**
- 검출되면 적절한 방법으로 **회복**

**사용 이유:**

- 예방과 회피는 오버헤드가 크거나 비현실적
- 교착 상태가 자주 발생하지 않는 시스템에서는 발생 시 처리하는 것이 효율적

---

### 4.2 교착 상태 검출 방법

### 자원 할당 그래프 (Resource Allocation Graph)

프로세스와 자원 간의 관계를 그래프로 표현하여 순환(Cycle)을 검출

**그래프 구성 요소:**

- 원(○): 프로세스
- 사각형(□): 자원
- 화살표: 자원 할당 또는 요청 관계

**검출 알고리즘:**

1. 자원 할당 그래프 생성
2. 그래프에서 순환 구조 탐색 (DFS, BFS 등)
3. 순환이 존재하면 교착 상태로 판단

---

### 4.3 교착 상태 회복 방법

교착 상태가 검출되면 다음 방법으로 회복합니다.

### 방법 1: 선점을 통한 회복

**개념:**
교착 상태에 빠진 프로세스로부터 자원을 강제로 회수하여 다른 프로세스에 할당

**절차:**

1. 교착 상태에 빠진 프로세스 선택
2. 해당 프로세스로부터 자원 회수
3. 회수한 자원을 대기 중인 다른 프로세스에 할당
4. 선점된 프로세스는 나중에 재시작

**고려사항:**

- **어떤 프로세스에서 선점할 것인가?**
    - 우선순위가 낮은 프로세스
    - 실행 시간이 짧은 프로세스
    - 적은 자원을 보유한 프로세스
- **선점된 프로세스의 처리:**
    - 롤백(Rollback): 이전 안전 지점으로 되돌리기
    - 재시작: 프로세스를 처음부터 다시 시작

**장점:**

- 신속한 해결 가능
- 시스템 전체를 중단하지 않음

**단점:**

- 선점된 프로세스의 작업 손실
- 롤백 메커니즘 구현 복잡
- 같은 프로세스가 반복적으로 선점될 수 있음 (기아 현상)

---

### 방법 2: 프로세스 강제 종료

**개념:**
교착 상태에 빠진 프로세스를 강제로 종료하여 자원을 회수

**방식 2-1: 전체 종료**

```
교착 상태에 빠진 모든 프로세스를 한 번에 종료
→ 빠른 회복, 하지만 작업 손실 큼

```

**방식 2-2: 단계적 종료**

```
한 번에 하나씩 프로세스를 종료하며 교착 상태 해소 확인
→ 최소한의 프로세스만 종료, 하지만 오버헤드 발생

```

**종료할 프로세스 선택 기준:**

- 우선순위가 낮은 프로세스
- 실행 시간이 짧은 프로세스 (손실이 적음)
- 사용한 자원이 적은 프로세스
- 대화형 프로세스보다 배치 프로세스 우선
- 남은 작업량이 적은 프로세스

**장점:**

- 구현이 비교적 간단
- 확실한 회복 보장

**단점:**

- 프로세스의 모든 작업 손실
- 사용자 불만 발생 가능
- 재시작 비용 발생

---

### 4.4 검출 및 회복의 장단점

**장점:**

- 교착 상태 예방이나 회피에 비해 오버헤드가 적음
- 자원 활용도가 높음
- 프로세스의 최대 자원 요구량을 미리 알 필요 없음

**단점:**

- 교착 상태가 발생하면 작업 손실 불가피
- 검출 알고리즘 실행에도 오버헤드 발생
- 사용자 경험 저하 가능

**실제 사용:**

- 대부분의 범용 운영체제(Windows, Linux 등)에서 사용
- 교착 상태가 드물게 발생하는 시스템에 적합

---

## 5. 연속 메모리 할당 (Contiguous Memory Allocation)

### 5.1 메모리 할당의 개념

**연속 메모리 할당**이란 프로세스를 메모리의 **연속된 하나의 공간**에 배치하는 방법입니다.

**특징:**

- 각 프로세스는 연속된 주소 공간 차지
- 메모리가 여러 프로세스로 분할됨
- 단순하고 구현이 쉬움
- **메모리 구조 예시:**

```
┌─────────────┐ 0x0000
│ 운영체제     │
├─────────────┤
│ 프로세스 A   │
├─────────────┤
│ 빈 공간      │
├─────────────┤
│ 프로세스 B   │
├─────────────┤
│ 프로세스 C   │
├─────────────┤
│ 빈 공간      │
└─────────────┘ 0xFFFF

```

---

### 5.1.1 스와핑 (Swapping)

스와핑은 메모리 공간이 부족할 때 프로세스를 메모리와 디스크 사이에서 이동시키는 기법입니다.

**스왑 아웃 (Swap Out):**

- 메모리에 있는 프로세스를 디스크의 스왑 영역으로 이동
- 메모리 공간 확보를 위해 실행

**스왑 인 (Swap In):**

- 디스크의 스왑 영역에 있던 프로세스를 다시 메모리로 가져옴
- 프로세스 실행을 재개하기 위해 필요

**스와핑 과정:**

```
메모리 부족 감지
    ↓
스왑 아웃: 우선순위 낮은 프로세스를 디스크로 이동
    ↓
메모리 공간 확보
    ↓
새로운 프로세스 또는 기존 프로세스 로드
    ↓
필요시 스왑 인: 디스크의 프로세스를 다시 메모리로
```

**특징:**

- 실제 물리 메모리보다 많은 프로세스 실행 가능
- 디스크 I/O가 발생하여 오버헤드 존재
- 컨텍스트 스위칭 시간 증가

---

### 5.2 메모리 배치 전략

운영체제는 새로운 프로세스를 메모리에 적재할 때, 여러 빈 공간 중 어디에 배치할지 결정해야 합니다.

---

### 5.2.1 최초 적합 (First Fit)

**정의:**
메모리의 **처음부터 순차적으로 검색**하여 프로세스가 들어갈 수 있는 **첫 번째 빈 공간**에 배치

**동작 과정:**

```
빈 공간 리스트: [30MB, 50MB, 100MB, 20MB]
새 프로세스: 40MB

1. 30MB 검사 → 불가능 (40MB > 30MB)
2. 50MB 검사 → 가능! (40MB < 50MB)
→ 50MB 공간에 배치
→ 남은 공간: 10MB

```

**장점:**

- **검색 속도가 가장 빠름** (첫 번째 적합 공간을 찾으면 종료)
- 구현이 간단
- 오버헤드가 적음

**단점:**

- 메모리 **앞부분에 작은 빈 공간들이 누적**될 수 있음 (외부 단편화)
- 큰 프로세스를 위한 공간이 부족해질 수 있음

**사용 상황:**

- 빠른 메모리 할당이 중요한 경우
- 시스템 부하가 높은 환경

---

### 5.2.2 최적 적합 (Best Fit)

**정의:모든 빈 공간을 검색**하여 프로세스가 들어갈 수 있는 **가장 작은 빈 공간**에 배치

**동작 과정:**

```
빈 공간 리스트: [30MB, 50MB, 100MB, 45MB, 20MB]
새 프로세스: 40MB

모든 빈 공간 검사:
- 30MB: 불가능 (40MB > 30MB)
- 50MB: 가능 (남은 공간 10MB)
- 100MB: 가능 (남은 공간 60MB)
- 45MB: 가능 (남은 공간 5MB) ← 최소!
- 20MB: 불가능

→ 45MB 공간에 배치
→ 남은 공간: 5MB

```

**장점:**

- **공간 낭비 최소화** (가장 적합한 크기 선택)
- 큰 빈 공간 보존 가능

**단점:**

- **검색 시간이 김** (모든 빈 공간 검색 필요)
- **아주 작은 빈 공간들이 많이 생성**됨 (외부 단편화 심화)
    - 예: 5MB 같은 작은 공간은 사용하기 어려움

**사용 상황:**

- 메모리가 제한적인 환경
- 공간 효율이 중요한 시스템

---

### 5.2.3 최악 적합 (Worst Fit)

**정의:모든 빈 공간을 검색**하여 프로세스가 들어갈 수 있는 **가장 큰 빈 공간**에 배치

**동작 과정:**

```
빈 공간 리스트: [30MB, 50MB, 100MB, 45MB, 20MB]
새 프로세스: 40MB

모든 빈 공간 검사:
- 30MB: 불가능
- 50MB: 가능 (남은 공간 10MB)
- 100MB: 가능 (남은 공간 60MB) ← 최대!
- 45MB: 가능 (남은 공간 5MB)
- 20MB: 불가능

→ 100MB 공간에 배치
→ 남은 공간: 60MB (여전히 큰 공간)

```

**아이디어:**
큰 빈 공간에 배치하면 남은 공간도 **충분히 커서** 다른 프로세스가 사용할 수 있을 것이라는 기대

**장점:**

- 남은 빈 공간이 **비교적 큼** (다른 프로세스 할당 가능)
- 아주 작은 단편이 덜 생김

**단점:**

- **검색 시간이 김** (모든 빈 공간 검색 필요)
- **큰 빈 공간이 빠르게 소진**됨
- 큰 프로세스를 위한 공간이 부족해질 수 있음

**사용 상황:**

- 프로세스 크기가 비슷한 환경
- 큰 프로세스가 드문 시스템

---

### 5.3 메모리 할당 기법 비교

| 기법 | 검색 방식 | 장점 | 단점 | 속도 |
| --- | --- | --- | --- | --- |
| **최초 적합** | 순차 검색 (첫 번째 발견 시 종료) | 빠른 속도, 낮은 오버헤드 | 메모리 앞부분 단편화 | 빠름 |
| **최적 적합** | 전체 검색 (최소 공간 선택) | 공간 효율 최대화 | 느린 속도, 작은 단편 다수 생성 | 느림 |
| **최악 적합** | 전체 검색 (최대 공간 선택) | 큰 단편 유지 | 느린 속도, 큰 공간 빠른 소진 | 느림 |

---

## 6. 외부 단편화 (External Fragmentation)

### 6.1 외부 단편화란?

**외부 단편화**는 메모리에 총 여유 공간은 충분하지만, **공간들이 흩어져 있어** 프로세스를 적재할 수 없는 현상입니다.

**발생 메커니즘:**

```
초기 상태:
┌─────────────┐
│ 프로세스 A   │ 50MB
├─────────────┤
│ 프로세스 B   │ 30MB
├─────────────┤
│ 프로세스 C   │ 100MB
├─────────────┤
│ 프로세스 D   │ 20MB
└─────────────┘

프로세스 B, D 종료:
┌─────────────┐
│ 프로세스 A   │ 50MB
├─────────────┤
│ 빈 공간      │ 30MB
├─────────────┤
│ 프로세스 C   │ 100MB
├─────────────┤
│ 빈 공간      │ 20MB
└─────────────┘

총 빈 공간: 50MB
새 프로세스: 40MB
→ 적재 불가능! (연속된 40MB 공간 없음)

```

**특징:**

- 총 여유 공간 ≥ 프로세스 크기
- 하지만 연속된 공간이 부족
- 프로세스의 생성과 종료가 반복되면서 심화

---

### 6.2 압축 (Compaction)

**압축**은 흩어진 빈 공간들을 **한곳으로 모아** 큰 연속 공간을 만드는 기법입니다.

**동작 과정:**

```
압축 전:
┌─────────────┐
│ 프로세스 A   │ 50MB
├─────────────┤
│ 빈 공간      │ 30MB
├─────────────┤
│ 프로세스 C   │ 100MB
├─────────────┤
│ 빈 공간      │ 20MB
└─────────────┘

압축 후 (프로세스들을 위로 이동):
┌─────────────┐
│ 프로세스 A   │ 50MB
├─────────────┤
│ 프로세스 C   │ 100MB
├─────────────┤
│ 빈 공간      │ 50MB (30MB + 20MB)
└─────────────┘

→ 40MB 프로세스 적재 가능!

```

**장점:**

- 외부 단편화 완전 해결
- 큰 연속 공간 확보
- 메모리 활용도 향상

**단점:**

- **프로세스 이동에 많은 시간과 자원 소요**
    - 프로세스 데이터를 메모리 내에서 복사
    - 프로세스가 많으면 오버헤드 급증
- **시스템 부하 증가**
    - 압축 중에는 다른 작업 중단 또는 지연
- **프로세스의 주소 재계산 필요**
    - 프로세스 내부의 포인터, 주소값 모두 업데이트

**실제 사용:**

- 오버헤드가 너무 커서 실제로는 거의 사용하지 않음
- 대신 **페이징(Paging)** 또는 **세그멘테이션(Segmentation)** 같은 비연속 할당 기법 사용

---

### 6.3 내부 단편화 vs 외부 단편화

| 구분 | 내부 단편화 | 외부 단편화 |
| --- | --- | --- |
| **발생 위치** | 프로세스 내부 | 프로세스 외부 (빈 공간) |
| **원인** | 고정 크기 할당 (프로세스보다 큰 공간 할당) | 가변 크기 할당 (빈 공간 조각화) |
| **예시** | 50MB 프로세스에 64MB 할당 → 14MB 낭비 | 여러 작은 빈 공간들 존재 |
| **해결 방법** | 가변 크기 할당, 적절한 블록 크기 선택 | 압축, 페이징, 세그멘테이션 |

---

## 7. 비연속 메모리 할당 (Non-contiguous Allocation)

### 7.1 페이징 (Paging)

**개념:**

- 메모리를 **고정 크기의 페이지(Page)** 로 분할
- 프로세스도 **같은 크기의 페이지**로 분할
- 프로세스의 페이지들을 메모리의 여러 위치에 **비연속적으로 배치**

**장점:**

- **외부 단편화 해결** (어떤 빈 페이지든 사용 가능)
- 압축 불필요
- 메모리 관리 간편

**단점:**

- 내부 단편화 발생 가능 (마지막 페이지)
- 페이지 테이블 관리 오버헤드

---

### 7.2 세그멘테이션 (Segmentation)

**개념:**

- 프로세스를 **논리적 단위(세그먼트)** 로 분할
- 각 세그먼트를 메모리의 여러 위치에 배치
- 세그먼트 크기는 **가변적**

**세그먼트 예시:**

- 코드 세그먼트
- 데이터 세그먼트
- 스택 세그먼트
- 힙 세그먼트

**장점:**

- 논리적 구조 반영
- 공유와 보호 용이

**단점:**

- 외부 단편화 발생 가능
- 세그먼트 테이블 관리 복잡

---

## 📝 핵심 요약

### 교착 상태 (Deadlock)

**발생 조건 (4가지 모두 충족 시):**

1. 상호 배제 (Mutual Exclusion)
2. 점유와 대기 (Hold and Wait)
3. 비선점 (No Preemption)
4. 원형 대기 (Circular Wait)

**해결 방법:**

- **예방 (Prevention)**: 4가지 조건 중 하나 제거 (비현실적)
- **회피 (Avoidance)**: 안전 상태 유지하며 자원 할당 (은행원 알고리즘)
- **검출 및 회복 (Detection & Recovery)**: 발생 후 처리 (실용적)

---

### 메모리 할당 기법

**연속 할당:**

- **최초 적합 (First Fit)**: 첫 번째 적합 공간 (빠름)
- **최적 적합 (Best Fit)**: 가장 작은 적합 공간 (공간 효율)
- **최악 적합 (Worst Fit)**: 가장 큰 공간 (큰 단편 유지)

**스와핑:**

- 메모리 ↔ 디스크 간 프로세스 이동 기법
- 스왑 아웃: 메모리 → 디스크 (공간 확보)
- 스왑 인: 디스크 → 메모리 (실행 재개)
- 장점: 물리 메모리보다 많은 프로세스 실행 가능
- 단점: 디스크 I/O로 인한 성능 저하

**비연속 할당:**

- **페이징 (Paging)**: 고정 크기 분할 (외부 단편화 해결)
- **세그멘테이션 (Segmentation)**: 논리적 단위 분할 (구조 반영)

---

### 단편화

**외부 단편화:**

- 문제: 빈 공간 흩어짐 → 프로세스 적재 불가
- 해결: 압축 (오버헤드 큼) 또는 비연속 할당

**내부 단편화:**

- 문제: 프로세스 내부 공간 낭비
- 해결: 가변 크기 할당

---

## 🎯 복습용 퀴즈

### Q1. 교착 상태가 발생하기 위한 4가지 조건이 아닌 것은?

1. 상호 배제 (Mutual Exclusion)
2. 점유와 대기 (Hold and Wait)
3. 선점 (Preemption)
4. 원형 대기 (Circular Wait)

정답: 3) 선점 (Preemption)

해설: 교착 상태의 4가지 필요조건은 상호 배제, 점유와 대기, **비선점**, 원형 대기입니다. 선택지 3번은 '선점'이라고 되어 있지만, 실제 조건은 '비선점'입니다. 자원을 선점할 수 있다면 교착 상태를 방지할 수 있으므로, 교착 상태 발생 조건은 '비선점(No Preemption)'이 맞습니다.

### Q2. 다음 상황에서 P2가 자원 2개를 추가로 요청할 때, 안전 순서열이 존재하는가?

```
시스템 총 자원: 12개

프로세스 | 최대 요구량 | 현재 사용량
P1      |    10     |     5
P2      |     4     |     2
P3      |     9     |     2

가용 자원: 3개

```

1. 안전 순서열이 존재하며, P2 → P1 → P3 순서로 완료 가능
2. 안전 순서열이 존재하지 않으며, 교착 상태 발생
3. 안전 순서열이 존재하며, P1 → P2 → P3 순서로 완료 가능
4. 자원이 부족하여 P2의 요청을 거부해야 함

정답: 1) 안전 순서열이 존재하며, P2 → P1 → P3 순서로 완료 가능

해설: P2에게 2개를 할당하면 P2는 총 4개(최대 요구량)를 보유하게 되어 작업을 완료하고 자원을 반납합니다. P2 완료 후 가용 자원은 5개가 되어 P1의 추가 요구량 5개를 충족할 수 있습니다. P1 완료 후에는 가용 자원이 10개가 되어 P3의 추가 요구량 7개도 충족 가능합니다. 따라서 안전 순서열 P2 → P1 → P3가 존재하므로 요청을 승인할 수 있습니다.

### Q3. 메모리 할당 기법 중 '최적 적합(Best Fit)'의 특징으로 옳은 것은?

1. 가장 빠른 검색 속도를 보장한다
2. 프로세스가 적재될 수 있는 가장 작은 빈 공간에 배치한다
3. 프로세스가 적재될 수 있는 첫 번째 빈 공간에 배치한다
4. 프로세스가 적재될 수 있는 가장 큰 빈 공간에 배치한다

정답: 2) 프로세스가 적재될 수 있는 가장 작은 빈 공간에 배치한다

해설: 최적 적합(Best Fit)은 모든 빈 공간을 검색하여 프로세스 크기에 가장 근접한 작은 빈 공간을 선택하는 방식입니다. 이를 통해 메모리 공간 낭비를 최소화할 수 있습니다. 하지만 모든 빈 공간을 검색해야 하므로 검색 속도는 느리며, 아주 작은 빈 공간들(단편)이 많이 생성되는 단점이 있습니다.

### Q4. 외부 단편화(External Fragmentation)에 대한 설명으로 옳지 않은 것은?

1. 메모리의 빈 공간이 여러 곳에 흩어져 있어 발생한다
2. 압축(Compaction)을 통해 해결할 수 있다
3. 프로세스 내부에서 사용하지 않는 메모리 공간으로 인해 발생한다
4. 총 여유 공간은 충분하지만 연속된 공간이 부족한 상황이다

정답: 3) 프로세스 내부에서 사용하지 않는 메모리 공간으로 인해 발생한다

해설: 프로세스 내부에서 할당받았지만 사용하지 않는 공간으로 인한 문제는 '내부 단편화(Internal Fragmentation)'입니다. 외부 단편화는 프로세스들 사이의 빈 공간들이 비연속적으로 흩어져 있어, 총 여유 공간은 충분하지만 새로운 프로세스를 적재할 수 있는 연속된 공간이 부족한 현상을 의미합니다.

### Q5. 교착 상태 회피(Avoidance)에서 '안전 상태(Safe State)'의 의미는?

1. 모든 프로세스가 동시에 실행되고 있는 상태
2. 시스템에 교착 상태가 이미 발생한 상태
3. 모든 프로세스를 교착 상태 없이 완료시킬 수 있는 실행 순서가 존재하는 상태
4. 자원이 부족하여 프로세스를 실행할 수 없는 상태

정답: 3) 모든 프로세스를 교착 상태 없이 완료시킬 수 있는 실행 순서가 존재하는 상태

해설: 안전 상태란 안전 순서열(Safe Sequence)이 존재하는 상태를 의미합니다. 즉, 어떤 순서로든 모든 프로세스에게 필요한 자원을 할당하여 교착 상태 없이 완료시킬 수 있는 상태입니다. 운영체제는 은행원 알고리즘 등을 통해 자원 할당 요청이 있을 때마다 안전 상태를 유지하는지 검사하고, 안전 상태가 유지되는 경우에만 자원을 할당합니다.

### Q6. 다음 중 최초 적합(First Fit) 메모리 할당 기법의 단점은?

1. 검색 시간이 가장 오래 걸린다
2. 메모리 앞부분에 작은 빈 공간들이 누적될 수 있다
3. 큰 빈 공간이 빠르게 소진된다
4. 매우 작은 단편들이 가장 많이 생성된다

정답: 2) 메모리 앞부분에 작은 빈 공간들이 누적될 수 있다

해설: 최초 적합(First Fit)은 메모리를 처음부터 순차적으로 검색하여 첫 번째로 발견된 적합한 빈 공간에 프로세스를 배치합니다. 이 때문에 메모리 앞부분이 자주 사용되고, 작은 빈 공간들이 메모리 앞부분에 누적되는 경향이 있습니다. 하지만 검색 속도는 가장 빠르며(첫 번째 적합 공간을 찾으면 즉시 종료), 작은 단편 생성은 최적 적합(Best Fit)에서 더 심각합니다.

### Q7. 압축(Compaction)에 대한 설명으로 옳은 것은?

1. 내부 단편화를 해결하기 위한 기법이다
2. 프로세스들을 이동시켜 빈 공간을 한곳으로 모은다
3. 오버헤드가 거의 없어 자주 사용된다
4. 페이징 기법에서만 사용 가능하다

정답: 2) 프로세스들을 이동시켜 빈 공간을 한곳으로 모은다

해설: 압축(Compaction)은 외부 단편화를 해결하기 위한 기법으로, 메모리에 흩어져 있는 프로세스들을 한쪽으로 이동시켜 빈 공간들을 하나의 큰 연속된 공간으로 통합합니다. 이를 통해 외부 단편화를 완전히 해결할 수 있지만, 프로세스 이동에 많은 시간과 자원이 소요되어 오버헤드가 매우 큽니다. 또한 프로세스의 모든 주소값을 재계산해야 하는 문제도 있습니다. 이러한 이유로 실제 시스템에서는 거의 사용되지 않으며, 대신 페이징이나 세그멘테이션 같은 비연속 할당 기법을 사용합니다.

### Q8. 다음 중 교착 상태 예방(Prevention)의 한계가 아닌 것은?

1. 자원 활용도가 크게 저하된다
2. 시스템 처리량이 감소한다
3. 프로세스의 최대 자원 요구량을 미리 알아야 한다
4. 실제 시스템에서는 자원 요청 패턴이 복잡하고 동적이다

정답: 3) 프로세스의 최대 자원 요구량을 미리 알아야 한다

해설: 프로세스의 최대 자원 요구량을 미리 알아야 하는 것은 교착 상태 회피(Avoidance), 특히 은행원 알고리즘의 한계입니다. 교착 상태 예방(Prevention)은 4가지 발생 조건 중 하나를 원천적으로 제거하는 방법으로, 점유와 대기 제거(모든 자원을 한 번에 할당), 비선점 제거(강제 선점), 원형 대기 제거(자원 번호 순서 할당) 등의 방법을 사용합니다. 예방의 주요 한계는 이러한 제약 조건들로 인해 자원 활용도가 떨어지고 시스템 효율성이 저하된다는 점입니다.
