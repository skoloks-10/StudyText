# 컴퓨터 시스템 구조 - RAID와 입출력 시스템

## 07-2 RAID의 정의와 종류

### 주제목: RAID 개요

### RAID란?

- **정의** : RAID(Redundant Array of Independent Disks)는 여러 개의 보조기억장치를 하나의 논리적 장치로 인식하게 하여 성능과 안정성을 향상시키는 기술
- **목적** :
- 대용량 저장 공간 확보
- 데이터 안정성 증대
- 입출력 속도 향상
- **구성** : 여러 개의 하드 디스크나 SSD를 사용하여 데이터 보호와 저장장치 성능을 향상

### RAID 사용 시나리오

**질문** : 1TB 하드 디스크 4개와 4TB 하드 디스크 1개를 비교했을 때?

- 1TB 디스크 4개로 RAID 구성 시: 4TB 하드 디스크보다 더 나은 성능과 안정성 확보 가능
- RAID는 여러 저장장치를 하나처럼 사용하면서도 개별 장치의 이점 활용

### 중제목: RAID 레벨별 상세 설명

### RAID 0 (스트라이핑)

**개념** :

- 여러 개의 보조기억장치에 데이터를 단순히 나누어 저장
- 가장 기본적인 RAID 방식으로 1TB 하드 디스크 4개로 구성 가능

  **특징** :

- 스트라이프(Stripe): 줄무늬 패턴으로 데이터 분산 저장
- 저장 방식: 데이터를 A1, A2, A3, A4로 분할하여 각 디스크에 순차적으로 저장
- 장점: 4TB의 저장공간 확보, 데이터 분산으로 입출력 속도 향상
- 단점: **데이터 복구 불가능** - 하나의 디스크 고장 시 모든 데이터 손실 위험

  **데이터 저장 구조** :

```
디스크1: A1, B1, C1, D1
디스크2: A2, B2, C2, D2
디스크3: A3, B3, C3, D3
디스크4: A4, B4, C4, D4

```

### RAID 1 (미러링)

**개념** :

- 복사본을 만드는 방식
- 완전한 백업본을 만드는 구성

  **특징** :

- 미러링(Mirroring): 거울처럼 데이터 복제
- 저장 방식: 동일한 데이터를 두 개의 디스크에 동시 저장
- 장점:
  - 하나의 디스크 고장 시에도 다른 디스크로 복구 가능
  - 데이터 안정성 최고 수준
- 단점:

  - 저장 용량 절반으로 감소 (2TB 하드 4개 = 실제 사용 공간 2TB)
  - 복사본 만들기에 사용되는 디스크로 인한 비용 증가

  **데이터 저장 구조** :

```
디스크1: A1, B1, C1, D1 (원본)
디스크2: A2, B2, C2, D2 (원본)
디스크3: A1, B1, C1, D1 (백업)
디스크4: A2, B2, C2, D2 (백업)

```

### RAID 4 (블록 단위 패리티)

**개념** :

- RAID 1처럼 완전한 복사본이 아닌 오류 검출하고 복구하기 위한 정보를 저장
- 패리티 비트(Parity bit) 방식 사용

  **특징** :

- 패리티 비트: 오류를 검출하고 복구하기 위한 정보
- 저장 방식:
  - 데이터 디스크: 실제 데이터 저장
  - 패리티 디스크: 오류 복구 정보만 저장
- 장점:
  - RAID 1보다 적은 하드 디스크로 데이터 안정성 확보
  - 저장 용량 효율적 (3TB + 1TB 패리티 = 3TB 사용 가능)
- 단점:

  - 패리티 디스크에 병목현상 발생 가능
  - 패리티를 저장하는 장치에만 데이터 쓰기 작업 집중

  **데이터 저장 구조** :

```
디스크1: A1, B1, C1, D1
디스크2: A2, B2, C2, D2
디스크3: A3, B3, C3, D3
디스크4: 패리티A, 패리티B, 패리티C, 패리티D

```

### RAID 5 (분산 패리티)

**개념** :

- RAID 4의 패리티 집중 문제를 개선
- 패리티 정보를 분산 저장

  **특징** :

- 저장 방식: 패리티 정보를 각 디스크에 분산하여 저장
- 장점:
  - 병목현상 해소
  - 안정성과 성능의 균형
- 구성: 최소 3개의 디스크 필요

  **데이터 저장 구조** :

```
디스크1: A1, B1, C1, 패리티D
디스크2: A2, B2, 패리티C, D2
디스크3: A3, 패리티B, C3, D3
디스크4: 패리티A, B4, C4, D4

```

### RAID 6 (이중 패리티)

**개념** :

- RAID 5와 구성이 기본적으로 같으나 서로 다른 두 개의 패리티 사용
- 오류를 검출하고 복구할 수 있는 수단 두 개 확보

  **특징** :

- 저장 방식: 두 종류의 패리티 정보 저장
- 장점:
  - RAID 4, 5보다 안정성 우수
  - 두 개의 디스크가 동시에 고장나도 복구 가능
- 단점:

  - 저장 속도는 RAID 5보다 느림
  - 쓰기 속도 저하
  - 패리티 저장 공간 증가로 실제 저장 공간 감소

  **데이터 저장 구조** :

```
디스크1: A1, B1, 패리티1C, 패리티2D
디스크2: A2, 패리티1B, C2, 패리티2E
디스크3: 패리티1A, B3, C3, D3
디스크4: 패리티2A, 패리티2B, C4, D4
디스크5: E1, E2, E3, E4

```

### RAID 레벨 비교표

| RAID 레벨 | 방식             | 최소 디스크 | 저장 용량 효율 | 안정성    | 속도 | 주요 특징              |
| --------- | ---------------- | ----------- | -------------- | --------- | ---- | ---------------------- |
| RAID 0    | 스트라이핑       | 2개         | 100%           | 낮음      | 빠름 | 복구 불가능, 속도 중심 |
| RAID 1    | 미러링           | 2개         | 50%            | 높음      | 보통 | 완전 백업, 안정성 최고 |
| RAID 4    | 블록 단위 패리티 | 3개         | (N-1)/N        | 중상      | 보통 | 패리티 병목현상        |
| RAID 5    | 분산 패리티      | 3개         | (N-1)/N        | 중상      | 빠름 | 패리티 분산, 균형적    |
| RAID 6    | 이중 패리티      | 4개         | (N-2)/N        | 매우 높음 | 보통 | 이중 안전장치          |

## 08-1 장치 컨트롤러와 장치 드라이버

### 주제목: 입출력 장치 기본 개념

### 입출력 장치의 종류

**정의** : 컴퓨터에 정보를 입력하거나 컴퓨터 외부에 정보를 출력하는 장치

**입출력 장치의 다양성** :

- 입력 장치: 키보드, 모니터, USB 메모리, CD-ROM, SSD, 마우스, 프린터, 스피커, 마이크 등
- 출력 장치: 모니터, 프린터, 스피커 등
- 특징: 장치마다 다양한 규격의 정보교환 형식과 속도 존재

### 장치의 분류

**전송 속도에 따른 분류** :

1. **저속 장치** : 키보드, 마우스
2. **고속 장치** : 하드 디스크, 그래픽 카드

**데이터 전송 단위에 따른 분류** :

1. **블록 단위 전송 장치** : 하드 디스크, CD-ROM (데이터를 블록 단위로 전송)
2. **문자 단위 전송 장치** : 키보드, 마우스 (한 문자씩 전송)

### 중제목: 장치 컨트롤러

### 장치 컨트롤러의 정의

**개념** :

- **장치 컨트롤러(Device Controller)** : 입출력 장치의 직접 연결되지 않고 장치 컨트롤러를 통해 연결
- CPU와 메모리는 컴퓨터 내부를 연결하는 통로인 시스템 버스(System Bus)와 연결
- 입출력 장치는 입출력 버스(I/O Bus)와 연결

### 장치 컨트롤러의 구성 요소

**1. 데이터 레지스터** :

- CPU와 입출력 장치 간 데이터 송수신
- 버퍼(Buffer) 역할 수행

  **2. 상태 레지스터** :

- 입출력 장치의 상태 정보 저장
- 준비 완료, 작업 완료, 오류 등의 상태 표현

  **3. 제어 레지스터** :

- CPU가 입출력 장치에 내리는 명령 저장
- 장치에 수행할 내용 저장

  **장치 컨트롤러의 역할** :

- CPU와 입출력 장치 간의 통신 중개
- 오류 검출
- 데이터 버퍼링

### 장치 컨트롤러와 통신

**통신 프로세스** :

```
CPU → 장치 컨트롤러(제어 레지스터) → 입출력 장치
      ↑                ↓
   명령 전달      상태 레지스터로 응답

데이터: CPU ↔ 버퍼(데이터 레지스터) ↔ 입출력 장치

```

**주요 특징** :

- 장치 컨트롤러의 세 레지스터는 버스를 통해 CPU나 메모리와 정보 교환
- 입출력 장치마다 컨트롤러가 입출력 작업 수행
- 실제 작업을 위해서는 장치 컨트롤러의 레지스터를 알아야 함

### 중제목: 장치 드라이버

### 장치 드라이버의 정의

**개념** :

- **장치 드라이버(Device Driver)** : 장치 컨트롤러의 동작을 감지하고 제어하는 프로그램
- 장치 컨트롤러가 컴퓨터 내부와 정보를 주고받을 수 있게 하는 프로그램

  **역할** :

- 장치 컨트롤러가 입출력 장치를 연결하기 위한 하드웨어적 통로
- 장치 드라이버는 입출력 장치를 연결하기 위한 소프트웨어적 통로

  **동작 방식** :

```
프로그램 요청
    ↓
CPU → 장치 컨트롤러(제어 레지스터) → 장치 드라이버 실행 → 입출력 장치 동작
    ↓
버퍼(데이터 레지스터) → 메모리로 데이터 전송

```

### 장치 드라이버 설치 필요성

**예시: 프린터 출력 과정** :

1. 응용 프로그램이 파일 출력 요청
2. CPU가 장치 드라이버 실행
3. 장치 드라이버가 장치 컨트롤러에 명령 전달
4. 장치 컨트롤러가 프린터 동작 제어

**주의사항** :

- 새 장치 연결 시 반드시 장치 드라이버 설치 필요
- 장치 드라이버 미설치 시:
  - 장치 인식 불가
  - 정상 작동 불가능
  - 예: "Printer driver was not installed" 오류 발생

## 08-2 다양한 입출력 방법

### 주제목: 프로그램 입출력

### 프로그램 입출력(Programmed I/O)의 개념

**정의** :

- 프로그램 속 명령어로 입출력 장치를 제어하는 방법
- CPU가 프로그램에 속 명령어를 실행하는 과정에서 입출력 명령어를 만나면 CPU는 입출력 장치에 연결된 장치 컨트롤러와 상호작용

### 메모리 접근 방식

**메모리에 저장된 정보를 하드 디스크에 백업하는 상황** :

**01단계: 메모리 → 하드 디스크 컨트롤러**

- CPU는 하드 디스크 컨트롤러의 레지스터에서 쓰기 명령 전달
- 실제 데이터는 메모리 → 하드 디스크 컨트롤러 전송

**02단계: 하드 디스크 컨트롤러 상태 확인**

- 하드 디스크가 준비되었는지 확인
- 하드 디스크 컨트롤러는 상태 레지스터에 준비되었다고 표현

**03단계: CPU → 하드 디스크**

- CPU는 상태 레지스터를 주기적으로 읽어 준비 여부 확인
- 하드 디스크가 준비되면 메모리에 저장된 정보를 읽고
- 하드 디스크 컨트롤러 레지스터에 쓰는 명령 수행

### 프로그램 입출력의 동작 과정

**상세 프로세스** :

```
메모리 데이터
    ↓
① CPU가 장치 컨트롤러 상태 확인 (준비 상태?)
    ↓
② 하드 디스크 컨트롤러 데이터 레지스터로 데이터 전송
    ↓
③ CPU가 쓰기 명령 실행
    ↓
하드 디스크 저장 완료

```

**주요 특징** :

- CPU가 517번째를 읽어 들여야 하는 명령어로 키보드 상태를 읽을 수 있음
- 그런데 518번지에서 써야 하는 명령어로 하드 디스크 컨트롤러의 데이터 레지스터로 데이터를 보낼 수 있음

### 중제목: 메모리 맵 입출력과 고립형 입출력

### 메모리 맵 입출력 (Memory-Mapped I/O)

**개념** :

- 메모리에 접근하기 위한 주소 공간과 입출력 장치에 접근하기 위한 주소 공간이 하나의 주소 공간으로 간주
- 가령 1,024개의 주소 공간을 가진 컴퓨터라고 가정할 때 주소 1,024개를 표현할 수 있음

  **특징** :

- 메모리 주소 공간에 입출력 장치를 위한 주소도 포함
- 메모리와 입출력 장치는 같은 주소 공간 사용
- 메모리 주소의 일부를 입출력 장치에 할당

  **주소 공간 구조** :

```
주소 공간 (1,024개)
├─ 0 ~ 511: 메모리 주소
├─ 512: 프린터 컨트롤러의 데이터 레지스터
├─ 517: 하드 디스크 컨트롤러의 상태 레지스터
├─ 518: 하드 디스크 컨트롤러의 데이터 레지스터
└─ 519: 하드 디스크 컨트롤러의 상태 레지스터

```

### 고립형 입출력 (Isolated I/O)

**개념** :

- 메모리를 위한 주소 공간과 입출력장치를 위한 주소 공간을 분리
- 가령 1,024개의 주소 공간을 분리

  **특징** :

- 메모리 주소 공간과 입출력 장치 주소 공간 분리
- 1,024개 메모리 주소 공간 전체 활용 가능
- 입출력 장치를 위한 전용 명령어 사용

  **주소 공간 구조** :

```
주소 공간 (메모리)        주소 공간 (입출력)
├─ 0 ~ 1,023: 메모리     ├─ 0 ~ 511: 입출력 레지스터
                          ├─ 512: 데이터 입/쓰기 설비 메모리 영역
                          └─ 513: 입출력 작업 시작 영역

```

**메모리 맵 입출력 vs 고립형 입출력 비교** :

| 구분                     | 메모리 맵 입출력        | 고립형 입출력           |
| ------------------------ | ----------------------- | ----------------------- |
| 주소 공간                | 통합 (단일)             | 분리 (이중)             |
| 메모리 주소 공간 사용    | 축소                    | 온전히 사용 가능        |
| 명령어                   | 메모리 접근 명령어 사용 | 입출력 전용 명령어 사용 |
| 메모리와 입출력장치 구분 | 주소로 구분             | 명령어로 구분           |

### 중제목: 인터럽트 기반 입출력

### 인터럽트 기반 입출력의 필요성

**문제점** :

- 프로그램 입출력 방식의 한계: CPU가 입출력 장치가 준비 여부를 확인하는 명령어를 반복 실행
- CPU가 프로그램을 실행하는 과정에서 입출력 명령어를 만나면 입출력 작업 수행

  **해결 방법** :

- **인터럽트 기반 입출력(Interrupt-Driven I/O)** : 입출력 장치가 CPU에게 인터럽트 요청 신호를 보내면 CPU는 하던 일을 잠시 멈추고 인터럽트 서비스 루틴 실행

### 인터럽트 기반 입출력 동작 과정

**프로세스** :

```
① CPU가 입출력 명령 실행
    ↓
② 장치 컨트롤러가 입출력 작업 수행
    (CPU는 다른 일 할 수 있음)
    ↓
③ 입출력 작업 완료 시 장치 컨트롤러가 CPU에 인터럽트 요청
    ↓
④ CPU가 하던 일 중단하고 인터럽트 서비스 루틴 실행
    ↓
⑤ 인터럽트 처리 완료 후 기존 작업 재개

```

**주요 특징** :

- CPU가 장치 컨트롤러에 의한 하드웨어 인터럽트를 처리하는 프로그램
- 인터럽트 서비스 루틴은 CPU가 다른 일을 할 수 있도록 허용
- 장치 컨트롤러가 CPU에게 자신과 관련된 인터럽트인지 알리는 방법 필요

### 중제목: 폴링과 인터럽트

### 폴링 (Polling)

**개념** :

- 인터럽트를 처음 비롯되는 개념은 폴링이라는 개념이 있음
- 입출력 장치들이 CPU에게 알리기 위해 여러 번이 인터럽트를 요청하는 장치들이 여러 개 있음

  **동작 방식** :

- CPU가 주기적으로 장치를 확인하는 방식
- CPU가 여러 장치의 상태를 순회하며 확인

  **단점** :

- CPU가 확인 작업에 시간 소모
- 폴링 방식은 답변하기 위해 CPU가 인터럽트 요청이 몇번이나 있는지 알기만 하면 됨

### NMI (Non-Maskable Interrupt)

**개념** :

- 폴링 없이 여러 개의 인터럽트를 처리하는 방법
- CPU가 우선순위를 판별하여 먼저 처리해야 할 인터럽트 결정

  **특징** :

- 마스킹 불가능한 인터럽트
- 하드웨어 고장이나 정전 등 긴급 상황에서 발생

### PIC (Programmable Interrupt Controller)

**개념** :

- 여러 장치 컨트롤러에 연결된 장치 컨트롤러에서 보낸 하드웨어 인터럽트 요청들을 관리하는 장치
- 하드웨어적으로 우선순위를 판별

  **PIC의 동작 과정** :

```
인터럽트 발생
    ↓
① PIC가 장치 컨트롤러에서 인터럽트 요청 신호(들)을 받음
    ↓
② PIC는 인터럽트 우선순위를 판단한 뒤 CPU에 처리해야 할 인터럽트 요청 신호 보냄
    ↓
③ CPU는 PIC에 인터럽트 확인 신호를 보냄
    ↓
④ PIC는 데이터 버스를 통해 CPU에 인터럽트 벡터를 보냄
    ↓
⑤ CPU는 인터럽트 벡터를 통해 인터럽트 요청의 주체를 알게 되고
   해당 정치의 인터럽트 서비스 루틴 실행

```

**다중 PIC 구성** :

- 연결성을 더 많이 복잡한 장치들의 인터럽트를 관리하기 위해 여러 개의 PIC를 두 개 이상 계층적으로 구성
- 여러 PIC를 사용하면 각각의 인터럽트 처리를 효율적으로 관리

## 08-2 다양한 입출력 방법

### 주제목: DMA 입출력

### DMA의 필요성

**프로그램 입출력과 인터럽트 기반 입출력의 한계** :

- 입출력 장치와 메모리 간의 데이터 이동은 여전히 CPU를 거쳐야 함
- CPU가 입출력 장치와 상호작용하는 과정에서 프로그램 실행이 방해받음

### DMA (Direct Memory Access)의 개념

**정의** :

- CPU를 거치지 않고 메모리와 직접 상호작용하며 백업할 정보를 읽어오는 입출력 방식
- CPU가 프로그램 실행에 집중할 수 있도록 함

### DMA 컨트롤러

**DMA 컨트롤러의 역할** :

- 입출력 장치와 메모리가 CPU를 거치지 않고 상호작용할 수 있도록 도와주는 장치
- CPU를 대신하여 시스템 버스에 연결된 DMA 컨트롤러라는 하드웨어가 메모리와 입출력장치 간 데이터를 주고받음

  **DMA 컨트롤러의 구성 요소** :

1. **메모리 주소 레지스터** : 입출력 장치와 데이터를 주고받을 메모리의 주소
2. **카운터** : 수행할 연산(읽기/쓰기), 입출력 장치 주소
3. **제어 레지스터** : 입출력 작업의 방향(읽기/쓰기) 설정
4. **상태 레지스터** : 작업 완료 여부 표시

### DMA 입출력 과정

**프로세스 (메모리 → 하드 디스크)** :

```
① CPU는 DMA 컨트롤러에 입출력 장치의 주소, 수행할 연산(읽기/쓰기),
   입출력할 메모리의 주소 등을 담은 정보를 명령함
    ↓
② DMA 컨트롤러는 CPU 대신 장치 컨트롤러와 상호작용하며 백업할 정보를 읽어옴
   이때 ②와 같은 하드 디스크의 장치 컨트롤러에 내부담함
    ↓
③ 입출력 작업이 끝나면 DMA 컨트롤러는 CPU에 인터럽트를 걸어 작업이 끝났음을 알림

```

**프로세스 (CPU 관점)** :

```
시스템 버스
     ↓
메모리 ↔ DMA 컨트롤러 ↔ 장치 컨트롤러 ↔ 입출력 장치
  ↑
CPU (인터럽트로 작업 완료 통지받음)

```

### DMA 입출력 과정 상세 설명

**01단계: DMA 컨트롤러 초기화**

- CPU는 DMA 컨트롤러 초기화
- 주소, 수행할 연산(읽기/쓰기) 입력 내용이 지정된 메모리 주소를 DMA 컨트롤러의 레지스터에 저장

**02단계: DMA가 하드 디스크의 장치 컨트롤러에 내부담함**

- DMA 컨트롤러가 CPU를 거치지 않고 메모리와 직접 상호작용하며 백업할 정보를 읽어옴

**03단계: 백업이 끝나면 DMA 컨트롤러는 CPU에 인터럽트를 걸어 작업이 끝났음을 알림**

```
CPU 시작
    ↓
① 인출 → 실행 → 저장
    (입출력 작업 요청)
    ↓
② DMA 컨트롤러가 메모리와 장치 간 데이터 전송
    (CPU는 다른 작업 수행 가능)
    ↓
③ 전송 완료 시 DMA가 CPU에 인터럽트 신호
    ↓
CPU가 인터럽트 처리

```

**주요 특징** :

- CPU가 프로그램 실행에 집중 가능
- 메모리-장치 간 직접 데이터 전송으로 효율성 향상
- 대용량 데이터 전송에 유리

### 중제목: 입출력 버스

### 입출력 버스의 필요성

**문제 상황** :

- CPU, 메모리, DMA 컨트롤러, 장치 컨트롤러 모두 같은 버스를 공유하면 문제 발생
- 250순서에서 동일한 메모리에 접근하면 상황을 다시 생각해 봅시다

  **해결 방법** :

- 이 문제를 해결하기 위해 시스템 버스를 두 개로 나눔
- 메모리와 DMA 컨트롤러가 사용하는 버스와 장치 컨트롤러가 사용하는 버스 분리

### 입출력 버스의 구조

**분리된 버스 구조** :

```
시스템 버스 (고속)
    ↓
메모리 ↔ DMA 컨트롤러
         ↓
    입출력 버스 (저속)
         ↓
    장치 컨트롤러 → 입출력 장치들

```

**입출력 버스의 종류** :

- **PCI (Peripheral Component Interconnect) 버스** : 주변 장치를 위한 버스
- **PCI Express (PCIe) 버스** : 도달 그래도 여러 입출력장치들을 PCIe 버스에 연결하여 주번 장치를 통해 시스템 버스와 통합됨

  **특징** :

- 대량 데이터의 입출력 장치가 사용하는 시스템 버스와 입출력 버스를 분리함으로써 더 빠른 연산 가능
- 전송 속도가 빠른 장치는 시스템 버스, 느린 장치는 입출력 버스 사용

## 여기서 잠깐: 더욱 발전한 DMA, 입출력 채널

### IOP (Input/Output Processor)의 개념

**정의** :

- DMA를 통해 시스템 버스를 나누어 자주 사용하면 그만큼 CPU가 시스템 버스를 사용하지 못함
- 이 문제를 DMA 컨트롤러의 집적 컨트롤러보다 상호작용을 입출력 채널(Input/Output Channel) 또는 IOP(Input/Output Processor) 불림

  **발전 과정** :

1. **기본 DMA** : CPU 관여 최소화
2. **입출력 채널** : 입출력 장치들을 관리하는 보조 프로세서 역할
3. **IOP** : 별도의 입출력 전용 프로세서

**특징** :

- 입출력 채널은 컴퓨터 내부의 시작 정보 처리를 수행
- 실제 입출력 기능만을 전담하는 프로세서
- 복잡한 입출력 작업을 위한 전용 운영체제 사용 가능

# 핵심 요약본

## RAID 핵심 정리

- **RAID 0** : 스트라이핑, 속도 빠름, 복구 불가
- **RAID 1** : 미러링, 완전 백업, 안정성 최고
- **RAID 4** : 블록 단위 패리티, 패리티 병목
- **RAID 5** : 분산 패리티, 균형적 성능
- **RAID 6** : 이중 패리티, 안정성 최고

## 입출력 시스템 핵심

- **장치 컨트롤러** : 하드웨어적 통로, 레지스터 3종
- **장치 드라이버** : 소프트웨어적 통로, 설치 필수
- **프로그램 입출력** : CPU 직접 제어, 비효율적
- **인터럽트 입출력** : 장치가 CPU에 알림
- **DMA 입출력** : CPU 우회, 직접 메모리 접근

## 입출력 방법 비교

| 방법            | CPU 개입 | 효율성 | 특징               |
| --------------- | -------- | ------ | ------------------ |
| 프로그램 입출력 | 상시     | 낮음   | CPU가 모든 것 제어 |
| 인터럽트 기반   | 요청 시  | 중간   | 장치가 CPU에 알림  |
| DMA             | 최소     | 높음   | CPU 우회 전송      |

# 복습용 퀴즈

## 퀴즈 1: RAID 레벨

**문제** : 데이터를 여러 디스크에 분산 저장하여 입출력 속도를 향상시키지만, 하나의 디스크가 고장나면 모든 데이터를 잃게 되는 RAID 레벨은?

A) RAID 0

B) RAID 1

C) RAID 5

D) RAID 6

**정답** : A) RAID 0

**해설** : RAID 0는 스트라이핑 방식으로 데이터를 분산 저장하여 속도는 빠르지만, 백업 기능이 없어 하나의 디스크만 고장나도 전체 데이터를 복구할 수 없습니다. 이는 RAID 0의 가장 큰 단점입니다.

---

## 퀴즈 2: RAID 패리티

**문제** : 패리티 정보를 각 디스크에 분산하여 저장함으로써 병목현상을 해소한 RAID 레벨은?

A) RAID 1

B) RAID 4

C) RAID 5

D) RAID 6

**정답** : C) RAID 5

**해설** : RAID 5는 RAID 4의 문제점인 패리티 디스크 병목현상을 해결하기 위해 패리티 정보를 모든 디스크에 분산하여 저장합니다. 이를 통해 안정성과 성능의 균형을 이룹니다.

---

## 퀴즈 3: 장치 컨트롤러의 구성

**문제** : 장치 컨트롤러를 구성하는 레지스터가 아닌 것은?

A) 데이터 레지스터

B) 상태 레지스터

C) 제어 레지스터

D) 명령 레지스터

**정답** : D) 명령 레지스터

**해설** : 장치 컨트롤러는 데이터 레지스터(버퍼 역할), 상태 레지스터(장치 상태 저장), 제어 레지스터(CPU 명령 저장)로 구성됩니다. 명령 레지스터는 장치 컨트롤러의 구성 요소가 아닙니다.

## 퀴즈 4: 장치 드라이버

**문제** : 장치 드라이버에 대한 설명으로 올바른 것은?

A) 하드웨어적 통로를 제공하는 장치

B) 장치 컨트롤러의 동작을 제어하는 소프트웨어

C) CPU와 메모리 간 데이터 전송을 담당

D) 입출력 버스를 관리하는 하드웨어

**정답** : B) 장치 컨트롤러의 동작을 제어하는 소프트웨어

**해설** : 장치 드라이버는 장치 컨트롤러가 입출력 장치를 연결하기 위한 소프트웨어적 통로입니다. 새로운 장치를 연결할 때 반드시 설치해야 하며, 설치하지 않으면 장치를 인식하거나 사용할 수 없습니다.

## 퀴즈 5: 메모리 맵 입출력

**문제** : 메모리 맵 입출력(Memory-Mapped I/O) 방식의 특징으로 올바른 것은?

A) 메모리와 입출력 장치의 주소 공간이 분리되어 있다

B) 입출력 전용 명령어를 사용한다

C) 메모리 주소 공간의 일부를 입출력 장치에 할당한다

D) 메모리 주소 공간을 온전히 사용할 수 있다

**정답** : C) 메모리 주소 공간의 일부를 입출력 장치에 할당한다

**해설** : 메모리 맵 입출력은 메모리와 입출력 장치가 하나의 주소 공간을 공유하며, 메모리 주소의 일부를 입출력 장치에 할당합니다. 이는 메모리 접근 명령어로 입출력 장치를 제어할 수 있다는 장점이 있지만, 사용 가능한 메모리 주소 공간이 줄어든다는 단점이 있습니다.

## 퀴즈 6: 인터럽트 기반 입출력

**문제** : 인터럽트 기반 입출력 방식의 장점은?

A) CPU가 입출력 작업 완료까지 대기하지 않아도 됨

B) 메모리에 직접 접근하여 속도가 빠름

C) 프로그래밍이 간단함

D) 하드웨어 비용이 저렴함

**정답** : A) CPU가 입출력 작업 완료까지 대기하지 않아도 됨

**해설** : 인터럽트 기반 입출력은 장치가 작업을 완료하면 CPU에 인터럽트 신호를 보내는 방식입니다. CPU는 입출력 명령 실행 후 다른 작업을 수행할 수 있으며, 작업이 완료되면 인터럽트를 통해 통지받습니다. 이는 프로그램 입출력 방식의 비효율성을 개선합니다.

## 퀴즈 7: PIC의 역할

**문제** : PIC(Programmable Interrupt Controller)의 주요 역할은?

A) 메모리와 장치 간 직접 데이터 전송

B) 여러 인터럽트 요청의 우선순위 판별

C) CPU의 명령어 실행 제어

D) 장치 드라이버 설치 및 관리

**정답** : B) 여러 인터럽트 요청의 우선순위 판별

**해설** : PIC는 여러 장치 컨트롤러로부터 받은 인터럽트 요청들을 관리하고 우선순위를 판별하여 CPU에 전달하는 장치입니다. 이를 통해 CPU는 폴링 없이 효율적으로 인터럽트를 처리할 수 있습니다.

## 퀴즈 8: DMA 입출력

**문제** : DMA(Direct Memory Access) 입출력 방식에 대한 설명으로 올바르지 않은 것은?

A) CPU를 거치지 않고 메모리와 장치가 직접 데이터를 주고받음

B) DMA 컨트롤러가 데이터 전송을 담당함

C) 작업 완료 시 CPU에 인터럽트 신호를 보냄

D) CPU의 개입이 프로그램 입출력보다 많이 필요함

**정답** : D) CPU의 개입이 프로그램 입출력보다 많이 필요함

**해설** : DMA 입출력의 가장 큰 장점은 CPU의 개입을 최소화한다는 것입니다. CPU는 초기 설정만 하고, 실제 데이터 전송은 DMA 컨트롤러가 담당합니다. 작업 완료 시에만 인터럽트로 CPU에 알립니다. 따라서 CPU의 개입이 프로그램 입출력보다 훨씬 적습니다.

## 퀴즈 9: 입출력 버스

**문제** : 입출력 버스를 시스템 버스와 분리하는 주된 이유는?

A) 비용 절감

B) 설치의 편의성

C) 버스 사용 충돌 방지 및 효율성 향상

D) 장치 호환성 향상

**정답** : C) 버스 사용 충돌 방지 및 효율성 향상

**해설** : CPU, 메모리, DMA 컨트롤러가 시스템 버스를 사용하는 동안 입출력 장치들이 같은 버스를 사용하면 충돌이 발생합니다. 입출력 버스를 분리하면 고속 장치는 시스템 버스를, 저속 장치는 입출력 버스를 사용하여 전체 시스템의 효율성이 향상됩니다.

## 퀴즈 10: RAID 6

**문제** : RAID 6가 RAID 5에 비해 가지는 가장 큰 장점은?

A) 저장 공간 효율이 더 좋음

B) 쓰기 속도가 더 빠름

C) 두 개의 디스크가 동시에 고장나도 복구 가능

D) 최소 필요 디스크 수가 적음

**정답** : C) 두 개의 디스크가 동시에 고장나도 복구 가능

**해설** : RAID 6는 두 종류의 패리티 정보를 저장하는 이중 패리티 방식을 사용합니다. 이를 통해 RAID 4, 5보다 안정성이 우수하며, 두 개의 디스크가 동시에 고장나도 데이터를 복구할 수 있습니다. 단, 이로 인해 쓰기 속도는 RAID 5보다 느리고 저장 공간 효율은 낮아집니다.
