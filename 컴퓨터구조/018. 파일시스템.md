# 파일 시스템 (File System) 완벽 정리

## 1. 파일 시스템의 기본 개념

### 1.1 파일 시스템이란?

파일 시스템은 컴퓨터의 보조기억장치(하드 디스크, SSD 등)에서 파일과 디렉터리를 효율적으로 관리하고 저장하는 체계입니다. 운영체제가 데이터를 조직화하고 검색할 수 있도록 하는 핵심 구조입니다.

### 1.2 파티셔닝 (Partitioning)

파티셔닝은 물리적 저장 장치를 논리적으로 분할하는 작업입니다.

**주요 특징:**
- 하나의 물리적 디스크를 여러 개의 논리적 영역으로 나눔
- 각 파티션은 독립적인 파일시스템을 가질 수 있음
- 운영체제 설치 시 디스크 구조를 계획하는 첫 단계

**활용 예시:**
- C 드라이브: 운영체제 및 프로그램 설치
- D 드라이브: 개인 데이터 저장
- E 드라이브: 백업 데이터 저장

### 1.3 포매팅 (Formatting)

포매팅은 파티션을 특정 파일시스템으로 초기화하는 작업입니다.

**포매팅의 역할:**
- 파일시스템 구조 생성
- 디렉터리 엔트리 초기화
- 블록 할당 정보 설정
- 데이터 저장을 위한 메타데이터 구조 구축

**포매팅 종류:**
- 빠른 포맷: 파일시스템 정보만 초기화
- 전체 포맷: 모든 섹터를 검사하고 초기화

## 2. 파일 할당 방법

파일 시스템은 파일 데이터를 블록 단위로 나누어 저장합니다. 이때 블록을 할당하는 방법에 따라 성능과 효율성이 달라집니다.

### 2.1 블록 (Block) 개념

**블록이란?**
- 운영체제가 파일을 읽고 쓸 때 사용하는 최소 단위
- 하나 이상의 섹터를 묶은 논리적 단위
- 일반적으로 4KB, 8KB 등의 크기를 가짐

**블록 사용 이유:**
- 섹터 단위로 관리하면 오버헤드가 너무 큼
- 적절한 블록 크기로 I/O 효율성 향상

### 2.2 연속 할당 (Contiguous Allocation)

연속 할당은 파일의 모든 블록을 연속된 공간에 저장하는 방식입니다.

**동작 방식:**
- 파일 생성 시 필요한 블록 수를 계산
- 연속된 빈 공간을 찾아 할당
- 파일 정보에 시작 블록과 길이만 저장

**장점:**
- 구현이 단순함
- 순차 접근 속도가 매우 빠름
- 파일의 위치를 시작 블록과 길이만으로 표현 가능

**단점:**
- 외부 단편화 발생 (빈 공간이 분산됨)
- 파일 크기 변경이 어려움
- 파일 삭제 후 공간 재활용이 비효율적

**예시 코드 (개념적 표현):**
```javascript
// 연속 할당 구조
class ContiguousFile {
  constructor(startBlock, length) {
    this.startBlock = startBlock;  // 시작 블록 번호
    this.length = length;          // 파일이 차지하는 블록 수
  }
  
  getBlockNumber(offset) {
    // offset번째 데이터가 위치한 블록 번호
    return this.startBlock + offset;
  }
}

// 사용 예시
const fileA = new ContiguousFile(5, 10);
// 파일 A는 블록 5~14를 연속으로 차지함
console.log(fileA.getBlockNumber(3)); // 출력: 8 (5 + 3)
```

### 2.3 연결 할당 (Linked Allocation)

연결 할당은 파일의 블록들을 연결 리스트로 관리하는 방식입니다.

**동작 방식:**
- 각 블록에 다음 블록의 주소를 저장
- 파일의 시작 블록만 디렉터리에 기록
- 블록들이 디스크 전체에 흩어져 있어도 연결 가능

**장점:**
- 외부 단편화 문제가 없음
- 파일 크기를 동적으로 확장 가능
- 디스크의 빈 공간을 유연하게 활용

**단점:**
- 순차 접근만 가능 (직접 접근 불가)
- 중간 블록 손상 시 이후 데이터 접근 불가
- 포인터 저장을 위한 추가 공간 필요

**예시 코드 (개념적 표현):**
```javascript
// 연결 할당 구조
class LinkedBlock {
  constructor(data, nextBlock = null) {
    this.data = data;          // 실제 데이터
    this.nextBlock = nextBlock; // 다음 블록의 주소
  }
}

class LinkedFile {
  constructor(startBlock) {
    this.startBlock = startBlock; // 첫 번째 블록
  }
  
  readFile(blocks) {
    let current = this.startBlock;
    const data = [];
    
    while (current !== null) {
      data.push(blocks[current].data);
      current = blocks[current].nextBlock;
    }
    
    return data;
  }
}

// 사용 예시
const blocks = {
  2: new LinkedBlock('Hello', 6),
  6: new LinkedBlock(' World', 13),
  13: new LinkedBlock('!', null)
};

const fileB = new LinkedFile(2);
console.log(fileB.readFile(blocks)); // ['Hello', ' World', '!']
```

### 2.4 색인 할당 (Indexed Allocation)

색인 할당은 파일의 모든 블록 주소를 하나의 인덱스 블록에 모아서 관리하는 방식입니다.

**동작 방식:**
- 파일마다 인덱스 블록(i-node)을 할당
- 인덱스 블록에 데이터 블록들의 주소를 저장
- 디렉터리는 인덱스 블록의 주소만 저장

**장점:**
- 직접 접근 가능 (임의의 블록에 빠르게 접근)
- 외부 단편화 없음
- 파일 크기 변경이 상대적으로 용이

**단점:**
- 인덱스 블록을 위한 추가 공간 필요
- 작은 파일도 인덱스 블록 필요 (공간 낭비)
- 큰 파일은 다단계 인덱스 필요

**예시 코드 (개념적 표현):**
```javascript
// 색인 할당 구조
class IndexBlock {
  constructor() {
    this.blockAddresses = []; // 데이터 블록들의 주소 배열
  }
  
  addBlock(blockNumber) {
    this.blockAddresses.push(blockNumber);
  }
  
  getBlock(index) {
    return this.blockAddresses[index];
  }
}

class IndexedFile {
  constructor(indexBlock) {
    this.indexBlock = indexBlock; // 인덱스 블록
  }
  
  readBlock(index, dataBlocks) {
    const blockNumber = this.indexBlock.getBlock(index);
    return dataBlocks[blockNumber];
  }
}

// 사용 예시
const dataBlocks = {
  4: 'First block',
  7: 'Second block',
  13: 'Third block',
  11: 'Fourth block'
};

const index = new IndexBlock();
index.addBlock(4);
index.addBlock(7);
index.addBlock(13);
index.addBlock(11);

const fileC = new IndexedFile(index);
console.log(fileC.readBlock(2, dataBlocks)); // 'Third block'
```

## 3. FAT 파일 시스템

### 3.1 FAT의 개념

FAT (File Allocation Table)는 연결 할당의 단점을 보완한 파일시스템으로, 각 블록의 다음 블록 정보를 별도의 테이블에 모아서 관리합니다.

**FAT의 특징:**
- MS-DOS에서 시작되어 USB 메모리, SD 카드 등에 널리 사용
- 블록 단위로 파일을 관리
- FAT 테이블로 블록 체인 구성

**FAT 종류:**
- FAT12: 12비트 주소 체계
- FAT16: 16비트 주소 체계
- FAT32: 32비트 주소 체계

### 3.2 FAT 테이블 구조

FAT 테이블은 파티션의 시작 부분에 위치하며, 각 블록의 상태와 다음 블록 정보를 저장합니다.

**FAT 엔트리 값의 의미:**
- `0`: 빈 블록 (사용 가능)
- `양수`: 다음 블록의 번호
- `-1 (0xFFFF)`: 파일의 마지막 블록
- `특수 값`: 손상된 블록 등

**FAT 테이블 예시:**

| 블록 번호 | FAT 엔트리 값 | 의미 |
|---------|------------|------|
| 0 | - | 예약 영역 |
| 1 | -1 | 파일의 마지막 블록 |
| 2 | 1 | 다음 블록은 1번 |
| 3 | 5 | 다음 블록은 5번 |
| 4 | 8 | 다음 블록은 8번 |
| 5 | -1 | 파일의 마지막 블록 |
| 6 | 0 | 빈 블록 |
| 7 | 13 | 다음 블록은 13번 |
| 8 | 3 | 다음 블록은 3번 |

**예시 코드 (FAT 구현):**
```javascript
// FAT 파일 시스템 구조
class FATFileSystem {
  constructor(totalBlocks) {
    // FAT 테이블 초기화 (모든 블록을 빈 상태로)
    this.fat = new Array(totalBlocks).fill(0);
    this.dataBlocks = new Array(totalBlocks).fill(null);
    
    // 0번 블록은 예약 영역
    this.fat[0] = -2; // 예약됨을 나타내는 특수 값
  }
  
  // 파일 생성 및 블록 할당
  allocateFile(blockNumbers) {
    if (blockNumbers.length === 0) return null;
    
    // 블록들을 체인으로 연결
    for (let i = 0; i < blockNumbers.length - 1; i++) {
      this.fat[blockNumbers[i]] = blockNumbers[i + 1];
    }
    
    // 마지막 블록은 -1로 표시
    this.fat[blockNumbers[blockNumbers.length - 1]] = -1;
    
    // 시작 블록 번호 반환
    return blockNumbers[0];
  }
  
  // 파일 읽기
  readFile(startBlock) {
    const blocks = [];
    let current = startBlock;
    
    while (current !== -1 && current !== 0) {
      blocks.push(this.dataBlocks[current]);
      current = this.fat[current];
    }
    
    return blocks;
  }
  
  // 파일 삭제
  deleteFile(startBlock) {
    let current = startBlock;
    
    while (current !== -1 && current !== 0) {
      const next = this.fat[current];
      this.fat[current] = 0; // 빈 블록으로 표시
      this.dataBlocks[current] = null;
      current = next;
    }
  }
  
  // FAT 테이블 출력
  printFAT() {
    console.log('블록 번호 | FAT 값');
    console.log('---------|-------');
    for (let i = 0; i < this.fat.length; i++) {
      console.log(`${i.toString().padStart(8)} | ${this.fat[i]}`);
    }
  }
}

// 사용 예시
const fs = new FATFileSystem(20);

// 파일 A 생성: 블록 4, 7, 13, 11 사용
const fileA = fs.allocateFile([4, 7, 13, 11]);
console.log('파일 A 시작 블록:', fileA); // 4

// 파일 B 생성: 블록 8, 9번 사용
const fileB = fs.allocateFile([8, 9]);

// FAT 테이블 상태 확인
fs.printFAT();

// 파일 A 읽기
const dataA = fs.readFile(fileA);
console.log('파일 A 데이터:', dataA);

// 파일 A 삭제
fs.deleteFile(fileA);
```

**실제 사용 상황:**
USB 메모리나 SD 카드를 컴퓨터에 연결하면 FAT 파일시스템으로 포맷되어 있는 경우가 많습니다. 윈도우, 맥OS, 리눅스 등 대부분의 운영체제에서 호환되기 때문입니다.

## 4. 유닉스 파일 시스템

### 4.1 i-node (Index Node)

유닉스 파일 시스템은 색인 할당 방식을 사용하며, 파일의 메타데이터를 저장하는 i-node라는 자료구조를 사용합니다.

**i-node의 구성 요소:**
- 파일 속성 정보 (크기, 생성 시간, 권한 등)
- 파일이 사용하는 블록 주소들
- 직접 블록 포인터
- 간접 블록 포인터

### 4.2 i-node 구조

i-node는 파일 속성 정보와 데이터 블록의 주소를 저장합니다. 파일의 크기에 따라 직접 블록, 단일 간접 블록, 이중 간접 블록, 삼중 간접 블록을 사용합니다.

**i-node 블록 포인터 종류:**

1. **직접 블록 (Direct Blocks)**: 데이터 블록을 직접 가리킴 (보통 12~15개)
2. **단일 간접 블록 (Single Indirect)**: 블록 주소들의 배열을 가리킴
3. **이중 간접 블록 (Double Indirect)**: 단일 간접 블록들의 배열을 가리킴
4. **삼중 간접 블록 (Triple Indirect)**: 이중 간접 블록들의 배열을 가리킴

**예시 코드 (i-node 구현):**
```javascript
// i-node 구조
class INode {
  constructor() {
    // 파일 메타데이터
    this.fileSize = 0;
    this.createdTime = new Date();
    this.modifiedTime = new Date();
    this.permissions = 0o644; // 읽기/쓰기 권한
    
    // 블록 포인터
    this.directBlocks = new Array(12).fill(null);  // 직접 블록 (12개)
    this.singleIndirect = null;  // 단일 간접 블록
    this.doubleIndirect = null;  // 이중 간접 블록
    this.tripleIndirect = null;  // 삼중 간접 블록
  }
  
  // 블록 인덱스로 실제 블록 번호 가져오기
  getBlockNumber(blockIndex, indirectBlocks) {
    // 직접 블록 범위 (0~11)
    if (blockIndex < 12) {
      return this.directBlocks[blockIndex];
    }
    
    // 단일 간접 블록 범위
    const singleIndirectSize = 256; // 블록당 저장 가능한 포인터 수
    if (blockIndex < 12 + singleIndirectSize) {
      const offset = blockIndex - 12;
      const indirectBlock = indirectBlocks[this.singleIndirect];
      return indirectBlock[offset];
    }
    
    // 이중 간접 블록 범위
    const doubleIndirectSize = singleIndirectSize * singleIndirectSize;
    if (blockIndex < 12 + singleIndirectSize + doubleIndirectSize) {
      const offset = blockIndex - 12 - singleIndirectSize;
      const firstLevel = Math.floor(offset / singleIndirectSize);
      const secondLevel = offset % singleIndirectSize;
      
      const firstIndirectBlock = indirectBlocks[this.doubleIndirect];
      const secondIndirectBlock = indirectBlocks[firstIndirectBlock[firstLevel]];
      return secondIndirectBlock[secondLevel];
    }
    
    // 삼중 간접 블록 (매우 큰 파일)
    // 구현 생략...
    
    return null;
  }
}

class UnixFileSystem {
  constructor() {
    this.inodes = {}; // i-node 테이블
    this.dataBlocks = {}; // 데이터 블록
    this.indirectBlocks = {}; // 간접 블록
    this.nextInodeNumber = 1;
    this.nextBlockNumber = 1;
  }
  
  // 파일 생성
  createFile(path) {
    const inode = new INode();
    const inodeNumber = this.nextInodeNumber++;
    this.inodes[inodeNumber] = inode;
    return inodeNumber;
  }
  
  // 파일에 데이터 쓰기
  writeFile(inodeNumber, data) {
    const inode = this.inodes[inodeNumber];
    const blocksNeeded = Math.ceil(data.length / 4096); // 4KB 블록 가정
    
    // 직접 블록 할당
    for (let i = 0; i < Math.min(blocksNeeded, 12); i++) {
      const blockNumber = this.nextBlockNumber++;
      inode.directBlocks[i] = blockNumber;
      this.dataBlocks[blockNumber] = data.slice(i * 4096, (i + 1) * 4096);
    }
    
    // 단일 간접 블록 할당 (필요한 경우)
    if (blocksNeeded > 12) {
      const indirectBlockNumber = this.nextBlockNumber++;
      inode.singleIndirect = indirectBlockNumber;
      this.indirectBlocks[indirectBlockNumber] = [];
      
      for (let i = 12; i < blocksNeeded; i++) {
        const blockNumber = this.nextBlockNumber++;
        this.indirectBlocks[indirectBlockNumber].push(blockNumber);
        this.dataBlocks[blockNumber] = data.slice(i * 4096, (i + 1) * 4096);
      }
    }
    
    inode.fileSize = data.length;
    inode.modifiedTime = new Date();
  }
  
  // 파일 읽기
  readFile(inodeNumber) {
    const inode = this.inodes[inodeNumber];
    let data = '';
    
    // 직접 블록 읽기
    for (let i = 0; i < 12 && inode.directBlocks[i] !== null; i++) {
      data += this.dataBlocks[inode.directBlocks[i]] || '';
    }
    
    // 간접 블록 읽기 (필요한 경우)
    if (inode.singleIndirect !== null) {
      const indirectBlock = this.indirectBlocks[inode.singleIndirect];
      for (const blockNumber of indirectBlock) {
        data += this.dataBlocks[blockNumber] || '';
      }
    }
    
    return data.slice(0, inode.fileSize);
  }
}

// 사용 예시
const unixFS = new UnixFileSystem();

// 파일 생성
const fileInode = unixFS.createFile('/home/minchul/a.sh');

// 데이터 쓰기
const content = 'echo "Hello, Unix File System!"';
unixFS.writeFile(fileInode, content);

// 데이터 읽기
const readContent = unixFS.readFile(fileInode);
console.log('파일 내용:', readContent);
```

### 4.3 디렉터리 구조

유닉스 파일시스템에서 디렉터리도 파일의 일종이며, i-node로 관리됩니다. 디렉터리 파일의 내용은 "파일명 - i-node 번호" 쌍의 목록입니다.

**디렉터리 예시 코드:**
```javascript
// 디렉터리 구조
class Directory {
  constructor(inodeNumber) {
    this.inodeNumber = inodeNumber; // 디렉터리 자신의 i-node
    this.entries = new Map(); // 파일명 -> i-node 번호 매핑
  }
  
  addEntry(filename, inodeNumber) {
    this.entries.set(filename, inodeNumber);
  }
  
  getEntry(filename) {
    return this.entries.get(filename);
  }
  
  listEntries() {
    return Array.from(this.entries.entries());
  }
}

// 파일 경로 탐색 예시
class UnixFileSystemWithDir extends UnixFileSystem {
  constructor() {
    super();
    this.directories = {};
    
    // 루트 디렉터리 생성
    const rootInode = this.createFile('/');
    this.directories[rootInode] = new Directory(rootInode);
  }
  
  // 경로를 따라 i-node 찾기
  findInode(path) {
    const parts = path.split('/').filter(p => p !== '');
    let currentDir = this.directories[1]; // 루트 디렉터리
    
    for (const part of parts) {
      const inodeNumber = currentDir.getEntry(part);
      if (inodeNumber === undefined) {
        return null; // 파일/디렉터리를 찾을 수 없음
      }
      
      if (this.directories[inodeNumber]) {
        currentDir = this.directories[inodeNumber];
      } else {
        return inodeNumber; // 파일의 i-node 번호
      }
    }
    
    return currentDir.inodeNumber;
  }
}
```

## 5. 디렉터리 파일 시스템

### 5.1 마운트 (Mount)

마운트는 유닉스나 리눅스 등의 운영체제에서 저장 장치를 파일시스템에 연결하는 작업입니다. 이는 별도의 예시로 이해하는 것이 좋습니다.

**마운트의 개념:**
- 저장 장치의 파일시스템을 특정 디렉터리(마운트 포인트)에 연결
- 마운트 포인트 하위로 저장 장치의 내용이 접근 가능해짐
- 운영체제 전체가 하나의 통합된 디렉터리 트리를 형성

**예시:**
```javascript
// 마운트 개념 시뮬레이션
class MountableFileSystem {
  constructor() {
    this.root = new Directory(1);
    this.mountPoints = new Map(); // 마운트 포인트 -> 파일시스템 매핑
  }
  
  mount(mountPoint, filesystem) {
    this.mountPoints.set(mountPoint, filesystem);
    console.log(`${filesystem.name}을(를) ${mountPoint}에 마운트했습니다.`);
  }
  
  unmount(mountPoint) {
    const filesystem = this.mountPoints.get(mountPoint);
    this.mountPoints.delete(mountPoint);
    console.log(`${mountPoint}를 언마운트했습니다.`);
  }
  
  resolvePath(path) {
    // 마운트 포인트를 고려하여 실제 파일시스템 탐색
    for (const [mountPoint, filesystem] of this.mountPoints.entries()) {
      if (path.startsWith(mountPoint)) {
        const relativePath = path.substring(mountPoint.length);
        return filesystem.findFile(relativePath);
      }
    }
    
    // 마운트되지 않은 경로는 루트 파일시스템에서 탐색
    return this.root.getEntry(path);
  }
}

// 사용 예시
const mainFS = new MountableFileSystem();

// USB 메모리를 /mnt 경로에 마운트
const usbFS = { name: 'USB 메모리', findFile: (path) => `USB:${path}` };
mainFS.mount('/mnt', usbFS);

// /mnt/pictures/Dog.jpg 접근 시
// -> USB 파일시스템의 /pictures/Dog.jpg로 연결됨
console.log(mainFS.resolvePath('/mnt/pictures/Dog.jpg'));
```

## 최종 핵심 요약

### 파일 시스템의 핵심 개념

1. **파일 시스템**: 보조기억장치에서 파일과 디렉터리를 효율적으로 관리하는 체계

2. **파티셔닝**: 물리적 디스크를 논리적으로 분할하는 작업

3. **포매팅**: 파티션을 특정 파일시스템으로 초기화하는 작업

4. **블록**: 파일을 저장하는 최소 단위 (여러 섹터를 묶음)

### 파일 할당 방법 비교

| 방식 | 장점 | 단점 | 사용 예 |
|-----|------|------|--------|
| 연속 할당 | 빠른 접근, 구현 간단 | 외부 단편화, 크기 변경 어려움 | CD-ROM |
| 연결 할당 | 단편화 없음, 동적 확장 | 순차 접근만 가능, 포인터 오버헤드 | 초기 파일시스템 |
| 색인 할당 | 직접 접근 가능, 유연함 | 인덱스 블록 오버헤드 | 유닉스/리눅스 |

### 주요 파일 시스템

1. **FAT (File Allocation Table)**
   - 연결 할당의 개선 버전
   - 별도의 테이블로 블록 체인 관리
   - USB, SD 카드 등에 널리 사용
   - FAT12, FAT16, FAT32 등 버전 존재

2. **유닉스 파일 시스템**
   - i-node를 사용한 색인 할당
   - 직접 블록 + 간접 블록 구조
   - 작은 파일부터 큰 파일까지 효율적 관리
   - 디렉터리도 파일로 관리 (파일명-i-node 쌍 저장)

### 문제 3. 연속 할당의 특징
다음 중 연속 할당(Contiguous Allocation)의 단점이 아닌 것은?

1. 외부 단편화가 발생한다
2. 파일 크기 변경이 어렵다
3. 순차 접근 속도가 느리다
4. 파일 삭제 후 공간 재활용이 비효율적이다
5. 연속된 빈 공간을 찾기 어렵다

정답: 3번

해설: 연속 할당의 장점은 순차 접근 속도가 매우 빠르다는 것입니다. 파일의 블록들이 연속되어 있어 디스크 헤드의 이동이 최소화되기 때문입니다. 반면 외부 단편화 발생, 파일 크기 변경의 어려움, 공간 재활용의 비효율성 등은 연속 할당의 단점입니다.

### 문제 4. 연결 할당의 특징
연결 할당(Linked Allocation) 방식에 대한 설명으로 올바른 것은?

1. 각 블록이 연속된 공간에 저장된다
2. 직접 접근(Random Access)이 가능하다
3. 각 블록에 다음 블록의 주소가 저장된다

5. 외부 단편화가 심각하게 발생한다

정답: 3번

해설: 연결 할당은 각 블록에 다음 블록의 주소를 저장하여 연결 리스트 형태로 파일을 관리하는 방식입니다. 블록들이 디스크 전체에 흩어져 있어도 연결할 수 있어 외부 단편화 문제가 없지만, 순차 접근만 가능하고 직접 접근은 불가능합니다.

### 문제 5. 색인 할당의 특징
색인 할당(Indexed Allocation)에서 i-node가 하는 역할은?

2. 파일의 모든 블록 주소를 모아서 관리한다
3. 파일의 데이터를 암호화한다
4. 파일의 백업 복사본을 생성한다

### 문제 6. FAT 파일 시스템
FAT 파일 시스템에서 FAT 엔트리 값이 -1(0xFFFF)인 경우의 의미는?

1. 빈 블록
2. 파일의 시작 블록
3. 파일의 마지막 블록
4. 손상된 블록
5. 예약된 블록

정답: 3번

해설: FAT 테이블에서 엔트리 값이 -1(또는 0xFFFF)인 경우는 해당 블록이 파일의 마지막 블록임을 나타냅니다. 0은 빈 블록, 양수 값은 다음 블록의 번호를 의미합니다. FAT는 연결 할당의 단점을 보완하기 위해 블록 체인 정보를 별도의 테이블에 모아서 관리합니다.

### 문제 7. i-node의 블록 포인터

1. 직접 블록만 사용
2. 단일 간접 블록만 사용
3. 직접 블록 + 간접 블록 (단일, 이중, 삼중)
4. FAT 테이블 사용
5. 연속 할당 사용

정답: 3번

해설: 유닉스 파일시스템의 i-node는 다단계 인덱스 구조를 사용합니다. 작은 파일은 직접 블록(보통 12개)으로 처리하고, 큰 파일은 단일 간접 블록, 이중 간접 블록, 삼중 간접 블록을 추가로 사용합니다. 이를 통해 작은 파일은 빠르게 접근하면서도 매우 큰 파일까지 지원할 수 있습니다.

### 문제 9. 마운트의 개념
리눅스에서 USB 메모리를 /mnt/usb에 마운트했을 때의 의미는?

1. USB 메모리의 파일을 /mnt/usb로 복사한다
2. USB 메모리를 /mnt/usb 경로를 통해 접근할 수 있게 연결한다
3. /mnt/usb 디렉터리를 USB 메모리로 백업한다
4. USB 메모리를 /mnt/usb로 이름을 변경한다
5. /mnt/usb 디렉터리를 삭제한다

정답: 2번

해설: 마운트는 저장 장치의 파일시스템을 특정 디렉터리(마운트 포인트)에 연결하는 작업입니다. /mnt/usb에 마운트하면, 해당 경로를 통해 USB 메모리의 파일들에 접근할 수 있게 됩니다. 이를 통해 운영체제 전체가 하나의 통합된 디렉터리 트리를 형성하며, 사용자는 물리적 장치를 의식하지 않고 파일에 접근할 수 있습니다.

### 문제 10. 파일 할당 방식 비교
다음 중 직접 접근(Random Access)이 가능한 파일 할당 방식은?

1. 연결 할당 (Linked Allocation)
2. 연속 할당 (Contiguous Allocation)과 색인 할당 (Indexed Allocation)
3. 연결 할당과 FAT
4. 연속 할당만
5. 색인 할당만

정답: 2번

해설: 직접 접근이 가능한 방식은 연속 할당과 색인 할당입니다. 연속 할당은 시작 블록과 오프셋으로 바로 계산할 수 있고, 색인 할당은 i-node의 인덱스를 통해 원하는 블록에 바로 접근할 수 있습니다. 반면 연결 할당과 FAT는 기본적으로 순차 접근만 가능하며, FAT의 경우 테이블을 메모리에 로드하면 다소 개선되지만 완전한 직접 접근은 아닙니다.

- [ ] 파일시스템 전체 구조를 그림으로 표현할 수 있다

### 실무 적용
- [ ] 어떤 상황에서 어떤 파일시스템을 선택해야 할지 판단할 수 있다
- [ ] 파일시스템 성능 최적화 방법을 제안할 수 있다
- [ ] 실제 운영체제에서 사용되는 파일시스템(NTFS, ext4 등)과 학습한 내용을 연결할 수 있다
- [ ] 파일시스템 관련 문제를 진단하고 해결할 수 있다
