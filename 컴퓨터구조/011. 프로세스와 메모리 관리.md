## 10-1 프로세스 개요

### 프로세스 정의

프로세스는 **실행 중인 프로그램**을 의미합니다. 단순히 저장장치에 저장된 프로그램 파일은 프로세스가 아니며, 메모리에 적재되어 CPU에 의해 실행되는 상태의 프로그램이 프로세스입니다.

```
프로그램 (저장장치) → 메모리 적재 → 프로세스 (실행 중)

```

### 백그라운드 프로세스

**포그라운드 프로세스(Foreground Process)**

- 사용자가 직접 상호작용하며 볼 수 있는 프로세스
- 예: 웹 브라우저, 텍스트 에디터

**백그라운드 프로세스(Background Process)**

- 사용자가 직접 보거나 상호작용하지 않고 백그라운드에서 실행되는 프로세스
- 리눅스에서는 **데몬(daemon)** , 윈도우에서는 **서비스(service)**라고 부름
- 예: 시스템 업데이트, 바이러스 검사 프로그램

### 프로세스 제어 블록 (PCB, Process Control Block)

PCB는 **운영체제가 프로세스를 관리하기 위해 필요한 정보를 저장하는 자료구조**입니다. 각 프로세스마다 하나의 PCB가 생성되며, 프로세스가 종료되면 PCB도 함께 제거됩니다.

### PCB의 주요 구성요소

| 구성요소              | 설명                                     | 목적                           |
| --------------------- | ---------------------------------------- | ------------------------------ |
| **프로세스 ID (PID)** | 프로세스를 식별하는 고유 번호            | 프로세스 구분 및 관리          |
| **레지스터 값**       | 프로그램 카운터, 스택 포인터 등          | 문맥 교환 시 복원을 위한 저장  |
| **프로세스 상태**     | new, ready, running, blocked, terminated | 현재 프로세스의 실행 상태 추적 |
| **CPU 스케줄링 정보** | 우선순위, 스케줄링 큐 포인터             | CPU 할당 순서 결정             |
| **메모리 관리 정보**  | 페이지 테이블, 세그먼트 테이블           | 메모리 영역 관리               |
| **파일/입출력 정보**  | 사용 중인 파일 목록, 입출력장치          | 자원 할당 및 관리              |

### 프로세스 ID (PID)

```bash
# 리눅스에서 프로세스 목록 확인
ps -ef

# 예시 출력
UID    PID   PPID  C STIME TTY    TIME     CMD
root   1     0     0 May17  ?      00:00:53 /lib/systemd/systemd
root   2     0     0 May17  ?      00:00:00 [kthreadd]

```

- **PID** : Process ID, 각 프로세스의 고유 식별 번호
- **PPID** : Parent PID, 부모 프로세스의 PID
- 리눅스의 모든 프로세스는 PID를 가지며, 맨 처음 실행되는 프로세스는 `systemd`(PID 1)입니다

## 10-2 프로세스 상태와 계층 구조

### 프로세스 상태 전이

프로세스는 실행되는 동안 여러 상태를 거치게 됩니다. 이를 **프로세스 생명 주기(Process Life Cycle)**라고 합니다.

### 프로세스의 5가지 상태

```
생성(new) → 준비(ready) ⇄ 실행(running) → 종료(terminated)
                ↓           ↑
              대기(blocked)

```

| 상태          | 영문 표기  | 설명                           | 특징                                 |
| ------------- | ---------- | ------------------------------ | ------------------------------------ |
| **생성 상태** | new        | 프로세스가 막 생성된 상태      | PCB가 할당되었지만 메모리에는 미적재 |
| **준비 상태** | ready      | CPU 할당을 기다리는 상태       | 메모리 적재 완료, 실행 대기 중       |
| **실행 상태** | running    | CPU를 할당받아 실행 중인 상태  | 실제로 명령어가 실행되는 상태        |
| **대기 상태** | blocked    | 입출력 작업 등을 기다리는 상태 | CPU를 양보하고 작업 완료 대기        |
| **종료 상태** | terminated | 프로세스 실행이 끝난 상태      | PCB와 메모리 자원 정리               |

### 상태 전이 용어

| 전이                   | 설명        | 발생 시점           |
| ---------------------- | ----------- | ------------------- |
| **디스패치(dispatch)** | 준비 → 실행 | 스케줄러가 CPU 할당 |
| **타이머 인터럽트**    | 실행 → 준비 | 할당 시간 종료      |
| **입출력 요청**        | 실행 → 대기 | I/O 작업 시작       |
| **입출력 완료**        | 대기 → 준비 | I/O 작업 종료       |

### 프로세스 계층 구조

운영체제에서 프로세스는 **계층적 구조**를 가집니다. 하나의 프로세스가 다른 프로세스를 생성할 수 있으며, 이때 생성하는 프로세스를 **부모 프로세스** , 생성된 프로세스를 **자식 프로세스**라고 합니다.

```
프로세스 A (PID: 100)
    ├── 프로세스 B (PID: 200, PPID: 100)
    │   └── 프로세스 D (PID: 400, PPID: 200)
    └── 프로세스 C (PID: 300, PPID: 100)

```

### fork()와 exec() 시스템 호출

**fork() 시스템 호출**

- 부모 프로세스를 복제하여 자식 프로세스 생성
- 자식 프로세스는 부모와 동일한 메모리 공간을 복사받음
- 반환값: 부모에게는 자식의 PID, 자식에게는 0 반환

```c
// fork() 사용 예시
#include <stdio.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        printf("자식 프로세스: PID=%d\\n", getpid());
    } else if (pid > 0) {
        printf("부모 프로세스: PID=%d, 자식PID=%d\\n", getpid(), pid);
    }

    return 0;
}

```

**exec() 시스템 호출**

- 현재 프로세스의 메모리 공간을 새로운 프로그램으로 교체
- fork() 후에 자식 프로세스가 다른 프로그램을 실행할 때 사용
- 실행 후에는 원래 프로세스로 돌아갈 수 없음

```c
// exec() 사용 예시
#include <unistd.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        // 자식 프로세스: ls 명령어 실행
        execl("/bin/ls", "ls", "-l", NULL);
    }

    return 0;
}

```

### fork()와 exec()의 조합

```
부모 프로세스
    ↓ fork()
부모 프로세스 → 자식 프로세스 (복사본)
                    ↓ exec()
                새로운 프로그램 실행

```

## 10-3 프로세스의 메모리 영역

프로세스가 생성되면 커널 영역에는 **PCB**가, 사용자 영역에는 **코드 영역, 데이터 영역, 힙 영역, 스택 영역**이 생성됩니다.

### 메모리 영역 구조

```
높은 주소
┌─────────────┐
│  스택 영역   │  ↓ (아래로 성장)
├─────────────┤
│             │
│  (여유공간)  │
│             │
├─────────────┤
│  힙 영역     │  ↑ (위로 성장)
├─────────────┤
│ 데이터 영역  │
├─────────────┤
│ 코드 영역    │
└─────────────┘
낮은 주소

```

### 각 영역의 특징

| 영역            | 영문 표기         | 저장 내용                      | 특징                                  |
| --------------- | ----------------- | ------------------------------ | ------------------------------------- |
| **코드 영역**   | Code/Text Segment | 실행 가능한 기계어 코드        | 읽기 전용, 프로그램 종료까지 유지     |
| **데이터 영역** | Data Segment      | 전역 변수, 정적 변수           | 프로그램 시작 시 할당, 종료 시 해제   |
| **힙 영역**     | Heap              | 동적 할당 메모리               | 프로그래머가 직접 관리 (malloc, free) |
| **스택 영역**   | Stack             | 지역 변수, 매개변수, 반환 주소 | 함수 호출 시 자동 할당/해제 (LIFO)    |

### 코드 영역 (Code Segment)

```c
int add(int a, int b) {
    return a + b;
}

int main() {
    int result = add(5, 3);
    return 0;
}

```

- `add()`, `main()` 함수의 기계어 코드가 저장
- 읽기 전용 영역으로 수정 불가
- 프로그램 실행 중 변하지 않음

### 데이터 영역 (Data Segment)

```c
int global_var = 100;        // 전역 변수
static int static_var = 200; // 정적 변수

int main() {
    // 코드...
}

```

| 저장 데이터 | 사용 시점     | 해제 시점     |
| ----------- | ------------- | ------------- |
| 전역 변수   | 프로그램 시작 | 프로그램 종료 |
| 정적 변수   | 프로그램 시작 | 프로그램 종료 |

### 힙 영역 (Heap)

```c
#include <stdlib.h>

int main() {
    // 동적 메모리 할당
    int *ptr = (int *)malloc(sizeof(int) * 10);

    // 메모리 사용
    ptr[0] = 100;

    // 메모리 해제
    free(ptr);

    return 0;
}

```

**JavaScript에서의 힙 사용**

```jsx
// 객체 생성 시 힙 영역 사용
const user = {
  name: "John",
  age: 30,
};

// 배열 생성 시 힙 영역 사용
const arr = [1, 2, 3, 4, 5];
```

| 특징             | 설명                      |
| ---------------- | ------------------------- |
| 성장 방향        | 낮은 주소 → 높은 주소 (↑) |
| 관리 주체        | 프로그래머                |
| 할당 방식        | malloc, new 등            |
| 해제 방식        | free, delete 등           |
| 메모리 누수 위험 | 있음 (수동 관리 시)       |

### 스택 영역 (Stack)

```c
int multiply(int x, int y) {
    int result = x * y;  // 지역 변수
    return result;
}

int main() {
    int a = 5;   // 지역 변수
    int b = 3;   // 지역 변수
    int c = multiply(a, b);  // 함수 호출
    return 0;
}

```

**스택 프레임 구조**

```
┌───────────────────┐
│   반환 주소        │
├───────────────────┤
│   매개변수 (y)     │
├───────────────────┤
│   매개변수 (x)     │
├───────────────────┤
│   지역변수(result) │  ← multiply() 함수의 스택 프레임
└───────────────────┘
┌───────────────────┐
│   지역변수 (c)     │
├───────────────────┤
│   지역변수 (b)     │
├───────────────────┤
│   지역변수 (a)     │  ← main() 함수의 스택 프레임
└───────────────────┘

```

| 특징             | 설명                      |
| ---------------- | ------------------------- |
| 성장 방향        | 높은 주소 → 낮은 주소 (↓) |
| 관리 주체        | 운영체제 (자동)           |
| 할당 시점        | 함수 호출 시              |
| 해제 시점        | 함수 종료 시              |
| 데이터 구조      | LIFO (Last In First Out)  |
| 메모리 누수 위험 | 없음 (자동 관리)          |

## 📋 핵심 요약

### 프로세스 기본 개념

- **프로세스** : 실행 중인 프로그램 (메모리에 적재 + CPU 실행)
- **PCB** : 프로세스 관리를 위한 정보를 담은 자료구조
- **PID** : 프로세스를 식별하는 고유 번호

### 프로세스 상태

- **5가지 상태** : 생성(new) → 준비(ready) → 실행(running) → 대기(blocked) → 종료(terminated)
- **디스패치** : 준비 → 실행
- **타이머 인터럽트** : 실행 → 준비

### 프로세스 생성

- **fork()** : 부모 프로세스 복제
- **exec()** : 새로운 프로그램으로 교체
- **계층 구조** : 부모-자식 관계 형성

### 메모리 영역

- **코드 영역** : 실행 코드 (읽기 전용)
- **데이터 영역** : 전역/정적 변수
- **힙 영역** : 동적 할당 (↑ 성장, 수동 관리)
- **스택 영역** : 지역변수/함수 호출 (↓ 성장, 자동 관리)

### 문제 1

프로세스 제어 블록(PCB)에 저장되지 **않는** 정보는 무엇입니까?

1. 프로세스 ID (PID)
2. CPU 레지스터 값
3. 하드디스크의 파일 목록
4. 프로세스 상태 정보

**정답: 3번**

**해설** : PCB에는 프로세스를 관리하기 위한 정보만 저장됩니다. 하드디스크의 전체 파일 목록은 프로세스와 무관한 정보이므로 PCB에 저장되지 않습니다. PCB에는 해당 프로세스가 **사용 중인** 파일 목록만 저장됩니다.

### 문제 2

다음 중 프로세스 상태 전이가 **잘못** 설명된 것은?

1. 디스패치: 준비 상태 → 실행 상태
2. 타이머 인터럽트: 실행 상태 → 준비 상태
3. 입출력 요청: 실행 상태 → 대기 상태
4. 입출력 완료: 대기 상태 → 실행 상태

**정답: 4번**

**해설** : 입출력이 완료되면 프로세스는 대기 상태에서 **준비 상태**로 전이됩니다. 실행 상태로 바로 전이되는 것이 아니라, 준비 큐에서 CPU 할당을 기다려야 합니다. 실행 상태로의 전이는 스케줄러의 디스패치를 통해서만 이루어집니다.

### 문제 3

fork() 시스템 호출에 대한 설명으로 **옳은** 것은?

1. 부모 프로세스의 메모리를 자식이 공유한다
2. 자식 프로세스에게는 0을 반환한다
3. 새로운 프로그램으로 메모리를 교체한다
4. 부모 프로세스가 먼저 종료된다

**정답: 2번**

**해설** : fork()는 부모 프로세스를 복제하여 자식 프로세스를 생성하며, 자식 프로세스에게는 0을 반환하고 부모 프로세스에게는 자식의 PID를 반환합니다. 메모리는 공유가 아닌 **복사**가 이루어지며, 메모리 교체는 exec() 시스템 호출의 역할입니다. 프로세스 종료 순서는 프로그램에 따라 다릅니다.

### 문제 4

다음 중 **힙 영역**에 대한 설명으로 틀린 것은?

1. 동적 메모리 할당에 사용된다
2. 낮은 주소에서 높은 주소로 성장한다
3. 함수가 종료되면 자동으로 해제된다
4. JavaScript의 객체는 힙 영역에 저장된다

**정답: 3번**

**해설** : 힙 영역은 프로그래머가 **수동으로 관리**해야 하는 영역입니다. C/C++에서는 malloc/free, new/delete를 사용해야 하며, 함수 종료 시 자동으로 해제되지 않습니다. 자동으로 해제되는 영역은 **스택 영역**입니다. JavaScript는 가비지 컬렉션이 있어 자동 관리되지만, 이는 언어 차원의 기능입니다.

### 문제 5

프로세스의 스택 영역에 저장되는 것을 **모두** 고른 것은?

```
ㄱ. 전역 변수
ㄴ. 지역 변수
ㄷ. 함수의 매개변수
ㄹ. 반환 주소

```

1. ㄱ, ㄴ
2. ㄴ, ㄷ
3. ㄴ, ㄷ, ㄹ
4. ㄱ, ㄴ, ㄷ, ㄹ

**정답: 3번**

**해설** : 스택 영역에는 함수 호출과 관련된 정보가 저장됩니다. 지역 변수(ㄴ), 함수의 매개변수(ㄷ), 함수 호출 후 돌아갈 반환 주소(ㄹ)가 스택에 저장됩니다. 반면 전역 변수(ㄱ)는 **데이터 영역**에 저장되며, 프로그램이 시작될 때 할당되어 종료될 때까지 유지됩니다.

### 문제 6

다음 중 백그라운드 프로세스에 대한 설명으로 **옳은** 것은?

1. 사용자와 직접 상호작용한다
2. 리눅스에서는 데몬(daemon)이라고 부른다
3. 항상 실행 상태를 유지한다
4. PCB를 가지지 않는다

**정답: 2번**

**해설** : 백그라운드 프로세스는 사용자가 직접 보거나 상호작용하지 않고 백그라운드에서 실행되는 프로세스입니다. 리눅스에서는 **데몬(daemon)** , 윈도우에서는 **서비스(service)**라고 부릅니다. 백그라운드 프로세스도 일반 프로세스처럼 상태가 변하며, 당연히 PCB를 가집니다.
