> **학습 날짜**: 2026-02-12  
> **주제**: 도메인 네임 시스템(DNS)과 자원 식별자(URL/URN)

---

## 🎯 DNS(Domain Name System)란?

### 왜 DNS가 필요한가?

컴퓨터는 **IP 주소**로 통신하지만, 사람은 숫자보다 **이름**을 기억하기 쉽습니다.

- 예: `192.168.0.1` ❌ 기억하기 어려움
- 예: `www.example.com` ✅ 기억하기 쉬움

**DNS의 역할**: 도메인 네임을 IP 주소로 변환해주는 시스템

### 🔍 언제 사용되는가?

웹 개발자라면 매일 접하는 상황:

```javascript
// 브라우저에서 API 호출할 때
fetch('https://api.example.com/users')
  .then(res => res.json())
```

이 순간 DNS가 작동합니다:
1. `api.example.com` → DNS 서버 조회
2. DNS가 IP 주소 반환 (예: `1.2.3.4`)
3. 실제로는 `1.2.3.4`로 접속

## 🏗️ 도메인 네임의 구조

### 계층적 구조

```
www.example.com.
 │    │      │  │
 │    │      │  └─ 루트(Root) - 생략 가능
 │    │      └──── 최상위 도메인(TLD): com, net, kr, org 등
 │    └─────────── 2차 도메인: example
 └──────────────── 3차 도메인(호스트명): www
```

### 실제 예시

| 도메인 | 구조 분해 |
|--------|-----------|
| `developers.naver.com` | `developers`(3차) + `naver`(2차) + `com`(TLD) |
| `git.kernel.org` | `git`(3차) + `kernel`(2차) + `org`(TLD) |
| `www.google.com` | `www`(3차) + `google`(2차) + `com`(TLD) |

### 🎨 TLD(최상위 도메인) 종류

- **일반 TLD**: `.com`, `.net`, `.org`
- **국가 TLD**: `.kr`(한국), `.jp`(일본), `.cn`(중국)
- **최근 추가**: `.doctor`, `.lawyer`, `.company`

---

## 🖥️ DNS 서버의 종류

### 1️⃣ 루트 네임 서버

- 전 세계에 13개 존재 (논리적으로)
- 모든 DNS 질의의 시작점
- TLD 네임 서버 위치 안내

### 2️⃣ TLD 네임 서버

- `.com`, `.net`, `.kr` 등 최상위 도메인 관리
- 2차 도메인의 네임 서버 위치 안내

### 3️⃣ 권한 있는 네임 서버 (Authoritative Name Server)

- 실제 도메인의 IP 주소 보유
- 최종 답변 제공

### 4️⃣ 로컬 네임 서버 (Local Name Server)

- ISP나 조직에서 운영
- 사용자와 가장 가까운 DNS 서버
- 캐싱 기능으로 빠른 응답

**💡 자주 사용하는 Public DNS**
- Google: `8.8.8.8`, `8.8.4.4`
- Cloudflare: `1.1.1.1`

## 🔄 DNS 질의 방식

### 재귀적 질의 (Recursive Query)

```
클라이언트 → 로컬 네임 서버
            ↓ (대신 찾아줌)
         루트 → TLD → 권한 서버
            ↓
클라이언트 ← 최종 결과
```

**특징**: 로컬 네임 서버가 모든 과정을 대신 처리

### 반복적 질의 (Iterative Query)

```
클라이언트 → 로컬 네임 서버 → 루트 (다음 서버 주소 알려줌)
클라이언트 → TLD 서버 (다음 서버 주소 알려줌)
클라이언트 → 권한 서버 → 최종 IP 주소
```

**특징**: 클라이언트가 직접 여러 서버에 질의

### 🎯 실무에서는?

대부분 **재귀적 질의** 사용 → 사용자 편의성 높음

## 📋 DNS 레코드 타입

실무에서 자주 마주치는 레코드들:

| 레코드 타입 | 설명 | 예시 |
|------------|------|------|
| **A** | 도메인 → IPv4 주소 | `example.com` → `1.2.3.4` |
| **AAAA** | 도메인 → IPv6 주소 | `example.com` → `2001:...` |
| **CNAME** | 별칭 지정 | `www.example.com` → `example.com` |
| **MX** | 메일 서버 지정 | `example.com`의 메일 서버 |
| **NS** | 네임 서버 지정 | 특정 호스트의 IP 주소 담당 서버 |

### 💼 프론트엔드 개발자가 알아야 할 이유

```javascript
// CNAME 레코드 활용 예시
// blog.mysite.com → mysite.github.io
// 실제로는 GitHub Pages를 가리킴

// A 레코드 예시
// api.mysite.com → 52.123.45.67
// API 서버의 실제 IP
```

## 🌐 URL (Uniform Resource Locator)

### URL의 구성 요소

```
https://www.example.com:8042/over/there?name=ferret#nose
└─┬─┘  └──────┬──────┘└┬─┘└────┬────┘└─────┬─────┘└┬─┘
scheme    authority   port   path      query    fragment
```

### 각 요소 상세 설명

#### 1️⃣ Scheme (스킴)

프로토콜 지정

- `http://` - 일반 HTTP
- `https://` - 보안 HTTP (SSL/TLS)
- `ftp://` - 파일 전송
- `mailto:` - 이메일

#### 2️⃣ Authority (권한)

호스트를 특정하는 부분 (도메인 네임 + 포트 번호)

```
www.example.com:8080
└──────┬──────┘└┬─┘
    호스트      포트
```

- 포트 생략 시: HTTP는 80, HTTPS는 443 사용

#### 3️⃣ Path (경로)

자원의 위치 지정

```
/home/images/a.png
```

- `/home/images/` - 디렉토리 경로
- `a.png` - 파일명

#### 4️⃣ Query (쿼리)

추가 파라미터 전달 (키=값 형태)

```
?query=value&query2=value2
```

**프론트엔드 예시**:
```javascript
// React Router 등에서 쿼리 파라미터 읽기
const params = new URLSearchParams(window.location.search);
const query = params.get('query'); // "value"
```

#### 5️⃣ Fragment (프래그먼트)

페이지 내 특정 위치로 이동

```
#nose
```

- HTML의 `id` 속성과 연결
- 페이지 새로고침 없이 스크롤 이동

## 🆚 URL vs URN

### URL (Uniform Resource Locator)

- **위치**를 기준으로 자원 식별
- 예: `http://example.com/home/images/a.png`
- 위치가 바뀌면 사용 불가

### URN (Uniform Resource Name)

- **이름**을 기준으로 자원 식별
- 위치와 무관하게 고유 식별자 사용
- 예: `urn:isbn:0451450523` (ISBN 번호)

### 🎯 실무 관점

- **URL**: 99% 이상 사용 (웹 개발에서)
- **URN**: 특수한 경우 (도서, 표준 문서 등)

## 🔧 hosts 파일

### 개념

DNS 조회 전에 먼저 확인하는 **로컬 파일**

### 위치

- Windows: `C:\Windows\System32\drivers\etc\hosts`
- Linux/Mac: `/etc/hosts`

### 내용 예시

```
127.0.0.1       localhost
255.255.255.255 broadcasthost
::1             localhost
```

### 💼 언제 사용하는가?

**개발 환경 테스트**

```
# hosts 파일에 추가
127.0.0.1  dev.example.com
```

그러면:
- 브라우저에서 `dev.example.com` 입력
- → `127.0.0.1`(로컬호스트)로 연결
- → 로컬 개발 서버 테스트 가능

## 📝 핵심 요약

### DNS의 역할
✅ 도메인 네임 → IP 주소 변환  
✅ 사람이 기억하기 쉬운 이름 사용 가능  
✅ 계층적 구조로 전 세계 도메인 관리

### 도메인 구조
✅ 루트(.) → TLD → 2차 도메인 → 3차 도메인  
✅ 역순으로 관리 (오른쪽이 상위)

### DNS 서버
✅ 루트 네임 서버: 최상위  
✅ TLD 네임 서버: .com, .kr 등 관리  
✅ 권한 있는 네임 서버: 실제 IP 보유  
✅ 로컬 네임 서버: 캐싱으로 빠른 응답

### URL 구성
✅ scheme + authority + path + query + fragment  
✅ 각 부분은 자원을 특정하는 역할

### DNS 레코드
✅ A: IPv4 매핑  
✅ CNAME: 별칭 설정  
✅ MX: 메일 서버

## 🧪 복습 퀴즈

### Q1. DNS의 주요 역할은?

① 웹 페이지를 저장하는 서버  
② 도메인 네임을 IP 주소로 변환  
③ 이메일을 전송하는 프로토콜  
④ 파일을 암호화하는 시스템

**정답: ②**  
해설: DNS(Domain Name System)는 사람이 기억하기 쉬운 도메인 네임(예: www.example.com)을 컴퓨터가 이해하는 IP 주소(예: 192.168.0.1)로 변환해주는 시스템입니다.

---

### Q2. `www.example.com`의 TLD(최상위 도메인)는?

① www  
② example  
③ com  
④ www.example

**정답: ③**  
해설: 도메인은 오른쪽부터 계층이 높습니다. com이 TLD(Top-Level Domain), example이 2차 도메인, www가 3차 도메인(호스트명)입니다.

---

### Q3. 다음 중 DNS 레코드 타입과 설명이 올바른 것은?

① A 레코드 - 도메인의 별칭 지정  
② CNAME 레코드 - IPv4 주소 매핑  
③ MX 레코드 - 메일 서버 지정  
④ NS 레코드 - IPv6 주소 매핑

**정답: ③**  
해설: A 레코드는 IPv4 주소 매핑, CNAME은 별칭 지정, MX는 메일 서버 지정, NS는 네임 서버 지정에 사용됩니다.

---

### Q4. URL `https://example.com:8080/path?name=value#top`에서 포트 번호는?

① https  
② 8080  
③ path  
④ top

**정답: ②**  
해설: 포트 번호는 호스트명 뒤에 콜론(:)과 함께 표시됩니다. 이 경우 8080이 포트 번호입니다. 포트를 생략하면 HTTP는 80, HTTPS는 443을 기본값으로 사용합니다.

---

### Q5. 재귀적 질의(Recursive Query)의 특징은?

① 클라이언트가 직접 여러 DNS 서버에 질의  
② 로컬 네임 서버가 모든 과정을 대신 처리  
③ DNS 캐싱을 사용하지 않음  
④ IP 주소 대신 도메인 네임을 반환

**정답: ②**  
해설: 재귀적 질의는 클라이언트가 로컬 네임 서버에 한 번만 요청하면, 로컬 네임 서버가 루트 → TLD → 권한 서버까지 모든 과정을 대신 처리해주는 방식입니다.

---

### Q6. hosts 파일의 용도로 적절한 것은?

① DNS 서버를 완전히 대체  
② 로컬 개발 환경에서 도메인 테스트  
③ 웹사이트 속도 향상  
④ 바이러스 백신 기능

**정답: ②**  
해설: hosts 파일은 DNS 조회 전에 먼저 확인되는 로컬 파일입니다. 개발자들은 이를 활용해 실제 DNS 등록 없이 로컬에서 도메인 이름으로 테스트할 수 있습니다 (예: 127.0.0.1 dev.example.com).
