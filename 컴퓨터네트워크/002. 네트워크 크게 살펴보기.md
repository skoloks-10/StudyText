## 프로토콜 (Protocol) 🤝

### 프로토콜이란?

**프로토콜**은 컴퓨터 간 데이터 통신을 위한 **약속된 규칙**입니다. 사람들이 대화할 때 언어를 사용하듯이, 컴퓨터들도 네트워크를 통해 통신하기 위해서는 공통된 규칙이 필요합니다.

### 주요 개념

**호스트(Host)**

- 네트워크에 연결된 컴퓨터 등의 장치
- 예: 개인용 PC, 서버, 스마트폰 등

**메시지 송수신 프로세스**

1. 송신 측에서 메시지 생성(패키징)
2. 네트워크를 통한 전송
3. 수신 측에서 메시지 수신
4. 메시지 해석 및 처리

### 프로토콜의 핵심 기능

### 1️⃣ 주소 설정 (Addressing)

- 네트워크 상에서 메시지를 올바른 목적지로 전달
- **IP 주소**: 논리적 주소 (예: 192.168.1.1)
- **MAC 주소**: 물리적 주소 (예: A1:B2:C3:D4:E5:F6)

### 2️⃣ 패킹 추출 (Packet Extraction)

- 데이터를 전송 가능한 단위로 분할
- 각 패킷에는 목적지 정보가 포함됨

### 3️⃣ 라우팅 (Routing)

- 패킷이 목적지까지 가는 최적 경로 결정
- 여러 경로 중 효율적인 경로 선택

### 사용 시기와 목적

**언제 사용하나요?**

- 두 개 이상의 장치가 네트워크를 통해 데이터를 주고받을 때
- 인터넷 접속, 파일 전송, 이메일 송수신 등 모든 네트워크 통신

**왜 필요한가요?**

- 서로 다른 제조사의 장치들이 통신 가능
- 안정적이고 효율적인 데이터 전송 보장
- 오류 검출 및 수정 기능 제공

### 예시: 실제 통신 과정

```
[사용자 A] "안녕!" 메시지 전송
    ↓
[프로토콜 처리]
- 메시지를 패킷으로 분할
- 수신자 주소 정보 추가
- 오류 검증 코드 추가
    ↓
[네트워크 전송]
    ↓
[수신자 B] 패킷 수신 및 재조립
    ↓
"안녕!" 메시지 표시

```

## 네트워크 참조 모델 🏗️

### OSI 7계층 모델

**OSI (Open Systems Interconnection) 모델**은 네트워크 통신을 7개의 논리적 계층으로 구분한 국제 표준 모델입니다.

### 계층 구조 (상위 → 하위)

| 계층 | 명칭 | 역할 | PDU |
| --- | --- | --- | --- |
| 7 | 응용 계층 (Application) | 사용자 인터페이스 제공 | 데이터 |
| 6 | 표현 계층 (Presentation) | 데이터 형식 변환, 암호화 | 데이터 |
| 5 | 세션 계층 (Session) | 연결 설정/유지/종료 관리 | 데이터 |
| 4 | 전송 계층 (Transport) | 신뢰성 있는 데이터 전송 | 세그먼트 |
| 3 | 네트워크 계층 (Network) | 경로 설정, IP 주소 지정 | 패킷 |
| 2 | 데이터 링크 계층 (Data Link) | 물리적 주소 지정, 오류 검출 | 프레임 |
| 1 | 물리 계층 (Physical) | 실제 전기 신호 전송 | 비트 |

### 계층별 상세 설명

### 📱 7계층: 응용 계층 (Application Layer)

**역할**: 사용자와 직접 상호작용하는 계층

**주요 기능**:

- 사용자 인터페이스 제공
- 네트워크 서비스를 응용 프로그램에 제공

**프로토콜 예시**:

- HTTP (웹 브라우징)
- FTP (파일 전송)
- SMTP (이메일 전송)

```
예시: 웹 브라우저에서 웹 페이지 요청
GET /index.html HTTP/1.1
Host: www.example.com

```

### 🔄 6계층: 표현 계층 (Presentation Layer)

**역할**: 데이터 형식을 변환하고 암호화

**주요 기능**:

- 문자 인코딩 변환 (ASCII, Unicode)
- 데이터 압축
- 암호화/복호화

**사용 예시**:

- JPEG 이미지를 화면에 표시 가능한 형태로 변환
- 암호화된 HTTPS 통신

### 🔗 5계층: 세션 계층 (Session Layer)

**역할**: 통신 세션을 설정, 유지, 종료

**주요 기능**:

- 대화 제어 (동시 양방향 통신 관리)
- 동기화 (체크포인트 설정)

**사용 예시**:

- 화상 회의 중 연결 유지
- 파일 전송 중 중단점 저장

### 📦 4계층: 전송 계층 (Transport Layer)

**역할**: 종단 간 신뢰성 있는 데이터 전송

**주요 프로토콜**:

**TCP (Transmission Control Protocol)**

- 연결 지향적
- 신뢰성 보장 (오류 검출 및 재전송)
- 순서 보장
- 속도가 상대적으로 느림

```
사용 예시: 웹 페이지 로딩, 파일 다운로드

```

**UDP (User Datagram Protocol)**

- 비연결형
- 신뢰성 보장 안 함
- 빠른 전송 속도
- 실시간 통신에 적합

```
사용 예시: 동영상 스트리밍, 온라인 게임

```

### 🗺️ 3계층: 네트워크 계층 (Network Layer)

**역할**: 패킷의 경로 설정 (라우팅)

**주요 기능**:

- IP 주소 지정
- 라우팅 (최적 경로 선택)
- 패킷 분할 및 재조립

**프로토콜**:

- IP (Internet Protocol)
- ICMP (ping 명령어)
- ARP (IP ↔ MAC 주소 변환)

```
예시: IP 주소를 이용한 패킷 전달
출발지: 192.168.1.10
목적지: 8.8.8.8 (Google DNS)

```

### 🔌 2계층: 데이터 링크 계층 (Data Link Layer)

**역할**: 물리적 네트워크를 통한 데이터 전송

**주요 기능**:

- MAC 주소 기반 통신
- 프레임 생성
- 오류 검출 (CRC)
- 흐름 제어

**특징**:

- 같은 네트워크(LAN) 내에서만 동작
- 스위치가 이 계층에서 작동

```
예시: MAC 주소를 이용한 로컬 통신
출발지 MAC: A1:B2:C3:D4:E5:F6
목적지 MAC: 01:23:45:67:89:AB

```

### ⚡ 1계층: 물리 계층 (Physical Layer)

**역할**: 실제 전기 신호 전송

**주요 기능**:

- 비트를 전기/광/전파 신호로 변환
- 케이블, 커넥터 등 물리적 매체 정의

**구성 요소**:

- 케이블 (UTP, 광섬유)
- 허브
- 리피터

### TCP/IP 4계층 모델

**TCP/IP 모델**은 실제 인터넷에서 사용되는 프로토콜 스택입니다.

| TCP/IP 계층 | 대응 OSI 계층 | 역할 |
| --- | --- | --- |
| 응용 계층 | 5~7계층 | 응용 프로그램 서비스 |
| 전송 계층 | 4계층 | 종단 간 통신 (TCP/UDP) |
| 인터넷 계층 | 3계층 | IP 주소 기반 라우팅 |
| 네트워크 액세스 계층 | 1~2계층 | 물리적 네트워크 접근 |

### OSI vs TCP/IP 비교

**OSI 모델**:

- 이론적, 학습용 모델
- 7계층으로 세분화
- 명확한 계층 구분

**TCP/IP 모델**:

- 실용적, 실제 구현 모델
- 4계층으로 단순화
- 인터넷 표준

## 캡슐화와 역캡슐화 📮

### 캡슐화 (Encapsulation)

**정의**: 상위 계층에서 하위 계층으로 데이터를 전달하면서 각 계층의 헤더 정보를 추가하는 과정

### 캡슐화 과정

```
[응용 계층] 원본 데이터
    ↓ (헤더 추가)
[전송 계층] TCP/UDP 헤더 + 데이터
    ↓ (헤더 추가)
[네트워크 계층] IP 헤더 + TCP 헤더 + 데이터
    ↓ (헤더 추가)
[데이터 링크 계층] 이더넷 헤더 + IP 헤더 + TCP 헤더 + 데이터 + 트레일러
    ↓
[물리 계층] 비트 신호로 전송

```

### 각 계층의 PDU (Protocol Data Unit)

**PDU란?** 각 계층에서 처리하는 데이터 단위

| 계층 | PDU 이름 | 포함 내용 |
| --- | --- | --- |
| 응용/표현/세션 | 데이터 (Data) | 사용자 정보 |
| 전송 | 세그먼트 (Segment) | TCP/UDP 헤더 + 데이터 |
| 네트워크 | 패킷 (Packet) | IP 헤더 + 세그먼트 |
| 데이터 링크 | 프레임 (Frame) | 이더넷 헤더 + 패킷 + 트레일러 |
| 물리 | 비트 (Bit) | 0과 1의 전기 신호 |

### 역캡슐화 (Decapsulation)

**정의**: 수신 측에서 하위 계층부터 헤더를 제거하면서 원본 데이터를 복원하는 과정

### 역캡슐화 과정

```
[물리 계층] 비트 신호 수신
    ↓ (헤더 제거)
[데이터 링크 계층] 이더넷 헤더 제거
    ↓ (헤더 제거)
[네트워크 계층] IP 헤더 제거
    ↓ (헤더 제거)
[전송 계층] TCP/UDP 헤더 제거
    ↓
[응용 계층] 원본 데이터 복원

```

### 실제 예시: 이메일 전송

```
1단계 [응용]: "안녕하세요" 이메일 작성
2단계 [전송]: TCP 헤더 추가 (포트 번호: 25)
3단계 [네트워크]: IP 헤더 추가 (목적지 IP)
4단계 [데이터 링크]: MAC 주소 헤더 추가
5단계 [물리]: 전기 신호로 변환 → 전송
---수신 측---
6단계 [물리]: 전기 신호 수신
7단계 [데이터 링크]: MAC 헤더 확인 및 제거
8단계 [네트워크]: IP 헤더 확인 및 제거
9단계 [전송]: TCP 헤더 확인 및 제거
10단계 [응용]: "안녕하세요" 이메일 표시

```

### 헤더에 포함되는 정보

**전송 계층 (TCP)**:

- 출발지 포트 번호
- 목적지 포트 번호
- 시퀀스 번호 (순서 보장)
- ACK 번호 (수신 확인)

**네트워크 계층 (IP)**:

- 출발지 IP 주소
- 목적지 IP 주소
- TTL (Time To Live)
- 프로토콜 타입

**데이터 링크 계층 (Ethernet)**:

- 출발지 MAC 주소
- 목적지 MAC 주소
- 프레임 타입
- CRC (오류 검증)

## 트래픽과 처리율 📊

### 트래픽 (Traffic)

**정의**: 특정 시간대에 네트워크를 통해 전송되는 데이터의 양

**특징**:

- 단위: bps (bits per second), Mbps, Gbps
- 대역폭의 사용률을 나타냄
- 시간대별로 변동

```
예시: 평일 점심시간 네트워크 트래픽 증가
오전 9시: 100 Mbps
점심시간: 450 Mbps
오후 3시: 200 Mbps

```

### 처리율 (Throughput)

**정의**: 단위 시간당 실제로 전송된 데이터의 양

**특징**:

- 실질적인 네트워크 성능 지표
- 대역폭보다 항상 작음 (오버헤드, 프로토콜 처리 등으로 인해)

**처리율에 영향을 미치는 요인**:

1. 네트워크 대역폭
2. 패킷 손실률
3. 지연 시간
4. 프로토콜 오버헤드

```
예시:
대역폭: 100 Mbps
실제 처리율: 85 Mbps (15%는 헤더, 재전송 등으로 소비)

```

### 대역폭 (Bandwidth)

**정의**: 네트워크가 전송할 수 있는 최대 데이터 전송량

**특징**:

- 이론적 최대값
- 네트워크 용량의 상한선

### 처리율 측정 방법

**ping 명령어**

```bash
$ ping 8.8.8.8
PING 8.8.8.8 (8.8.8.8): 56 data bytes
64 bytes from 8.8.8.8: icmp_seq=0 ttl=113 time=34.105 ms
64 bytes from 8.8.8.8: icmp_seq=1 ttl=113 time=38.382 ms

--- 8.8.8.8 ping statistics ---
7 packets transmitted, 7 packets received, 0.0% packet loss
round-trip min/avg/max/stddev = 31.339/33.502/38.382/2.133 ms

```

**측정 항목**:

- RTT (Round-Trip Time): 왕복 지연 시간
- Packet Loss: 패킷 손실률
- Jitter: 지연 시간 변동

### 네트워크 성능 최적화

**개선 방법**:

1. 대역폭 증설
2. QoS (Quality of Service) 설정
3. 트래픽 분산 (로드 밸런싱)
4. 캐싱 서버 활용
5. 불필요한 프로토콜 오버헤드 감소

## 최종 핵심 요약 ⭐

### 프로토콜

- 네트워크 통신을 위한 약속된 규칙
- 주소 설정, 데이터 분할, 경로 설정 기능 제공
- IP, TCP, HTTP 등 다양한 프로토콜 존재

### OSI 7계층

- 네트워크 통신을 7개 논리적 계층으로 구분
- 각 계층은 독립적으로 동작하며 특정 역할 수행
- 하위 계층: 물리적 전송 담당
- 상위 계층: 응용 서비스 제공

### TCP/IP 4계층

- 실제 인터넷에서 사용되는 모델
- OSI 모델을 단순화한 실용적 구조
- 네트워크 액세스 → 인터넷 → 전송 → 응용 계층

### 캡슐화/역캡슐화

- 캡슐화: 송신 시 각 계층의 헤더 추가
- 역캡슐화: 수신 시 헤더 제거 및 데이터 복원
- PDU: 각 계층의 데이터 처리 단위

### 트래픽과 처리율

- 트래픽: 네트워크를 통과하는 데이터 양
- 처리율: 실제 전송된 데이터 양
- 대역폭: 이론적 최대 전송 용량

### 문제 1

프로토콜의 주요 기능이 아닌 것은?

① 주소 설정 (Addressing)
② 패킷 추출 (Packet Extraction)
③ 라우팅 (Routing)
④ 하드웨어 제조
⑤ 데이터 형식 변환

정답: ④

해설: 프로토콜은 네트워크 통신을 위한 소프트웨어적인 규칙이며, 하드웨어 제조는 프로토콜의 기능이 아닙니다. 주소 설정, 패킷 추출, 라우팅, 데이터 형식 변환은 모두 프로토콜이 수행하는 핵심 기능입니다.

### 문제 2

OSI 7계층 모델에서 IP 주소를 사용하여 패킷의 경로를 설정하는 계층은?

① 물리 계층 (Physical Layer)
② 데이터 링크 계층 (Data Link Layer)
③ 네트워크 계층 (Network Layer)
④ 전송 계층 (Transport Layer)
⑤ 응용 계층 (Application Layer)

정답: ③

해설: 네트워크 계층(3계층)은 IP 주소를 이용하여 패킷의 경로를 설정하는 라우팅 기능을 담당합니다. 데이터 링크 계층은 MAC 주소를 사용하고, 전송 계층은 포트 번호를 사용합니다.

### 문제 3

TCP와 UDP에 대한 설명으로 올바른 것은?

① TCP는 비연결형 프로토콜이다
② UDP는 신뢰성을 보장한다
③ TCP는 순서를 보장하지 않는다
④ UDP는 실시간 스트리밍에 적합하다
⑤ TCP가 UDP보다 항상 빠르다

정답: ④

해설: UDP는 비연결형 프로토콜로 신뢰성은 보장하지 않지만 빠른 전송 속도를 제공하여 실시간 스트리밍, 온라인 게임 등에 적합합니다. TCP는 연결 지향적이며 신뢰성과 순서를 보장하지만 UDP보다 느립니다.

### 문제 4

캡슐화 과정에서 전송 계층의 PDU는?

① 비트 (Bit)
② 프레임 (Frame)
③ 패킷 (Packet)
④ 세그먼트 (Segment)
⑤ 데이터 (Data)

정답: ④

해설: 각 계층의 PDU는 다음과 같습니다.

- 전송 계층: 세그먼트 (Segment)
- 네트워크 계층: 패킷 (Packet)
- 데이터 링크 계층: 프레임 (Frame)
- 물리 계층: 비트 (Bit)

### 문제 5

다음 중 데이터 링크 계층(2계층)에서 사용하는 주소 체계는?

① IP 주소
② 포트 번호
③ MAC 주소
④ URL
⑤ 도메인 네임

정답: ③

해설: 데이터 링크 계층은 MAC(Media Access Control) 주소를 사용하여 같은 네트워크 내에서 통신합니다. IP 주소는 네트워크 계층(3계층)에서, 포트 번호는 전송 계층(4계층)에서 사용됩니다.

---

### 문제 6

역캡슐화(Decapsulation) 과정에 대한 설명으로 올바른 것은?

① 송신 측에서 헤더를 추가하는 과정이다
② 수신 측에서 상위 계층부터 헤더를 제거한다
③ 수신 측에서 하위 계층부터 헤더를 제거한다
④ 데이터를 암호화하는 과정이다
⑤ 데이터를 압축하는 과정이다

정답: ③

해설: 역캡슐화는 수신 측에서 물리 계층(하위)부터 시작하여 각 계층의 헤더를 순차적으로 제거하면서 원본 데이터를 복원하는 과정입니다. 캡슐화는 송신 측에서 헤더를 추가하는 과정입니다.

---

### 문제 7

처리율(Throughput)에 대한 설명으로 옳은 것은?

① 대역폭과 항상 같은 값이다
② 이론적인 최대 전송 속도이다
③ 실제로 전송된 데이터의 양을 나타낸다
④ 네트워크 용량과 무관하다
⑤ 항상 대역폭보다 크다

정답: ③

해설: 처리율은 단위 시간당 실제로 전송된 데이터의 양을 의미합니다. 대역폭은 이론적 최대값이며, 처리율은 프로토콜 오버헤드, 패킷 손실 등의 이유로 항상 대역폭보다 작습니다.

### 문제 8

OSI 모델에서 세션 계층(5계층)의 주요 역할은?

① 물리적 신호 전송
② 연결 설정, 유지, 종료 관리
③ 데이터 암호화
④ IP 주소 할당
⑵ MAC 주소 관리

정답: ②

해설: 세션 계층은 통신 세션을 설정하고 유지하며 종료하는 역할을 담당합니다. 대화 제어와 동기화(체크포인트 설정) 기능을 제공하여 안정적인 통신을 지원합니다.

### 문제 9

다음 중 네트워크 계층(3계층)에서 동작하는 프로토콜은?

① HTTP
② TCP
③ ICMP (ping)
④ FTP
⑤ SMTP

정답: ③

해설: ICMP(Internet Control Message Protocol)는 네트워크 계층에서 동작하며, ping 명령어에서 사용됩니다. TCP는 전송 계층(4계층), HTTP/FTP/SMTP는 응용 계층(7계층) 프로토콜입니다.

### 문제 10

TCP/IP 모델과 OSI 모델의 비교 설명으로 올바르지 않은 것은?

① TCP/IP 모델은 4계층으로 구성된다
② OSI 모델은 7계층으로 구성된다
③ TCP/IP 모델이 실제 인터넷에서 사용된다
④ OSI 모델은 이론적, 학습용 모델이다
⑤ TCP/IP 모델이 OSI 모델보다 더 세분화되어 있다

정답: ⑤

해설: TCP/IP 모델(4계층)은 OSI 모델(7계층)을 단순화한 실용적인 모델입니다. OSI 모델이 더 세분화되어 있으며, TCP/IP 모델은 실제 인터넷 구현에 사용되는 반면 OSI 모델은 주로 학습과 이론적 이해를 위해 사용됩니다.
