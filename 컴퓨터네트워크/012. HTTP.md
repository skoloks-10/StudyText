# 📡 HTTP 완벽 정리

## 1. HTTP란?

**HTTP(Hypertext Transfer Protocol)**는 웹에서 클라이언트와 서버가 데이터를 주고받기 위한 프로토콜입니다.

### 🎯 언제 쓰나요?
- 웹 브라우저가 서버에 페이지를 요청할 때
- API 호출할 때 (fetch, axios 등)
- 웹 애플리케이션의 모든 네트워크 통신

### 💡 핵심 특징

**요청-응답 기반 프로토콜**
- 클라이언트가 요청(Request)을 보냄
- 서버가 응답(Response)을 반환
- 항상 클라이언트가 먼저 요청해야 함

---

## 2. HTTP의 주요 특성

### 📌 미디어 독립적 프로토콜

HTTP는 다양한 형식의 데이터를 전송할 수 있습니다.

**MIME 타입으로 데이터 형식을 구분**
- `text/html`, `text/css`, `text/javascript`
- `image/png`, `image/jpeg`, `image/gif`
- `application/json`, `application/pdf`
- `video/mp4`, `audio/wav`

```
Content-Type: application/json
```

### 🔄 스테이트리스(Stateless) 프로토콜

**각 요청은 독립적이며, 서버는 이전 요청을 기억하지 못합니다.**

#### 실무에서 자주 헷갈리는 포인트
- 로그인 상태 유지는 HTTP 자체 기능이 아님
- 쿠키/세션/토큰으로 상태를 관리해야 함
- 같은 사용자라도 매 요청마다 인증 정보를 보내야 함

## 3. HTTP 메시지 구조

모든 HTTP 메시지는 다음 3부분으로 구성됩니다:

### 📝 구조

```
1. 시작 라인 (Start Line)
2. 헤더 (Headers)
3. 본문 (Body)
```

#### ① 요청 메시지 예시
```http
GET /example-page HTTP/1.1
Host: www.example.com
Accept: text/html
```

#### ② 응답 메시지 예시
```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234

<!DOCTYPE html>
<html>...</html>
```

## 4. HTTP 메서드

### 🛠️ 주요 메서드

| 메서드 | 용도 | 언제 쓰나요? |
|--------|------|--------------|
| **GET** | 자원 조회 | 데이터 가져올 때 (검색, 목록 조회) |
| **POST** | 자원 생성/제출 | 데이터 전송 (회원가입, 글 작성) |
| **PUT** | 자원 전체 수정 | 데이터 전체 교체 |
| **PATCH** | 자원 일부 수정 | 데이터 일부만 변경 |
| **DELETE** | 자원 삭제 | 데이터 삭제 |
| **HEAD** | 헤더만 조회 | 메타데이터만 확인 |

### 💡 실무 패턴

#### GET vs POST
- **GET**: URL에 데이터 포함, 브라우저 히스토리에 남음
  ```javascript
  fetch('/api/users?id=123')
  ```

- **POST**: 본문에 데이터 포함, 보안상 안전
  ```javascript
  fetch('/api/users', {
    method: 'POST',
    body: JSON.stringify({ name: 'Kim' })
  })
  ```

#### PUT vs PATCH
- **PUT**: 전체 데이터 교체
  ```json
  // 전체 객체를 새로 보냄
  { "id": 1, "title": "수정된 제목", "content": "새 내용" }
  ```

- **PATCH**: 일부만 수정
  ```json
  // 바뀐 부분만 보냄
  { "title": "수정된 제목" }
  ```

## 5. HTTP 상태 코드

### 📊 상태 코드 분류

| 범위 | 의미 | 대표 코드 |
|------|------|-----------|
| **1XX** | 정보성 | 거의 안 씀 |
| **2XX** | 성공 | 200, 201, 204 |
| **3XX** | 리다이렉션 | 301, 302, 307 |
| **4XX** | 클라이언트 에러 | 400, 401, 403, 404 |
| **5XX** | 서버 에러 | 500, 502, 503 |

### 🔍 자주 쓰는 상태 코드

#### 2XX 성공
- **200 OK**: 요청 성공
- **201 Created**: 새 자원 생성 성공 (POST 후)
- **204 No Content**: 성공했지만 반환할 본문 없음

#### 3XX 리다이렉션
- **301 Moved Permanently**: 영구 이동 (URL이 완전히 바뀜)
- **302 Found**: 임시 리다이렉션
- **307 Temporary Redirect**: 임시 리다이렉션 (메서드 유지)

#### 4XX 클라이언트 에러
- **400 Bad Request**: 잘못된 요청
- **401 Unauthorized**: 인증 필요
- **403 Forbidden**: 권한 없음
- **404 Not Found**: 자원을 찾을 수 없음
- **405 Method Not Allowed**: 허용되지 않은 메서드

#### 5XX 서버 에러
- **500 Internal Server Error**: 서버 오류
- **502 Bad Gateway**: 게이트웨이/프록시 오류
- **503 Service Unavailable**: 서비스 일시 중단

### 💡 실무에서 자주 헷갈리는 포인트

**301 vs 302**
- 301: SEO에 영향, 브라우저가 새 URL 기억
- 302: 임시 이동, 원래 URL 유지

**401 vs 403**
- 401: 로그인하면 해결됨 (인증 안 됨)
- 403: 로그인해도 안 됨 (권한 없음)

## 6. HTTP 버전

### 📈 버전별 특징

#### HTTP/0.9
- 최초 버전
- GET 메서드만 지원
- 매우 단순

#### HTTP/1.0
- HEAD, POST 추가
- 상태 코드, 헤더 도입

#### HTTP/1.1 ⭐ (가장 많이 사용)
- 연결 재사용 가능 (Persistent Connection)
- 파이프라이닝 지원
- 추가 메서드 도입

#### HTTP/2.0
- 멀티플렉싱: 여러 요청을 동시에
- 헤더 압축
- 서버 푸시 기능

#### HTTP/3.0
- UDP 기반 (QUIC 프로토콜)
- 더 빠른 연결 설정

## 📝 복습 퀴즈

### Q1. HTTP의 특징으로 올바른 것은?
1. 클라이언트가 요청하면 서버가 응답한다
2. 서버가 먼저 데이터를 보낼 수 있다
3. 이전 요청 정보를 서버가 자동으로 기억한다
4. 텍스트만 전송할 수 있다

**정답: 1번**
HTTP는 요청-응답 기반 프로토콜로, 항상 클라이언트가 먼저 요청해야 합니다. 서버는 스테이트리스 특성상 이전 요청을 기억하지 못하며, MIME 타입을 통해 다양한 형식의 데이터를 전송할 수 있습니다.

---

### Q2. 다음 중 올바른 메서드 사용은?
1. 사용자 목록 조회 → POST
2. 회원 가입 → GET
3. 프로필 사진만 변경 → PATCH
4. 게시글 삭제 → PUT

**정답: 3번**
PATCH는 자원의 일부만 수정할 때 사용합니다. 1번은 GET, 2번은 POST, 4번은 DELETE를 사용해야 합니다.

---

### Q3. HTTP 상태 코드 설명이 올바른 것은?
1. 200 OK - 요청 실패
2. 404 Not Found - 서버 오류
3. 301 Moved Permanently - 영구 이동
4. 500 Internal Server Error - 클라이언트 오류

**정답: 3번**
301은 자원이 영구적으로 다른 URL로 이동했음을 의미합니다. 200은 성공, 404는 클라이언트 에러(자원 없음), 500은 서버 에러입니다.

---

### Q4. PUT과 PATCH의 차이는?
1. PUT은 생성, PATCH는 삭제
2. PUT은 전체 수정, PATCH는 일부 수정
3. PUT은 조회, PATCH는 수정
4. 둘 다 같은 기능

**정답: 2번**
PUT은 자원 전체를 교체하고, PATCH는 일부만 수정합니다. 예를 들어 사용자 정보 중 이름만 바꿀 때는 PATCH를 사용합니다.

---

### Q5. 다음 중 클라이언트 에러 코드가 아닌 것은?
1. 400 Bad Request
2. 401 Unauthorized
3. 404 Not Found
4. 502 Bad Gateway

**정답: 4번**
502는 5XX 범위로 서버 에러입니다. 게이트웨이나 프록시 서버의 문제를 의미합니다. 나머지는 모두 4XX 범위의 클라이언트 에러입니다.
