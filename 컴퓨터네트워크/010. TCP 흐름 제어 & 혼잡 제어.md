# 📚 TCP 흐름 제어 & 혼잡 제어 복습 자료

---

## 1️⃣ 오류 검출과 재전송 (Error Detection & Retransmission)

### 📌 기본 개념
TCP는 **신뢰성 있는 데이터 전송**을 위해 오류를 검출하고 재전송하는 메커니즘을 갖추고 있습니다.

### 🔍 재전송이 필요한 상황
TCP 세그먼트의 오류 검출을 위한 체크섬 필드가 있으며, 체크섬은 세그먼트의 헤더와 데이터를 포함한 전체를 대상으로 계산됩니다.

**재전송을 결정하는 요소:**
- ① 중복된 ACK 세그먼트를 받았을 때
- ② 오류를 검지하여 피해(재전송)를 알리는 ACK 세그먼트 수신
- ③ **타임아웃 발생** (중요!)

### ⚠️ 헷갈리는 포인트
- TCP가 신뢰성을 보장하려면 **수신 측의 ACK 세그먼트** 없이는 데이터를 보낸 측이 재전송 여부를 알 수 없음
- 타임아웃은 "여러 번 중복된 ACK"를 받거나 일정 시간 동안 ACK를 받지 못했을 때 발생

---

## 2️⃣ 흐름 제어 (Flow Control)

### 📌 정의
**수신 호스트**가 보낼 수 있는 **ACK 세그먼트를 수신했을 때** 송신 측이 데이터 전송 속도를 조절하는 메커니즘

### 🎯 언제 쓰는지?
- 송신 호스트가 데이터를 너무 빠르게 보내면 수신 호스트의 **버퍼 오버플로우** 발생 가능
- 수신 측의 처리 능력에 맞춰 송신 속도를 조절하기 위해 사용

### 💡 실무에서 자주 등장하는 패턴
수신 측 ACK 세그먼트를 통해 **윈도우 크기(수신 가능한 데이터 양)**를 송신 측에 알림

---

## 3️⃣ ARQ 기법 (Automatic Repeat Request)

### 📌 정의
오류 상황에서 **세그먼트를 재전송하는 방식**을 정의한 것. 수신 호스트의 답변(ACK)에 따라 발생하는 방식으로 문제를 감지하고 재전송

### 🔢 ARQ의 종류

#### 1) Stop-and-Wait ARQ
- **동작 방식**: 송신 호스트가 한 번에 하나의 세그먼트만 보내고, ACK를 받을 때까지 대기
- **언제 쓰는지**: 가장 단순한 방식이지만 **효율이 낮음** (매번 ACK 대기)
- **헷갈리는 포인트**: n+1번 세그먼트 보내기 전에 n번 ACK가 반드시 와야 함

#### 2) Go-Back-N ARQ
- **동작 방식**:
    - 파이프라이닝 방식으로 여러 세그먼트를 전송
    - 도중에 잘못된 세그먼트 발견 시 **그 지점부터 다시 전송**
    - 송신 호스트는 n+2번 세그먼트까지 보낼 수 있음 (수신 측 윈도우는 1)
- **언제 쓰는지**: Stop-and-Wait보다 효율적이지만, 불필요한 재전송 발생 가능
- **헷갈리는 포인트**:
    - 수신 측은 **순서대로만** 받음 (비순서적 세그먼트는 폐기)
    - ACK 세그먼트는 누적 확인(Cumulative Acknowledgment) 방식

#### 3) Selective Repeat ARQ
- **동작 방식**:
    - 오류가 발생한 **그 세그먼트만** 재전송
    - Go-Back-N ARQ와 달리 수신 측도 **윈도우를 가짐**
    - 비순서적으로 도착한 세그먼트도 버퍼에 저장
- **언제 쓰는지**: **가장 효율적**이지만 구현이 복잡
- **실무 포인트**:
    - TCP는 이 방식을 파이프라이닝하여 사용
    - Go-Back-N ARQ와 Selective Repeat ARQ를 조합한 방식 사용

### ⚠️ 자주 헷갈리는 포인트
- **빠른 재전송(Fast Retransmit)**: 타임아웃을 기다리지 않고 중복된 ACK 3개를 받으면 즉시 재전송
- **SACK(Selective ACK)**: 선택적 재전송을 위한 옵션

---

## 4️⃣ 슬라이딩 윈도우 (Sliding Window)

### 📌 정의
송신 호스트에서 **데이터를 보낼 수 있는 범위**를 윈도우라고 하며, ACK 수신에 따라 이 윈도우가 이동하는 것

### 🎯 언제 쓰는지?
- 흐름 제어를 위해 **수신 측이 처리 가능한 양**만큼만 전송
- 슬라이딩 윈도우는 **송신 윈도우**와 **수신 윈도우**로 구분

### 💡 실무 패턴
예를 들어 송신 호스트가 보낸 데이터의 ACK 세그먼트를 받으면:
- 수신 윈도우가 그만큼 비워지고
- 송신 호스트는 다음 세그먼트를 보낼 수 있는 양이 증가

### ⚠️ 헷갈리는 포인트
- **04-2에서 TCP 세그먼트 구조를 학습할 때**: 윈도우 필드는 수신 호스트의 수신 윈도우 크기를 송신 호스트에게 알리기 위한 것
- 송신 호스트는 이 정보를 바탕으로 **송신 윈도우 크기를 조절**

---

## 5️⃣ 혼잡 제어 (Congestion Control)

### 📌 정의
**네트워크의 혼잡도**에 따라 송신 속도를 조절하는 메커니즘

### 🔍 흐름 제어 vs 혼잡 제어
| 구분 | 흐름 제어 | 혼잡 제어 |
|------|----------|----------|
| **목적** | 수신 호스트 보호 | 네트워크 전체 보호 |
| **조절 대상** | 수신 윈도우 | 혼잡 윈도우(cwnd) |
| **알고리즘** | ACK 기반 | AIMD, 느린 시작, 빠른 회복 등 |

### 🎯 언제 쓰는지?
- 송신 호스트가 수신 호스트는 감당할 수 있지만, **네트워크 전체가 감당할 수 없는 경우**
- 라우터에서 패킷 손실이 발생할 때

### 💡 혼잡 제어의 핵심 개념
**혼잡 윈도우(Congestion Window, cwnd)**
- TCP 세그먼트를 수신하는 호스트는 **제한 없음**
- 흐름 제어는 수신 윈도우, 혼잡 제어는 **혼잡 윈도우**를 통해 조절
- 최종 윈도우 = `min(수신 윈도우, 혼잡 윈도우)`

---

## 6️⃣ 혼잡 제어 알고리즘

### 🚀 느린 시작 (Slow Start)

#### 동작 방식
1. 처음에는 혼잡 윈도우 크기를 **1 MSS**(Maximum Segment Size)로 시작
2. ACK를 받을 때마다 **지수적으로 증가** (1 → 2 → 4 → 8 → ...)
3. **임계치(ssthresh)**에 도달하면 혼잡 회피로 전환

#### 언제 쓰는지
- TCP 연결 초기
- 타임아웃 발생 후

#### 헷갈리는 포인트
- "느린 시작"이라는 이름과 달리 **지수적 증가**로 빠르게 증가함
- 느린 시작 임계치는 타임아웃 발생 시 **현재 윈도우 크기의 절반**으로 설정

---

### 📈 AIMD (Additive Increase/Multiplicative Decrease)

#### 동작 방식
- **Additive Increase**: ACK 수신 시 윈도우 크기를 **1씩 증가** (선형 증가)
- **Multiplicative Decrease**: 혼잡 감지 시 윈도우 크기를 **절반으로 감소**

#### 언제 쓰는지
혼잡 회피 단계에서 사용. 느린 시작 임계치 이후 **보수적으로 증가**

#### 실무 포인트
- RTT(Round Trip Time) 마다 1 MSS씩 증가하므로, 느린 시작보다 완만한 증가

---

### 🔄 혼잡 회피 (Congestion Avoidance)

#### 동작 방식
- 느린 시작 임계치에 도달하면 **선형 증가**(AIMD의 Additive Increase)
- 타임아웃 발생 시:
    - ssthresh = 현재 윈도우 크기 / 2
    - cwnd = 1 MSS로 리셋
    - 느린 시작으로 다시 시작

#### 헷갈리는 포인트
- 타임아웃 vs 중복 ACK에 따른 처리가 다름
- **타임아웃**: 심각한 혼잡 → 느린 시작으로 리셋
- **중복 ACK 3개**: 가벼운 혼잡 → 빠른 회복

---

### ⚡ 빠른 회복 (Fast Recovery)

#### 동작 방식
1. **중복 ACK 3개** 수신 시 발동
2. ssthresh = cwnd / 2
3. cwnd = ssthresh (타임아웃처럼 1로 리셋하지 않음!)
4. 혼잡 회피 단계로 진입

#### 언제 쓰는지
- 빠른 재전송 이후
- 타임아웃보다 **가벼운 혼잡**으로 간주

#### 실무 포인트
현대 TCP(Reno 이후)는 중복 ACK 발생 시 느린 시작을 거치지 않고 바로 빠른 회복 사용

---

## 7️⃣ ECN (Explicit Congestion Notification)

### 📌 정의
**라우터가 혼잡 상태를 명시적으로 알려주는 기법**

### 🎯 동작 방식
1. 송신 호스트가 B에게 패킷 전송 시 ECN 비트를 설정
2. 라우터가 혼잡하면 IP 헤더의 **ECN 비트를 설정**하여 수신 호스트에 전달
3. 수신 호스트 B가 경험한 혼잡 정보를 송신 호스트 A에게 **TCP ACK 세그먼트**의 ECE 비트로 통보
4. 송신 호스트가 혼잡임을 인지하고 ECE 비트로 설정된 값을 감지 → 송신 호스트는 **CWR 비트**로 혼잡 윈도우를 줄였음을 알림

### 💡 언제 쓰는지
- 패킷 손실 전에 **사전에 혼잡을 감지**
- 중복 ACK 세그먼트를 통해 더 빠르게 혼잡을 감지하고, ACK 세그먼트를 통해 수신 호스트의 ACK로 혼잡임을 알림

### ⚠️ 헷갈리는 포인트
- ECN은 **선택적 기능**이므로 모든 호스트와 라우터가 지원하지 않을 수 있음
- ECN 지원 여부는 **TCP/IP 프로토콜** 설정에서 확인

## 8️⃣ 핵심 요약본

### ✅ 주요 개념 정리

| 개념 | 핵심 포인트 |
|------|-----------|
| **오류 검출 & 재전송** | 체크섬 필드로 오류 검출, 중복 ACK/타임아웃 시 재전송 |
| **흐름 제어** | 수신 호스트 보호 목적, ACK 윈도우 크기로 조절 |
| **Stop-and-Wait ARQ** | 한 번에 하나씩, 비효율적 |
| **Go-Back-N ARQ** | 오류 지점부터 전부 재전송, 수신 윈도우=1 |
| **Selective Repeat ARQ** | 오류 세그먼트만 재전송, 가장 효율적 |
| **슬라이딩 윈도우** | 송신 가능 범위, ACK에 따라 이동 |
| **혼잡 제어** | 네트워크 전체 보호 목적, cwnd 조절 |
| **느린 시작** | 1 MSS부터 지수 증가, 임계치까지 |
| **AIMD** | 선형 증가 + 절반 감소 |
| **혼잡 회피** | ssthresh 이후 선형 증가 |
| **빠른 회복** | 중복 ACK 3개 → cwnd=ssthresh, 리셋 안함 |
| **ECN** | 라우터가 혼잡 명시적 통보, 사전 감지 |

### 🎯 타임아웃 vs 중복 ACK 비교

| 상황 | ssthresh | cwnd | 다음 단계 |
|------|----------|------|----------|
| **타임아웃** | cwnd / 2 | 1 MSS | 느린 시작 |
| **중복 ACK 3개** | cwnd / 2 | ssthresh | 빠른 회복 → 혼잡 회피 |

### 💡 윈도우 크기 결정
```
최종 송신 윈도우 = min(수신 윈도우, 혼잡 윈도우)
```

## 9️⃣ 복습용 객관식 퀴즈

### Q1. TCP의 흐름 제어와 혼잡 제어에 대한 설명으로 **틀린** 것은?
1. 흐름 제어는 수신 호스트의 버퍼 오버플로우를 방지하기 위해 사용된다
2. 혼잡 제어는 네트워크의 혼잡도에 따라 송신 속도를 조절한다
3. 송신 윈도우 크기는 항상 수신 윈도우 크기와 동일하다
4. 혼잡 윈도우(cwnd)는 혼잡 제어에서 사용되는 개념이다

**정답: 3번**  
해설: 송신 윈도우 크기는 `min(수신 윈도우, 혼잡 윈도우)`로 결정됩니다. 두 값 중 작은 값을 따르므로 항상 동일하지 않습니다.

---

### Q2. Go-Back-N ARQ와 Selective Repeat ARQ에 대한 설명으로 옳은 것은?
1. Go-Back-N ARQ는 오류가 발생한 세그먼트만 재전송한다
2. Selective Repeat ARQ는 수신 윈도우 크기가 1이다
3. Go-Back-N ARQ는 비순서적으로 도착한 세그먼트를 버퍼에 저장한다
4. Selective Repeat ARQ는 오류가 발생한 세그먼트만 선택적으로 재전송한다

**정답: 4번**  
해설: Selective Repeat ARQ는 오류가 발생한 세그먼트만 재전송하여 가장 효율적입니다. Go-Back-N ARQ는 오류 지점부터 이후 모든 세그먼트를 재전송하며, 수신 윈도우 크기가 1입니다.

---

### Q3. 느린 시작(Slow Start) 알고리즘에 대한 설명으로 **틀린** 것은?
1. 초기 혼잡 윈도우 크기는 1 MSS이다
2. ACK를 받을 때마다 선형적으로 증가한다
3. 임계치(ssthresh)에 도달하면 혼잡 회피로 전환된다
4. 타임아웃 발생 후 다시 느린 시작부터 시작한다

**정답: 2번**  
해설: 느린 시작은 ACK를 받을 때마다 **지수적으로 증가**합니다(1→2→4→8...). 선형 증가는 혼잡 회피 단계에서 사용됩니다.

---

### Q4. 다음 중 타임아웃 발생 시 TCP의 동작으로 옳은 것은?
1. ssthresh = cwnd / 2, cwnd = ssthresh
2. ssthresh = cwnd / 2, cwnd = 1 MSS
3. ssthresh = 변경 없음, cwnd = 1 MSS
4. ssthresh = 1 MSS, cwnd = cwnd / 2

**정답: 2번**  
해설: 타임아웃은 심각한 혼잡으로 간주하여 ssthresh는 현재 cwnd의 절반으로 설정하고, cwnd는 1 MSS로 리셋한 후 느린 시작부터 다시 시작합니다.

---

### Q5. ECN(Explicit Congestion Notification)에 대한 설명으로 옳은 것은?
1. ECN은 송신 호스트가 혼잡을 감지하는 기법이다
2. ECN은 라우터가 혼잡 상태를 명시적으로 알려주는 기법이다
3. ECN은 모든 TCP 연결에서 필수적으로 사용된다
4. ECN은 타임아웃 발생 후에만 동작한다

**정답: 2번**  
해설: ECN은 라우터가 IP 헤더의 ECN 비트를 설정하여 혼잡 상태를 명시적으로 알려주는 기법입니다. 선택적 기능이므로 모든 연결에서 필수는 아닙니다.
