# 📚 네트워크 기초 - 스위치, VLAN, IP 프로토콜 복습자료

## 🔌 02-4. 스위치 (Switch)

### 스위치란?

스위치는 **데이터 링크 계층의 네트워크 장비**로, L2 스위치라고도 불립니다. 2계층에서 사용되는 하드웨어 주소인 **MAC 주소**를 학습하고 저장하여, 해당 포트로만 프레임을 전달합니다.

> 💡 **핵심**: 스위치는 MAC 주소를 학습해 필요한 포트로만 데이터를 보내므로, 네트워크 효율성이 높아집니다.

### 스위치의 특징

- **L3 스위치**: 데이터 링크 계층 상위 계층에서 사용되는 L3 스위치도 존재 (하지만 L2가 일반적)
- **2계층 주소 = MAC 주소**: 스위치는 MAC 주소 학습을 통해 프레임을 전달
- **포트와 연결**: 스위치의 여러 포트는 호스트의 물리적 LAN을 분리하는 가상의 LAN, **VLAN**을 구성

---

## 📋 MAC 주소 학습

### 언제 필요한가?

스위치가 처음 켜지거나 MAC 주소 테이블이 비어있을 때, 자동으로 학습하여 효율적인 프레임 전달을 위해 필요합니다.

### MAC 주소 학습 과정

1. **플러딩(Flooding)**: 처음에는 모든 포트로 프레임을 전송
2. **필터링(Filtering)**: 학습 후 해당 MAC 주소가 있는 포트로만 전송
3. **에이징(Aging)**: 일정 시간 사용하지 않으면 테이블에서 삭제

```
switch# show mac-address-table
VLAN | MAC Address    | Type      | Age | Port
-----|----------------|-----------|-----|-------
  1  | abcd.abcd.8123 | dynamic   | 10  | Eth1/3
  1  | abcd.abcd.1234 | dynamic   | 200 | Eth1/3
Total MAC Addresses: 2
```

### 주요 포인트

- 🔄 **동적(Dynamic) 학습**: 스위치가 자동으로 MAC 주소를 학습
- 📍 **포트 매핑**: MAC 주소와 포트를 연결하여 테이블에 저장
- ⏱️ **에이징 타임**: 일정 시간 후 사용하지 않으면 자동 삭제

---

## 🏢 VLAN (Virtual LAN)

### VLAN이란?

**물리적으로 다른 층이나 위치에 있어도 가상으로 같은 LAN처럼** 묶을 수 있는 기술입니다.

### 언제 사용하는가?

- 부서별로 네트워크를 논리적으로 분리하고 싶을 때
- 보안을 강화하고 브로드캐스트 도메인을 제한하고 싶을 때
- 물리적 위치와 관계없이 같은 네트워크로 묶고 싶을 때

### VLAN의 종류

**1️⃣ 포트 기반 VLAN (Port-based VLAN)**

- 스위치의 각 포트에 VLAN을 할당하는 방식
- 가장 단순하고 많이 사용되는 방식
- 예: 포트 1-4번은 VLAN1, 5-8번은 VLAN2

**2️⃣ MAC 기반 VLAN**

- 호스트의 MAC 주소에 따라 VLAN을 결정
- 포트가 아닌 장비 자체에 VLAN이 할당됨

**3️⃣ 트렁크 포트 (Trunk Port)**

- 여러 VLAN의 트래픽을 하나의 포트로 전송
- **태그(Tag)**를 붙여서 VLAN을 구분
- 스위치 간 연결이나 라우터 연결에 사용

### 트렁크 포트의 동작

```
[스위치 A] ----트렁크 포트---- [스위치 B]
  VLAN1                         VLAN1
  VLAN2   →  태그 추가/제거  ←  VLAN2
  VLAN3                         VLAN3
```

### 자주 헷갈리는 포인트

- ❌ **VLAN ≠ 물리적 네트워크**: VLAN은 논리적 구분일 뿐, 물리적으로는 같은 스위치에 연결
- ✅ **브로드캐스트 도메인 분리**: 각 VLAN은 독립적인 브로드캐스트 도메인
- ⚠️ **VLAN 간 통신**: 서로 다른 VLAN끼리는 라우터(L3)가 있어야 통신 가능

---

## 🌐 03-1. LAN을 넘어서는 네트워크 계층

### 데이터 링크 계층의 한계

물리 계층과 데이터 링크 계층만으로는 **LAN을 넘어서 다른 지역의 네트워크와 통신 불가**합니다.

> 🚫 **문제점**: MAC 주소는 "개발이 있는가?"라는 정보만 제공하며, "어디에 있는가?"는 알려주지 못합니다.

### 네트워크 계층이 필요한 이유

- 📍 **라우팅**: 여러 네트워크를 거쳐 목적지까지 경로 설정
- 🗺️ **논리적 주소**: IP 주소를 통해 위치 정보 제공
- 🔀 **네트워크 간 연결**: 서로 다른 네트워크를 연결

---

## 🏷️ 인터넷 프로토콜

### IP (Internet Protocol)의 역할

네트워크 계층의 가장 핵심적인 프로토콜로, **주소 지정(Addressing)**과 **단편화(Fragmentation)** 두 가지 기능을 수행합니다.

### IP 주소 체계

#### IPv4 주소 형태

- **32비트(4바이트)** 주소 체계
- **0~255 범위의 10진수** 4개로 표기
- 예: `192.168.1.1`

```
IP 주소 예시:
192.168.1.1

[십진수 표기]     [이진수 표기]
192               11000000
168               10101000
1                 00000001
1                 00000001
```

#### IPv4의 구성 요소

**① 식별자 (Identifier)**

- 패킷의 원본을 식별하는 고유 ID

**② 플래그 (Flag)**

- 단편화 관련 설정
- **DF (Don't Fragment)**: 단편화 금지
- **MF (More Fragment)**: 뒤에 단편화된 패킷이 더 있음

**③ 단편화 오프셋 (Fragment Offset)**

- 단편화된 패킷의 순서 정보

**④ TTL (Time To Live)**

- 패킷의 생존 시간 (홉 수)
- 라우터를 거칠 때마다 1씩 감소
- 0이 되면 패킷 폐기

### 자주 헷갈리는 포인트

- ⚠️ **TTL의 의미**: "시간"이 아니라 **거칠 수 있는 라우터의 개수**
- 🔢 **단편화는 언제?**: MTU(Maximum Transmission Unit)보다 큰 패킷이 있을 때
- 📦 **DF 플래그 설정 시**: 단편화가 필요하면 패킷을 버림 (ICMP 오류 메시지 전송)

---

## 📊 IPv6

### IPv4의 한계

- 주소 고갈 문제 (약 43억 개)
- NAT, 사설 IP 등 임시방편으로 해결

### IPv6의 특징

- **128비트** 주소 체계 (거의 무한대)
- **16진수 8그룹**으로 표기
- 예: `2001:0230:abcd:ffff:0000:0000:ffff:1111`

```
IPv4 주소:         192.168.1.1
IPv6 주소:         2001:0230:abcd:ffff:0000:0000:ffff:1111
```

### IPv6의 개선점

- ✅ **더 많은 주소 공간**: 사실상 무한대
- ✅ **헤더 단순화**: 빠른 처리 속성
- ✅ **보안 강화**: IPsec 기본 내장

---

## 🔍 ARP (Address Resolution Protocol)

### ARP란?

**IP 주소를 MAC 주소로 변환**하는 프로토콜입니다. 네트워크 계층(IP)과 데이터 링크 계층(MAC)을 연결하는 다리 역할을 합니다.

### 언제 필요한가?

- 같은 네트워크 내에서 **IP 주소는 알지만 MAC 주소를 모를 때**
- 스위치가 프레임을 전달하려면 목적지 MAC 주소가 필요
- IP 통신을 위해서는 반드시 필요

### ARP 동작 과정

**1️⃣ ARP 요청 (ARP Request)**

```
호스트 A: "IP 10.0.0.2의 MAC 주소가 뭐지?"
→ 브로드캐스트로 모든 호스트에게 전송
```

**2️⃣ ARP 응답 (ARP Reply)**

```
호스트 B: "10.0.0.2는 나야! 내 MAC 주소는 aa:bb:cc:dd:ee:ff"
→ 유니캐스트로 호스트 A에게만 전송
```

**3️⃣ ARP 테이블 갱신**

```
호스트 A의 ARP 테이블:
IP 주소      | MAC 주소
-------------|------------------
10.0.0.2     | aa:bb:cc:dd:ee:ff
```

### ARP 테이블 확인 (실습)

```bash
# Windows/Linux/macOS
$ arp -a

? (192.168.0.2) at 1a:2b:3c:4d:5e:6e on en6 [ethernet]
? (192.168.0.1) at 1b:2c:3d:4d:5e:6e on en0 ifscope [ethernet]
```

### 자주 헷갈리는 포인트

- ❌ **ARP는 라우터를 넘지 못함**: 같은 네트워크(서브넷) 내에서만 동작
- ⚠️ **ARP 캐시 타임**: 일정 시간이 지나면 테이블에서 삭제되어 다시 요청
- 🔒 **ARP 스푸핑 공격**: 악의적으로 잘못된 MAC 주소를 알려줄 수 있음

---

## 🛣️ IP 단편화를 피하는 방법

### 문제점

IP 패킷이 **MTU(Maximum Transmission Unit)**보다 크면 단편화가 발생하여 성능 저하가 일어납니다.

### MTU란?

- 한 번에 전송할 수 있는 **최대 패킷 크기**
- 일반적인 이더넷: **1500바이트**

### 해결 방법

**1️⃣ 경로 MTU 발견 (Path MTU Discovery)**

```
[호스트 A] → 작은 MTU 발견 → [라우터] → [호스트 B]
            DF 플래그 설정
            ICMP 오류 메시지 수신
            → 패킷 크기 조절
```

- **DF(Don't Fragment) 플래그 설정**: 단편화 금지
- MTU가 작은 구간을 발견하면 패킷 크기를 줄여서 재전송
- **134쪽의 설명**: 로부터 처리 불가능 크기임을 알고 MTU 크기를 넘어선 IP 패킷을 전달받았는데, DF 플래그가 설정되어 있다면 IP 패킷을 전달한 호스트에게 "DF 플래그가 설정되어 있는데 이걸 단편화 없이 처리할 수 없습니다"라는 특정 오류 메시지를 전달

**2️⃣ 적절한 패킷 크기 사용**

- 애플리케이션 레벨에서 데이터 크기를 적절히 분할

## 📝 최종 핵심 요약

### 🔌 스위치

- MAC 주소를 학습하여 해당 포트로만 전달
- 플러딩 → 필터링 → 에이징 과정으로 동작

### 🏢 VLAN

- 물리적 위치와 무관하게 논리적으로 네트워크 분리
- 포트 기반 VLAN이 가장 일반적
- VLAN 간 통신은 라우터(L3) 필요

### 🌐 IP 프로토콜

- IPv4: 32비트 주소 (192.168.1.1)
- IPv6: 128비트 주소 (거의 무한대)
- 주소 지정 + 단편화 기능

### 🔍 ARP

- IP 주소 → MAC 주소 변환
- ARP 요청(브로드캐스트) → ARP 응답(유니캐스트)
- 같은 네트워크 내에서만 동작

### 📦 IP 단편화

- MTU보다 큰 패킷은 단편화 필요
- DF 플래그로 단편화 금지 가능
- 경로 MTU 발견으로 단편화 방지

## ❓ 복습용 퀴즈

### Q1. 스위치가 MAC 주소를 학습하는 과정으로 올바른 순서는?

A) 플러딩 → 필터링 → 에이징  
B) 필터링 → 플러딩 → 에이징  
C) 에이징 → 플러딩 → 필터링  
D) 플러딩 → 에이징 → 필터링

**정답: A) 플러딩 → 필터링 → 에이징**

해설: 스위치는 처음에 MAC 주소 테이블이 비어있을 때 모든 포트로 프레임을 전송(플러딩)합니다. 그 후 MAC 주소를 학습하여 해당 포트로만 전송(필터링)하고, 일정 시간 사용하지 않으면 테이블에서 삭제(에이징)합니다.

### Q2. VLAN에 대한 설명으로 틀린 것은?

A) 물리적으로 다른 위치에 있어도 같은 LAN처럼 묶을 수 있다  
B) 서로 다른 VLAN끼리는 스위치만으로도 통신이 가능하다  
C) 포트 기반 VLAN이 가장 일반적으로 사용된다  
D) 브로드캐스트 도메인을 분리할 수 있다

**정답: B) 서로 다른 VLAN끼리는 스위치만으로도 통신이 가능하다**

해설: 서로 다른 VLAN은 독립적인 브로드캐스트 도메인이므로, VLAN 간 통신을 위해서는 L3 장비인 라우터가 필요합니다. 스위치(L2)만으로는 불가능합니다.

### Q3. ARP 프로토콜의 역할로 가장 적절한 것은?

A) MAC 주소를 IP 주소로 변환한다  
B) IP 주소를 MAC 주소로 변환한다  
C) IP 주소를 도메인 이름으로 변환한다  
D) MAC 주소를 도메인 이름으로 변환한다

**정답: B) IP 주소를 MAC 주소로 변환한다**

해설: ARP(Address Resolution Protocol)는 네트워크 계층의 IP 주소를 데이터 링크 계층의 MAC 주소로 변환하는 프로토콜입니다. 이를 통해 같은 네트워크 내에서 실제 물리적 주소로 프레임을 전달할 수 있습니다.

### Q4. IPv4 패킷 헤더의 TTL 필드에 대한 설명으로 올바른 것은?

A) 패킷이 생성된 후 경과한 시간을 나타낸다  
B) 패킷이 거칠 수 있는 라우터의 최대 개수를 나타낸다  
C) 패킷의 우선순위를 나타낸다  
D) 패킷의 크기를 나타낸다

**정답: B) 패킷이 거칠 수 있는 라우터의 최대 개수를 나타낸다**

해설: TTL(Time To Live)은 이름과 달리 "시간"이 아니라 패킷이 거칠 수 있는 라우터(홉)의 개수를 의미합니다. 라우터를 거칠 때마다 1씩 감소하며, 0이 되면 패킷이 폐기되어 무한 루프를 방지합니다.

### Q5. IP 단편화와 관련된 설명으로 틀린 것은?

A) MTU보다 큰 패킷은 단편화가 필요하다  
B) DF 플래그가 설정되면 단편화가 금지된다  
C) 단편화된 패킷은 목적지에서만 재조립된다  
D) 모든 라우터는 자동으로 단편화를 수행한다  
E) 단편화 오프셋은 단편화된 패킷의 순서를 나타낸다

**정답: D) 모든 라우터는 자동으로 단편화를 수행한다**

해설: DF(Don't Fragment) 플래그가 설정된 경우, 라우터는 단편화를 수행하지 않고 ICMP 오류 메시지를 전송합니다. 이는 경로 MTU 발견(Path MTU Discovery) 메커니즘에 사용되며, 호스트가 적절한 패킷 크기를 스스로 조절하도록 합니다.
