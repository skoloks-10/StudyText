# 컴퓨터 네트워크 기초

## 01-1. 컴퓨터 네트워크를 알아야 하는 이유

### 네트워크란 무엇인가

컴퓨터 네트워크(Computer Network)는 여러 장치들이 통신 기술을 활용하여 서로 연결된 통신망을 의미합니다. 이를 통해 물리적으로 떨어져 있는 장치들도 정보를 주고받을 수 있습니다.

**핵심 개념**

- 네트워크는 '노드(Node)'와 '링크(Link)'로 구성됩니다
- 노드: 데이터를 송수신할 수 있는 장치 (컴퓨터, 스마트폰, 서버 등)
- 링크: 노드들을 연결하는 통신 경로 (유선/무선)

### 프로그램 관점에서의 네트워크

개발자가 네트워크를 이해해야 하는 이유는 현대의 대부분의 프로그램이 네트워크를 통해 데이터를 주고받기 때문입니다.

**주요 프로토콜 계층**

1. **응용 계층 프로토콜**: HTTP, HTTPS, DNS 등
2. **전송 계층 프로토콜**: TCP/IP, UDP
3. **네트워크 계층**: IP 주소 기반 라우팅

**Python에서의 HTTP 통신 예시**

```python
import http.cookies

# HTTP 쿠키를 통한 상태 관리
cookies = http.cookies.SimpleCookie()
cookies['session_id'] = 'abc123'
cookies['user_name'] = 'developer'

print(cookies.output())
# 출력: Set-Cookie: session_id=abc123
#       Set-Cookie: user_name=developer

```

**사용 상황**: 웹 애플리케이션에서 사용자의 로그인 상태를 유지하거나, API 요청 시 인증 토큰을 전달할 때 사용합니다.

**HTTP 상태 코드 처리 예시**

```python
import requests

try:
    response = requests.get('https://api.example.com/data')

    if response.status_code == 200:
        data = response.json()
        print("데이터 수신 성공:", data)
    elif response.status_code == 404:
        print("리소스를 찾을 수 없습니다")
    else:
        print(f"오류 발생: {response.status_code}")

except requests.exceptions.ConnectionError:
    print("네트워크 연결 오류")

```

**사용 상황**: REST API와 통신할 때 서버의 응답 상태를 확인하고 적절한 오류 처리를 수행해야 합니다.

### 프로토콜의 역할

프로토콜(Protocol)은 네트워크에서 데이터를 주고받기 위한 규칙과 약속입니다.

**주요 프로토콜**

- **HTTP/HTTPS**: 웹 페이지 전송
- **TCP/UDP**: 신뢰성 있는/빠른 데이터 전송
- **IP**: 네트워크 주소 지정
- **DNS**: 도메인 이름을 IP 주소로 변환

**Spring 프레임워크의 TCP/UDP 지원 예시 (개념)**

```
Spring Integration provides Channel Adapters for receiving and sending messages over internet protocols.
Both UDP (User Datagram Protocol) and TCP (Transmission Control Protocol) adapters are provided.
Each adapter provides for one-way communication over the underlying protocol.

```

이는 Spring 프레임워크가 TCP와 UDP 프로토콜을 모두 지원하여, 개발자가 필요에 따라 신뢰성(TCP) 또는 속도(UDP)를 선택할 수 있음을 보여줍니다.

## 01-2. 네트워크 거시적으로 살펴보기

### 네트워크의 기본 구조

네트워크는 다양한 장치와 연결 방식으로 구성됩니다.

**네트워크 구성 요소**

1. **엔드 시스템 (End System)**: 최종 사용자의 장치 (PC, 스마트폰 등)
2. **라우터 (Router)**: 네트워크 간 데이터 경로를 결정
3. **스위치 (Switch)**: 같은 네트워크 내에서 데이터 전달

### 호스트 (Host)

호스트는 네트워크에 연결된 컴퓨터나 장치를 의미합니다.

**호스트의 종류**

- **노드(Node)**: 네트워크 상의 모든 장치
- **호스트(Host)**: 데이터를 송수신하는 엔드포인트 장치
- **서버**: 서비스를 제공하는 호스트
- **클라이언트**: 서비스를 요청하는 호스트

**JavaScript에서의 호스트 식별**

```jsx
// 브라우저에서 현재 호스트 정보 확인
const hostname = window.location.hostname;
const port = window.location.port;
const protocol = window.location.protocol;

console.log(`${protocol}//${hostname}:${port}`);
// 출력 예: https://www.example.com:443
```

**사용 상황**: 웹 애플리케이션에서 현재 접속한 서버의 정보를 확인하거나, API 엔드포인트를 동적으로 구성할 때 사용합니다.

### 네트워크 장비

### 서버 (Server)

서버는 클라이언트의 요청에 응답하여 서비스를 제공하는 호스트입니다.

**서버의 특징**

- 24시간 가동
- 높은 안정성과 성능
- 여러 클라이언트 동시 처리

### 클라이언트 (Client)

클라이언트는 서버에 서비스를 요청하는 호스트입니다.

**클라이언트-서버 통신 예시**

```jsx
// Fetch API를 사용한 서버 요청
async function fetchUserData(userId) {
  try {
    const response = await fetch(`https://api.example.com/users/${userId}`, {
      method: "GET",
      headers: {
        "Content-Type": "application/json",
        Authorization: "Bearer your-token-here",
      },
    });

    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }

    const userData = await response.json();
    return userData;
  } catch (error) {
    console.error("데이터 가져오기 실패:", error);
    throw error;
  }
}

// 사용 예시
fetchUserData(123)
  .then((user) => console.log("사용자 정보:", user))
  .catch((err) => console.error("오류:", err));
```

**사용 상황**: 웹 애플리케이션에서 서버의 데이터를 가져오거나, RESTful API를 호출할 때 사용합니다.

### 메시지 (Message)

메시지는 네트워크를 통해 전송되는 데이터 단위입니다.

**메시지 전송 과정**

1. 클라이언트가 요청 메시지 생성
2. 네트워크를 통해 서버로 전송
3. 서버가 요청 처리
4. 서버가 응답 메시지 생성
5. 클라이언트가 응답 수신

**HTTP 메시지 구조 예시**

```jsx
// HTTP 요청 메시지 생성
const requestMessage = {
  method: "POST",
  url: "/api/data",
  headers: {
    "Content-Type": "application/json",
    Accept: "application/json",
  },
  body: JSON.stringify({
    name: "example",
    value: 100,
  }),
};

// Fetch API로 전송
fetch(requestMessage.url, {
  method: requestMessage.method,
  headers: requestMessage.headers,
  body: requestMessage.body,
})
  .then((response) => response.json())
  .then((data) => console.log("응답:", data));
```

**사용 상황**: RESTful API에 데이터를 전송하거나, 웹 폼 제출 시 사용합니다.

### 통신 매체

네트워크 장비들을 연결하는 물리적 또는 무선 매체입니다.

**통신 매체의 종류**

## 법위에 따른 네트워크 분류

### LAN (Local Area Network)

**정의**: 가정, 사무실 등 제한된 지역 내의 네트워크

**LAN의 특징**

- 빠른 전송 속도
- 낮은 지연 시간
- 사설 IP 주소 사용
- 물리적으로 가까운 거리

**LAN 구성 예시**

```
가정 내 LAN:
- 공유기(라우터) 1대
- 컴퓨터 A, B, C
- 스마트폰 D, E, F

각 장치는 같은 네트워크(예: 192.168.0.x)에 속함

```

**JavaScript에서 로컬 네트워크 확인**

```jsx
// 브라우저에서 네트워크 정보 확인 (일부 제한됨)
function checkNetworkType() {
  if ("connection" in navigator) {
    const connection =
      navigator.connection ||
      navigator.mozConnection ||
      navigator.webkitConnection;

    console.log("연결 타입:", connection.effectiveType);
    console.log("다운링크 속도:", connection.downlink + " Mbps");

    // LAN 환경에서는 일반적으로 높은 속도
    if (connection.downlink > 10) {
      console.log("고속 연결 (LAN 가능성 높음)");
    }
  }
}

checkNetworkType();
```

**사용 상황**: 네트워크 품질에 따라 콘텐츠 품질을 조정하거나, 오프라인 기능을 제공할 때 사용합니다.

### WAN (Wide Area Network)

**정의**: 지리적으로 넓은 범위를 연결하는 네트워크

**WAN의 특징**

- LAN들을 상호 연결
- 인터넷이 대표적인 WAN
- ISP(Internet Service Provider)를 통해 연결
- 공인 IP 주소 사용

**CAN과 MAN (중간 규모 네트워크)**

- **CAN (Campus Area Network)**: 대학 캠퍼스 등 여러 건물을 연결
- **MAN (Metropolitan Area Network)**: 도시 규모의 네트워크

### 메시지 교환 방식에 따른 네트워크 분류

### 회선 교환 방식 (Circuit Switching)

**정의**: 통신 전에 미리 전용 회선을 설정하여 데이터를 전송하는 방식

**회선 교환의 특징**

- 안정적인 전송
- 실시간 통신에 적합
- 예: 전화 통신

**개념적 흐름**

```
1. 연결 설정 (A → 중간 노드들 → B)
2. 데이터 전송 (전용 경로 사용)
3. 연결 해제

```

### 패킷 교환 방식 (Packet Switching)

**정의**: 데이터를 작은 패킷으로 나누어 전송하는 방식

**패킷 교환의 특징**

- 효율적인 대역폭 사용
- 인터넷에서 사용
- 경로가 동적으로 변경 가능

**패킷 구조 시뮬레이션**

```jsx
// 패킷 데이터 구조 예시
class Packet {
  constructor(data, sequenceNumber, sourceIP, destIP) {
    this.header = {
      sourceIP: sourceIP,
      destinationIP: destIP,
      sequenceNumber: sequenceNumber,
      timestamp: Date.now(),
      checksum: this.calculateChecksum(data),
    };
    this.payload = data;
  }

  calculateChecksum(data) {
    // 간단한 체크섬 계산 (실제로는 더 복잡)
    return data.split("").reduce((sum, char) => sum + char.charCodeAt(0), 0);
  }

  toJSON() {
    return {
      header: this.header,
      payload: this.payload,
    };
  }
}

// 사용 예시
const message = "Hello, Network!";
const maxPacketSize = 5;
const packets = [];

for (let i = 0; i < message.length; i += maxPacketSize) {
  const chunk = message.slice(i, i + maxPacketSize);
  const packet = new Packet(
    chunk,
    i / maxPacketSize,
    "192.168.1.100",
    "192.168.1.200"
  );
  packets.push(packet);
}

console.log(
  "전송할 패킷들:",
  packets.map((p) => p.toJSON())
);
```

**사용 상황**: 대용량 파일 전송 시 데이터를 작은 조각으로 나누어 전송하거나, 네트워크 프로토콜을 학습할 때 사용합니다.

**패킷 라우팅 개념**

```jsx
// 패킷이 여러 경로를 통해 전달되는 시뮬레이션
class Router {
  constructor(name) {
    this.name = name;
    this.routingTable = new Map();
  }

  addRoute(destination, nextHop) {
    this.routingTable.set(destination, nextHop);
  }

  forward(packet) {
    const nextHop = this.routingTable.get(packet.header.destinationIP);

    if (nextHop) {
      console.log(
        `${this.name}: 패킷 ${packet.header.sequenceNumber}번을 ${nextHop}로 전달`
      );
      return nextHop;
    } else {
      console.log(`${this.name}: 목적지를 찾을 수 없음`);
      return null;
    }
  }
}

// 라우터 네트워크 구성
const routerA = new Router("Router A");
const routerB = new Router("Router B");
const routerC = new Router("Router C");

routerA.addRoute("192.168.1.200", "Router B");
routerB.addRoute("192.168.1.200", "Router C");
routerC.addRoute("192.168.1.200", "Destination");

// 패킷 전달 시뮬레이션
const testPacket = new Packet("Data", 0, "192.168.1.100", "192.168.1.200");
routerA.forward(testPacket);
```

**사용 상황**: 네트워크 라우팅 알고리즘을 이해하거나, 패킷이 어떻게 목적지까지 도달하는지 학습할 때 사용합니다.

## 주소와 송수신지 유형에 따른 전송 방식

### 주소 (Address)

**정의**: 송수신자를 특정할 수 있는 정보

네트워크에서 장치를 식별하기 위해 사용되는 고유한 값입니다. 패킷이 올바른 목적지로 전달되기 위해 반드시 필요합니다.

**주요 주소 유형**

- **IP 주소**: 네트워크 계층에서 사용 (예: 192.168.0.1)
- **MAC 주소**: 데이터 링크 계층에서 사용 (예: AA:BB:CC:DD:EE:FF)

**IP 주소와 MAC 주소는 각각 3장과 2장에서 더 자세히 학습합니다.**

### 전송 방식의 종류

### 유니캐스트 (Unicast)

**정의**: 일대일 통신 방식으로, 송신자와 수신자가 일대일로 메시지를 주고받는 방식

**유니캐스트의 특징**

- 가장 일반적인 통신 방식
- 특정 호스트에게만 전송
- 효율적인 대역폭 사용

**JavaScript에서의 유니캐스트 통신 예시**

```jsx
// WebSocket을 사용한 일대일 통신
class UnicastClient {
  constructor(serverUrl) {
    this.ws = new WebSocket(serverUrl);
    this.setupEventListeners();
  }

  setupEventListeners() {
    this.ws.onopen = () => {
      console.log("서버와 연결됨 (유니캐스트)");
    };

    this.ws.onmessage = (event) => {
      console.log("서버로부터 메시지 수신:", event.data);
    };

    this.ws.onerror = (error) => {
      console.error("통신 오류:", error);
    };
  }

  sendMessage(message) {
    if (this.ws.readyState === WebSocket.OPEN) {
      this.ws.send(
        JSON.stringify({
          type: "unicast",
          recipient: "specific-user-id",
          message: message,
        })
      );
    }
  }
}

// 사용 예시
const client = new UnicastClient("ws://example.com/socket");
client.sendMessage("Hello, specific user!");
```

**사용 상황**: 일반적인 웹 요청, 이메일 전송, 개인 메시지 전송 등에 사용됩니다.

### 브로드캐스트 (Broadcast)

**정의**: 같은 네트워크 상의 모든 호스트에게 전송하는 방식

**브로드캐스트의 특징**

- 네트워크의 모든 장치가 수신
- 브로드캐스트 도메인 내에서만 전송
- 주로 ARP, DHCP 등에서 사용

**브로드캐스트 시뮬레이션**

```jsx
// 로컬 네트워크에서 브로드캐스트 개념 시뮬레이션
class BroadcastNetwork {
  constructor() {
    this.hosts = [];
  }

  addHost(host) {
    this.hosts.push(host);
    console.log(`호스트 ${host.name} 네트워크 참가`);
  }

  broadcast(senderName, message) {
    console.log(`\n${senderName}이(가) 브로드캐스트 전송: "${message}"`);

    this.hosts.forEach((host) => {
      if (host.name !== senderName) {
        host.receive(senderName, message);
      }
    });
  }
}

class Host {
  constructor(name, ipAddress) {
    this.name = name;
    this.ipAddress = ipAddress;
  }

  receive(sender, message) {
    console.log(`  → ${this.name} (${this.ipAddress}) 수신: "${message}"`);
  }

  sendBroadcast(network, message) {
    network.broadcast(this.name, message);
  }
}

// 사용 예시
const network = new BroadcastNetwork();

const hostA = new Host("Computer A", "192.168.1.10");
const hostB = new Host("Computer B", "192.168.1.20");
const hostC = new Host("Computer C", "192.168.1.30");

network.addHost(hostA);
network.addHost(hostB);
network.addHost(hostC);

hostA.sendBroadcast(network, "Who has 192.168.1.20? Tell 192.168.1.10");
```

**사용 상황**: ARP 요청(MAC 주소 찾기), DHCP 요청(IP 주소 할당), 네트워크 서비스 발견 등에 사용됩니다.

### 멀티캐스트 (Multicast)

**정의**: 특정 그룹에 속한 호스트들에게만 전송하는 방식

**멀티캐스트의 특징**

- 그룹에 속한 호스트만 수신
- 효율적인 대역폭 사용
- 스트리밍, 화상회의 등에 적합

**멀티캐스트 그룹 관리 예시**

```jsx
// 멀티캐스트 그룹 시뮬레이션
class MulticastGroup {
  constructor(groupAddress) {
    this.groupAddress = groupAddress;
    this.members = new Set();
  }

  join(host) {
    this.members.add(host);
    console.log(`${host.name}이(가) 그룹 ${this.groupAddress}에 참가`);
  }

  leave(host) {
    this.members.delete(host);
    console.log(`${host.name}이(가) 그룹 ${this.groupAddress}에서 탈퇴`);
  }

  multicast(sender, message) {
    console.log(
      `\n${sender}이(가) 그룹 ${this.groupAddress}로 멀티캐스트: "${message}"`
    );

    this.members.forEach((member) => {
      member.receive(sender, message, this.groupAddress);
    });
  }
}

class MulticastHost {
  constructor(name, ipAddress) {
    this.name = name;
    this.ipAddress = ipAddress;
    this.groups = [];
  }

  joinGroup(group) {
    group.join(this);
    this.groups.push(group);
  }

  receive(sender, message, groupAddress) {
    console.log(
      `  → ${this.name} (${this.ipAddress}) [그룹: ${groupAddress}] 수신: "${message}"`
    );
  }
}

// 사용 예시
const videoStreamGroup = new MulticastGroup("224.0.0.100");
const audioStreamGroup = new MulticastGroup("224.0.0.101");

const viewer1 = new MulticastHost("Viewer 1", "192.168.1.10");
const viewer2 = new MulticastHost("Viewer 2", "192.168.1.20");
const viewer3 = new MulticastHost("Viewer 3", "192.168.1.30");

// 일부 사용자는 비디오만, 일부는 비디오와 오디오 모두 구독
viewer1.joinGroup(videoStreamGroup);
viewer2.joinGroup(videoStreamGroup);
viewer2.joinGroup(audioStreamGroup);
viewer3.joinGroup(audioStreamGroup);

videoStreamGroup.multicast("Streamer", "Video frame data...");
audioStreamGroup.multicast("Streamer", "Audio sample data...");
```

**사용 상황**: 라이브 스트리밍, IPTV, 화상회의, 온라인 게임의 그룹 통신 등에 사용됩니다.

### 애니캐스트 (Anycast)

**정의**: 동일한 주소를 가진 여러 호스트 중 가장 가까운 호스트에게 전송하는 방식

**애니캐스트의 특징**

- 가장 가까운 서버로 자동 라우팅
- 부하 분산과 장애 대응에 유용
- DNS, CDN 서비스에서 주로 사용

**애니캐스트 개념 시뮬레이션**

```jsx
// 애니캐스트 라우팅 시뮬레이션
class AnycastServer {
  constructor(name, location, ip) {
    this.name = name;
    this.location = location;
    this.ip = ip;
    this.load = 0;
  }

  handleRequest(clientLocation) {
    this.load++;
    console.log(
      `${this.name} (${this.location})가 ${clientLocation}의 요청 처리`
    );
    console.log(`  현재 부하: ${this.load}개 요청`);
  }
}

class AnycastRouter {
  constructor() {
    this.servers = [];
  }

  registerServer(server) {
    this.servers.push(server);
  }

  calculateDistance(location1, location2) {
    // 간단한 거리 계산 (실제로는 지리적 거리나 네트워크 홉 수)
    const distances = {
      "Seoul-Tokyo": 10,
      "Seoul-Singapore": 30,
      "Seoul-LA": 50,
      "Tokyo-Singapore": 25,
      "Tokyo-LA": 40,
      "Singapore-LA": 60,
    };

    const key = `${location1}-${location2}`;
    const reverseKey = `${location2}-${location1}`;

    return distances[key] || distances[reverseKey] || 100;
  }

  routeRequest(clientLocation, anycastIP) {
    console.log(`\n클라이언트 (${clientLocation})가 ${anycastIP}로 요청`);

    // 가장 가까운 서버 찾기
    let nearestServer = null;
    let minDistance = Infinity;

    this.servers.forEach((server) => {
      if (server.ip === anycastIP) {
        const distance = this.calculateDistance(
          clientLocation,
          server.location
        );
        console.log(
          `  - ${server.name} (${server.location}): 거리 ${distance}`
        );

        if (distance < minDistance) {
          minDistance = distance;
          nearestServer = server;
        }
      }
    });

    if (nearestServer) {
      console.log(`  ✓ 가장 가까운 서버 선택: ${nearestServer.name}`);
      nearestServer.handleRequest(clientLocation);
    }
  }
}

// 사용 예시 - CDN 네트워크
const router = new AnycastRouter();

// 동일한 IP를 가진 여러 서버 (Anycast IP: 1.1.1.1)
const serverTokyo = new AnycastServer("Tokyo Server", "Tokyo", "1.1.1.1");
const serverSingapore = new AnycastServer(
  "Singapore Server",
  "Singapore",
  "1.1.1.1"
);
const serverLA = new AnycastServer("LA Server", "LA", "1.1.1.1");

router.registerServer(serverTokyo);
router.registerServer(serverSingapore);
router.registerServer(serverLA);

// 다양한 위치의 클라이언트 요청
router.routeRequest("Seoul", "1.1.1.1"); // Tokyo 서버로 라우팅
router.routeRequest("Singapore", "1.1.1.1"); // Singapore 서버로 라우팅
router.routeRequest("Seoul", "1.1.1.1"); // Tokyo 서버로 라우팅
```

**사용 상황**: Cloudflare, Google Public DNS(8.8.8.8) 같은 글로벌 서비스에서 사용자에게 가장 가까운 서버로 자동 연결할 때 사용됩니다.

## 핵심 요약

### 네트워크의 기본 개념

- **네트워크**: 여러 장치가 통신 기술로 연결된 통신망
- **프로토콜**: 네트워크 통신의 규칙 (HTTP, TCP/IP, UDP 등)
- **호스트**: 네트워크에 연결된 장치 (서버, 클라이언트)

### 네트워크 분류

- **LAN**: 제한된 지역 내 네트워크 (가정, 사무실)
- **WAN**: 지리적으로 넓은 범위의 네트워크 (인터넷)
- **회선 교환**: 전용 회선을 미리 설정 (전화)
- **패킷 교환**: 데이터를 패킷으로 나누어 전송 (인터넷)

### 전송 방식

- **유니캐스트**: 일대일 통신 (일반적인 웹 요청)
- **브로드캐스트**: 네트워크내 모든 호스트에게 전송 (ARP, DHCP)
- **멀티캐스트**: 특정 그룹에게만 전송 (스트리밍, 화상회의)
- **애니캐스트**: 가장 가까운 호스트에게 전송 (CDN, DNS)

### 주요 프로토콜

- **HTTP/HTTPS**: 웹 통신
- **TCP**: 신뢰성 있는 연결 지향 통신
- **UDP**: 빠른 비연결 통신
- **IP**: 네트워크 주소 지정
- **DNS**: 도메인을 IP 주소로 변환

### 문제 8
