# 📡 Chapter 04-1: 전송 계층 개요 - IP의 한계와 포트

> **출처**: 네트워크 기본 교재 Chapter 04 | 전송 계층

---

## 🎯 학습 목표

IP 프로토콜만으로 통신이 이루어질 때의 한계를 이해하고, 이를 보완하기 위한 전송 계층의 역할과 포트의 개념을 파악한다.

---

## 1️⃣ 신뢰할 수 없는 통신과 비연결형 통신

### 📌 IP 프로토콜의 한계

네트워크 계층의 핵심 프로토콜인 **IP**는 크게 두 가지 한계가 있습니다.

#### ① 비연결형 통신 (connectionless)
- IP는 패킷을 보내기 전 수신자와의 연결을 확립하지 않음
- 데이터를 보낸 후 제대로 도착했는지 확인하지 않음
- **문제점**: 패킷 손실 가능성 존재

#### ② 신뢰할 수 없는 통신 (unreliable)
- IP만으로는 패킷이 정확한 순서로 전달됨을 보장하지 못함
- 도중에 손실되거나 순서가 뒤바뀔 수 있음
- **문제점**: 데이터 무결성 보장 불가

> 💡 **쉽게 비유하면**
> IP는 편지를 우체통에 넣기만 할 뿐, 상대방이 받았는지 확인하지 않는 것과 같습니다.

---

## 2️⃣ IP의 한계를 보완하는 전송 계층

### 🔧 전송 계층의 역할

네트워크 계층의 핵심 프로토콜인 IP의 단점을 보완하기 위해 **전송 계층**이 존재합니다.

#### 주요 프로토콜

| 프로토콜 | 특징 | 연결 방식 | 신뢰성 |
|---------|------|----------|--------|
| **TCP** | 신뢰성 보장 | 연결형 | ✅ 높음 |
| **UDP** | 빠른 전송 | 비연결형 | ⚠️ 낮음 |

#### TCP의 특징
- 패킷이 제대로 도착했는지 **확인**
- 손실된 패킷이 있으면 **재전송**
- 패킷의 **순서를 보장**
- 연결 설정 후 데이터 전송 (3-way handshake)

#### UDP의 특징
- 빠른 전송 속도가 필요한 경우 사용
- 신뢰성보다 **속도**를 우선
- 예: 실시간 스트리밍, VoIP, 온라인 게임

---

## 3️⃣ 응용 계층과의 연결 다리, 포트

### 🚪 포트(Port)란?

포트는 **IP 주소와 함께 사용되어 특정 응용 프로그램을 식별**하는 번호입니다.

#### 왜 포트가 필요한가?

- IP 주소만으로는 **어떤 응용 프로그램**에게 데이터를 보낼지 알 수 없음
- 한 컴퓨터에서 여러 프로그램이 동시에 네트워크를 사용할 수 있음
- 포트 번호로 **프로세스를 구분**

#### 📬 주소 체계 비유
```
IP 주소 = 아파트 주소 (건물 위치)
포트 번호 = 호수 (특정 집)
```

예시:
- `192.168.0.5:8000` → 192.168.0.5 컴퓨터의 8000번 포트
- IP는 목적지 컴퓨터를 찾고, 포트는 그 안의 특정 프로그램을 찾음

---

### 📊 포트의 종류

포트 번호는 **0~65535**번까지 존재하며, 용도에 따라 구분됩니다.

#### 1. 잘 알려진 포트 (Well-known Ports): **0~1023**
- 주요 프로토콜과 서비스에 할당
- 일반적으로 서버에서 사용

| 포트 번호 | 서비스 | 설명 |
|----------|--------|------|
| 20, 21 | FTP | 파일 전송 |
| 22 | SSH | 보안 원격 접속 |
| 23 | TELNET | 원격 터미널 |
| 53 | DNS | 도메인 이름 변환 |
| 67, 68 | DHCP | IP 자동 할당 |
| 80 | HTTP | 웹 페이지 전송 |
| 443 | HTTPS | 보안 웹 페이지 |

#### 2. 등록된 포트 (Registered Ports): **1024~49151**
- 특정 응용 프로그램에서 사용
- IANA에 등록하여 사용

| 포트 번호 | 서비스 |
|----------|--------|
| 1194 | OpenVPN |
| 1433 | Microsoft SQL Server |
| 3306 | MySQL |
| 6379 | Redis |
| 8080 | HTTP 대체 |

#### 3. 동적 포트 (Dynamic Ports): **49152~65535**
- 클라이언트가 임시로 사용
- 동적 할당

---

### 🔍 프로세스와 포트의 관계

#### Windows에서 포트 확인하기
```bash
netstat
```

- 현재 사용 중인 포트와 연결 상태를 확인할 수 있는 명령어
- 어떤 프로세스가 어떤 포트를 사용하는지 파악 가능

#### 실행 예시
- `chrome.exe`는 여러 개의 동적 포트 사용
- 웹 서버는 80번 포트(HTTP) 또는 443번 포트(HTTPS) 사용

---

## 4️⃣ 포트 기반 NAT (Network Address Translation)

### 🔄 NAT란?

**NAT**는 사설 IP 주소를 공인 IP 주소로 변환하는 기술입니다.

#### NAT의 필요성
- IPv4 주소 고갈 문제 해결
- 하나의 공인 IP로 여러 사설 IP 기기 사용 가능
- 보안 강화 (외부에서 내부 네트워크 직접 접근 차단)

---

### 📋 NAT 변환 테이블

NAT는 **변환 테이블**을 통해 사설 IP와 공인 IP를 매핑합니다.

#### 동작 원리

| 네트워크 입장 | 네트워크 내부 |
|--------------|--------------|
| `공인 IP : 포트` | `사설 IP : 포트` |
| `1.2.3.4 : 1234` | `192.168.0.5 : 5000` |
| `1.2.3.4 : 1235` | `192.168.0.6 : 6000` |

#### 예시 시나리오
1. 내부 네트워크의 `192.168.0.5` 기기가 외부로 패킷 전송
2. NAT 라우터는 출발지를 `1.2.3.4:포트번호`로 변환
3. 외부에서 응답이 오면, NAT 테이블 참조하여 원래 사설 IP로 전달

> 💡 **핵심**
> NAT를 이용하면 외부에서 보기에는 하나의 공인 IP만 보이지만, 실제로는 여러 기기가 포트 번호로 구분됩니다.

---

### ⚙️ 포트 포워딩 (Port Forwarding)

#### 정의
**포트 포워딩**은 외부에서 내부 네트워크의 특정 호스트로 접속할 수 있도록 미리 포트와 IP 주소를 매핑하는 기술입니다.

#### 사용 사례
- 외부에서 내부 서버로 접속할 때
- 집에 설치한 NAS, 웹 서버에 외부에서 접근
- 게임 서버 호스팅

#### 설정 예시

| 서비스 | 외부 포트 | 내부 IP | 내부 포트 |
|--------|----------|---------|----------|
| 웹 서버 | 1234 | 192.168.100.100 | 1025 |
| SSH | 4321 | 192.168.100.101 | 1026 |

- 외부에서 `공인IP:1234`로 접속하면 → 내부 `192.168.100.100:1025`로 전달
- 외부에서 `공인IP:4321`로 접속하면 → 내부 `192.168.100.101:1026`로 전달

#### 주의사항
- 보안 위험이 있으므로 신중하게 설정
- 불필요한 포트는 열어두지 않기
- 방화벽 규칙과 함께 관리

---

## 5️⃣ ICMP (Internet Control Message Protocol)

### 📡 ICMP란?

**ICMP**는 IP의 신뢰할 수 없는 특성과 비연결성 통신 특성을 보완하기 위한 **네트워크 계층의 프로토콜**입니다.

#### 주요 역할
- IP 패킷의 전송 과정에 대한 **피드백 메시지** 제공
- 네트워크 문제 진단
- 오류 보고

---

### 🔢 ICMP 메시지 타입

| 타입 이름(번호) | 코드 번호 | 코드 설명 |
|----------------|----------|----------|
| 에코 요청 (8) | 0 | 에코 요청 |
| 에코 응답 (0) | 0 | 에코 응답 |
| 리다이렉트 (5) | 0 | 리다이렉트 필요 메시지 (호스트에 대한 재전송 경로 알림) |
| 포트 도달 불가 (3) | 2 | 프로토콜 도달 불가 (수신지에서 특정 프로토콜을 사용할 수 없음) |
| 포트 도달 불가 (3) | 3 | 포트 도달 불가 |
| 대비지 정보 차단 (11) | 0 | DF가 1로 설정되어 단편화 불가능 |
| 시간 초과 (11) | 0 | TTL 만료 |

---

### 🛠️ ICMP 활용 명령어

#### 1. **ping** (에코 요청/응답)
- 네트워크 연결 상태 확인
- 특정 호스트가 살아있는지 테스트
- 왕복 시간(RTT) 측정

```bash
ping google.com
```

#### 2. **traceroute** (경로 추적)
- 목적지까지의 경로 확인
- 각 구간의 응답 시간 측정
- 네트워크 병목 지점 파악

```bash
traceroute google.com
# Windows: tracert google.com
```

---

### ⚠️ RFC 792 - ICMP의 신뢰성

> **The Internet Protocol is not designed to be absolutely reliable.**
>
> (인터넷 프로토콜은 절대적으로 신뢰할 수 있도록 설계되지 않았습니다.)

ICMP는 IP의 문제를 보고하기 위한 도구일 뿐, **ICMP 메시지 자체도 손실될 수 있습니다.**

- ICMP로 신뢰성을 완전히 보장할 수는 없음
- 문제 진단 및 피드백 제공이 주 목적
- 신뢰성은 전송 계층(TCP)에서 보장

## 📝 핵심 요약

### 1. IP의 한계
- ❌ **비연결형**: 패킷 전송 전 연결 확립 없음
- ❌ **신뢰할 수 없음**: 순서 보장 X, 손실 가능성

### 2. 전송 계층의 역할
- **TCP**: 신뢰성 있는 연결형 통신 (순서 보장, 재전송)
- **UDP**: 빠른 비연결형 통신 (실시간 데이터)

### 3. 포트
- **정의**: IP 주소 + 포트 번호 = 특정 프로세스 식별
- **범위**: 0~65535
    - 0~1023: 잘 알려진 포트
    - 1024~49151: 등록된 포트
    - 49152~65535: 동적 포트

### 4. NAT
- **목적**: 사설 IP ↔ 공인 IP 변환
- **장점**: IPv4 주소 절약, 보안 강화
- **NAT 테이블**: 포트 기반으로 내부/외부 주소 매핑

### 5. 포트 포워딩
- **용도**: 외부에서 내부 서버 접속
- **방법**: 공인 IP의 특정 포트를 내부 IP:포트로 연결

### 6. ICMP
- **역할**: 네트워크 오류 보고 및 진단
- **도구**: `ping`, `traceroute`
- **한계**: ICMP 자체도 손실될 수 있음

## 🧠 복습용 퀴즈

### Q1. IP 프로토콜의 한계가 아닌 것은?
1. 비연결형 통신
2. 신뢰할 수 없는 통신
3. 패킷 암호화 기능 부재
4. 순서 보장 불가
5. 패킷 손실 가능성

**정답: 3번**
IP의 한계는 비연결형과 신뢰성 부족이 핵심입니다. 암호화는 IP의 설계 목적이 아니며, 다른 계층(예: 응용 계층의 TLS/SSL)에서 처리합니다.

---

### Q2. 다음 중 TCP의 특징으로 올바른 것은?
1. 비연결형 프로토콜이다
2. 빠른 속도가 장점이다
3. 패킷 순서를 보장하지 않는다
4. 손실된 패킷을 재전송한다
5. 실시간 스트리밍에 적합하다

**정답: 4번**
TCP는 연결형 프로토콜로, 패킷 순서 보장과 손실 시 재전송을 통해 신뢰성을 제공합니다. 빠른 속도와 실시간 전송은 UDP의 특징입니다.

---

### Q3. 포트 번호의 범위와 설명이 올바르게 짝지어진 것은?
1. 0~1023: 동적 포트
2. 1024~49151: 잘 알려진 포트
3. 49152~65535: 등록된 포트
4. 0~1023: 잘 알려진 포트
5. 1024~65535: 동적 포트

**정답: 4번**
포트는 0~1023(잘 알려진 포트), 1024~49151(등록된 포트), 49152~65535(동적 포트)로 구분됩니다.

---

### Q4. HTTP 프로토콜이 기본적으로 사용하는 포트 번호는?
1. 22
2. 53
3. 80
4. 443
5. 8080

**정답: 3번**
HTTP는 80번 포트를 사용하고, HTTPS는 443번 포트를 사용합니다. 8080은 HTTP의 대체 포트로 자주 사용됩니다.

---

### Q5. NAT의 주요 목적이 아닌 것은?
1. IPv4 주소 절약
2. 보안 강화
3. 사설 IP와 공인 IP 변환
4. 패킷 암호화
5. 여러 기기가 하나의 공인 IP 사용

**정답: 4번**
NAT는 IP 주소 변환을 통해 주소 절약과 보안을 제공하지만, 패킷 암호화는 NAT의 기능이 아닙니다. 암호화는 별도의 보안 프로토콜(IPsec, TLS 등)에서 처리합니다.

---

### Q6. 포트 포워딩에 대한 설명으로 올바른 것은?
1. 내부에서 외부로만 접속 가능하게 한다
2. 외부에서 내부 특정 호스트로 접속할 수 있게 한다
3. 모든 포트를 자동으로 열어준다
4. NAT 없이도 동작한다
5. 보안 위험이 전혀 없다

**정답: 2번**
포트 포워딩은 외부에서 내부 네트워크의 특정 서버로 접속하기 위해 공인 IP의 특정 포트를 내부 IP:포트로 연결하는 기술입니다. 보안 위험이 있으므로 신중하게 설정해야 합니다.

---

### Q7. ICMP의 역할로 올바른 것은?
1. 데이터 암호화
2. 네트워크 오류 보고 및 진단
3. IP 주소 자동 할당
4. 파일 전송
5. 도메인 이름 변환

**정답: 2번**
ICMP는 IP 패킷 전송 과정에서 발생하는 문제를 보고하고 네트워크를 진단하는 프로토콜입니다. ping과 traceroute가 ICMP를 활용합니다.

---

### Q8. `ping` 명령어가 사용하는 ICMP 메시지 타입은?
1. 리다이렉트
2. 에코 요청/응답
3. 포트 도달 불가
4. 시간 초과
5. 프로토콜 도달 불가

**정답: 2번**
ping은 ICMP의 에코 요청(Type 8)을 보내고 에코 응답(Type 0)을 받아 네트워크 연결 상태를 확인합니다.
