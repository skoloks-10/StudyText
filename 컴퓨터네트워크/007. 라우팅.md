# 📡 네트워크 라우팅 복습자료

---

## 📌 라우팅이란?

> 출발지에서 목적지까지 데이터를 전달하는 최적의 경로를 찾는 과정

**핵심 개념**
- 라우팅은 OSI 7계층 중 **L3 스위치(네트워크 계층)**에서 처리
- 라우터는 네트워크 계층의 핵심 장비
- 패킷의 경로를 결정하고 전달하는 역할 수행

**라우팅의 역할**
- 원시 패킷을 하나씩 스위칭하며 목적 계층에 속하는 장치로 전송
- 사용자는 컴퓨터와 메우 수십만대가 연결됨

---

## 🔍 라우팅 테이블

### 언제 쓰는지?
- 라우터가 패킷을 어디로 보낼지 판단할 때 참조하는 정보 저장소
- 네트워크 경로 정보를 명시한 안내판 역할

### 주요 구성 요소

#### 1️⃣ 수신지 IP 주소
- 패킷이 최종적으로 도착할 목적지 주소

#### 2️⃣ 서브넷 마스크
- 네트워크 대역을 구분하기 위한 값

#### 3️⃣ 게이트웨이
- 다른 네트워크로 가기 위해 거쳐야 할 중간 라우터 주소

#### 4️⃣ 인터페이스
- 패킷을 내보낼 물리적 또는 논리적 출구 (예: eth0, eth1)

#### 5️⃣ 메트릭
- 경로의 우선순위를 나타내는 값
- 숫자가 낮을수록 우선순위가 높음

### 라우팅 테이블 예시

```
수신지 IP 주소      서브넷 마스크        게이트웨이         인터페이스    메트릭
192.168.2.0      255.255.255.0      192.168.2.1       eth0         30
```

---

## 🛠️ 라우팅 테이블 명령어

### 라우팅 테이블 확인

**Windows**
```cmd
route print
```

**macOS**
```bash
netstat -rn
```

**Linux**
```bash
sudo route add -net 10.0.0.0 netmask 255.255.255.0 gw 192.168.1.1
```

**Cisco**
```
# ip route 10.0.0.0 255.255.255.0 192.168.1.1
```

### 자주 헷갈리는 포인트 ⚠️
- **기본 라우트(default route)**: 0.0.0.0/0로 표시되며, 어디로 갈지 모를 때 사용하는 만능 경로
- **직접 라우트**: 라우터에 직접 연결된 네트워크는 자동 등록됨
- **메트릭이 낮을수록** 우선순위 높음 (반대로 생각하기 쉬움!)

## 🌐 traceroute 명령어

### 언제 쓰는지?
- 패킷이 목적지까지 거쳐가는 **경로를 추적**할 때 사용
- 네트워크 병목 구간이나 장애 지점을 파악할 때 유용

### 동작 원리
- CMD에서 `traceroute www.google.com` 실행
- 라우터들을 하나씩 거쳐가며 경로 정보 수집
- 각 라우터의 IP 주소와 응답 시간 출력

### 출력 예시
```
traceroute to www.google.com (142.250.66.110), 64 hops max, 52 byte packets
1  192.168.219.1 (192.168.219.1)  7.140 ms  3.289 ms  4.244 ms
2  123.456.789.123 (123.456.789.123)  5.781 ms  6.884 ms
3  321.654.987.321 (321.654.987.321)  17.071 ms  6.871 ms  6.636 ms
...
15  hkg12s28-in-f14.1e100.net (142.250.66.110)  42.446 ms  61.722 ms
```

### 실무에서 자주 쓰는 패턴
- 특정 구간에서 지연이 크게 발생하면 → 해당 라우터 문제 의심
- 중간에 응답이 없으면 (timeout) → 방화벽이나 ACL로 차단된 경우

## 🔀 정적 라우팅 vs 동적 라우팅

### 정적 라우팅 (Static Routing)

**언제 쓰는지?**
- 네트워크 구성이 단순하고 변경이 적을 때
- 관리자가 수동으로 경로를 직접 설정

**특징**
- ✅ 설정이 간단하고 예측 가능
- ✅ 보안상 안전 (외부 라우터와 정보 교환 없음)
- ❌ 네트워크 변경 시 수동 업데이트 필요
- ❌ 대규모 네트워크에는 비효율적

**설정 예시**
```bash
# Windows
route add 10.0.0.0 mask 255.255.255.0 192.168.1.1

# Linux
sudo route add -net 10.0.0.0/24 192.168.1.1
```

---

### 동적 라우팅 (Dynamic Routing)

**언제 쓰는지?**
- 네트워크 규모가 크고 경로가 자주 바뀔 때
- 라우터끼리 자동으로 경로 정보를 교환하여 최적 경로 선택

**특징**
- ✅ 네트워크 변화에 자동 대응
- ✅ 관리 부담 감소
- ❌ 초기 설정 복잡
- ❌ 라우터 간 통신으로 인한 네트워크 부하 발생

**자주 헷갈리는 포인트 ⚠️**
- 정적 라우팅은 "수동", 동적 라우팅은 "자동" 경로 설정
- 동적 라우팅은 라우팅 프로토콜 필요 (RIP, OSPF, BGP 등)

---

## 🌍 라우팅 프로토콜

### AS (Autonomous System, 자율 시스템)

**정의**
- 단일 관리 주체가 운영하는 IP 네트워크의 집합
- 각 AS는 고유한 **AS 번호**를 가짐

**예시**
- 한국통신(KT), SKT, LG U+ 등 각각이 하나의 AS

---

### 🔸 IGP (Interior Gateway Protocol)

> AS 내부에서 사용하는 라우팅 프로토콜

#### 1) RIP (Routing Information Protocol)

**언제 쓰는지?**
- 소규모 네트워크에서 간단하게 라우팅 구성할 때

**특징**
- 거리 벡터(distance vector) 방식
- 최대 홉(hop) 수: 15개 (16개 이상은 무한대로 간주)
- 30초마다 라우팅 정보 교환

**자주 헷갈리는 포인트**
- RIP는 **거리(hop 수)**만 고려 → 실제 대역폭은 무시
- 따라서 느린 경로라도 hop이 적으면 선택될 수 있음

---

#### 2) OSPF (Open Shortest Path First)

**언제 쓰는지?**
- 중대형 네트워크에서 빠르고 효율적인 라우팅이 필요할 때

**특징**
- 링크 스테이트(link state) 방식
- 대역폭, 지연 시간 등을 고려해 최적 경로 계산
- Area 개념으로 네트워크를 계층화 가능

**RIP와 차이점**
| 항목 | RIP | OSPF |
|------|-----|------|
| 방식 | 거리 벡터 | 링크 스테이트 |
| 최대 hop | 15 | 제한 없음 |
| 수렴 속도 | 느림 | 빠름 |
| 확장성 | 소규모 | 대규모 |

**실무에서 자주 쓰는 패턴**
- OSPF는 변화 감지 즉시 업데이트 (RIP보다 훨씬 빠름)
- Area 0 (백본 영역)을 중심으로 다른 Area 연결

---

#### 3) EIGRP (Enhanced Interior Gateway Routing Protocol)

**특징**
- Cisco 전용 프로토콜
- RIP과 OSPF의 장점을 결합한 하이브리드 방식

---

### 🔹 EGP (Exterior Gateway Protocol)

> AS 간에 사용하는 라우팅 프로토콜

#### BGP (Border Gateway Protocol)

**언제 쓰는지?**
- 인터넷 백본 네트워크에서 서로 다른 AS 간 경로를 교환할 때
- ISP 간 연결에 필수적

**특징**
- 경로 벡터(path vector) 방식
- AS 단위로 경로 정보 교환
- 정책 기반 라우팅 가능 (특정 AS 경유 금지 등)

**자주 헷갈리는 포인트**
- BGP는 **AS 간** 라우팅용 → 내부 네트워크에선 사용 안 함
- BGP는 신뢰성보다는 **정책과 제어**에 중점

**실무에서 자주 쓰는 패턴**
- eBGP: 다른 AS와 연결
- iBGP: 같은 AS 내부에서 BGP 정보 동기화

---

## 🎯 BGP 동작 원리

### AS-PATH 속성

**정의**
- BGP가 경로 정보를 전달할 때 거쳐온 AS 목록을 기록하는 속성

**동작 방식**
1. AS1에서 AS2로 경로 전달 → AS-PATH: AS1
2. AS2에서 AS3로 전달 → AS-PATH: AS2 AS1

**자주 헷갈리는 포인트**
- AS-PATH가 짧을수록 우선순위 높음
- 하지만 AS1에서 공정한 AS2로 가는 경로도 있을 수 있음

---

### NEXT-HOP 속성

**정의**
- 다음 홉(라우터)의 IP 주소를 나타냄

**동작 방식**
- AS1과 연결된 라우터 a의 IP 주소가 NEXT-HOP
- AS1에서 AS3를 거쳐 AS2에 도달하는 경로의 NEXT-HOP은 AS1과 연결된 라우터 b

---

### LOCAL-PREF 속성

**정의**
- 지역 선호도, AS 내부에서 어떤 경로를 우선할지 결정

**동작 방식**
- LOCAL-PREF 값이 **높을수록** 우선순위 높음
- AS-PATH나 NEXT-HOP보다 우선 적용

**자주 헷갈리는 포인트**
- 메트릭은 낮을수록 우선, LOCAL-PREF는 높을수록 우선! (정반대)

---

### BGP 정책 예시

**여러 AS에서 같은 목적지를 광고하는 경우**

1. LOCAL-PREF가 있으면 → 가장 높은 값 선택
2. AS-PATH 길이 → 짧은 경로 선택
3. NEXT-HOP → 가까운 라우터 선택

**실무에서 자주 쓰는 패턴**
- 메인 회선과 백업 회선이 있을 때, 메인 회선에 높은 LOCAL-PREF 부여
- AS-PATH가 같으면 NEXT-HOP으로 최종 결정

---

## 📝 핵심 요약

1. **라우팅**: 출발지에서 목적지까지 패킷을 전달하는 경로를 찾는 과정
2. **라우팅 테이블**: 경로 정보를 저장한 일람표 (수신지, 서브넷, 게이트웨이, 인터페이스, 메트릭)
3. **정적 라우팅**: 관리자가 수동으로 경로 설정 (안정적이지만 유연성 부족)
4. **동적 라우팅**: 라우터끼리 자동으로 경로 정보 교환 (유연하지만 복잡)
5. **IGP**: AS 내부 라우팅 (RIP, OSPF, EIGRP)
6. **EGP**: AS 간 라우팅 (BGP)
7. **BGP**: 인터넷 백본에서 사용하는 경로 벡터 프로토콜
8. **AS-PATH**: 거쳐온 AS 목록 (짧을수록 우선)
9. **NEXT-HOP**: 다음 라우터 IP 주소
10. **LOCAL-PREF**: AS 내부 우선순위 (높을수록 우선)

## ✅ 복습 퀴즈

### Q1. 라우팅 테이블에서 메트릭 값이 의미하는 것은?
1) 패킷의 크기
2) 경로의 우선순위 (낮을수록 높은 우선순위)
3) 경로의 우선순위 (높을수록 높은 우선순위)
4) 라우터의 처리 속도

**정답: 2번**
메트릭은 경로의 비용 또는 우선순위를 나타내며, 값이 낮을수록 우선순위가 높습니다.

---

### Q2. RIP 프로토콜의 최대 hop 수는?
1) 10
2) 15
3) 20
4) 제한 없음

**정답: 2번**
RIP는 최대 15 hop까지만 허용하며, 16 hop 이상은 도달 불가능한 것으로 간주합니다.

---

### Q3. BGP에서 AS-PATH가 짧을수록 우선순위가 높은 이유는?
1) 거리가 가까워서
2) 대역폭이 넓어서
3) 경유하는 AS가 적어 경로가 단순하기 때문
4) 보안이 강화되어서

**정답: 3번**
AS-PATH는 거쳐온 AS의 개수를 나타내며, 경로가 단순할수록 (AS가 적을수록) 효율적이라고 판단합니다.

---

### Q4. OSPF와 RIP의 가장 큰 차이점은?
1) OSPF는 거리 벡터, RIP는 링크 스테이트 방식
2) OSPF는 링크 스테이트, RIP는 거리 벡터 방식
3) OSPF는 AS 간, RIP는 AS 내부에서만 사용
4) OSPF는 Cisco 전용, RIP는 표준 프로토콜

**정답: 2번**
OSPF는 링크 스테이트 방식으로 네트워크 전체 토폴로지를 파악하고, RIP는 거리 벡터 방식으로 hop 수만 고려합니다.

---

### Q5. BGP의 LOCAL-PREF 속성에 대한 설명으로 올바른 것은?
1) 값이 낮을수록 우선순위가 높다
2) AS 간 경로 교환에 사용된다
3) 값이 높을수록 우선순위가 높다
4) NEXT-HOP보다 우선순위가 낮다

**정답: 3번**
LOCAL-PREF는 AS 내부에서 경로 우선순위를 결정하며, 값이 높을수록 우선순위가 높습니다. (메트릭과 반대!)

---

### Q6. traceroute 명령어의 주요 용도는?
1) 라우팅 테이블 확인
2) 패킷이 목적지까지 거쳐가는 경로 추적
3) 네트워크 대역폭 측정
4) DNS 서버 조회

**정답: 2번**
traceroute는 패킷이 목적지까지 도달하는 동안 거쳐가는 모든 라우터의 경로를 추적하고 표시합니다.
