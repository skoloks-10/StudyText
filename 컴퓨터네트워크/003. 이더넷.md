# 📡 이더넷 (Ethernet) 완벽 정리

## 🎯 이더넷이란?

**이더넷**은 유선 LAN 환경에서 가장 널리 사용되는 네트워크 기술입니다. 같은 물리적 계층에서 여러 컴퓨터가 데이터를 주고받을 수 있게 해주는 프로토콜입니다.

> 💡 **핵심**: 이더넷은 국제 표준(IEEE 802.3)으로 제정된 근거리 통신망 기술입니다.

---

## 📊 이더넷 표준과 속도

### 전송 속도 진화

- **2.5G** → 2.5Gbps
- **5G** → 5Gbps
- **10G** → 10Gbps
- **40G** → 40Gbps
- **100G** → 100Gbps

### 주요 IEEE 802.3 표준

| 표준 규격    | 전송 매체                | 속도      |
| ------------ | ------------------------ | --------- |
| IEEE 802.3i  | 10BASE-T                 | 10Mbps    |
| IEEE 802.3u  | 100BASE-TX               | 100Mbps   |
| IEEE 802.3ab | 1000BASE-T               | 1Gbps     |
| IEEE 802.3bz | 2.5GBASE-T, 5GBASE-T     | 2.5/5Gbps |
| IEEE 802.3an | 10GBASE-T                | 10Gbps    |
| IEEE 802.3z  | 1000BASE-SX, 1000BASE-LX | 1Gbps     |
| IEEE 802.3ae | 10GBASE-SR, 10GBASE-LR   | 10Gbps    |

---

## 🔌 BASE와 전송 매체

### BASE의 의미

**BASE**는 **베이스밴드(Baseband)** 방식을 의미합니다.

- **베이스밴드**: 신호를 변조하지 않고 디지털 신호 그대로 전송
- **브로드밴드(BROADBAND)**: 여러 신호를 변조하여 동시에 전송 (케이블 TV처럼)

> ⚠️ **참고**: BASE 외에 BROAD로 표기하는 브로드밴드 방식도 있지만, 대부분 베이스밴드를 사용합니다.

---

## 🎭 추가 특성 표기

### 추가 특성 문자

표준 뒤에 붙는 추가 문자는 전송 매체의 특성을 나타냅니다.

- **C**: 동축 케이블
- **T**: 트위스티드 페어 케이블
- **S**: 단파장 광섬유 케이블
- **L**: 장파장 광섬유 케이블

> 💡 **예시**: 10BASE-T는 10Mbps 속도로 트위스티드 페어 케이블을 사용하는 이더넷입니다.

---

## 🔍 전송 속도 표기 읽기

### 명칭 구조 분석

**1000BASE-T**를 예로 들면:

- **1000**: 속도를 의미 (1000Mbps = 1Gbps)
- **BASE**: 베이스밴드 방식
- **T**: 트위스티드 페어 케이블

**10BASE-T**의 경우:

- **10**: 10Mbps 속도
- **BASE**: 베이스밴드
- **T**: 트위스티드 페어 케이블

**100BASE-TX**의 경우:

- **100**: 100Mbps 속도
- **BASE**: 베이스밴드
- **TX**: 향상된 트위스티드 페어 (Enhanced)

---

## 🌐 통신 매체 표기 형태

### 전송 속도와 BASE 조합

```
전송 속도(Mbps 또는 Gbps) + BASE + 추가 특성
```

### 실제 예시들

- `10BASE-T`: 10Mbps, 트위스티드 페어
- `100BASE-TX`: 100Mbps, 향상된 트위스티드 페어
- `1000BASE-SX`: 1Gbps, 단파장 광섬유
- `1000BASE-LX`: 1Gbps, 장파장 광섬유
- `10GBASE-T`: 10Gbps, 트위스티드 페어

---

## 🖼️ 이더넷 프레임 구조

이더넷 프레임은 데이터를 전송하기 위한 기본 단위입니다.

### 프레임 구성 요소

```
[프리앰블] → [수신지 MAC 주소] → [송신지 MAC 주소] → [타입/길이] → [데이터] → [FCS]
```

| 필드       | 크기          | 설명               |
| ---------- | ------------- | ------------------ |
| 프리앰블   | 8바이트       | 동기화 신호        |
| 수신지 MAC | 6바이트       | 목적지 주소        |
| 송신지 MAC | 6바이트       | 출발지 주소        |
| 타입/길이  | 2바이트       | 상위 프로토콜 정보 |
| 데이터     | 46~1500바이트 | 실제 전송 데이터   |
| FCS        | 4바이트       | 오류 검사          |

---

## 🎯 프리앰블 (Preamble)

### 프리앰블의 역할

프리앰블은 이더넷 프레임의 시작을 알리는 8바이트 크기의 정보입니다.

- **패턴**: `10101010` 반복 (7바이트) + `10101011` (1바이트)
- **목적**: 수신 장치가 간의 동기화를 맞추기 위한 신호
- **특징**: 충돌 감지를 위해서도 사용됨

---

## 🔐 MAC 주소 (Media Access Control Address)

### MAC 주소란?

**MAC 주소**는 네트워크 인터페이스 카드(NIC)에 부여된 고유한 하드웨어 주소입니다.

### MAC 주소의 특징

- **크기**: 48비트 (6바이트)
- **표기법**: 16진수 형태 (예: `A1:C2:E3:4D:C5:E6`)
- **구성**:
  - 앞 24비트: 제조사 식별 코드 (OUI)
  - 뒤 24비트: 제조사가 부여한 고유 번호

### MAC 주소 확인 방법

**Windows에서 확인**:

```cmd
getmac /v
```

**Linux/macOS에서 확인**:

```bash
ifconfig
```

출력 예시에서 `ether` 또는 `HWaddr` 뒤에 표시되는 값이 MAC 주소입니다.

---

## 📍 송신지/수신지 MAC 주소

### 데이터 전송 과정

1. 네트워크의 모든 장치가 프레임을 수신
2. 수신지 MAC 주소를 확인
3. 자신의 MAC 주소와 일치하면 처리
4. 일치하지 않으면 폐기

### MAC 주소의 역할

- **송신지 MAC**: 데이터를 보낸 장치 식별
- **수신지 MAC**: 데이터를 받을 장치 지정
- **고유성**: NIC마다 전 세계적으로 유일한 주소 보장

---

## 📝 타입/길이 필드

### 타입 필드의 역할

타입/길이 필드는 **상위 계층 프로토콜**을 식별하는 2바이트 크기의 정보입니다.

### 주요 타입 값

| 타입 값 | 프로토콜 |
| ------- | -------- |
| 0x0800  | IPv4     |
| 0x86DD  | IPv6     |
| 0x0806  | ARP      |

> 💡 **참고**: 값이 1500 이하면 길이, 1536 이상이면 타입을 나타냅니다.

---

## 💾 데이터 필드

### 데이터의 크기 제한

- **최소 크기**: 46바이트
- **최대 크기**: 1500바이트
- **패딩**: 데이터가 46바이트보다 작으면 패딩을 추가하여 최소 크기 맞춤

> ⚠️ **MTU (Maximum Transmission Unit)**: 이더넷에서 한 번에 전송할 수 있는 최대 데이터 크기는 1500바이트입니다.

---

## ✅ FCS (Frame Check Sequence)

### FCS의 역할

**FCS**는 프레임의 오류를 검사하는 4바이트 크기의 체크섬입니다.

### 작동 방식

1. 송신측에서 프레임 전체를 CRC 알고리즘으로 계산
2. 계산된 값을 FCS 필드에 저장하여 전송
3. 수신측에서 같은 방법으로 재계산
4. FCS 값과 비교하여 오류 검사

> 💡 **CRC (Cyclic Redundancy Check)**: 순환 중복 검사 방식으로 오류를 검출합니다.

---

## 🔄 충돌과 재전송

### 충돌 발생 상황

이더넷에서 여러 장치가 동시에 데이터를 전송하면 **충돌(Collision)**이 발생합니다.

### CSMA/CD 방식

- **CSMA/CD**: Carrier Sense Multiple Access with Collision Detection
- 전송 전에 네트워크가 비어있는지 확인
- 충돌 감지 시 랜덤 시간만큼 대기 후 재전송

> 📌 **현대 이더넷**: 스위치 기반 전이중(Full-Duplex) 통신으로 충돌이 거의 발생하지 않습니다.

---

## 🔁 토큰 링 (Token Ring)

### 토큰 링이란?

이더넷과는 다른 LAN 기술로, **토큰(Token)**이라는 특별한 프레임을 사용합니다.

### 작동 원리

1. 네트워크에서 토큰이 순환
2. 데이터를 전송하려면 토큰을 획득해야 함
3. 호스트가 토큰을 받으면 데이터 전송 가능
4. 전송 완료 후 토큰을 다시 네트워크에 반환

### 토큰 링의 장점

- 충돌이 발생하지 않음
- A→B 메시지 전송 가능 (C, D 메시지 중계)

### 토큰 링의 단점

- 토큰 손실 시 전체 네트워크 마비
- 현대에는 거의 사용되지 않음

---

# 📋 최종 핵심 요약

## 이더넷 기본 개념

- 유선 LAN의 표준 기술 (IEEE 802.3)
- 베이스밴드 방식으로 디지털 신호 직접 전송
- 속도는 10Mbps부터 100Gbps까지 다양

## 프레임 구조

```
프리앰블(8) + 수신지MAC(6) + 송신지MAC(6) + 타입(2) + 데이터(46-1500) + FCS(4)
```

## MAC 주소

- 48비트 하드웨어 고유 주소
- NIC마다 전 세계적으로 유일
- 16진수 표기: `A1:C2:E3:4D:C5:E6`

## 전송 표준 읽기

- **10BASE-T**: 10Mbps, 트위스티드 페어
- **1000BASE-SX**: 1Gbps, 단파장 광섬유
- **속도 + BASE + 매체 특성** 순서로 표기

## 오류 검사

- FCS로 CRC 알고리즘 사용
- 프레임 무결성 검증

# 🧪 복습 퀴즈

### Q1. 다음 중 이더넷 프레임의 필드 순서로 올바른 것은?

1. 프리앰블 → 송신지 MAC → 수신지 MAC → 데이터 → FCS
2. 프리앰블 → 수신지 MAC → 송신지 MAC → 타입/길이 → 데이터 → FCS
3. 수신지 MAC → 송신지 MAC → 프리앰블 → 데이터 → FCS
4. 송신지 MAC → 수신지 MAC → 프리앰블 → 타입/길이 → 데이터

**정답**: 2번

**해설**: 이더넷 프레임은 프리앰블로 시작하여 동기화 신호를 보낸 후, 수신지 MAC 주소로 목적지를 지정하고, 송신지 MAC 주소로 출발지를 표시합니다. 그 다음 타입/길이 필드로 상위 프로토콜을 식별하고, 실제 데이터를 전송한 뒤 FCS로 오류를 검사합니다.

---

### Q2. MAC 주소에 대한 설명으로 틀린 것은?

1. MAC 주소는 48비트 크기입니다
2. MAC 주소는 네트워크 인터페이스 카드에 부여된 고유 주소입니다
3. MAC 주소의 앞 24비트는 제조사 식별 코드입니다
4. MAC 주소는 소프트웨어적으로 언제든지 변경할 수 있습니다

**정답**: 4번

**해설**: MAC 주소는 하드웨어 고유 주소로 NIC에 물리적으로 할당됩니다. 일반적으로 변경할 수 없으며, 전 세계적으로 유일한 값을 보장합니다. 앞 24비트는 IEEE가 제조사에 할당한 OUI이고, 뒤 24비트는 제조사가 부여한 고유 번호입니다.

---

### Q3. 1000BASE-SX 표준에 대한 설명으로 옳은 것은?

1. 1000Mbps 속도로 트위스티드 페어 케이블을 사용합니다
2. 1000Mbps 속도로 단파장 광섬유 케이블을 사용합니다
3. 100Mbps 속도로 단파장 광섬유 케이블을 사용합니다
4. 10Gbps 속도로 장파장 광섬유 케이블을 사용합니다

**정답**: 2번

**해설**: 1000은 1000Mbps(1Gbps)를 의미하고, BASE는 베이스밴드 방식, S는 단파장(Short wavelength) 광섬유, X는 광섬유 케이블을 나타냅니다. 따라서 1000BASE-SX는 1Gbps 속도로 단파장 광섬유 케이블을 사용하는 이더넷 표준입니다.

---

### Q4. 이더넷 프레임의 데이터 필드 크기 범위로 올바른 것은?

1. 8 ~ 1500 바이트
2. 46 ~ 1500 바이트
3. 64 ~ 1518 바이트
4. 0 ~ 무제한

**정답**: 2번

**해설**: 이더넷 프레임의 데이터 필드는 최소 46바이트에서 최대 1500바이트까지입니다. 데이터가 46바이트보다 작으면 패딩을 추가하여 최소 크기를 맞춥니다. 1500바이트는 MTU(Maximum Transmission Unit)로 한 번에 전송할 수 있는 최대 크기입니다.

---

### Q5. FCS(Frame Check Sequence)의 역할로 올바른 것은?

1. 프레임의 시작을 알리는 동기화 신호
2. 상위 계층 프로토콜을 식별하는 정보
3. 프레임의 오류를 검사하는 체크섬
4. 송신지와 수신지의 MAC 주소를 저장

**정답**: 3번

**해설**: FCS는 프레임의 마지막에 위치하며, CRC 알고리즘을 사용하여 프레임 전체의 무결성을 검사합니다. 송신측에서 계산한 값을 FCS에 저장하여 전송하고, 수신측에서 같은 방법으로 재계산하여 비교함으로써 전송 중 오류 발생 여부를 확인합니다.
