## 1. CSS 요소 구분 방법

웹 페이지에서 HTML 요소들을 CSS와 JavaScript로 제어하기 위해서는 각 요소를 명확하게 구분할 수 있는 방법이 필요합니다. 이 섹션에서는 세 가지 주요 방식을 비교하고, 각각의 장단점을 살펴봅니다.

### 1.1 태그 위주 방식

**개념** : HTML의 시맨틱 태그(article, aside, header 등)를 사용하여 요소를 선택하는 방식입니다.

**특징** :

- HTML 태그의 계층 구조를 활용
- 클래스명 없이 CSS 선택자만으로 스타일 지정
- 가장 기본적인 방식

  **사용 예시** :

```html
<article>
  <aside>
    <figure></figure>
  </aside>
  <div>
    <header></header>
    <ul>
      <li class="special"></li>
      <li></li>
      <li></li>
    </ul>
  </div>
</article>
```

```css
article {
  /* 카드 컨테이너 스타일 */
}
article aside {
  /* 썸네일 영역 스타일 */
}
article aside figure {
  /* 이미지 스타일 */
}
article div header {
  /* 제목 스타일 */
}
article ul li {
  /* 리스트 아이템 스타일 */
}
article div ul li.special {
  /* 특별한 리스트 아이템 */
}
```

**장점** :

- HTML 구조가 간결함
- 추가 클래스명을 고민할 필요 없음

  **단점** :

- 선택자가 장황해짐 (깊은 중첩 필요)
- CSS 선택자만으로는 요소의 역할을 파악하기 어려움
- 동일한 태그 구조를 가진 다른 컴포넌트 구분 불가능
- 유지보수 시 HTML 구조 변경에 취약

  **사용 상황** : 매우 간단한 페이지나 프로토타입에서만 권장됩니다.

---

### 1.2 클래스 위주 방식

**개념** : 각 요소에 의미 있는 클래스명을 부여하여 선택하는 방식입니다.

**특징** :

- 모든 요소에 클래스명 할당
- 클래스명으로 요소의 역할 표현
- 여전히 계층 구조 유지

  **사용 예시** :

```html
<article class="card">
  <aside class="thumb">
    <figure class="image"></figure>
  </aside>
  <div class="body">
    <header class="title"></header>
    <ul class="list">
      <li class="list-item special"></li>
      <li class="list-item"></li>
      <li class="list-item"></li>
    </ul>
  </div>
</article>
```

```css
.card {
  /* 카드 컨테이너 */
}
.card .thumb {
  /* 썸네일 영역 */
}
.card .thumb .image {
  /* 이미지 */
}
.card .body .title {
  /* 제목 */
}
.card .body .list {
  /* 리스트 */
}
.card .body .list .list-item {
  /* 리스트 아이템 */
}
.card .body .list .list-item.special {
  /* 특별 아이템 */
}
```

**장점** :

- 태그 방식보다 요소의 역할이 명확함
- HTML 태그 변경에 영향받지 않음

  **단점** :

- 여전히 선택자가 장황할 수 있음
- 클래스명 중복 가능성 (`thumb`, `image`, `title` 등은 다른 컴포넌트에서도 사용될 수 있음)
- 중첩된 선택자로 인한 CSS 우선순위 문제 발생 가능

  **사용 상황** : 중소규모 프로젝트에서 사용 가능하나, 대규모 프로젝트에서는 명명 충돌 문제가 발생할 수 있습니다.

### 1.3 BEM 명명 규칙

**개념** : Block Element Modifier의 약자로, 컴포넌트 기반의 체계적인 CSS 명명 규칙입니다.

**BEM 문법** :

```css
.BLOCK__ELEMENT--MODIFIER {
  /* ... */
}
```

- **Block (블록)** : 독립적인 컴포넌트 단위 (예: `card`, `menu`, `button`)
- **Element (요소)** : 블록 내부의 구성 요소, `__`로 연결 (예: `card__title`, `menu__item`)
- **Modifier (수정자)** : 블록이나 요소의 변형, `-`로 연결 (예: `button--primary`, `card__item--active`)

  **특징** :

- 블록(컴포넌트) 단위로 독립적인 명명
- 네이밍만으로 계층 구조 파악 가능
- 중첩 선택자 불필요

  **사용 예시** :

```html
<article class="card">
  <aside class="card__thumb">
    <figure class="card__image"></figure>
  </aside>
  <div class="card__body">
    <header class="card__title"></header>
    <ul class="card__list">
      <li class="card__list-item card__list-item--special"></li>
      <li class="card__list-item"></li>
      <li class="card__list-item"></li>
    </ul>
  </div>
</article>
```

```css
.card {
  /* 카드 블록 */
}
.card__thumb {
  /* 카드의 썸네일 요소 */
}
.card__image {
  /* 카드의 이미지 요소 */
}
.card__title {
  /* 카드의 제목 요소 */
}
.card__list {
  /* 카드의 리스트 요소 */
}
.card__list-item {
  /* 카드의 리스트 아이템 요소 */
}
.card__list-item--special {
  /* 특별한 상태의 리스트 아이템 */
}
```

**장점** :

- ⭐ **간결한 선택자** : 중첩 없이 단일 클래스로 선택 가능
- ⭐ **명확한 네이밍** : 클래스명만 보고 어떤 컴포넌트의 어떤 요소인지 즉시 파악
- ⭐ **중복 방지** : 블록명이 접두사 역할을 하여 클래스명 충돌 해소
- ⭐ **높은 가독성** : 코드 구조를 이해하기 쉬움
- ⭐ **유지보수 용이** : 컴포넌트 단위로 관리 가능
- 코드량 감소 (중첩 선택자 불필요)

  **단점** :

- 클래스명이 길어질 수 있음
- 초기 학습 곡선 존재

  **사용 상황** : 중대규모 프로젝트, 컴포넌트 기반 개발, 팀 협업 환경에서 강력히 권장됩니다.

  **참고 자료** :

- 공식 사이트: [bem.info](http://getbem.com/)
- BEM 치트시트: 빠른 참조용 가이드

  **실전 예시 - 버튼 컴포넌트** :

```html
<!-- 기본 버튼 -->
<button class="button">클릭</button>

<!-- 주요 버튼 (Modifier) -->
<button class="button button--primary">확인</button>

<!-- 큰 사이즈 버튼 (Modifier) -->
<button class="button button--large">큰 버튼</button>

<!-- 아이콘이 있는 버튼 (Element) -->
<button class="button">
  <span class="button__icon">🔍</span>
  <span class="button__text">검색</span>
</button>
```

```css
/* Block */
.button {
  padding: 10px 20px;
  border: none;
  cursor: pointer;
}

/* Modifier - 주요 버튼 */
.button--primary {
  background-color: blue;
  color: white;
}

/* Modifier - 큰 버튼 */
.button--large {
  padding: 15px 30px;
  font-size: 18px;
}

/* Elements */
.button__icon {
  margin-right: 5px;
}

.button__text {
  font-weight: bold;
}
```

## 2. 기타 미디어 활용

### 2.1 SVG (Scalable Vector Graphic)

**개념** : 확장 가능한 벡터 그래픽 형식으로, 수학적 계산으로 이미지를 표현하는 방식입니다.

**특징** :

- XML 기반의 벡터 이미지
- 해상도에 관계없이 선명함 (확대해도 깨지지 않음)
- 파일 크기가 작음
- CSS와 JavaScript로 제어 가능

  **장점** :

- 비교적 복잡하지 않은 도형, 아이콘, 그래픽 표현에 유리
- 반응형 디자인에 적합
- 애니메이션 적용 가능
- 색상 변경이 용이

  **단점** :

- 복잡한 사진이나 이미지에는 부적합
- 브라우저 호환성 고려 필요 (구형 브라우저)

  **사용 방법 1 - img 태그** :

```html
<!-- 외부 SVG 파일 링크 -->
<img src="logo.svg" alt="로고" />
```

**사용 방법 2 - 인라인 SVG** :

```html
<!-- HTML에 직접 작성 -->
<svg width="100" height="100" xmlns="<http://www.w3.org/2000/svg>">
  <circle cx="50" cy="50" r="40" fill="blue" />
</svg>
```

**사용 상황** :

- 로고, 아이콘
- 차트, 그래프
- 간단한 일러스트레이션
- 반응형 그래픽이 필요한 경우

  **유용한 SVG 도구** :

- [Shape Divider](https://www.shapedivider.app/): 섹션 구분선 생성
- [Haikei](https://haikei.app/): 다양한 배경 패턴 생성

  **참고 자료** : [MDN SVG 문서](https://developer.mozilla.org/ko/docs/Web/SVG)

### 2.2 오디오와 동영상

HTML5에서는 플러그인 없이 미디어를 재생할 수 있는 `<audio>`와 `<video>` 태그를 제공합니다.

### 방법 1: src 속성 사용

**audio 태그** :

```html
<audio src="audio.mp3" controls autoplay loop>
  이 브라우저는 오디오를 지원하지 않습니다.
</audio>
```

**video 태그** :

```html
<video src="video.mp4" controls autoplay loop width="640" height="360">
  이 브라우저는 비디오를 지원하지 않습니다.
</video>
```

### 방법 2: source 태그 사용 (권장)

**개념** : 여러 포맷의 미디어 파일을 제공하여 브라우저 호환성을 높입니다.

**audio 예시** :

```html
<audio controls>
  <source src="audio.mp3" type="audio/mpeg" />
  <source src="audio.ogg" type="audio/ogg" />
  <source src="audio.wav" type="audio/wav" />
  이 브라우저는 오디오를 지원하지 않습니다.
</audio>
```

**video 예시** :

```html
<video controls width="640" height="360">
  <source src="video.mp4" type="video/mp4" />
  <source src="video.webm" type="video/webm" />
  <source src="video.ogg" type="video/ogg" />
  이 브라우저는 비디오를 지원하지 않습니다.
</video>
```

### 주요 속성

| 속성             | 설명                                  | 비고                                            |
| ---------------- | ------------------------------------- | ----------------------------------------------- |
| `src`            | 미디어 파일 위치                      | source 태그로 대체 가능                         |
| `controls`       | 재생/일시정지 등 제어 인터페이스 표시 | 불리언 속성                                     |
| `autoplay`       | 자동 재생                             | 대부분의 브라우저에서 제한됨 (사용자 경험 보호) |
| `loop`           | 반복 재생                             | 불리언 속성                                     |
| `muted`          | 음소거                                | autoplay와 함께 사용 시 작동 가능성 높음        |
| `preload`        | 페이지 로드 시 미디어 로딩 방식       | `none`,`metadata`,`auto`                        |
| `poster`         | 비디오 로드 전 표시할 이미지          | video 전용                                      |
| `width`,`height` | 재생 영역 크기                        | video 전용                                      |

**사용 상황** :

- `src` 속성: 단일 포맷만 지원하면 될 때
- `source` 태그: 크로스 브라우저 호환성이 중요할 때 (권장)

  **주의사항** :

- `autoplay`는 대부분의 브라우저에서 사용자 경험 보호를 위해 차단됩니다
- `autoplay`를 사용하려면 `muted` 속성과 함께 사용하세요
- 접근성을 위해 `<track>` 태그로 자막을 제공하는 것이 좋습니다

## 3. CSS 코드 재사용

### 3.1 CSS 파일 임포트

**개념** : `@import` 규칙을 사용하여 다른 CSS 파일의 내용을 현재 CSS 파일로 가져오는 기능입니다.

**문법** :

```css
@import url(파일경로);
```

**특징** :

- 절대 경로와 상대 경로 모두 사용 가능
- 여러 페이지에서 공통으로 사용하는 스타일을 모듈화
- CSS 파일의 최상단에 작성해야 함

  **사용 예시** :

**shared.css** (공통 스타일):

```css
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border-width: 0;
}

body {
  font-family: Arial, sans-serif;
  line-height: 1.6;
}
```

**main.css** (개별 페이지 스타일):

```css
/* shared.css의 내용을 가져옴 */
@import url(./shared.css);

body {
  margin: 0;
  padding: 24px;
  background-color: #f5f5f5;
}

.container {
  max-width: 1200px;
  margin: 0 auto;
}
```

**장점** :

- 코드 중복 제거
- 유지보수 편의성 증대
- 모듈화를 통한 체계적인 관리

  **단점** :

- HTTP 요청 증가 (성능 고려 필요)
- 브라우저가 CSS를 순차적으로 로드하므로 렌더링 지연 가능

  **사용 상황** :

- 여러 페이지에서 공통으로 사용하는 리셋 스타일
- 컴포넌트별 스타일 파일 분리
- 테마나 색상 체계 관리

  **주의사항** :

- `@import`는 CSS 파일의 최상단에 위치해야 합니다
- 중첩된 `@import`는 피하는 것이 좋습니다 (성능 문제)
- 프로덕션 환경에서는 빌드 도구로 CSS를 번들링하는 것이 권장됩니다

### 3.2 CSS 변수

**개념** : CSS에서 재사용 가능한 값을 변수로 정의하여 사용하는 기능입니다. CSS Custom Properties라고도 불립니다.

**문법** :

```css
/* 변수 정의 */
선택자 {
  --변수명: 값;
}

/* 변수 사용 */
선택자 {
  속성: var(--변수명);
  속성: var(--변수명, 기본값); /* 변수가 없을 때 기본값 사용 */
}
```

### 변수 스코프

**1. 특정 요소 스코프** :

```css
/* u 태그 내부에서만 사용 가능한 변수 */
u {
  --not-good: wavy underline orange;
  --wrong: wavy underline red;
}

/* 사용 */
.not-good {
  text-decoration: var(--not-good);
}
```

**2. 전역 스코프 (`:root`)** :

```css
/* 모든 요소에서 사용 가능한 변수 */
:root {
```

## 핵심 요약

### CSS 명명 규칙

- **태그 위주** : 장황한 선택자, 유지보수 어려움
- **클래스 위주** : 중복 가능성, 여전히 복잡한 선택자
- **BEM 규칙** : `Block__Element--Modifier` 형식으로 명확하고 간결한 명명, 대규모 프로젝트에 최적

### 미디어 활용

- **SVG** : 벡터 그래픽, 확대해도 선명, 아이콘/로고에 적합
- **Audio/Video** : `controls`, `autoplay`, `loop` 속성, `source` 태그로 다중 포맷 지원

### CSS 재사용

- **@import** : 공통 스타일을 별도 파일로 분리하여 임포트
- **CSS 변수** : `:root`에 전역 변수 정의, `var(--변수명)`로 사용, 디자인 시스템 구축에 필수

### 퀴즈 5

CSS에서 모든 요소에서 사용할 수 있는 전역 변수를 정의할 때 사용하는 선택자는?

1.
2. `body`

**정답** : 3번

**해설** : `:root` 선택자는 문서의 최상위 요소(보통 html)를 선택하며, 전역 CSS 변수를 정의하는 표준 방식입니다. `:root`에 정의된 변수는 모든 하위 요소에서 `var()` 함수로 접근할 수 있습니다.

### 퀴즈 6

다음 BEM 명명 중 올바르지 않은 것은?

1. `.button`
2. `.button__icon`
3. `.button--primary`
4. `.button__icon--larg`
5. `.button--primary__icon`

**정답** : 5번

**해설** : BEM에서는 `Block--Modifier__Element` 형식은 사용하지 않습니다. Modifier는 Block 또는 Element에 적용되며, 올바른 순서는 `Block__Element--Modifier`입니다. 예: `.button__icon--large`는 올바르지만, `.button--primary__icon`는 잘못된 형식입니다.

### 퀴즈 7

CSS 변수를 사용할 때, 변수가 정의되지 않은 경우 대체값을 지정하는 올바른 문법은?

1. `var(--color-main || #FF0000)`
2. `var(--color-main, #FF0000)`
3. `var(--color-main default #FF0000)`
4. `var(--color-main ? #FF0000)`
5. `var(--color-main: #FF0000)`

**정답** : 2번

**해설** : CSS 변수의 대체값은 쉼표(`,`)로 구분하여 지정합니다. `var(--변수명, 대체값)` 형식으로 사용하며, 변수가 정의되지 않았거나 유효하지 않을 때 대체값이 사용됩니다.
