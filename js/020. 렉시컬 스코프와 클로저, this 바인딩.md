# 렉시컬 스코프와 클로저, this 바인딩 완벽 정리

## 📌 렉시컬(정적) 스코프

### 핵심 개념
**변수/함수가 코드 상 '어디에 정의되었는가'에 따라 상위 스코프가 결정되는 방식**

- 호출 위치가 아닌 **선언 위치**가 기준
- 동적 스코프(호출 위치 기준)와 반대되는 개념

### 언제 중요한가?
- 함수 안에 함수를 중첩할 때
- 콜백 함수를 사용할 때
- 클로저를 활용할 때

```javascript
const x = 1;
const y = 1;

function outer() {
  const y = 2;
  
  function inner() {
    console.log(x, y); // 1, 2 출력
    // inner는 outer 안에서 '정의'되었으므로 outer의 y를 참조
  }
  
  inner();
}

outer();
```

### 자주 헷갈리는 포인트
❌ "함수를 어디서 **호출**했는지가 중요하다"
✅ "함수를 어디서 **정의**했는지가 중요하다"

## 🔐 렉시컬 환경 (Lexical Environment)

### 정의
코드 블록(전역, 함수, {})이 실행되기 전에 만들어지는 내부 객체

### 구성 요소
1. **환경 레코드** (Environment Record): 현재 스코프의 변수/함수
2. **외부 렉시컬 환경 참조** (Outer Reference): 상위 스코프 참조

### 동작 방식
```javascript
function outer(a) {
  const b = 2;
  
  function inner(c) {
    const d = 4;
    console.log(a, b, c, d); // 모두 접근 가능
  }
  
  inner(3);
}

outer(1);
```

**실행 시 생성되는 렉시컬 환경:**
- 전역 환경: { outer: function, ... }
- outer 환경: { a: 1, b: 2, inner: function, outer참조: 전역 }
- inner 환경: { c: 3, d: 4, outer참조: outer }

## 🎯 클로저 (Closure)

### 핵심 개념
**내부 함수가 외부 함수의 변수에 접근할 수 있고, 외부 함수 실행이 끝나도 그 변수를 기억하는 현상**

### 언제 쓰는가?
- 데이터 은닉 (private 변수 구현)
- 상태 유지가 필요한 함수
- 팩토리 패턴
- 이벤트 핸들러에서 특정 값 기억

### 실무 패턴 1: 카운터 함수
```javascript
function createCounter(start) {
  let count = start; // 외부에서 접근 불가
  
  return function() {
    return ++count;
  }
}

const counter = createCounter(0);
counter(); // 1
counter(); // 2
counter(); // 3
```

### 실무 패턴 2: Private 필드 흉내내기
```javascript
function createUser(name, age) {
  let _name = name;
  let _age = age;
  
  return {
    getName: () => _name,
    getAge: () => _age,
    setAge: (age) => { _age = age; },
    aging: (years) => { _age += years; }
  };
}

const user = createUser('김철수', 25);
console.log(user._age); // undefined (직접 접근 불가)
console.log(user.getAge()); // 25 (메서드로만 접근)
```

### 자주 헷갈리는 포인트
- 클로저는 값을 **복사**하는 게 아니라 **참조**를 유지함
- 외부 함수가 종료되어도 내부 함수가 살아있으면 변수도 메모리에 유지됨

## 🔄 this의 동적 바인딩

### 기본 규칙
`this`는 **함수를 누가, 어떻게 호출했는가**에 따라 달라짐

### 상황별 this 정리

| 호출 방식 | this가 가리키는 대상 |
|---------|------------------|
| `obj.method()` | obj |
| `func()` (일반 모드) | 전역 객체 (globalThis) |
| `func()` (strict 모드) | undefined |
| `new Func()` | 생성될 인스턴스 |
| `func.call(obj)` | 첫 번째 인자 (obj) |

### 언제 문제가 되는가?
```javascript
const person = {
  name: '철수',
  greet: function() {
    console.log(`안녕, ${this.name}`);
  }
};

person.greet(); // "안녕, 철수"

const greet = person.greet;
greet(); // "안녕, undefined" ❌ this가 전역 객체를 가리킴
```

### 해결 방법들

#### 1️⃣ `call()` - 즉시 실행하며 this 지정
```javascript
const korean = {
  food: '김치',
  cook: function(spicy, pots) {
    return `${spicy ? '매운' : '순한'} ${this.food}찌개 ${pots}냄비`;
  }
};

const italian = { food: '피자' };

korean.cook.call(italian, true, 2); // "매운 피자찌개 2냄비"
```

#### 2️⃣ `apply()` - call과 동일하지만 인자를 배열로
```javascript
korean.cook.apply(italian, [false, 1]); // "순한 피자찌개 1냄비"
```

#### 3️⃣ `bind()` - this가 고정된 새 함수 생성 ⭐ 가장 많이 씀
```javascript
const boundFunc = korean.cook.bind(korean);
italian.wrongCook = boundFunc;

italian.wrongCook(true, 1); // "매운 김치찌개 1냄비" (italian이 호출해도 korean 유지)
```

### 실무 패턴: 생성자 함수에서 미리 바인딩
```javascript
function User(name) {
  this.name = name;
  this.greet = function() {
    return `안녕, ${this.name}`;
  };
  
  this.greet = this.greet.bind(this); // ⭐ 여기서 고정!
}

const user = new User('영희');
const greet = user.greet;
greet(); // "안녕, 영희" ✅ 분리해도 정상 작동
```

### 자주 헷갈리는 포인트
- `call`, `apply`는 **즉시 실행**
- `bind`는 **새 함수를 반환**만 함 (실행 X)

## ⚡ this의 정적 바인딩 (화살표 함수)

### 핵심 차이점
**화살표 함수의 this는 선언 위치의 상위 스코프로 고정됨 (동적 변경 불가)**

### 함수 종류별 비교

| 구분 | 생성자 가능 | 프로토타입 | this 바인딩 |
|-----|----------|---------|-----------|
| `function func() {}` | ✅ | ✅ | 동적 |
| `func() {}` (메서드) | ❌ | ❌ | 동적 |
| `() => {}` (화살표) | ❌ | ❌ | 정적 |

### 언제 쓰는가?

#### ✅ 화살표 함수가 유리한 경우
```javascript
class Timer {
  constructor() {
    this.seconds = 0;
    
    // 화살표 함수로 this 고정
    setInterval(() => {
      this.seconds++;
      console.log(this.seconds);
    }, 1000);
  }
}
```

일반 함수였다면 `setInterval` 내부의 `this`는 전역 객체를 가리킴!

#### ❌ 화살표 함수를 피해야 할 경우
```javascript
const obj = {
  name: '철수',
  greet: () => {
    console.log(this.name); // ❌ obj가 아닌 상위 스코프를 가리킴
  }
};

obj.greet(); // undefined
```

객체 메서드는 일반 함수나 메서드 문법 사용!

### 실무 패턴: 동적 vs 정적 바인딩 활용
```javascript
class Korean {
  constructor() {
    this.food = '김치';
    
    // 화살표 함수 - this 고정
    this.fryRice = (spicy) => {
      return `${spicy ? '매운' : '순한'} ${this.food}볶음밥`;
    };
  }
  
  // 메서드 - this 동적
  makeStew(spicy) {
    return `${spicy ? '매운' : '순한'} ${this.food}찌개`;
  }
}

const korean = new Korean();
const italian = { food: '피자' };

italian.makeStew = korean.makeStew;
italian.fryRice = korean.fryRice;

italian.makeStew(true); // "매운 피자찌개" (동적 변경됨)
italian.fryRice(true);  // "매운 김치볶음밥" (고정됨)
```

### 자주 헷갈리는 포인트
- 화살표 함수는 `call`, `apply`, `bind`로도 this 변경 불가
- 객체 리터럴의 화살표 함수는 해당 객체가 아닌 **상위 스코프** 참조
- 생성자 함수로 사용 불가 (`new` 사용 불가)

## 🎓 핵심 요약

### 렉시컬 스코프
- 함수가 **정의된 위치**에 따라 상위 스코프 결정
- 호출 위치는 무관

### 클로저
- 외부 함수 종료 후에도 내부 함수가 외부 변수에 접근 가능
- private 변수, 상태 유지, 팩토리 패턴에 활용

### this - 동적 바인딩 (일반 함수/메서드)
- 호출 방식에 따라 this가 달라짐
- `call`, `apply`, `bind`로 제어 가능
- `bind`는 this가 고정된 새 함수 반환

### this - 정적 바인딩 (화살표 함수)
- 선언 위치의 상위 스코프로 this 고정
- `call`, `apply`, `bind` 무시됨
- 객체 메서드로 부적합, 콜백에 유리

## 📝 복습 퀴즈

### Q1. 다음 코드의 출력 결과는?
```javascript
const x = 10;

function outer() {
  const x = 20;
  
  function inner() {
    console.log(x);
  }
  
  return inner;
}

const func = outer();
func();
```

**① 10**  
**② 20**  
**③ undefined**  
**④ ReferenceError**

<details>
<summary>정답 및 해설</summary>

**정답: ② 20**

`inner` 함수는 `outer` 함수 내부에서 **정의**되었으므로, 렉시컬 스코프 규칙에 따라 `outer`의 `x` 값인 20을 참조합니다. 전역의 `x = 10`은 무시됩니다.
</details>

---

### Q2. 클로저의 올바른 설명은?
**① 외부 함수가 종료되면 내부 함수는 외부 변수에 접근할 수 없다**  
**② 내부 함수가 외부 변수의 값을 복사해서 저장한다**  
**③ 외부 함수 종료 후에도 내부 함수가 외부 변수를 참조할 수 있다**  
**④ 클로저는 화살표 함수에서만 동작한다**

<details>
<summary>정답 및 해설</summary>

**정답: ③ 외부 함수 종료 후에도 내부 함수가 외부 변수를 참조할 수 있다**

클로저는 외부 함수가 종료되어도 내부 함수가 외부 함수의 렉시컬 환경을 계속 참조하는 현상입니다. 값을 복사하는 것이 아니라 참조를 유지하며, 일반 함수와 화살표 함수 모두에서 동작합니다.
</details>

---

### Q3. 다음 코드의 출력 결과는?
```javascript
const obj = {
  name: '김철수',
  greet: function() {
    console.log(this.name);
  }
};

const greet = obj.greet;
greet();
```

**① "김철수"**  
**② undefined**  
**③ ReferenceError**  
**④ "greet"**

<details>
<summary>정답 및 해설</summary>

**정답: ② undefined**

`greet` 변수에 함수만 복사되어 일반 함수로 호출되었습니다. 일반 함수 호출 시 this는 전역 객체를 가리키며, 전역에는 `name` 속성이 없으므로 undefined가 출력됩니다. (strict 모드에서는 에러 발생)
</details>

### Q4. `bind()` 메서드의 특징으로 올바른 것은?
**① 함수를 즉시 실행하며 this를 바인딩한다**  
**② this가 고정된 새로운 함수를 반환한다**  
**③ 인자를 배열로 전달해야 한다**  
**④ 화살표 함수의 this도 변경할 수 있다**

<details>
<summary>정답 및 해설</summary>

**정답: ② this가 고정된 새로운 함수를 반환한다**

`bind()`는 즉시 실행하지 않고 this가 바인딩된 **새 함수를 반환**합니다. `call`/`apply`는 즉시 실행하지만, `bind`는 나중에 호출할 함수를 만듭니다. 화살표 함수의 this는 변경할 수 없습니다.
</details>

---

### Q5. 화살표 함수의 this에 대한 설명으로 틀린 것은?
**① 선언 위치의 상위 스코프로 this가 고정된다**  
**② call, apply, bind로 this를 변경할 수 없다**  
**③ 객체의 메서드로 사용하기 적합하다**  
**④ 생성자 함수로 사용할 수 없다**

<details>
<summary>정답 및 해설</summary>

**정답: ③ 객체의 메서드로 사용하기 적합하다**

화살표 함수는 객체 메서드로 부적합합니다. 객체 리터럴의 화살표 함수는 해당 객체가 아닌 상위 스코프(보통 전역)를 가리키기 때문입니다. 대신 콜백 함수나 this를 고정해야 하는 상황에 유리합니다.
</details>
