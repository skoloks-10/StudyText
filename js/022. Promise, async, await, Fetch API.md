## 2️⃣ Promise 기본 사용법

### Promise는 무엇인가요?

"시간이 걸리는 작업이 끝나면 ~를 실행하겠다"는 약속 객체입니다.

### 언제 사용하나요?

- 서버에서 데이터 가져올 때
- 파일을 읽거나 쓸 때
- 타이머 처리할 때
- 여러 비동기 작업을 체이닝할 때

### 기본 구조

```javascript
const myPromise = new Promise((resolve, reject) => {
  // 비동기 작업 수행
  if (/* 성공 조건 */) {
    resolve(결과값);  // 성공 시
  } else {
    reject(에러메시지);  // 실패 시
  }
});

myPromise
  .then(결과 => { /* 성공 처리 */ })
  .catch(에러 => { /* 실패 처리 */ })
  .finally(() => { /* 성공/실패 상관없이 실행 */ });
```

### ⚠️ 헷갈리는 포인트

1. **Promise는 생성 즉시 실행됩니다**
   ```javascript
   const promise = new Promise((resolve) => {
     console.log('즉시 실행!');  // Promise 생성 시점에 바로 실행됨
     setTimeout(() => resolve('완료'), 1000);
   });
   ```

2. **reject 실행 후 resolve는 무시됩니다**
   ```javascript
   new Promise((resolve, reject) => {
     reject('에러');
     resolve('성공');  // 무시됨
   });
   ```

### 체이닝 패턴 (실무 핵심!)

```javascript
// ✅ then은 또 다른 Promise를 반환하므로 계속 체이닝 가능
fetchUser(userId)
  .then(user => fetchPosts(user.id))
  .then(posts => filterActivePosts(posts))
  .then(activePosts => renderPosts(activePosts))
  .catch(error => showError(error));
```

**인자를 그대로 전달하는 경우 함수명만 써도 됩니다**
```javascript
moneyLend(20)
  .then(result => moneyLend(result))  // 일반적 방식
  .then(moneyLend)  // ✅ 간결한 방식
  .then(moneyLend)
  .then(moneyLend);
```

## 3️⃣ Promise 병렬 처리 메서드

### 언제 사용하나요?

여러 비동기 작업을 **동시에** 실행하고 싶을 때 (API 여러 개 동시 호출 등)

### 1. Promise.all()

**특징:** 모든 Promise가 성공해야 성공

```javascript
// 사용 시기: 모든 데이터가 필수적일 때
Promise.all([
  fetchUserInfo(),
  fetchUserPosts(),
  fetchUserComments()
])
.then(([user, posts, comments]) => {
  // 모두 성공 시 실행
})
.catch(error => {
  // 하나라도 실패하면 여기로
});
```

**⚠️ 주의:** 하나라도 실패하면 전체가 실패 처리됩니다!

### 2. Promise.allSettled()

**특징:** 성공/실패 관계없이 모든 결과 반환

```javascript
// 사용 시기: 일부 실패해도 나머지 결과가 필요할 때
Promise.allSettled([
  fetchAPI1(),
  fetchAPI2(),
  fetchAPI3()
])
.then(results => {
  results.forEach(result => {
    if (result.status === 'fulfilled') {
      console.log('성공:', result.value);
    } else {
      console.log('실패:', result.reason);
    }
  });
});
```

**실무 활용:** 여러 소스에서 데이터를 가져오는데, 일부만 실패해도 괜찮을 때

### 3. Promise.any()

**특징:** 가장 먼저 성공한 Promise 하나만 반환

```javascript
// 사용 시기: 여러 서버 중 가장 빠른 응답만 필요할 때
Promise.any([
  fetchFromServer1(),
  fetchFromServer2(),
  fetchFromServer3()
])
.then(fastestResult => {
  console.log('가장 빠른 응답:', fastestResult);
});
```

### 4. Promise.race()

**특징:** 성공이든 실패든 가장 먼저 완료된 것 반환

```javascript
// 사용 시기: 타임아웃 구현할 때
Promise.race([
  fetchData(),
  new Promise((_, reject) => 
    setTimeout(() => reject('타임아웃'), 5000)
  )
])
.then(data => console.log(data))
.catch(error => console.log(error));  // 5초 안에 못 가져오면 타임아웃
```

### 🔍 비교표

| 메서드 | 성공 조건 | 반환값 | catch 동작 | 실무 용도 |
|--------|---------|--------|-----------|---------|
| **all** | 모두 성공 | 모든 결과 배열 | 하나라도 실패 시 | 모든 데이터 필수 |
| **allSettled** | 항상 성공 | 모든 상태+결과 | 동작 안 함 | 부분 실패 허용 |
| **any** | 하나라도 성공 | 첫 성공 결과 | 모두 실패 시 | 빠른 응답 우선 |
| **race** | 첫 완료 | 첫 완료 결과 | 첫 실패 시 | 타임아웃 처리 |

## 4️⃣ async/await

### 언제 사용하나요?

- Promise 체이닝이 복잡해질 때
- 동기 코드처럼 읽기 쉽게 작성하고 싶을 때
- 순차적 비동기 작업이 많을 때

### 기본 구조

```javascript
async function 함수명() {
  try {
    const result1 = await 비동기함수1();
    const result2 = await 비동기함수2(result1);
    const result3 = await 비동기함수3(result2);
    return result3;
  } catch (error) {
    console.error(error);
  } finally {
    console.log('완료');
  }
}
```

### ⚠️ 중요한 규칙

1. **await은 async 함수 안에서만 사용 가능**
   ```javascript
   // ❌ 안 됨
   function normal() {
     const data = await fetchData();
   }
   
   // ✅ 됨
   async function good() {
     const data = await fetchData();
   }
   ```

2. **await은 코드 실행을 멈춥니다**
   ```javascript
   async function example() {
     console.log(1);
     const data = await fetchData();  // 여기서 대기
     console.log(2);  // fetchData 완료 후 실행
   }
   example();
   console.log(3);  // 이건 먼저 실행됨!
   
   // 출력 순서: 1 → 3 → 2
   ```

3. **에러 처리는 try-catch 사용**
   ```javascript
   async function safeFetch() {
     try {
       const data = await fetchData();
       return data;
     } catch (error) {
       console.error('에러 발생:', error);
       return null;
     }
   }
   ```

### Promise vs async/await 비교

```javascript
// Promise 방식
function getDataPromise() {
  return fetch('/api/user')
    .then(res => res.json())
    .then(user => fetch(`/api/posts/${user.id}`))
    .then(res => res.json())
    .then(posts => posts.filter(p => p.active))
    .catch(error => console.error(error));
}

// async/await 방식 - 훨씬 읽기 쉬움!
async function getDataAsync() {
  try {
    const userRes = await fetch('/api/user');
    const user = await userRes.json();
    
    const postsRes = await fetch(`/api/posts/${user.id}`);
    const posts = await postsRes.json();
    
    return posts.filter(p => p.active);
  } catch (error) {
    console.error(error);
  }
}
```

## 5️⃣ Fetch API로 네트워크 통신

### 언제 사용하나요?

- 서버에서 데이터를 가져올 때 (GET)
- 서버로 데이터를 전송할 때 (POST, PUT, DELETE)
- RESTful API와 통신할 때

### 기본 사용법

```javascript
// fetch는 Promise를 반환합니다
fetch('https://api.example.com/data')
  .then(response => response.json())  // JSON 파싱
  .then(data => console.log(data))
  .catch(error => console.error(error));
```

### ⚠️ 헷갈리는 포인트

1. **response.json()도 Promise입니다!**
   ```javascript
   // ❌ 잘못된 방식
   fetch(url)
     .then(response => {
       console.log(response.json());  // [object Promise] 출력됨
     });
   
   // ✅ 올바른 방식
   fetch(url)
     .then(response => response.json())
     .then(data => console.log(data));
   ```

2. **fetch는 404 에러에도 catch로 가지 않습니다**
   ```javascript
   fetch(url)
     .then(response => {
       if (!response.ok) {  // 수동으로 체크 필요
         throw new Error('HTTP 에러!');
       }
       return response.json();
     })
     .catch(error => console.error(error));
   ```

### 실무 패턴: 연속 API 호출

**시나리오:** 경기 결과 → 1등 선수 정보 → 학교 정보 순서로 가져오기

```javascript
// 방법 1: Promise 체이닝
fetch('/api/race-result')
  .then(res => res.json())
  .then(results => results.sort((a, b) => a.time - b.time)[0])
  .then(winner => fetch(`/api/runner/${winner.id}`))
  .then(res => res.json())
  .then(runner => fetch(`/api/school/${runner.school_id}`))
  .then(res => res.json())
  .then(school => console.log(school))
  .catch(error => console.error(error));

// 방법 2: async/await (더 읽기 쉬움!)
async function getWinnerSchool() {
  try {
    const raceRes = await fetch('/api/race-result');
    const results = await raceRes.json();
    const winner = results.sort((a, b) => a.time - b.time)[0];
    
    const runnerRes = await fetch(`/api/runner/${winner.id}`);
    const runner = await runnerRes.json();
    
    const schoolRes = await fetch(`/api/school/${runner.school_id}`);
    const school = await schoolRes.json();
    
    console.log(school);
  } catch (error) {
    console.error(error);
  }
}
```

### 실무 팁: 여러 API 동시 호출

```javascript
// ❌ 비효율적: 순차적으로 3초 소요
async function sequential() {
  const user = await fetch('/api/user');      // 1초
  const posts = await fetch('/api/posts');    // 1초
  const comments = await fetch('/api/comments'); // 1초
}

// ✅ 효율적: 병렬로 1초 소요
async function parallel() {
  const [user, posts, comments] = await Promise.all([
    fetch('/api/user'),
    fetch('/api/posts'),
    fetch('/api/comments')
  ]);
}
```

## 📋 핵심 요약

### Promise 핵심 3줄

1. Promise는 "미래의 값"을 나타내는 객체 (성공/실패 상태 가짐)
2. then/catch/finally로 체이닝하여 순차 처리
3. 생성 즉시 실행되며, reject 후 resolve는 무시됨

### 병렬 처리 메서드 선택 가이드

- 모든 결과 필요 + 하나라도 실패하면 안 됨 → `Promise.all()`
- 모든 결과 필요 + 일부 실패 허용 → `Promise.allSettled()`
- 가장 빠른 성공 결과만 필요 → `Promise.any()`
- 가장 빠른 결과 (성공/실패 무관) → `Promise.race()`

### async/await 핵심 3줄

1. async 함수는 항상 Promise를 반환
2. await은 Promise가 완료될 때까지 코드 실행을 멈춤
3. try-catch로 에러 처리, finally로 마무리 작업

### Fetch API 핵심 3줄

1. fetch()는 Promise를 반환 (네트워크 요청)
2. response.json()도 Promise를 반환 (JSON 파싱)
3. HTTP 에러는 catch로 안 가므로 response.ok 체크 필요

### 실무에서 자주 쓰는 패턴

```javascript
// 패턴 1: async/await + try-catch
async function fetchData() {
  try {
    const response = await fetch('/api/data');
    if (!response.ok) throw new Error('HTTP 에러');
    return await response.json();
  } catch (error) {
    console.error('에러:', error);
    return null;
  }
}

// 패턴 2: 병렬 처리
async function fetchMultiple() {
  const [data1, data2, data3] = await Promise.all([
    fetch('/api/1').then(r => r.json()),
    fetch('/api/2').then(r => r.json()),
    fetch('/api/3').then(r => r.json())
  ]);
}

// 패턴 3: 타임아웃 추가
async function fetchWithTimeout(url, timeout = 5000) {
  return Promise.race([
    fetch(url),
    new Promise((_, reject) => 
      setTimeout(() => reject('타임아웃'), timeout)
    )
  ]);
}
```

## 🎯 복습 퀴즈

### 문제 1
다음 중 Promise.all()에 대한 설명으로 올바른 것은?

1) 가장 먼저 완료된 Promise의 결과만 반환한다
2) 모든 Promise가 성공해야 then이 실행된다
3) 하나라도 실패해도 나머지 결과를 받을 수 있다
4) 성공/실패 여부와 관계없이 모든 결과를 배열로 반환한다
5) catch 블록은 사용할 수 없다

**정답: 2번**

해설: Promise.all()은 전달된 모든 Promise가 성공(resolve)해야만 then 블록이 실행됩니다. 하나라도 실패(reject)하면 즉시 catch 블록으로 이동하며, 나머지 Promise의 결과는 받을 수 없습니다. 1번은 Promise.race(), 3번과 4번은 Promise.allSettled()의 특징입니다.

### 문제 2
다음 코드의 출력 순서로 올바른 것은?

```javascript
console.log('A');

async function test() {
  console.log('B');
  await new Promise(resolve => setTimeout(resolve, 100));
  console.log('C');
}

test();
console.log('D');
```

1) A → B → C → D
2) A → B → D → C
3) A → D → B → C
4) B → A → D → C
5) A → C → B → D

**정답: 2번 (A → B → D → C)**

해설: 실행 순서를 단계별로 보면:
1. 'A' 출력 (동기 코드)
2. test() 함수 호출되어 'B' 출력 (async 함수도 await 전까지는 동기적으로 실행)
3. await를 만나면서 test() 함수가 일시 중지되고 제어권이 밖으로 나감
4. 'D' 출력 (메인 스레드의 동기 코드)
5. 100ms 후 Promise가 완료되면 'C' 출력

await은 해당 Promise가 완료될 때까지 함수 실행을 멈추지만, 전체 프로그램을 멈추는 것은 아닙니다.

### 문제 3
fetch API를 사용할 때 주의해야 할 점으로 옳지 않은 것은?

1) response.json()은 Promise를 반환하므로 await 또는 then을 사용해야 한다
2) 404 에러가 발생하면 자동으로 catch 블록으로 이동한다
3) fetch()는 Promise를 반환한다
4) response.ok를 확인하여 HTTP 에러를 체크할 수 있다
5) 네트워크 오류 시에는 catch 블록으로 이동한다

**정답: 2번**

해설: fetch는 네트워크 요청 자체가 실패한 경우(네트워크 끊김 등)에만 Promise를 reject합니다. HTTP 상태 코드가 404, 500 등의 에러 코드여도 Promise는 resolve되므로 catch로 가지 않습니다. 따라서 response.ok (status 200-299 여부)를 수동으로 체크해야 합니다.

```javascript
// 올바른 에러 처리 방법
fetch(url)
  .then(response => {
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }
    return response.json();
  })
  .catch(error => console.error('Error:', error));
```

### 문제 4
다음 중 async/await에 대한 설명으로 올바르지 않은 것은?

1) async 함수는 항상 Promise를 반환한다
2) await 키워드는 일반 함수 내부에서도 사용할 수 있다
3) try-catch 블록으로 에러를 처리할 수 있다
4) await은 Promise가 완료될 때까지 함수 실행을 멈춘다
5) async 함수 내부에서 return한 값은 자동으로 Promise.resolve()로 감싸진다

**정답: 2번**

해설: await 키워드는 반드시 async 함수 내부에서만 사용할 수 있습니다 (또는 최상위 모듈에서). 일반 함수에서 사용하면 SyntaxError가 발생합니다.

```javascript
// ❌ 에러 발생
function normal() {
  const data = await fetchData();  // SyntaxError!
}

// ✅ 올바른 사용
async function correct() {
  const data = await fetchData();
}
```

나머지 설명은 모두 맞습니다. async 함수는 명시적으로 Promise를 반환하지 않아도 반환값이 자동으로 Promise로 감싸지며, try-catch로 reject된 Promise를 처리할 수 있습니다.

### 문제 5
다음 코드의 실행 시간으로 가장 가까운 것은? (각 fetch는 1초 소요)

```javascript
async function fetchData() {
  const result1 = await fetch('/api/1');
  const result2 = await fetch('/api/2');
  const result3 = await fetch('/api/3');
  return [result1, result2, result3];
}
```

1) 약 1초
2) 약 2초
3) 약 3초
4) 약 4초
5) 실행 시간을 알 수 없음

**정답: 3번 (약 3초)**

해설: 이 코드는 순차적으로 실행됩니다:
1. 첫 번째 fetch 완료까지 1초 대기
2. 두 번째 fetch 완료까지 1초 대기
3. 세 번째 fetch 완료까지 1초 대기
   총 약 3초가 소요됩니다.

만약 병렬로 실행하려면 Promise.all()을 사용해야 합니다:

```javascript
// ✅ 병렬 실행: 약 1초 소요
async function fetchDataParallel() {
  const [result1, result2, result3] = await Promise.all([
    fetch('/api/1'),
    fetch('/api/2'),
    fetch('/api/3')
  ]);
  return [result1, result2, result3];
}
```

이것이 실무에서 성능 최적화를 위해 Promise.all()을 자주 사용하는 이유입니다.
