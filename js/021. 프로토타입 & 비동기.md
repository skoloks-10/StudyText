# 📚 JavaScript 프로토타입 & 비동기 복습 노트

## 1️⃣ 프로토타입 (Prototype)

### 💡 프로토타입이란?

**자바스크립트는 프로토타입 기반 객체지향 언어**
- 모든 객체는 `[[Prototype]]`을 가지고 있음
- 빈 객체도 `toString()`, `valueOf()` 같은 메서드를 쓸 수 있는 이유

### 🔍 언제 쓰는가?

**생성자 함수나 클래스로 여러 인스턴스를 만들 때 메모리 절약**
- 같은 메서드를 각 인스턴스마다 만들지 않고, 프로토타입에 한 번만 정의
- 모든 인스턴스가 프로토타입의 메서드를 공유

### 🌲 프로토타입 체인

```
특정 객체 → 생성자의 Prototype → Object.prototype → null
```

- 객체에서 프로퍼티/메서드를 찾을 때, 없으면 프로토타입을 거슬러 올라가며 탐색
- 최상위는 `Object.prototype`
- 그 위는 `null`

### 📝 프로토타입 접근 방법

#### ❌ `__proto__` (사용 비권장, Deprecated)
```javascript
console.log([].__proto__);
```

#### ✅ `Object.getPrototypeOf()` / `Object.setPrototypeOf()`
```javascript
Object.getPrototypeOf([]);  // 읽기
Object.setPrototypeOf(obj, proto);  // 수정
```

#### ⭐ 생성자 함수에서는 `.prototype`
```javascript
function Person(name) {
  this.name = name;
}

Person.prototype.greet = function() {
  console.log(`안녕, ${this.name}`);
};
```

### 🎯 인스턴스 프로퍼티 vs 프로토타입 프로퍼티

| 위치 | 특징 | 메모리 |
|------|------|--------|
| **인스턴스** | 각 객체마다 별도 생성 | 인스턴스 수만큼 차지 |
| **프로토타입** | 모든 인스턴스가 공유 | 한 번만 차지 ✅ |

```javascript
function YalcoChicken(name, no) {
  this.name = name;  // 인스턴스 프로퍼티
  this.no = no;
}

// 프로토타입 프로퍼티 (메모리 절약!)
YalcoChicken.prototype.introduce = function() {
  return `안녕하세요, ${this.no}호 ${this.name}점입니다!`;
};
```

### ⚠️ 자주 헷갈리는 포인트

1. **`__proto__`는 쓰지 말 것** → `Object.getPrototypeOf()` 사용
2. **생성자 함수의 `.prototype` ≠ 인스턴스의 `[[Prototype]]`**
    - `Person.prototype` : 생성자가 가진 프로토타입 객체
    - 인스턴스의 `[[Prototype]]` : 위 객체를 가리킴
3. **클래스의 메서드는 자동으로 프로토타입에 들어감**
   ```javascript
   class Dog {
     bark() {}  // Dog.prototype.bark
   }
   ```

## 2️⃣ 프로토타입 상속

### 💡 상속이란?

**부모 생성자의 프로토타입을 자식이 물려받아 재사용**

### 🔧 `Object.create()` 사용법

```javascript
function Bird(name, sound) {
  this.name = name;
  this.sound = sound;
}

Bird.prototype.fly = function() {
  console.log(`${this.name} 비행중`);
};

function Eagle(name, sound, prey) {
  Bird.call(this, name, sound);  // 부모 생성자 호출
  this.prey = prey;
}

// ⭐ 순서 중요! 상속 먼저
Eagle.prototype = Object.create(Bird.prototype);

// 그 다음 자신의 메서드 추가
Eagle.prototype.hunt = function() {
  console.log(`${this.name} 사냥중`);
};
```

### 🎯 언제 쓰는가?

- **공통 기능을 여러 생성자가 공유**해야 할 때
- 클래스의 `extends`가 내부적으로 이렇게 동작함

### ⚠️ 주의사항

1. **상속을 먼저 설정한 후 자식 메서드 추가**
   ```javascript
   // ❌ 잘못된 순서
   Eagle.prototype.hunt = function() {};
   Eagle.prototype = Object.create(Bird.prototype);  // hunt 날아감!
   
   // ✅ 올바른 순서
   Eagle.prototype = Object.create(Bird.prototype);
   Eagle.prototype.hunt = function() {};
   ```

2. **부모 생성자 호출은 `call()` 사용**
   ```javascript
   Bird.call(this, name, sound);  // this 바인딩
   ```

### 🧩 클래스로 상속

```javascript
class Bird {
  constructor(name, sound) {
    this.name = name;
    this.sound = sound;
  }
  
  fly() {  // 자동으로 Bird.prototype에 추가됨
    console.log(`${this.name} 비행중`);
  }
}

class Eagle extends Bird {
  constructor(name, sound, prey) {
    super(name, sound);  // 부모 생성자 호출
    this.prey = prey;
  }
  
  hunt() {
    console.log(`${this.name} 사냥중`);
  }
}
```

**클래스도 내부적으로는 프로토타입 기반!**

### 🎨 Mixin 패턴

**한 부모가 아니라 여러 기능을 조합**

```javascript
const runner = {
  run() { console.log(`${this.name} 질주중`); }
};

const swimmer = {
  swim() { console.log(`${this.name} 수영중`); }
};

const hunter = {
  hunt() { console.log(`${this.name} 사냥중`); }
};

class PolarBear {
  constructor(name) { this.name = name; }
}

// 여러 기능을 섞어서 추가
Object.assign(PolarBear.prototype, runner, swimmer, hunter);

const bear = new PolarBear('극곰이');
bear.run();   // 질주중
bear.swim();  // 수영중
bear.hunt();  // 사냥중
```

### 🔍 언제 쓰는가?

- **다중 상속이 필요할 때** (JS는 단일 상속만 지원)
- **여러 클래스에 공통 메서드를 추가**할 때

## 3️⃣ 비동기와 setTimeout

### 💡 비동기(Asynchronous)란?

**코드가 순서대로 실행되지 않는 것**
- 시간이 걸리는 작업을 나중에 처리
- 그동안 다른 코드를 먼저 실행

### ⏲️ `setTimeout()`

```javascript
setTimeout(콜백함수, 밀리초);

setTimeout(() => {
  console.log('1초 후 실행');
}, 1000);
```

### 🔍 언제 쓰는가?

- **일정 시간 후 작업 실행**
- **애니메이션, 타이머 구현**
- **딜레이 후 API 호출**
- **디바운싱/스로틀링** 구현

### 📊 실행 순서 예제

```javascript
console.log('1. 하나');

setTimeout(() => {
  console.log('2. 둘');
}, 0);  // 0초 후에도!

console.log('3. 셋');

// 출력:
// 1. 하나
// 3. 셋
// 2. 둘  ← 마지막에 출력됨
```

**왜 0초로 설정해도 나중에 실행될까?**

### 🏃 이벤트 루프 (Event Loop)

```
┌─ Call Stack (싱글 스레드) ─┐
│  동기 코드 실행             │
└─────────────────────────────┘
              ↓
┌─ Web API (멀티 스레드) ────┐
│  setTimeout, fetch 등       │
│  비동기 작업 처리           │
└─────────────────────────────┘
              ↓
┌─ Task Queue ───────────────┐
│  완료된 콜백 대기           │
└─────────────────────────────┘
              ↓
    이벤트 루프가 계속 확인
    Call Stack 비면 실행!
```

#### 🔄 동작 원리

1. **Call Stack** : 동기 코드 실행 (싱글 스레드)
2. **비동기 코드** 만나면 → Web API로 넘김
3. **Web API** : 타이머/네트워크 등 처리 (멀티 스레드)
4. 완료되면 **Task Queue**에 콜백 추가
5. **Event Loop** : Call Stack이 비면 Queue에서 하나씩 꺼내서 실행

### ⚠️ 자주 헷갈리는 포인트

1. **`setTimeout(..., 0)`도 비동기**
    - 동기 코드가 모두 끝난 후 실행됨

2. **비동기 코드 순서는 보장 안 됨**
   ```javascript
   setTimeout(() => console.log('A'), 100);
   setTimeout(() => console.log('B'), 50);
   // 출력: B → A
   ```

3. **자바스크립트는 싱글 스레드지만, 환경(브라우저, Node.js)은 멀티 스레드**
    - 비동기 작업은 환경에서 처리

### 💼 실무 패턴

```javascript
// 디바운싱 예제
let timer;
function debounce(callback, delay) {
  clearTimeout(timer);
  timer = setTimeout(callback, delay);
}

// 검색창에서 자주 사용
input.addEventListener('input', () => {
  debounce(() => {
    console.log('검색 API 호출');
  }, 300);
});
```

## 🎯 핵심 요약

### 프로토타입
- 모든 객체는 `[[Prototype]]` 가짐
- 프로토타입 체인으로 상위 프로퍼티 탐색
- **메모리 절약**: 공통 메서드는 프로토타입에 한 번만 정의
- 접근: `Object.getPrototypeOf()` 또는 생성자의 `.prototype`
- 클래스 메서드도 내부적으로 프로토타입에 추가됨

### 상속
- `Object.create(부모.prototype)`로 상속 구조 생성
- 순서: 상속 설정 → 자식 메서드 추가
- 부모 생성자는 `call()`로 호출
- Mixin: `Object.assign()`으로 여러 기능 조합

### 비동기
- 시간 걸리는 작업을 뒤로 미룸
- `setTimeout(콜백, 밀리초)`로 지연 실행
- **0초로 설정해도 동기 코드 후 실행**
- 이벤트 루프: Call Stack 비면 Task Queue에서 꺼내서 실행
- 자바스크립트 = 싱글 스레드, 환경 = 멀티 스레드

## 📝 복습 퀴즈

### Q1. 다음 코드의 출력 결과는?

```javascript
function Dog(name) {
  this.name = name;
}
Dog.prototype.bark = function() {
  console.log('멍멍');
};

const dog1 = new Dog('바둑이');
const dog2 = new Dog('순둥이');

console.log(dog1.bark === dog2.bark);
```

1. `true`
2. `false`
3. `undefined`
4. 에러 발생
5. `null`

**정답: 1번 `true`**

해설: `bark` 메서드는 `Dog.prototype`에 정의되어 있습니다. `dog1`과 `dog2`는 같은 프로토타입 객체를 참조하므로, 두 인스턴스의 `bark`는 동일한 함수 객체를 가리킵니다. 이것이 프로토타입을 사용한 메모리 절약의 핵심입니다.

### Q2. 다음 중 프로토타입 상속 구현 시 올바른 순서는?

```javascript
function Parent() {}
Parent.prototype.parentMethod = function() {};

function Child() {}
```

1. `Child.prototype.childMethod = function() {}; → Child.prototype = Object.create(Parent.prototype);`
2. `Child.prototype = Parent.prototype; → Child.prototype.childMethod = function() {};`
3. `Child.prototype = Object.create(Parent.prototype); → Child.prototype.childMethod = function() {};`
4. `Child.prototype = new Parent(); → Child.prototype.childMethod = function() {};`
5. `Child.prototype.childMethod = function() {}; → Child.prototype = new Parent();`

**정답: 3번**

해설: 상속 설정(`Object.create()`)을 먼저 해야 합니다. 그 다음 자식의 메서드를 추가해야 메서드가 사라지지 않습니다. 2번은 부모와 자식이 같은 프로토타입을 공유하게 되어 부모에도 영향을 줍니다. 4번의 `new Parent()`는 작동은 하지만 불필요한 인스턴스 생성이므로 `Object.create()`가 더 권장됩니다.

### Q3. 다음 코드의 출력 순서는?

```javascript
console.log('A');

setTimeout(() => {
  console.log('B');
}, 0);

console.log('C');

setTimeout(() => {
  console.log('D');
}, 0);

console.log('E');
```

1. A → B → C → D → E
2. A → C → E → B → D
3. A → C → B → E → D
4. B → D → A → C → E
5. A → B → C → E → D

**정답: 2번 A → C → E → B → D**

해설: `setTimeout`은 비동기 함수로, 지연 시간이 0이어도 Task Queue에 들어갑니다. 먼저 모든 동기 코드(A, C, E)가 실행된 후, Call Stack이 비면 이벤트 루프가 Queue에서 순서대로 콜백을 꺼내 실행합니다(B, D).

### Q4. 다음 코드에서 `eagle` 인스턴스가 사용할 수 있는 메서드는?

```javascript
function Bird(name) {
  this.name = name;
}
Bird.prototype.fly = function() {};

function Eagle(name) {
  Bird.call(this, name);
}
Eagle.prototype = Object.create(Bird.prototype);
Eagle.prototype.hunt = function() {};

const eagle = new Eagle('독수리');
```

1. `hunt()`만
2. `fly()`만
3. `hunt()`와 `fly()` 둘 다
4. 둘 다 사용 불가
5. `name()`만

**정답: 3번 `hunt()`와 `fly()` 둘 다**

해설: `Eagle.prototype = Object.create(Bird.prototype)`로 상속 구조를 만들었으므로, `eagle`은 프로토타입 체인을 통해 `Eagle.prototype.hunt()`와 `Bird.prototype.fly()` 모두 접근할 수 있습니다. 프로토타입 체인: `eagle` → `Eagle.prototype` → `Bird.prototype` → `Object.prototype`.

### Q5. `Object.assign()`을 사용한 Mixin 패턴의 특징이 아닌 것은?

1. 여러 객체의 메서드를 한 프로토타입에 복사할 수 있다
2. 단일 상속의 제약을 우회할 수 있다
3. 자동으로 프로토타입 체인을 생성한다
4. 같은 이름의 메서드가 있으면 나중 것으로 덮어씌워진다
5. 프로토타입에 직접 메서드를 추가하는 방식이다

**정답: 3번 자동으로 프로토타입 체인을 생성한다**

해설: `Object.assign()`은 단순히 객체의 프로퍼티를 복사하는 메서드입니다. 프로토타입 체인을 생성하지 않고, 대상 객체에 직접 메서드를 추가합니다. 프로토타입 체인은 `Object.create()`나 `extends`로 생성합니다. Mixin은 상속이 아니라 '조합'의 개념입니다.
