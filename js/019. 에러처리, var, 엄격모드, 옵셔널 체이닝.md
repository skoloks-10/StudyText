# JavaScript 에러 처리 & 핵심 문법 정리

## 📚 1. try...catch와 에러 핸들링

### 🎯 언제 사용하는가?
- 런타임에 발생할 수 있는 예상 가능한 에러를 처리할 때
- 외부 API 호출, JSON 파싱, 사용자 입력 검증 등
- 스크립트가 중단되는 것을 방지하고 싶을 때

### 📌 기본 구조

```javascript
try {
  // 에러가 발생할 수 있는 코드
} catch (err) {
  // 에러 처리
} finally {
  // 항상 실행되는 코드 (선택사항)
}
```

### ⚠️ 자주 헷갈리는 포인트

**1. try...catch는 런타임 에러만 잡는다**
```javascript
// ❌ 문법 에러는 잡지 못함
try {
  {{{{{{
} catch(e) {
  // 실행되지 않음
}

// ✅ 런타임 에러는 잡음
try {
  undefined_variable;
} catch(e) {
  console.log('에러 잡음!');
}
```

**2. 비동기 코드의 에러는 내부에서 처리해야 함**
```javascript
// ❌ 잡지 못함
try {
  setTimeout(() => {
    noSuchVariable;
  }, 1000);
} catch (e) {
  console.log('여기서는 못 잡음');
}

// ✅ 올바른 방법
setTimeout(() => {
  try {
    noSuchVariable;
  } catch (e) {
    console.log('여기서 잡음!');
  }
}, 1000);
```

### 💡 실무 패턴

**API 호출 시**
```javascript
async function fetchUserData(userId) {
  try {
    const response = await fetch(`/api/users/${userId}`);
    const data = await response.json();
    return data;
  } catch (error) {
    console.error('사용자 데이터 로딩 실패:', error);
    // 사용자에게 알림 표시
    showErrorMessage('데이터를 불러올 수 없습니다.');
    return null;
  }
}
```

**JSON 파싱 시**
```javascript
function parseUserData(jsonString) {
  try {
    const user = JSON.parse(jsonString);
    
    if (!user.name) {
      throw new ValidationError('이름이 필요합니다');
    }
    
    return user;
  } catch (e) {
    if (e instanceof SyntaxError) {
      console.error('잘못된 JSON 형식');
    } else if (e instanceof ValidationError) {
      console.error('유효성 검사 실패:', e.message);
    }
    return null;
  }
}
```

### 🔍 에러 객체의 주요 프로퍼티

```javascript
try {
  undefined_variable;
} catch (err) {
  console.log(err.name);     // "ReferenceError"
  console.log(err.message);  // "undefined_variable is not defined"
  console.log(err.stack);    // 호출 스택 정보
}
```

### 🎲 finally 활용

**언제 사용?**
- 에러 발생 여부와 관계없이 반드시 실행해야 하는 코드
- 리소스 정리, 로딩 인디케이터 숨기기, 시간 측정 등

```javascript
function loadData() {
  showLoadingSpinner();  // 로딩 표시
  
  try {
    const data = fetchData();
    processData(data);
  } catch (error) {
    showError(error);
  } finally {
    hideLoadingSpinner();  // 항상 실행됨
  }
}
```

## 🎨 2. 커스텀 에러와 에러 확장

### 🎯 언제 사용하는가?
- 에러 종류를 명확히 구분하고 싶을 때
- 에러에 추가 정보를 담고 싶을 때
- 도메인별로 에러를 체계적으로 관리하고 싶을 때

### 📌 기본 커스텀 에러 생성

```javascript
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}

// 사용
function validateUser(user) {
  if (!user.age) {
    throw new ValidationError('나이가 필요합니다');
  }
}
```

### 💡 실무 패턴: 에러 계층 구조

```javascript
// 기본 에러 클래스
class AppError extends Error {
  constructor(message) {
    super(message);
    this.name = this.constructor.name;  // 자동으로 클래스 이름 설정
  }
}

// 구체적인 에러들
class ValidationError extends AppError {}
class NetworkError extends AppError {}
class AuthError extends AppError {}

// 더 세분화된 에러
class EmailValidationError extends ValidationError {
  constructor(email) {
    super(`유효하지 않은 이메일: ${email}`);
    this.email = email;
  }
}
```

### 🔄 에러 다시 던지기 (Rethrowing)

**언제?**
- catch에서 처리할 수 없는 에러를 상위로 전달
- 특정 에러만 처리하고 나머지는 밖으로 보낼 때

```javascript
try {
  const user = JSON.parse(json);
  
  if (!user.name) {
    throw new ValidationError('이름 없음');
  }
  
  processUser(user);  // 알 수 없는 에러 발생 가능
  
} catch (e) {
  if (e instanceof ValidationError) {
    alert('검증 오류: ' + e.message);
  } else {
    throw e;  // 다른 에러는 다시 던짐
  }
}
```

### 🎁 예외 감싸기 (Exception Wrapping)

**목적:** 여러 종류의 에러를 하나의 포괄적인 에러로 통합

```javascript
class ReadError extends Error {
  constructor(message, cause) {
    super(message);
    this.cause = cause;  // 원본 에러 저장
    this.name = 'ReadError';
  }
}

function readUser(json) {
  try {
    const user = JSON.parse(json);
    validateUser(user);
    return user;
  } catch (err) {
    if (err instanceof SyntaxError) {
      throw new ReadError('JSON 파싱 실패', err);
    } else if (err instanceof ValidationError) {
      throw new ReadError('검증 실패', err);
    } else {
      throw err;
    }
  }
}

// 호출하는 쪽에서는 ReadError만 확인
try {
  const user = readUser(jsonData);
} catch (e) {
  if (e instanceof ReadError) {
    console.log('읽기 실패:', e.message);
    console.log('원인:', e.cause);  // 필요시 원본 에러 확인
  }
}
```

## 🔄 3. var의 특성 (피해야 할 이유)

### 🎯 알아야 하는 이유
- 레거시 코드 유지보수
- var를 let으로 리팩토링할 때 주의사항 파악
- 면접 질문 대비

### ⚠️ var의 문제점

**1. 블록 스코프 무시**
```javascript
// ❌ var는 블록을 무시함
if (true) {
  var x = 10;
}
console.log(x);  // 10 (접근 가능!)

// ✅ let은 블록 스코프를 지킴
if (true) {
  let y = 10;
}
console.log(y);  // ReferenceError
```

**2. 중복 선언 허용**
```javascript
var user = 'Pete';
var user = 'John';  // 에러 없음!
console.log(user);  // 'John'

let user2 = 'Pete';
let user2 = 'John';  // SyntaxError!
```

**3. 호이스팅**
```javascript
console.log(name);  // undefined (에러 아님!)
var name = 'John';

// 실제로는 이렇게 동작
var name;           // 선언은 최상단으로
console.log(name);  // undefined
name = 'John';      // 할당은 원래 위치에서
```

### 💡 let/const를 사용해야 하는 이유
- 블록 스코프로 변수 범위 명확
- 중복 선언 방지로 버그 감소
- 호이스팅 문제 해결 (TDZ)
- 모던 코드의 표준

## 🔒 4. 엄격 모드 (use strict)

### 🎯 언제 사용하는가?
- 실수로 전역 변수를 만드는 것을 방지
- 안전하지 않은 동작을 에러로 표시
- 더 나은 코드 품질 유지

### 📌 기본 사용법

```javascript
"use strict";  // 스크립트 최상단

// 또는 함수 내부에서만
function strictFunction() {
  "use strict";
  // 이 함수만 엄격 모드
}
```

### 💡 엄격 모드의 효과

**1. 선언 없는 변수 할당 금지**
```javascript
"use strict";
x = 10;  // ReferenceError!
```

**2. 읽기 전용 프로퍼티 쓰기 금지**
```javascript
"use strict";
const obj = {};
Object.defineProperty(obj, 'x', { value: 10, writable: false });
obj.x = 20;  // TypeError!
```

### ⚠️ 자주 헷갈리는 포인트
- 모듈과 클래스에서는 자동으로 엄격 모드 적용
- "use strict"는 반드시 최상단에 위치
- 일부만 적용하고 싶다면 함수 내부에서 사용

## ❓ 5. 옵셔널 체이닝 (?.)

### 🎯 언제 사용하는가?
- 중첩된 객체의 프로퍼티에 안전하게 접근
- null/undefined 체크를 간결하게 처리
- API 응답이나 선택적 데이터 다룰 때

### 📌 기본 사용법

```javascript
// ❌ 기존 방식 (길고 복잡)
const street = user && user.address && user.address.street;

// ✅ 옵셔널 체이닝
const street = user?.address?.street;
```

### 💡 실무 패턴

**1. 객체 프로퍼티 접근**
```javascript
const user = {
  name: 'John',
  address: {
    city: 'Seoul'
  }
};

console.log(user?.address?.city);    // 'Seoul'
console.log(user?.address?.street);  // undefined (에러 없음)
```

**2. 메서드 호출**
```javascript
const user = {
  admin() {
    console.log('관리자');
  }
};

user.admin?.();      // '관리자' 출력
user.regularUser?.(); // 에러 없음, 실행 안 됨
```

**3. 배열/대괄호 접근**
```javascript
const users = {
  list: ['John', 'Jane']
};

console.log(users?.list?.[0]);  // 'John'
console.log(users?.list?.[5]);  // undefined
```

**4. delete와 함께 사용**
```javascript
delete user?.address;  // user가 존재하면 address 삭제
```

### ⚠️ 주의사항

**1. 남용 금지**
```javascript
// ❌ 나쁜 예: 반드시 있어야 하는 값에 사용
const name = user?.name;  // user는 항상 있어야 함!

// ✅ 좋은 예: 선택적인 값에만 사용
const zipCode = user.address?.zipCode;
```

**2. 왼쪽 변수는 반드시 선언되어야 함**
```javascript
// ❌ user가 선언되지 않음
user?.name;  // ReferenceError

// ✅ 올바른 사용
let user;
user?.name;  // undefined
```

**3. 쓰기에는 사용 불가**
```javascript
user?.name = 'John';  // SyntaxError!
```

### 🎯 실전 활용

**API 응답 처리**
```javascript
async function getUserCity(userId) {
  const response = await fetch(`/api/users/${userId}`);
  const data = await response.json();
  
  // 안전하게 접근
  return data?.user?.address?.city ?? '도시 정보 없음';
}
```

**이벤트 핸들러**
```javascript
const button = document.querySelector('.my-button');
button?.addEventListener('click', handleClick);
// button이 없어도 에러 없음
```

## 📝 핵심 요약

### ✅ try...catch
- **목적:** 런타임 에러를 안전하게 처리
- **핵심:** 문법 에러는 못 잡음, 비동기는 내부에서 처리
- **패턴:** API 호출, JSON 파싱, 유효성 검증에 필수

### ✅ 커스텀 에러
- **목적:** 에러를 명확하게 구분하고 추가 정보 포함
- **핵심:** Error 상속, instanceof로 타입 체크
- **패턴:** 에러 계층 구조, 예외 감싸기

### ✅ var vs let/const
- **var 문제:** 블록 스코프 무시, 중복 선언 허용, 호이스팅
- **해결책:** let/const 사용 (모던 코드의 표준)
- **이유:** 더 안전하고 예측 가능한 코드

### ✅ use strict
- **목적:** 안전하지 않은 동작 방지
- **효과:** 선언 없는 변수 금지, 더 엄격한 에러 검출
- **자동 적용:** 모듈, 클래스

### ✅ 옵셔널 체이닝
- **목적:** null/undefined 안전하게 접근
- **문법:** `?.`, `?.()`, `?.[]`
- **주의:** 반드시 있어야 하는 값에는 사용 금지

## 🧪 복습용 객관식 퀴즈

### Q1. 다음 중 try...catch로 잡을 수 없는 에러는?
```javascript
// A
try {
  {{{{{
} catch(e) {
  console.log('잡힘');
}

// B
try {
  undefined_variable;
} catch(e) {
  console.log('잡힘');
}

// C
try {
  setTimeout(() => {
    throw new Error('에러');
  }, 100);
} catch(e) {
  console.log('잡힘');
}

// D
try {
  JSON.parse('잘못된 json');
} catch(e) {
  console.log('잡힘');
}
```

① A만  
② A와 C  
③ B와 D  
④ C만  
⑤ 모두 잡힘

**정답: ②**

A는 문법 에러(parse-time error)로 try...catch가 실행되기 전에 발생하므로 잡을 수 없습니다. C는 비동기 코드에서 발생한 에러로, try...catch가 이미 종료된 후에 에러가 발생하므로 잡을 수 없습니다. B와 D는 런타임 에러이므로 정상적으로 잡힙니다.

### Q2. 다음 코드의 출력 결과는?
```javascript
"use strict";

function test() {
  if (true) {
    var x = 10;
    let y = 20;
  }
  console.log(x);
  console.log(y);
}

test();
```

① 10, 20  
② 10, ReferenceError  
③ undefined, ReferenceError  
④ ReferenceError, ReferenceError  
⑤ 10, undefined

**정답: ②**

var는 함수 스코프를 가지므로 블록 밖에서도 접근 가능합니다(호이스팅됨). 하지만 let은 블록 스코프를 가지므로 if 블록 밖에서 접근 시 ReferenceError가 발생합니다.

### Q3. 옵셔널 체이닝에 대한 설명으로 올바른 것은?

① `user?.name = 'John'`은 user가 없을 때 안전하게 값을 할당한다  
② `user?.address?.street`에서 user가 null이면 에러가 발생한다  
③ `delete user?.name`은 user가 존재할 때만 name을 삭제한다  
④ 옵셔널 체이닝은 모든 프로퍼티 접근에 사용하는 것이 좋다  
⑤ `user?.getName?.()`에서 user가 없으면 TypeError가 발생한다

**정답: ③**

①은 쓰기에 사용할 수 없어 SyntaxError가 발생합니다. ②는 에러가 발생하지 않고 undefined를 반환합니다. ④는 남용하면 안 되며, 선택적인 값에만 사용해야 합니다. ⑤는 에러가 발생하지 않고 undefined를 반환합니다. ③이 정답으로, user가 존재할 때만 delete가 실행됩니다.

### Q4. 다음 중 커스텀 에러 생성에 대한 올바른 패턴은?

```javascript
// A
class MyError extends Error {
  constructor(message) {
    super(message);
    this.name = "MyError";
  }
}

// B
class MyError extends Error {
  constructor(message) {
    this.message = message;
  }
}

// C
class MyError extends Error {
  constructor(message) {
    super(message);
    this.name = this.constructor.name;
  }
}

// D
class MyError {
  constructor(message) {
    this.message = message;
    this.name = "MyError";
  }
}
```

① A만 올바름  
② A와 C만 올바름  
③ B와 D만 올바름  
④ C만 올바름  
⑤ 모두 올바름

**정답: ②**

A와 C는 올바른 패턴입니다. A는 name을 수동으로 설정하고, C는 자동으로 클래스 이름을 설정합니다. B는 super()를 호출하지 않아 부모 생성자가 실행되지 않습니다. D는 Error를 상속받지 않아 stack 추적 등의 기능이 없고, instanceof Error 체크도 불가능합니다.

### Q5. 다음 코드의 실행 결과는?
```javascript
let result;

try {
  result = riskyOperation();
  console.log('A');
} catch (error) {
  console.log('B');
} finally {
  console.log('C');
}

console.log('D');

// riskyOperation()이 에러를 던진다고 가정
```

① A, C, D  
② B, C, D  
③ A, D  
④ B, D  
⑤ C, D

**정답: ②**

riskyOperation()이 에러를 던지므로 try 블록의 나머지(A)는 실행되지 않습니다. 에러가 발생했으므로 catch 블록(B)이 실행됩니다. finally 블록(C)은 에러 발생 여부와 관계없이 항상 실행됩니다. 마지막으로 try...catch...finally 밖의 코드(D)가 실행됩니다. 따라서 출력 순서는 B → C → D입니다.
