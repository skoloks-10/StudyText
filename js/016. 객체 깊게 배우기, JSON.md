## 📌 Object 클래스

### 기본 개념

- 모든 JavaScript 객체의 원형(prototype)
- String, Number, Array, Function 등 모든 것이 Object의 인스턴스

```javascript
// 모든 객체는 Object의 인스턴스
new String('ABC') instanceof Object  // true
[] instanceof Object                 // true

```

## 🔧 Object 주요 정적 메서드

### 1️⃣ Object.assign()

**언제 쓰나요?**

- 여러 객체를 하나로 합칠 때
- 객체 복사가 필요할 때
- 기본값 설정 + 사용자 설정 병합할 때

```javascript
// 실무 패턴: 옵션 객체 병합
const defaultConfig = { timeout: 3000, retry: 3 };
const userConfig = { timeout: 5000 };
const finalConfig = Object.assign({}, defaultConfig, userConfig);
// { timeout: 5000, retry: 3 }
```

**⚠️ 자주 헷갈리는 포인트**

- 첫 번째 인자가 **변경됨** (원본 수정)
- **얕은 복사**만 수행 (중첩 객체는 참조 공유)
- 같은 키는 뒤에 오는 값으로 덮어씀

```javascript
const obj1 = { x: 1 };
Object.assign(obj1, { y: 2 });
console.log(obj1); // { x: 1, y: 2 } - obj1이 변경됨!

// 얕은 복사 문제
const original = { nested: { value: 1 } };
const copy = Object.assign({}, original);
copy.nested.value = 2;
console.log(original.nested.value); // 2 - 원본도 변경됨!
```

---

### 2️⃣ Object.keys() / values() / entries()

**언제 쓰나요?**

- 객체를 배열로 변환해서 반복 작업할 때
- 객체의 프로퍼티 개수 확인할 때
- 객체를 필터링/매핑할 때

```javascript
const user = { name: "김코딩", age: 25, job: "개발자" };

// 실무 패턴 1: 객체 필터링
const filtered = Object.fromEntries(
  Object.entries(user).filter(([key, value]) => typeof value === "string"),
);

// 실무 패턴 2: 객체 값 변환
const doubled = Object.fromEntries(
  Object.entries({ a: 1, b: 2 }).map(([k, v]) => [k, v * 2]),
);
```

**배열에 사용하면?**

```javascript
const arr = [10, 20, 30];
Object.keys(arr); // ['0', '1', '2'] - 인덱스가 키
Object.values(arr); // [10, 20, 30]
```

### 3️⃣ Object.preventExtensions()

**언제 쓰나요?**

- 객체에 새 프로퍼티 추가를 막고 싶을 때
- 기존 프로퍼티는 수정/삭제 가능

```javascript
const config = { apiKey: "secret" };
Object.preventExtensions(config);

config.apiKey = "new-secret"; // ✅ 수정 가능
delete config.apiKey; // ✅ 삭제 가능
config.newProp = "value"; // ❌ 추가 불가 (조용히 실패)
```

---

### 4️⃣ Object.seal()

**언제 쓰나요?**

- 프로퍼티 추가/삭제는 막고, 값 변경만 허용할 때
- 객체 구조를 고정하고 싶을 때

```javascript
const settings = { theme: "dark", lang: "ko" };
Object.seal(settings);

settings.theme = "light"; // ✅ 수정 가능
delete settings.lang; // ❌ 삭제 불가
settings.newSetting = "val"; // ❌ 추가 불가
```

**비교표**

| 메서드            | 추가 | 삭제 | 수정 |
| ----------------- | ---- | ---- | ---- |
| preventExtensions | ❌   | ✅   | ✅   |
| seal              | ❌   | ❌   | ✅   |
| freeze            | ❌   | ❌   | ❌   |

---

### 5️⃣ Object.freeze()

**언제 쓰나요?**

- 완전히 불변 객체를 만들 때
- 상수 객체를 정의할 때

```javascript
const CONSTANTS = Object.freeze({
  API_URL: "https://api.example.com",
  MAX_RETRY: 3,
});

CONSTANTS.API_URL = "hacked"; // ❌ 아무 일도 일어나지 않음
```

**⚠️ 얕게만 동결됨!**

```javascript
const obj = Object.freeze({
  x: 1,
  nested: { y: 2 },
});

obj.x = 10; // ❌ 변경 안됨
obj.nested.y = 20; // ✅ 변경됨! (중첩 객체는 동결 안됨)
```

## 🔐 프로퍼티 어트리뷰트

### 데이터 프로퍼티 속성

| 어트리뷰트       | 의미                     | 기본값    |
| ---------------- | ------------------------ | --------- |
| [[Value]]        | 프로퍼티 값              | undefined |
| [[Writable]]     | 수정 가능 여부           | false     |
| [[Enumerable]]   | 열거 가능 여부           | false     |
| [[Configurable]] | 삭제/설정 변경 가능 여부 | false     |

### 접근자 프로퍼티 속성

```javascript
const person = {
  firstName: "길동",
  lastName: "홍",

  // getter
  get fullName() {
    return `${this.lastName}${this.firstName}`;
  },

  // setter
  set fullName(name) {
    [this.lastName, this.firstName] = name.split(" ");
  },
};

person.fullName = "김 철수";
console.log(person.firstName); // '철수'
```

### Object.defineProperty()

**언제 쓰나요?**

- 프로퍼티 동작을 세밀하게 제어할 때
- 읽기 전용 프로퍼티를 만들 때
- 숨겨진 프로퍼티를 만들 때

```javascript
const user = {};

// 읽기 전용 프로퍼티
Object.defineProperty(user, "id", {
  value: 12345,
  writable: false, // 수정 불가
  enumerable: true, // for-in, Object.keys에 노출
  configurable: false, // 삭제 및 속성 변경 불가
});

user.id = 99999; // ❌ 변경 안됨
delete user.id; // ❌ 삭제 안됨
```

**실무 패턴: 숨겨진 프로퍼티**

```javascript
const obj = { public: "visible" };

Object.defineProperty(obj, "secret", {
  value: "hidden",
  enumerable: false, // Object.keys()에 안 나타남
});

console.log(Object.keys(obj)); // ['public']
console.log(obj.secret); // 'hidden' - 접근은 가능
```

### Object.getOwnPropertyDescriptor()

**언제 쓰나요?**

- 프로퍼티 속성 확인할 때
- 디버깅할 때

```javascript
const obj = { name: "test" };

console.log(Object.getOwnPropertyDescriptor(obj, "name"));
// {
//   value: 'test',
//   writable: true,
//   enumerable: true,
//   configurable: true
// }
```

### 깊은 동결 (Deep Freeze)

**언제 쓰나요?**

- 중첩된 객체까지 완전히 불변으로 만들 때

```javascript
function deepFreeze(obj) {
  const propNames = Object.getOwnPropertyNames(obj);

  for (const name of propNames) {
    const value = obj[name];
    if (value && typeof value === "object") {
      deepFreeze(value);
    }
  }

  return Object.freeze(obj);
}

const config = {
  db: {
    host: "localhost",
    credentials: { user: "admin" },
  },
};

deepFreeze(config);
config.db.credentials.user = "hacker"; // ❌ 변경 안됨
```

## 📄 JSON (JavaScript Object Notation)

### JSON.stringify()

**언제 쓰나요?**

- 서버에 데이터 전송할 때
- localStorage에 객체 저장할 때
- 객체를 문자열로 변환해야 할 때

```javascript
const user = {
  name: "김철수",
  age: 30,
  skills: ["JS", "React"],
};

const json = JSON.stringify(user);
// '{"name":"김철수","age":30,"skills":["JS","React"]}'
```

**⚠️ 직렬화 안 되는 것들**

```javascript
JSON.stringify({
  fn: () => {}, // undefined (함수 제외)
  sym: Symbol("hi"), // undefined (심볼 제외)
  inf: Infinity, // null
  nan: NaN, // null
  date: new Date(), // "2024-01-22T..." (문자열로 변환)
  // bigInt: 1n           // ❌ 에러 발생
});
```

**실무 패턴 1: replacer로 필터링**

```javascript
const obj = { password: "secret", username: "user", email: "test@test.com" };

const safe = JSON.stringify(obj, (key, value) => {
  if (key === "password") return undefined; // 비밀번호 제외
  return value;
});
// {"username":"user","email":"test@test.com"}
```

**실무 패턴 2: 특정 키만 직렬화**

```javascript
const data = { id: 1, name: "test", secret: "hide", token: "xxx" };
const publicData = JSON.stringify(data, ["id", "name"]);
// {"id":1,"name":"test"}
```

**가독성 높이기**

```javascript
const obj = { a: 1, b: { c: 2 } };

JSON.stringify(obj, null, 2);
// {
//   "a": 1,
//   "b": {
//     "c": 2
//   }
// }
```

### JSON.parse()

**언제 쓰나요?**

- 서버에서 받은 JSON 문자열을 객체로 변환할 때
- localStorage에서 데이터 읽어올 때

```javascript
const json = '{"name":"김철수","age":30}';
const obj = JSON.parse(json);
console.log(obj.name); // '김철수'
```

**⚠️ 주의사항**

```javascript
// ❌ 잘못된 JSON
JSON.parse('{name: "test"}'); // 에러 (키에 따옴표 없음)
JSON.parse("{'name': 'test'}"); // 에러 (작은따옴표 사용)

// ✅ 올바른 JSON
JSON.parse('{"name": "test"}'); // OK
```

**실무 패턴: reviver로 데이터 변환**

```javascript
const json = '{"date":"2024-01-22T10:00:00.000Z","count":"100"}';

const obj = JSON.parse(json, (key, value) => {
  if (key === "date") return new Date(value); // Date 객체로 복원
  if (key === "count") return Number(value); // 숫자로 변환
  return value;
});

console.log(obj.date instanceof Date); // true
console.log(typeof obj.count); // 'number'
```

## 📋 깊은 복사 (Deep Copy)

### 방법 1: JSON 활용

**언제 쓰나요?**

- 간단한 데이터 구조 복사할 때
- 함수, Symbol 등이 없을 때

```javascript
const original = {
  a: 1,
  b: { c: 2 },
};

const copy = JSON.parse(JSON.stringify(original));

original.b.c = 999;
console.log(copy.b.c); // 2 (영향 없음)
```

**⚠️ 한계**

```javascript
const obj = {
  fn: () => {}, // 함수 사라짐
  date: new Date(), // 문자열로 변환됨
  sym: Symbol("hi"), // 사라짐
  undef: undefined, // 사라짐
  // big: 1n            // 에러
};

const copy = JSON.parse(JSON.stringify(obj));
console.log(copy); // { date: "2024-01-22T..." }
```

---

### 방법 2: structuredClone()

**언제 쓰나요?**

- Date, Map, Set 등을 제대로 복사해야 할 때
- JSON 방식보다 빠른 성능이 필요할 때
- 최신 브라우저 환경에서

```javascript
const original = {
  date: new Date(),
  big: 1n,
  map: new Map([["key", "value"]]),
};

const copy = structuredClone(original);

console.log(copy.date instanceof Date); // true
console.log(copy.big === 1n); // true
console.log(copy.map instanceof Map); // true
```

**비교표**

| 특징          | JSON 방식     | structuredClone |
| ------------- | ------------- | --------------- |
| 함수          | ❌            | ❌              |
| Symbol        | ❌            | ❌              |
| Date          | 문자열로 변환 | ✅              |
| BigInt        | ❌ 에러       | ✅              |
| Map/Set       | ❌            | ✅              |
| 성능          | 느림          | 빠름            |
| 브라우저 지원 | 전부          | 최신만          |

## ⚡ 최종 핵심 요약

### Object 메서드 사용 시나리오

```
Object.assign()      → 객체 병합, 옵션 설정
Object.keys/values   → 객체를 배열로 변환해서 처리
Object.freeze()      → 상수 객체 정의
Object.seal()        → 구조 고정, 값만 변경
defineProperty()     → 세밀한 프로퍼티 제어
```

### 동결 단계별

```
일반 객체
  ↓ preventExtensions
추가 금지 (수정/삭제 가능)
  ↓ seal
추가/삭제 금지 (수정만 가능)
  ↓ freeze
완전 읽기 전용 (얕은 동결)
  ↓ deepFreeze
완전 불변 (깊은 동결)
```

### JSON 사용

```
직렬화: 객체 → 문자열 (stringify)
역직렬화: 문자열 → 객체 (parse)

주의: 함수, Symbol, undefined는 사라짐
Date는 문자열로 변환됨
BigInt는 에러 발생
```

### 깊은 복사

```
간단한 경우: JSON.parse(JSON.stringify(obj))
복잡한 경우: structuredClone(obj) (최신 환경)
```

## 📝 복습 퀴즈

### Q1. Object.assign()의 동작에 대한 설명으로 옳은 것은?

1. 깊은 복사를 수행하여 중첩된 객체도 완전히 복사된다
2. 첫 번째 인자 객체는 변경되지 않고 새로운 객체를 반환한다
3. 첫 번째 인자 객체가 변경되며, 얕은 복사만 수행된다
4. 함수 프로퍼티는 복사되지 않는다
5. 같은 키가 있으면 앞에 오는 값을 우선한다

**정답: 3번**

해설: Object.assign()은 첫 번째 인자로 받은 대상 객체를 직접 변경하고 반환합니다. 또한 얕은 복사(shallow copy)만 수행하므로 중첩된 객체는 참조가 복사됩니다. 같은 키가 있으면 뒤에 오는 값이 앞의 값을 덮어씁니다.

### Q2. 다음 코드의 실행 결과는?

```javascript
const obj = { x: 1, y: { z: 2 } };
Object.freeze(obj);
obj.x = 10;
obj.y.z = 20;
console.log(obj.x, obj.y.z);
```

1. 1, 2
2. 10, 20
3. 1, 20
4. 10, 2
5. 에러 발생

**정답: 3번 (1, 20)**

해설: Object.freeze()는 얕은 동결(shallow freeze)만 수행합니다. 따라서 obj.x = 10은 무시되어 x는 1로 유지되지만, 중첩된 객체 obj.y는 동결되지 않아서 obj.y.z = 20은 성공적으로 실행됩니다.

### Q3. JSON.stringify()로 직렬화할 때 결과에 포함되지 않는 것은?

1. 문자열 값
2. 숫자 값
3. 함수 값
4. 배열 값
5. null 값

**정답: 3번**

해설: JSON.stringify()는 함수, Symbol, undefined를 직렬화에서 제외합니다. 객체의 프로퍼티가 함수인 경우 해당 프로퍼티는 결과 문자열에 포함되지 않습니다.

### Q4. 다음 중 프로퍼티 추가만 금지하고 수정과 삭제는 허용하는 메서드는?

1. Object.freeze()
2. Object.seal()
3. Object.preventExtensions()
4. Object.defineProperty()
5. Object.lock()

**정답: 3번**

해설: Object.preventExtensions()는 새로운 프로퍼티 추가만 금지하고, 기존 프로퍼티의 수정과 삭제는 허용합니다. Object.seal()은 추가와 삭제를 모두 금지하고, Object.freeze()는 추가, 삭제, 수정을 모두 금지합니다.

### Q5. 깊은 복사를 위해 JSON을 사용하는 방법의 한계가 아닌 것은?

1. 함수는 복사되지 않는다
2. Date 객체는 문자열로 변환된다
3. 숫자 값이 복사되지 않는다
4. Symbol은 복사되지 않는다
5. BigInt는 에러를 발생시킨다

**정답: 3번**

해설: JSON 방식의 깊은 복사에서 일반 숫자 값은 정상적으로 복사됩니다. 하지만 함수, Symbol, undefined는 제외되고, Date는 문자열로 변환되며, BigInt는 에러를 발생시킵니다.

### Q6. 다음 코드의 실행 결과는?

```javascript
const obj = { a: 1, b: 2, c: 3 };
const result = JSON.stringify(obj, ["a", "c"]);
```

1. "{"a":1,"b":2,"c":3}"
2. "{"a":1,"c":3}"
3. "{"b":2}"
4. "{}"
5. 에러 발생

**정답: 2번**

해설: JSON.stringify()의 두 번째 인자로 배열을 전달하면 해당 키들만 직렬화됩니다. 따라서 'a'와 'c' 프로퍼티만 결과에 포함됩니다.

### Q7. Object.seal()과 Object.freeze()의 차이점으로 옳은 것은?

1. seal은 수정을 허용하지만 freeze는 허용하지 않는다
2. seal은 삭제를 허용하지만 freeze는 허용하지 않는다
3. seal은 추가를 허용하지만 freeze는 허용하지 않는다
4. 둘 다 동일하게 동작한다
5. seal은 깊은 동결이지만 freeze는 얕은 동결이다

**정답: 1번**

해설: Object.seal()은 프로퍼티 추가와 삭제를 금지하지만 기존 프로퍼티 값의 수정은 허용합니다. 반면 Object.freeze()는 추가, 삭제, 수정을 모두 금지합니다. 둘 다 얕은 동결만 수행합니다.

### Q8. structuredClone()의 장점이 아닌 것은?

1. JSON 방식보다 빠르다
2. Date 객체를 제대로 복사한다
3. BigInt를 복사할 수 있다
4. 함수를 복사할 수 있다
5. Map과 Set을 복사할 수 있다

**정답: 4번**

해설: structuredClone()도 함수와 Symbol은 복사할 수 없습니다. 하지만 JSON 방식과 달리 Date, BigInt, Map, Set 등을 제대로 복사할 수 있고 성능도 더 우수합니다.
