## 📌 HTML에 JavaScript 불러오기

### 🔴 잘못된 방법들과 그 이유

#### 1️⃣ `<head>`에서 직접 로드
```html
<head>
  <script src="./script.js"></script>
</head>
<body>
  <span>변경 전...</span>
</body>
```

**문제점**
- DOM 요소가 아직 로드되지 않아 `querySelector`가 null 반환
- 스크립트가 클 경우 페이지 렌더링이 지연됨 (동기적 로드)

#### 2️⃣ `<body>` 맨 아래에 로드
```html
<body>
  <span>변경 전...</span>
  <script src="./script.js"></script>
</body>
```

**문제점**
- 동작은 하지만 HTML 문서가 길면 스크립트 로드가 늦어짐
- 구조상 스크립트가 문서 끝에 있어야 하는 제약

#### 3️⃣ `window.onload` 이벤트 사용
```javascript
window.onload = function () {
  document.querySelector('span').innerText = '텍스트 변경됨';
}
```

**문제점**
- 추가 이벤트 리스너 코드 필요
- 여전히 동기적 로드 문제 존재

---

### ✅ 올바른 방법: `defer` 속성

```html
<head>
  <script defer src="./script.js"></script>
</head>
<body>
  <span>변경 전...</span>
</body>
```

**왜 `defer`가 최선인가?**
- HTML 파싱과 **병렬로 비동기 다운로드**
- HTML 파싱이 **완료된 후** 순서대로 실행
- 별도의 이벤트 리스너 불필요
- 페이지 로딩 속도 개선

> **💡 `async` vs `defer`**
> - `async`: 다운로드 완료 즉시 실행 (순서 보장 X)
> - `defer`: HTML 파싱 후 순서대로 실행 (권장)

## 🧩 모듈 시스템

### ⚠️ 여러 스크립트 파일 사용 시 문제점

#### 문제 1: 네임스페이스 충돌
```html
<script defer src="./script1.js"></script>
<script defer src="./script2.js"></script>
```

```javascript
// script1.js
const x = 1;

// script2.js
const x = 2; // ❌ 오류: 이미 선언된 변수
```

**실무 문제**
- 대규모 프로젝트에서 변수명 중복 확인 어려움
- 팀 협업 시 네이밍 충돌 빈번

#### 문제 2: 파일 순서 의존성
```javascript
// script1.js
const x = 1;

// script2.js
console.log(x, y); // script1의 x에 의존
```

**실무 문제**
- 파일 순서 변경 시 오류 발생
- 의존성 관리 복잡

### ✅ ES6 모듈 사용하기

#### 기본 문법

**모듈 내보내기 (`export`)**
```javascript
// module1.js
export const x = 1;
export const y = 2;

export const person = {
  name: '홍길동',
  age: 20
};
```

**모듈 가져오기 (`import`)**
```javascript
// main.js
import { x, y, person } from './module1.js';

console.log(x, y); // 1 2
console.log(person); // { name: '홍길동', age: 20 }
```

**HTML에서 모듈 로드**
```html
<script type="module" src="./main.js"></script>
```

> **🎯 핵심**: `type="module"` 속성 추가 시 자동으로 `defer` 방식 적용

---

### 📚 다양한 모듈 패턴

#### 1️⃣ 이름 변경하여 가져오기
```javascript
import {
  x as a,
  y as b,
  person as individual
} from './module1.js';
```

**언제 쓰나?**
- 여러 모듈에서 같은 이름의 변수를 가져올 때
- 더 명확한 이름으로 사용하고 싶을 때

#### 2️⃣ 선별적 가져오기
```javascript
// 필요한 것만 선택
import { x, y } from './module1.js';
import { add, mult } from './module2.js';
import { Eagle } from './module3.js';
```

**실무 팁**: 사용하지 않는 코드까지 로드하면 번들 크기 증가

#### 3️⃣ 네임스페이스로 묶어서 가져오기
```javascript
import * as funcs from './module4.js';

funcs.logResult(
  [1, 2, 3, 4, 5].filter(funcs.isOdd)
);
```

**언제 쓰나?**
- 특정 모듈의 여러 함수를 하나의 객체로 관리하고 싶을 때
- 함수명이 짧아서 헷갈릴 수 있을 때

#### 4️⃣ `default` export
```javascript
// module5.js
export default {
  x: 1,
  isEven: x => !(x % 2)
};

// main.js
import mod5 from './module5.js'; // 중괄호 없음!
```

**규칙**
- 한 파일당 하나의 `default` export만 가능
- `let`, `const` 키워드와 함께 사용 불가
- import 시 중괄호 `{}` 사용하지 않음

**언제 쓰나?**
- 특정 주제의 유틸리티 함수들을 하나의 객체로 제공할 때
- 라이브러리의 메인 기능을 제공할 때

---

### 🌟 모듈의 특별한 기능

#### Top-level `await` 사용 가능
```javascript
// 모듈에서는 async 함수 없이도 await 직접 사용 가능
const raceResults = await fetch(
  'https://api.example.com/race-result'
).then(response => response.json());

console.log(raceResults);
```

**실무에서 자주 쓰는 경우**
- API 데이터를 모듈 로드 시점에 가져와야 할 때
- 설정 파일을 비동기로 로드할 때

---

### 📦 외부 라이브러리 사용

#### CDN에서 직접 로드
```javascript
import Big from 'https://unpkg.com/big.js@6.2.1/big.mjs';

console.log(
  new Big(0.1).plus(0.2).toNumber() // 0.3 (정확함)
);
```

#### 로컬 파일로 다운로드 후 사용
```javascript
import Big from './big.mjs';

// 부동소수점 연산 문제 해결
console.log(0.1 + 0.2); // 0.30000000000000004
console.log(new Big(0.1).plus(0.2).toNumber()); // 0.3
```

**실무 팁**: 프로덕션에서는 로컬 파일 사용 권장 (CDN 장애 대비)

## 🎁 Webpack: 번들러

### 📖 Webpack이란?

**정의**: 여러 JavaScript 파일을 하나 또는 소수의 파일로 압축하는 도구

**왜 사용하나?**
- 여러 모듈을 하나로 합쳐 HTTP 요청 횟수 감소
- 파일 크기 최적화로 로딩 속도 향상
- 코드 난독화로 보안 강화

**유사 도구**: Rollup, Parcel, Vite, Gulp

---

### 🛠️ Webpack 설정 방법

#### 1단계: 소스 폴리 분리
```
프로젝트/
  ├─ src/
  │   ├─ main.js
  │   ├─ module1.js
  │   └─ module2.js
  └─ index.html
```

#### 2단계: 설치
```bash
npm install webpack webpack-cli --save-dev
```

#### 3단계: 설정 파일 작성
```javascript
// webpack.config.js
const path = require('path');

module.exports = {
  entry: './src/main.js',
  output: {
    filename: 'main.js',
    path: path.resolve(__dirname, 'dist'),
  },
  watch: true, // 파일 변경 시 자동 재빌드
  experiments: {
    topLevelAwait: true // 모듈 await 가능
  }
};
```

**설정 설명**
- `entry`: 시작점 파일 (모든 모듈이 여기서부터 연결됨)
- `output`: 빌드 결과물 위치
- `watch`: 개발 중 실시간 반영

#### 4단계: 빌드 명령 추가
```json
// package.json
{
  "scripts": {
    "build": "webpack"
  }
  // "type": "module" 삭제!
}
```

#### 5단계: 빌드 및 사용
```bash
npm run build
```

```html
<!-- index.html -->
<script defer src="./dist/main.js"></script>
```

## 🔄 Babel: 트랜스파일러

### 📖 Babel이란?

**정의**: 최신 JavaScript 문법을 구형 브라우저에서도 동작하도록 변환하는 도구

**왜 필요한가?**
- IE 11 같은 구형 브라우저 지원
- 최신 문법(`const`, `let`, 화살표 함수 등)을 ES5로 변환

---

### 🧪 Babel 변환 예시

**입력 (ES6+)**
```javascript
const x = 1;
const add = (x, y) => x + y;
class Bird {
  wings = 2
}
```

**출력 (ES5)**
```javascript
var x = 1;
var add = function(x, y) { return x + y; };
var Bird = function() {
  this.wings = 2;
};
```

---

### 🛠️ Webpack에 Babel 적용

#### 1단계: 설치
```bash
npm install --save-dev babel-loader @babel/core @babel/preset-env
```

#### 2단계: Webpack 설정 추가
```javascript
// webpack.config.js
module.exports = {
  target: ['web', 'es5'], // ES5로 변환
  module: {
    rules: [
      {
        test: /\.m?js$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
          options: {
            presets: [
              ['@babel/preset-env', { targets: "ie 11" }]
            ]
          }
        }
      }
    ]
  }
};
```

**설정 설명**
- `test`: `.js` 또는 `.mjs` 파일에 적용
- `exclude`: `node_modules`는 변환하지 않음 (이미 변환된 코드)
- `targets`: 지원할 브라우저 버전

#### 3단계: 빌드
```bash
npm run build
```

## 🎯 핵심 요약

### HTML에 스크립트 로드
- ✅ **`defer` 속성 사용**이 최선
- `async`는 실행 순서 보장 안 됨
- 모듈(`type="module"`)은 자동 defer 적용

### 모듈 시스템
- **`export`**: 다른 파일에서 사용할 코드 공개
- **`import`**: 필요한 코드만 선택적으로 가져오기
- **`import * as`**: 네임스페이스로 묶어서 관리
- **`export default`**: 파일당 하나의 메인 값 제공
- **모듈에서는 top-level `await` 가능**

### 주요 차이점
| 방식 | 네임스페이스 | 순서 의존성 | 비동기 로드 |
|------|--------------|-------------|-------------|
| 여러 스크립트 | ❌ 충돌 위험 | ❌ 순서 의존 | ⚠️ 옵션 필요 |
| 모듈 | ✅ 독립적 | ✅ 명시적 import | ✅ 자동 |

### Webpack
- **목적**: 여러 파일을 하나로 번들링
- **장점**: 로딩 속도 향상, 코드 최적화
- **핵심 설정**: `entry`, `output`, `watch`

### Babel
- **목적**: 최신 문법 → 구형 브라우저 호환 코드 변환
- **사용 예**: `const` → `var`, 클래스 → 함수
- **Webpack과 함께 사용**: `babel-loader`로 통합

## 📝 복습 퀴즈

### Q1. HTML에서 JavaScript를 로드할 때 권장되는 방법은?
1. `<head>`에 `<script src="script.js"></script>` 추가
2. `<body>` 맨 아래에 `<script src="script.js"></script>` 추가
3. `<head>`에 `<script defer src="script.js"></script>` 추가
4. `<head>`에 `<script async src="script.js"></script>` 추가

**정답: 3번**
`defer` 속성은 HTML 파싱과 병렬로 스크립트를 다운로드하고, 파싱이 완료된 후 순서대로 실행합니다. 별도의 이벤트 리스너 없이도 DOM 요소에 안전하게 접근할 수 있으며, 페이지 로딩 속도도 개선됩니다.

---

### Q2. 다음 중 ES6 모듈에 대한 설명으로 올바르지 않은 것은?
1. `export default`는 파일당 여러 개 선언할 수 있다
2. `import * as name`으로 모든 export를 하나의 객체로 가져올 수 있다
3. 모듈에서는 top-level `await`를 사용할 수 있다
4. `type="module"` 속성이 있는 스크립트는 자동으로 defer 방식으로 로드된다

**정답: 1번**
`export default`는 파일당 하나만 선언할 수 있습니다. 한 파일에서 여러 개의 일반 export는 가능하지만, default export는 오직 하나만 존재해야 합니다.

---

### Q3. 다음 코드의 실행 결과는?
```javascript
// module.js
export const x = 10;
export const y = 20;

// main.js
import { x as a, y as x } from './module.js';
console.log(a, x);
```
1. 10 20
2. 20 10
3. 10 10
4. 에러 발생

**정답: 1번**
`import`에서 `as` 키워드를 사용하면 원하는 이름으로 변경하여 가져올 수 있습니다. `x`를 `a`로, `y`를 `x`로 이름을 바꿨지만, 가져오는 값 자체는 원본 모듈의 `x`(10)와 `y`(20)이므로 출력은 `10 20`입니다.

### Q4. Webpack에 대한 설명으로 올바른 것은?
1. Webpack은 JavaScript 코드를 구형 브라우저 호환 코드로 변환한다
2. Webpack은 여러 모듈 파일을 하나 또는 소수의 파일로 번들링한다
3. Webpack은 자동으로 Babel 기능을 포함하고 있다
4. Webpack 설정 파일에서 `entry`는 빌드 결과물의 위치를 지정한다

**정답: 2번**
Webpack은 번들러로, 여러 JavaScript 모듈과 의존성을 하나의 파일(또는 소수의 파일)로 묶어주는 도구입니다. 코드 변환은 Babel의 역할이며(1번), Babel은 별도로 설치 및 설정해야 합니다(3번). `entry`는 번들링의 시작점을 지정하고, `output`이 결과물 위치를 지정합니다(4번).

---

### Q5. Babel과 Webpack을 함께 사용할 때 필요한 설정으로 올바른 것은?
1. `package.json`에 `"type": "module"` 추가
2. `webpack.config.js`의 `module.rules`에 `babel-loader` 설정 추가
3. HTML 파일에 `<script type="babel">`로 스크립트 로드
4. 모든 `.js` 파일명을 `.babel.js`로 변경

**정답: 2번**
Webpack에서 Babel을 사용하려면 `webpack.config.js`의 `module.rules` 항목에 `babel-loader`를 설정해야 합니다. 이를 통해 Webpack이 번들링 과정에서 자동으로 Babel을 거쳐 코드를 변환하게 됩니다. `package.json`의 `"type": "module"`은 Webpack 사용 시 오히려 제거해야 하며(1번), 나머지 옵션들은 존재하지 않는 방법입니다.
