## 1. 클래스 기본

### 1.1 클래스란?

**출처** : ES6(ECMAScript 2015)에서 도입된 문법

**개념** : 클래스는 객체 지향 프로그래밍의 핵심 개념으로, 객체를 생성하기 위한 템플릿입니다. JavaScript에서는 **Syntactic Sugar** (문법적 설탕)로, 기존의 프로토타입 기반 상속을 더 명확하고 간결하게 작성할 수 있게 해줍니다.

**중요** : 클래스는 생성자 함수의 대체가 아니라, 가독성을 높이기 위한 문법적 편의입니다. 내부적으로는 여전히 프로토타입 기반으로 동작합니다.

### 1.2 클래스 선언과 인스턴스 생성

**문법적 속성** :

- `class` 키워드로 클래스를 선언합니다
- `new` 키워드로 인스턴스를 생성합니다
- 클래스명은 관례상 대문자로 시작합니다 (PascalCase)

  **사용 상황** : 동일한 구조를 가진 여러 객체를 생성할 때 사용합니다.

  **예시 코드** :

```jsx
class YalcoChicken {
  constructor(name, no) {
    this.name = name;
    this.no = no;
  }

  introduce() {
    return `안녕하세요, ${this.no}호 ${this.name}점입니다!`;
  }
}

const chain1 = new YalcoChicken("판교", 3);
const chain2 = new YalcoChicken("강남", 17);

console.log(chain1.introduce()); // "안녕하세요, 3호 판교점입니다!"
console.log(chain2.introduce()); // "안녕하세요, 17호 강남점입니다!"
```

### 1.3 클래스와 생성자 함수의 차이

**차이점 1 - 호이스팅** :

- 클래스는 호이스팅되지 않습니다 (정확히는 TDZ에 있음)
- 생성자 함수는 함수 호이스팅이 발생합니다

```jsx
// ❌ 오류 발생
const chain1 = new YalcoChicken("판교", 3);

class YalcoChicken {
  constructor(name, no) {
    this.name = name;
    this.no = no;
  }
}
```

**차이점 2 - new 키워드 필수** :

- 클래스는 `new` 없이 호출하면 오류 발생
- 생성자 함수는 `new` 없이 호출 가능 (undefined 반환)

```jsx
class YalcoChicken {
  constructor(name, no) {
    this.name = name;
    this.no = no;
  }
}

// ❌ 오류 발생
const chain = YalcoChicken("강남", 17);
```

**차이점 3 - 엄격 모드** :

- 클래스 내부는 자동으로 엄격 모드(strict mode)가 적용됩니다

### 1.4 Constructor 메서드

**개념** : 인스턴스 생성 시 자동으로 호출되는 특수 메서드로, 프로퍼티 초기화를 담당합니다.

**문법적 속성** :

- 클래스 당 하나만 존재 가능
- 메서드명은 반드시 `constructor`
- 기본값 설정 가능
- 인자가 없으면 생략 가능
- 값을 반환하지 않음 (암묵적으로 `this` 반환)

  **사용 상황** : 인스턴스 생성 시 초기 상태를 설정할 때 사용합니다.

  **예시 코드** :

```jsx
class Person {
  constructor(name, age, married = false) {
    this.name = name;
    this.age = age;
    this.married = married;
  }
}

const person1 = new Person("박영희", 30, true);
const person2 = new Person("오동수", 18); // married는 기본값 false

console.log(person1); // Person { name: '박영희', age: 30, married: true }
console.log(person2); // Person { name: '오동수', age: 18, married: false }

// constructor가 필요없는 경우
class Empty {}
console.log(new Empty()); // Empty {}
```

### 1.5 클래스의 메서드

**개념** : 클래스에 정의된 함수로, 모든 인스턴스가 공유하는 기능을 정의합니다.

**문법적 속성** :

- 프로토타입에 자동으로 등록됨
- `function` 키워드 없이 정의
- 각 인스턴스마다 메서드를 복사하지 않아 메모리 효율적

  **생성자 함수의 메서드와의 차이** :

```jsx
// 클래스 메서드 - 프로토타입에 등록
class Dog {
  bark() {
    return "멍멍";
  }
}

// 생성자 함수 - 인스턴스마다 복사
function Dog2() {
  this.bark = function () {
    return "멍멍";
  };
}
```

**사용 상황** : 인스턴스가 수행할 동작을 정의할 때 사용합니다.

**예시 코드** :

```jsx
class Dog {
  bark() {
    return "멍멍";
  }
}

const badugi = new Dog();
console.log(badugi.bark()); // "멍멍"

// [[Prototype]]에서 bark 메서드 확인 가능
```

### 1.6 필드 (Field)

**출처** : 2022년 정식 표준으로 채택된 비교적 최신 문법

**개념** : `constructor` 밖에서 `this.` 없이 인스턴스의 프로퍼티를 정의하는 방법입니다.

**문법적 속성** :

- 클래스 최상단에 선언
- `this` 키워드 불필요
- 초기값 설정 가능
- 브라우저 지원: 대부분의 모던 브라우저 지원, Babel로 변환 가능

  **사용 상황** :

- 모든 인스턴스가 동일한 초기값을 가질 때
- `constructor`가 불필요하거나 간단할 때

  **예시 코드** :

```jsx
// 필드를 사용한 간단한 클래스
class Slime {
  hp = 50;
  op = 4;

  attack(enemy) {
    enemy.hp -= this.op;
    this.hp += this.op / 4;
  }
}

const slime1 = new Slime();
const slime2 = new Slime();

console.log(slime1); // Slime { hp: 50, op: 4 }

slime1.attack(slime2);
console.log(slime1); // Slime { hp: 51, op: 4 }
console.log(slime2); // Slime { hp: 46, op: 4 }
```

**필드와 constructor 함께 사용** :

```jsx
class YalcoChicken {
  no = 0;
  menu = { 후라이드: 10000, 양념치킨: 12000 };

  constructor(name, no) {
    this.name = name;
    if (no) this.no = no; // 필드의 기본값 덮어쓰기
  }

  introduce() {
    return `안녕하세요, ${this.no}호 ${this.name}점입니다!`;
  }

  order(name) {
    return `${this.menu[name]}원입니다.`;
  }
}

const chain0 = new YalcoChicken("(미정)");
console.log(chain0.introduce()); // "안녕하세요, 0호 (미정)점입니다!"

const chain1 = new YalcoChicken("판교", 3);
console.log(chain1.introduce()); // "안녕하세요, 3호 판교점입니다!"

chain1.menu["양념치킨"] = 13000;
console.log(chain0.order("양념치킨")); // "12000원입니다."
console.log(chain1.order("양념치킨")); // "13000원입니다."
```

### 1.7 정적(Static) 필드와 메서드

**개념** : 인스턴스가 아닌 클래스 자체에 속한 속성과 메서드입니다.

**문법적 속성** :

- `static` 키워드로 선언
- 클래스명으로 직접 접근
- 인스턴스에서는 접근 불가
- 메모리를 인스턴스 수와 관계없이 한 곳만 차지

  **사용 상황** :

- 유틸리티 함수나 공통 설정값
- 인스턴스와 무관한 클래스 레벨의 기능
- 팩토리 메서드 구현

  **주의사항** : 정적 메서드에서는 정적 필드만 사용 가능 (`this`는 클래스 자체를 가리킴)

  **예시 코드** :

```jsx
class YalcoChicken {
  // 정적 필드
  static brand = "얄코치킨";

  // 정적 메서드
  static contact() {
    return `${this.brand}입니다. 무엇을 도와드릴까요?`;
  }

  constructor(name, no) {
    this.name = name;
    this.no = no;
  }

  introduce() {
    return `안녕하세요, ${this.no}호 ${this.name}점입니다!`;
  }
}

// 클래스 자체에서 호출
console.log(YalcoChicken.brand); // "얄코치킨"
console.log(YalcoChicken.contact()); // "얄코치킨입니다. 무엇을 도와드릴까요?"

const chain1 = new YalcoChicken("판교", 3);
console.log(chain1.introduce()); // "안녕하세요, 3호 판교점입니다!"
// console.log(chain1.brand); // undefined (인스턴스에서 접근 불가)
```

### 1.8 클래스는 함수이자 일급 객체

**개념** : JavaScript에서 클래스는 특별한 형태의 함수입니다.

**문법적 속성** :

- `typeof` 연산자 결과: `"function"`
- 변수에 할당 가능
- 함수의 인자로 전달 가능
- 함수의 반환값으로 사용 가능

  **예시 코드** :

```jsx
class Dog {
  bark() {
    return "멍멍";
  }
}

console.log(typeof Dog); // "function"

const 개 = Dog; // 할당 가능
const 바둑이 = new 개();

console.log(바둑이); // Dog { }
console.log(바둑이.bark()); // "멍멍"
```

## 2. 접근자 프로퍼티와 은닉

### 2.1 접근자 프로퍼티 (Accessor Property)

**개념** : getter와 setter를 통해 프로퍼티 값을 읽거나 쓸 때 특정 로직을 실행할 수 있는 특수한 프로퍼티입니다.

**문법적 속성** :

- `get` 키워드: 값을 읽을 때 실행
- `set` 키워드: 값을 쓸 때 실행
- 함수처럼 정의하지만 프로퍼티처럼 사용
- 스스로는 값을 갖지 않음

  **사용 상황** :

- 프로퍼티 값을 가공하여 반환할 때
- 프로퍼티 값 설정 시 유효성 검사가 필요할 때
- 읽기 전용 프로퍼티를 만들 때

### 2.2 객체 리터럴에서의 접근자 프로퍼티

**예시 코드** :

```jsx
const person1 = {
  age: 17,

  // getter: 읽기 전용처럼 사용
  get koreanAge() {
    return this.age + 1;
  },

  // setter: 값 설정 로직 제어
  set koreanAge(krAge) {
    this.age = krAge - 1;
  },
};

console.log(person1.koreanAge); // 18 (함수 호출이 아닌 프로퍼티 접근)

person1.koreanAge = 20; // setter 호출
console.log(person1.age); // 19
console.log(person1.koreanAge); // 20
```

### 2.3 클래스에서의 접근자 프로퍼티

**문법적 속성** :

- 클래스의 프로토타입에 등록됨
- getter는 반드시 값을 반환해야 함
- setter는 하나의 인자만 받음

  **예시 코드** :

```jsx
class YalcoChicken {
  constructor(name, no) {
    this.name = name;
    this.no = no;
  }

  // getter: 데이터 가공
  get chainTitle() {
    return `${this.no}호 ${this.name}점`;
  }

  // setter: 유효성 검사
  set chainNo(chainNo) {
    if (typeof chainNo !== "number") return;
    if (chainNo <= 0) return;
    this.no = chainNo;
  }
}

const chain1 = new YalcoChicken("판교", 3);
console.log(chain1.chainTitle); // "3호 판교점"

chain1.chainNo = "4"; // 숫자가 아니므로 무시
console.log(chain1.no); // 3

chain1.chainNo = -1; // 0 이하이므로 무시
console.log(chain1.no); // 3

chain1.chainNo = 4; // 유효한 값
console.log(chain1.no); // 4
console.log(chain1.chainTitle); // "4호 판교점"
```

### 2.4 접근자 프로퍼티 이름 충돌 문제

**주의사항** : 필드명과 setter의 이름이 같으면 무한 재귀 호출이 발생합니다.

**문제 코드** :

```jsx
class YalcoChicken {
  constructor(name, no) {
    this.name = name;
    this.no = no; // setter 호출 → setter에서 다시 setter 호출 → 무한 재귀
  }

  get no() {
    return this.no + "호점";
  }

  set no(no) {
    this.no = no; // 무한 재귀!
  }
}

// ❌ 오류 발생!
const chain1 = new YalcoChicken("판교", 3);
```

**해결책** : 내부 필드명에 언더스코어(`_`) 접두사를 사용

```jsx
class YalcoChicken {
  constructor(name, no) {
    this.name = name;
    this.no = no; // setter 호출
  }

  get no() {
    return this._no + "호점"; // 내부 필드 _no 참조
  }

  set no(no) {
    this._no = no; // 내부 필드 _no에 저장
  }
}

const chain1 = new YalcoChicken("판교", 3);
console.log(chain1); // YalcoChicken { name: '판교', _no: 3 }
console.log(chain1.no); // "3호점"
```

### 2.5 캡슐화(Encapsulation)와 은닉

**개념** : 객체 지향 프로그래밍의 핵심 원칙 중 하나로, 객체 내부의 데이터를 외부에서 직접 접근하지 못하도록 보호하는 것입니다.

**문법적 속성** :

- JavaScript의 기본 필드는 `public` (외부 접근 가능)
- 은닉이 필요한 경우 `private` 필드 사용

### 2.6 Private 필드

**출처** : ES2022에서 정식 표준으로 채택

**개념** : `#`으로 시작하는 필드로, 클래스 외부에서 접근할 수 없는 진정한 은닉을 제공합니다.

**문법적 속성** :

- 필드명 앞에 `#` 기호 사용
- 반드시 클래스 최상단에 선언
- constructor에만 선언하면 안 됨
- 클래스 내부에서만 접근 가능

  **사용 상황** :

- 외부에서 직접 수정하면 안 되는 데이터
- 내부 구현 세부사항 감추기
- 불변성 유지

  **예시 코드** :

```jsx
class Employee {
  #name = ""; // private 필드 선언 필수
  #age = 0;

  constructor(name, age) {
    this.#name = name;
    this.#age = age;
  }
}

const emp1 = new Employee("김복동", 32);

console.log(emp1); // Employee {}
// console.log(emp1.#name); // ❌ 오류 발생
console.log(emp1["#name"]); // undefined
```

**접근자 프로퍼티와 함께 사용** :

```jsx
class Employee {
  #name = "";
  #age = 0;

  constructor(name, age) {
    this.#name = name;
    this.#age = age;
  }

  // getter: 가공된 데이터만 노출
  get name() {
    return this.#name[0] + "모씨";
  }

  get age() {
    return this.#age - (this.#age % 10) + "대";
  }

  // setter: 유효성 검증 후 내부 데이터 수정
  set age(age) {
    if (typeof age === "number" && age > 0) {
      this.#age = age;
    }
  }

  // 메서드: 내부 데이터 조작
  getOlder(years) {
    this.#age += years;
  }
}

const emp1 = new Employee("김복동", 22);

console.log(emp1.name); // "김모씨"
console.log(emp1.age); // "20대"

emp1.age = 0; // 유효하지 않은 값, 무시됨
console.log(emp1.age); // "20대"

emp1.age = 35;
console.log(emp1.age); // "30대"

emp1.getOlder(20);
console.log(emp1.age); // "50대"
```

## 3. 상속

### 3.1 상속(Inheritance)의 개념

**개념** : 기존 클래스의 속성과 메서드를 다른 클래스가 물려받아 재사용하고 확장하는 객체 지향 프로그래밍의 핵심 개념입니다.

**목적** :

- 코드의 중복 제거
- 코드 재사용성 향상
- 계층적 관계 표현
- 유지보수성 향상

  **용어** :

- 부모 클래스 (Parent Class) / 슈퍼 클래스 (Super Class) / 기반 클래스 (Base Class)
- 자식 클래스 (Child Class) / 서브 클래스 (Sub Class) / 파생 클래스 (Derived Class)

### 3.2 클래스 상속 문법

**문법적 속성** :

- `extends` 키워드 사용
- `class 자식클래스 extends 부모클래스` 형태
- 다중 상속은 불가능 (하나의 부모만 가능)
- 상속 체인 가능 (자식이 또 다른 자식을 가질 수 있음)

  **사용 상황** :

- 공통 속성을 가진 여러 클래스를 만들 때
- IS-A 관계가 성립할 때 (예: Eagle IS-A Bird)

  **예시 코드** :

```jsx
class Bird {
  wings = 2;
}

class Eagle extends Bird {
  claws = 2;
}

class Penguin extends Bird {
  swim() {
    console.log("수영중...");
  }
}

class EmperorPenguin extends Penguin {
  size = "XXXL";
}

const birdy = new Bird();
const eaglee = new Eagle();
const pengu = new Penguin();
const pengdol = new EmperorPenguin();

console.log(birdy); // Bird { wings: 2 }
console.log(eaglee); // Eagle { wings: 2, claws: 2 }
console.log(pengu); // Penguin { wings: 2 }
console.log(pengdol); // EmperorPenguin { wings: 2, size: 'XXXL' }
```

### 3.3 instanceof 연산자

**개념** : 객체가 특정 클래스의 인스턴스인지 확인하는 연산자입니다.

**문법적 속성** :

- `객체 instanceof 클래스` 형태
- 상속 관계도 `true` 반환
- 최종적으로 모든 객체는 `Object`의 인스턴스

  **예시 코드** :

```jsx
console.log(birdy instanceof Bird); // true
console.log(eaglee instanceof Bird); // true (상속 관계)
console.log(eaglee instanceof Eagle); // true
console.log(pengdol instanceof Penguin); // true (상속 관계)
console.log(pengdol instanceof Bird); // true (상속 체인)
console.log(birdy instanceof Eagle); // false

pengu.swim(); // "수영중..."
pengdol.swim(); // "수영중..." (부모 메서드 사용 가능)
// eaglee.swim(); // ❌ 오류 (Eagle은 swim 메서드 없음)
```

**실무 예시** :

```jsx
class YalcoChicken {
  no = 0;
  menu = { 후라이드: 10000, 양념치킨: 12000 };

  constructor(name, no) {
    this.name = name;
    if (no) this.no = no;
  }

  introduce() {
    return `안녕하세요, ${this.no}호 ${this.name}점입니다!`;
  }

  order(name) {
    return `${this.menu[name]}원입니다.`;
  }
}

class YalcoChickenAndCafe extends YalcoChicken {
  cafeMenu = { 아메리카노: 4000, 라떼: 4500 };

  cafeOrder(name) {
    return `${this.cafeMenu[name]}원입니다.`;
  }
}

const chain1 = new YalcoChickenAndCafe("서면", 2);

console.log(chain1);
// YalcoChickenAndCafe {
//   no: 2,
//   menu: { '후라이드': 10000, '양념치킨': 12000 },
//   name: '서면',
//   cafeMenu: { '아메리카노': 4000, '라떼': 4500 }
// }

console.log(chain1.order("후라이드")); // "10000원입니다."
console.log(chain1.cafeOrder("라떼")); // "4500원입니다."
```

### 3.4 오버라이딩 (Overriding)

**개념** : 자식 클래스에서 부모 클래스로부터 상속받은 메서드나 속성을 재정의하여 덮어쓰는 것입니다.

**사용 상황** :

- 부모의 기능을 자식에 맞게 수정할 때
- 같은 인터페이스를 유지하되 다른 동작이 필요할 때

  **예시 코드** :

```jsx
class Bird {
  wings = 2;
  canFly = true;
  travel() {
    console.log("비행중...");
  }
}

class Eagle extends Bird {
  claws = 2;
}

class Penguin extends Bird {
  canFly = false; // 필드 오버라이딩
  travel() {
    // 메서드 오버라이딩
    console.log("수영중...");
  }
}

const eaglee = new Eagle();
const pengu = new Penguin();

console.log(eaglee.canFly); // true
eaglee.travel(); // "비행중..."

console.log(pengu.canFly); // false (오버라이딩됨)
pengu.travel(); // "수영중..." (오버라이딩됨)
```

**실무 예시** :

```jsx
class YalcoChicken {
  no = 0;
  menu = { 후라이드: 10000, 양념치킨: 12000 };

  constructor(name, no) {
    this.name = name;
    if (no) this.no = no;
  }

  introduce() {
    return `안녕하세요, ${this.no}호 ${this.name}점입니다!`;
  }

  order(name) {
    return `${this.menu[name]}원입니다.`;
  }
}

class YorkNannyYalcoChicken extends YalcoChicken {
  // 메서드 오버라이딩
  introduce() {
    return `또 뭐 쳐먹으러 기어들어왔어.`;
  }

  order(name) {
    return `${this.menu[name]}원이여.`;
  }
}

const chain1 = new YorkNannyYalcoChicken("종로", 48);

console.log(chain1.introduce()); // "또 뭐 쳐먹으러 기어들어왔어."
console.log(chain1.order("양념치킨")); // "12000원이여."
```

### 3.5 super 키워드

**개념** : 부모 클래스의 constructor나 메서드에 접근하기 위한 특수 키워드입니다.

**문법적 속성** :

- 자식 클래스에서만 사용 가능
- constructor 내부: 부모의 constructor 호출
- 메서드 내부: 부모 클래스 자체를 참조
- 자식 constructor에서 `this` 사용 전 반드시 `super()` 호출 필요

  **사용 상황** :

- 부모의 초기화 로직을 재사용할 때
- 부모의 메서드에 기능을 추가할 때
- 오버라이딩하면서도 부모의 기능을 일부 활용할 때

  **예시 코드 - constructor에서 super** :

```jsx
class YalcoChicken {
  no = 0;
  menu = { 후라이드: 10000, 양념치킨: 12000 };

  constructor(name, no) {
    this.name = name;
    if (no) this.no = no;
  }

  introduce() {
    return `안녕하세요, ${this.no}호 ${this.name}점입니다!`;
  }

  order(name) {
    return `${this.menu[name]}원입니다.`;
  }
}

class ConceptYalcoChicken extends YalcoChicken {
  #word = "";

  constructor(name, no, word) {
    super(name, no); // 부모 constructor 호출
    this.#word = word; // super() 이후에 this 사용 가능
  }

  // 부모 메서드에 기능 추가
  introWithConcept() {
    return super.introduce() + " " + this.#word;
  }

  // 부모 메서드 오버라이딩하면서 부모 메서드 활용
  order(name) {
    return super.order(name) + " " + this.#word;
  }
}

const pikaChain = new ConceptYalcoChicken("도봉", 50, "피카피카~");

console.log(pikaChain);
// ConceptYalcoChicken {
//   no: 50,
//   menu: { '후라이드': 10000, '양념치킨': 12000 },
//   name: '도봉',
//   #word: '피카피카~'
// }

console.log(pikaChain.introWithConcept());
// "안녕하세요, 50호 도봉점입니다! 피카피카~"

console.log(pikaChain.order("후라이드"));
// "10000원입니다. 피카피카~"
```

**정적 메서드에서의 super** :

```jsx
class YalcoChicken {
  static brand = "얄코치킨";

  static contact() {
    console.log(`${this.brand}입니다. 무엇을 도와드릴까요?`);
  }
}

class ConceptYalcoChicken extends YalcoChicken {
  static contact() {
    super.contact(); // 부모의 정적 메서드 호출
    console.log("컨셉 가맹문의는 홈페이지를 참조하세요.");
  }
}

ConceptYalcoChicken.contact();
// "얄코치킨입니다. 무엇을 도와드릴까요?"
// "컨셉 가맹문의는 홈페이지를 참조하세요."
```

## 4. 객체의 스프레드와 디스트럭쳐링

### 4.1 스프레드 (Spread)

**출처** : ES6(ECMAScript 2015)에서 도입

**개념** : `...` 연산자를 사용하여 객체나 배열의 요소를 펼쳐서 복사하거나 결합하는 문법입니다.

**문법적 속성** :

- `...` 연산자 사용
- 객체와 배열 모두 사용 가능
- 얕은 복사 (shallow copy) 수행

  **사용 상황** :

- 객체 복사
- 객체 병합
- 불변성을 유지하며 객체 수정

### 4.2 기본 문법

**예시 코드** :

```jsx
const class1 = {
  x: 1,
  y: "A",
  z: true,
};

const class2 = { ...class1 }; // 스프레드로 복사

// ⚠️ 참조 복사와 다름!
// const class2 = class1; // 같은 객체를 가리킴

console.log(class2); // { x: 1, y: 'A', z: true }

class2.x = 999;
console.log(class1.x); // 1 (원본은 변경되지 않음)
console.log(class2.x); // 999
```

### 4.3 객체 결합

**사용 상황** : 여러 객체를 하나로 합치거나, 기존 객체에 새 속성을 추가할 때

**예시 코드** :

```jsx
const class1 = {
  a: 1,
  b: "A",
  c: true,
};

const class2 = {
  d: { x: 10, y: 100 },
  e: [1, 2, 3],
};

// 기존 객체에 속성 추가
const class3 = {
  ...class1,
  z: 0,
};

// 여러 객체 결합
const class4 = {
  ...class2,
  ...class3,
  ...class2.d,
};

console.log(class3);
// { a: 1, b: 'A', c: true, z: 0 }

console.log(class4);
// { d: { x: 10, y: 100 }, e: [1, 2, 3], a: 1, b: 'A', c: true, z: 0, x: 10, y: 100 }
```

### 4.4 프로퍼티 덮어쓰기

**규칙** : 중복되는 프로퍼티는 뒤에 오는 것이 앞의 것을 덮어씁니다.

**예시 코드** :

```jsx
const class1 = {
  ...{ a: 1, b: 2 },
  ...{ b: 3, c: 4, d: 5 }, // b가 3으로 덮어씀
  ...{ c: 6, d: 7, e: 8 }, // c가 6, d가 7로 덮어씀
};

console.log(class1);
// { a: 1, b: 3, c: 6, d: 7, e: 8 }
```

### 4.5 복사의 깊이 - 얕은 복사

**중요 개념** : 스프레드는 얕은 복사(shallow copy)만 수행합니다.

**특징** :

- 1단계 깊이의 원시값: 복사됨
- 중첩된 객체/배열 (참조값): 참조만 복사됨 (같은 객체를 가리킴)

  **예시 코드** :

```jsx
const class1 = {
  x: 1, // 원시값
  y: { a: 2 }, // 참조값 (객체)
  z: [3, 4], // 참조값 (배열)
};

const class2 = { ...class1 };

class1.x++; // 원시값 변경
class1.y.a++; // 참조값 내부 변경
class1.z[0]++; // 참조값 내부 변경

console.log(class1);
// { x: 2, y: { a: 3 }, z: [4, 4] }

console.log(class2);
// { x: 1, y: { a: 3 }, z: [4, 4] }
// x는 독립적으로 복사되었지만, y와 z는 같은 객체를 참조
```

**주의사항** : 완전한 깊은 복사가 필요한 경우 별도의 방법 필요 (JSON.parse/stringify, 재귀 함수, 라이브러리 등)

### 4.6 디스트럭쳐링 (Destructuring)

**출처** : ES6(ECMAScript 2015)에서 도입

**개념** : 객체나 배열에서 필요한 값을 추출하여 변수에 할당하는 간편한 문법입니다.

**사용 상황** :

- 객체의 특정 속성만 추출할 때
- 함수 인자를 명확하게 받을 때
- 코드 가독성 향상

### 4.7 기본 문법

**기존 방식** :

```jsx
const obj1 = {
  x: 1,
  y: 2,
  z: 3,
};

const x = obj1.x;
const y = obj1.y;
const z = obj1.z;

console.log(x, y, z); // 1 2 3
```

**디스트럭쳐링 방식** :

```jsx
const obj1 = {
  x: 1,
  y: 2,
  z: 3,
};

const { x, y, z } = obj1;

console.log(x, y, z); // 1 2 3
```

**일부만 가져오기** :

```jsx
const obj1 = {
  x: 1,
  y: 2,
  z: 3,
};

const { x, z } = obj1; // y는 가져오지 않음

console.log(x, z); // 1 3
```

### 4.8 실전 활용 - 배열 메서드

**예시 코드** :

```jsx
const array1 = [1, 2, 3, 4, 5];

// 기존 방식
// const length = array1.length;

// 디스트럭쳐링 방식
const { length } = array1;

console.log(length); // 5
```

### 4.9 실전 활용 - 함수 인자

**문제 상황** : 인자가 많은 함수는 가독성이 떨어지고 순서를 기억해야 합니다.

**기존 방식 (좋지 않음)** :

```jsx
function introduce(name, age, job, married) {
  console.log(
    `제 이름은 ${name}, ` +
      `나이는 ${age}세구요. ` +
      `직업은 ${job}, ` +
      `${married ? "기혼" : "미혼"}입니다.`
  );
}

// ⚠️ 순서를 정확히 지켜야 함, 가독성 떨어짐
introduce("김철수", 28, "개발자", false);
```

**객체로 묶기 (개선)** :

```jsx
function introduce(person) {
  console.log(
    `제 이름은 ${person.name}, ` +
      `나이는 ${person.age}세구요. ` +
      `직업은 ${person.job}, ` +
      `${person.married ? "기혼" : "미혼"}입니다.`
  );
}

const person1 = {
  job: "개발자",
  age: 28,
  married: false,
  name: "김철수",
  blood: "O", // 추가 속성 있어도 무관
};

introduce(person1);
```

**디스트럭쳐링 활용 (최적)** :

```jsx
function introduce({ age, married, job, name }) {
  // 순서 무관
  // 필요한 프로퍼티들을 명시적으로 표현

  console.log(
    `제 이름은 ${name}, ` +
      `나이는 ${age}세구요. ` +
      `직업은 ${job}, ` +
      `${married ? "기혼" : "미혼"}입니다.`
  );
}

const person1 = {
  job: "개발자",
  age: 28,
  married: false,
  name: "김철수",
  blood: "O",
};

introduce(person1);
// "제 이름은 김철수, 나이는 28세구요. 직업은 개발자, 미혼입니다."
```

**장점** :

1. 가독성: 어떤 속성이 필요한지 명확
2. 순서 무관: 프로퍼티명만 일치하면 됨
3. 유연성: 추가 속성이 있어도 문제없음
4. 유지보수: 인자 추가/제거가 쉬움

## 📝 핵심 요약

### 클래스 기본

- **클래스** : 객체 생성을 위한 템플릿, 프로토타입 기반의 Syntactic Sugar
- **차이점** : 클래스는 호이스팅 안 됨, new 필수, 자동 strict mode
- **constructor** : 인스턴스 초기화, 클래스당 하나만 가능
- **메서드** : 프로토타입에 등록, 모든 인스턴스가 공유
- **필드** : constructor 밖에서 프로퍼티 정의 (ES2022)
- **static** : 클래스 레벨의 속성/메서드, 인스턴스와 무관

### 접근자 프로퍼티와 은닉

- **getter/setter** : 프로퍼티처럼 사용하지만 로직 실행 가능
- **getter** : 값 반환 필수, 데이터 가공
- **setter** : 단일 인자, 유효성 검사
- **이름 충돌** : 내부 필드명에 언더스코어(\_) 사용
- **캡슐화** : 내부 데이터 보호
- **private 필드** : #으로 시작, 클래스 외부 접근 불가

### 상속

- **extends** : 부모 클래스 상속, 코드 재사용
- **instanceof** : 상속 관계 확인
- **오버라이딩** : 부모의 속성/메서드 재정의
- **super** : 부모의 constructor/메서드 호출
- **constructor에서** : 부모 constructor 호출
- **메서드에서** : 부모 클래스 참조

### 스프레드와 디스트럭쳐링

- **스프레드(...)** : 객체 펼치기, 복사, 결합
- **얕은 복사** : 1단계 깊이만 복사, 중첩 객체는 참조 복사
- **덮어쓰기** : 뒤의 프로퍼티가 앞의 것을 덮어씀
- **디스트럭쳐링** : 필요한 값만 추출
- **함수 인자** : 가독성과 유연성 향상

    this.author = author;

### 문제 2: 정적 메서드 활용

**설명** : 온도 변환 유틸리티 클래스를 만드세요.

**요구사항** :

- 정적 메서드: celsiusToFahrenheit(celsius) - 섭씨를 화씨로 변환
- 정적 메서드: fahrenheitToCelsius(fahrenheit) - 화씨를 섭씨로 변환
- 인스턴스를 생성할 필요가 없어야 함

**기본 코드:**

```jsx
class TemperatureConverter {
  // 여기에 코드 작성
}

// 테스트 코드
console.log(TemperatureConverter.celsiusToFahrenheit(0));
console.log(TemperatureConverter.celsiusToFahrenheit(100));
console.log(TemperatureConverter.fahrenheitToCelsius(32));
console.log(TemperatureConverter.fahrenheitToCelsius(212));
```

**정답** :

```jsx
class TemperatureConverter {
  static celsiusToFahrenheit(celsius) {
    return (celsius * 9) / 5 + 32;
  }

  static fahrenheitToCelsius(fahrenheit) {
    return ((fahrenheit - 32) * 5) / 9;
  }
}

console.log(TemperatureConverter.celsiusToFahrenheit(0)); // 32
console.log(TemperatureConverter.celsiusToFahrenheit(100)); // 212
console.log(TemperatureConverter.fahrenheitToCelsius(32)); // 0
console.log(TemperatureConverter.fahrenheitToCelsius(212)); // 100
```

**해설** :

- static 키워드로 정의하여 클래스 레벨에서 직접 호출 가능합니다
- 유틸리티 함수는 인스턴스가 필요 없으므로 정적 메서드가 적합합니다
- 공식: C = (F - 32) × 5/9, F = C × 9/5 + 32

### 문제 3: 접근자 프로퍼티와 Private 필드

**설명** : 은행 계좌 클래스를 구현하세요.

**요구사항** :

- private 필드: #balance (잔액)
- constructor: 계좌주 이름과 초기 잔액
- getter: balance - 잔액 조회
- 메서드: deposit(amount) - 입금 (양수만 허용)
- 메서드: withdraw(amount) - 출금 (잔액 부족 시 실패)

  **기본 코드** :

```jsx
class BankAccount {
  // 여기에 코드 작성
}

// 테스트 코드
const account = new BankAccount("김철수", 10000);
console.log(account.balance);
account.deposit(5000);
console.log(account.balance);
account.withdraw(3000);
console.log(account.balance);
account.withdraw(20000);
```

**정답** :

```jsx
class BankAccount {
  #balance = 0;

  constructor(owner, initialBalance) {
    this.owner = owner;
    this.#balance = initialBalance;
  }

  get balance() {
    return this.#balance;
  }

  deposit(amount) {
    if (amount > 0) {
      this.#balance += amount;
      console.log(`${amount}원 입금 완료. 잔액: ${this.#balance}원`);
    } else {
      console.log("입금액은 양수여야 합니다.");
    }
  }

  withdraw(amount) {
    if (amount > 0 && amount <= this.#balance) {
      this.#balance -= amount;
      console.log(`${amount}원 출금 완료. 잔액: ${this.#balance}원`);
    } else if (amount > this.#balance) {
      console.log("잔액이 부족합니다.");
    } else {
      console.log("출금액은 양수여야 합니다.");
    }
  }
}

const account = new BankAccount("김철수", 10000);
console.log(account.balance); // 10000
account.deposit(5000); // "5000원 입금 완료. 잔액: 15000원"
console.log(account.balance); // 15000
account.withdraw(3000); // "3000원 출금 완료. 잔액: 12000원"
console.log(account.balance); // 12000
account.withdraw(20000); // "잔액이 부족합니다."
```

**해설** :

### 문제 4: 상속과 오버라이딩

**설명** : 직원 관리 시스템을 구현하세요.

**요구사항** :

- Employee 클래스: name, salary, getSalary() 메서드
- Manager 클래스: Employee 상속, bonus 추가, getSalary() 오버라이딩 (salary + bonus)
- Developer 클래스: Employee 상속, language 추가, getInfo() 메서드

  **기본 코드** :

```jsx
class Employee {
  // 여기에 코드 작성
}

class Manager extends Employee {
  // 여기에 코드 작성
}

class Developer extends Employee {
  // 여기에 코드 작성
}

// 테스트 코드
const emp = new Employee("김사원", 3000);
const mgr = new Manager("박팀장", 5000, 1000);
const dev = new Developer("이개발", 4000, "JavaScript");

console.log(emp.getSalary());
console.log(mgr.getSalary());
console.log(dev.getInfo());
```

**정답** :

```jsx
class Employee {
  constructor(name, salary) {
    this.name = name;
    this.salary = salary;
  }

  getSalary() {
    return `${this.name}의 급여: ${this.salary}만원`;
  }
}

class Manager extends Employee {
  constructor(name, salary, bonus) {
    super(name, salary);
    this.bonus = bonus;
  }

  getSalary() {
    const total = this.salary + this.bonus;
    return `${this.name}의 급여: ${total}만원 (기본급 ${this.salary} + 보너스 ${this.bonus})`;
  }
}

class Developer extends Employee {
  constructor(name, salary, language) {
    super(name, salary);
    this.language = language;
  }

  getInfo() {
    return `${this.name} - ${this.language} 개발자, 급여: ${this.salary}만원`;
  }
}

const emp = new Employee("김사원", 3000);
const mgr = new Manager("박팀장", 5000, 1000);
const dev = new Developer("이개발", 4000, "JavaScript");

console.log(emp.getSalary());
// "김사원의 급여: 3000만원"

console.log(mgr.getSalary());
// "박팀장의 급여: 6000만원 (기본급 5000 + 보너스 1000)"

console.log(dev.getInfo());
// "이개발 - JavaScript 개발자, 급여: 4000만원"
```

**해설** :

- super(name, salary)로 부모의 constructor를 호출하여 공통 속성을 초기화합니다
- Manager는 getSalary()를 오버라이딩하여 보너스를 포함한 총액을 반환합니다
- Developer는 새로운 getInfo() 메서드를 추가합니다

### 문제 5: super 키워드 활용

**설명** : 게임 캐릭터 시스템을 구현하세요.

**요구사항** :

- Character 클래스: name, hp, attack(enemy) 메서드
- Warrior 클래스: Character 상속, defense 추가, attack 오버라이딩 (부모 attack + 추가 데미지)
- attack시 자신의 방어력만큼 추가 데미지

  **기본 코드** :

```jsx
class Character {
  // 여기에 코드 작성
}

class Warrior extends Character {
  // 여기에 코드 작성
}

// 테스트 코드
const char1 = new Character("기본캐릭터", 100);
const warrior1 = new Warrior("전사", 150, 20);
const enemy = new Character("적", 200);

char1.attack(enemy);
console.log(enemy.hp);

warrior1.attack(enemy);
console.log(enemy.hp);
```

**정답** :

```jsx
class Character {
  constructor(name, hp) {
    this.name = name;
    this.hp = hp;
  }

  attack(enemy) {
    const damage = 10;
    enemy.hp -= damage;
    console.log(`${this.name}의 공격! ${enemy.name}에게 ${damage} 데미지`);
  }
}

class Warrior extends Character {
  constructor(name, hp, defense) {
    super(name, hp);
    this.defense = defense;
  }

  attack(enemy) {
    super.attack(enemy); // 부모의 기본 공격 실행
    const extraDamage = this.defense;
    enemy.hp -= extraDamage;
    console.log(`방어력 기반 추가 공격! ${extraDamage} 데미지`);
  }
}

const char1 = new Character("기본캐릭터", 100);
const warrior1 = new Warrior("전사", 150, 20);
const enemy = new Character("적", 200);

char1.attack(enemy);
// "기본캐릭터의 공격! 적에게 10 데미지"
console.log(enemy.hp); // 190

warrior1.attack(enemy);
// "전사의 공격! 적에게 10 데미지"
// "방어력 기반 추가 공격! 20 데미지"
console.log(enemy.hp); // 160
```

**해설** :

- super.attack(enemy)로 부모 클래스의 기본 공격 로직을 재사용합니다
- 이후 Warrior만의 추가 공격 로직을 실행합니다
- 코드 중복 없이 기능을 확장하는 상속의 장점을 보여줍니다
