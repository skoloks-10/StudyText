# 🗂 Git 복습 자료 — 변경사항 관리 & 태그

> 📅 학습 범위: `git clean` / `git restore` / `git reflog` / `git tag` / 원격 태그 & 릴리즈

---

## 1️⃣ git clean — 추적되지 않는 파일 삭제

### 📌 언제 쓰는가?

- `git status`에서 **Untracked files**로 표시되는 파일들을 한 번에 정리할 때
- 빌드 결과물, 임시 파일, 테스트용 파일 등을 깔끔히 제거하고 싶을 때

### 🔧 주요 옵션

| 옵션 | 역할 |
| --- | --- |
| `-n` | 실제 삭제 없이 삭제될 목록만 미리 확인 (dry run) |
| `-i` | 인터랙티브 모드 — 파일을 골라서 삭제 가능 |
| `-d` | 디렉토리(폴더) 포함 삭제 |
| `-f` | 강제 삭제 (확인 없이 바로 실행) |
| `-x` | `.gitignore`에 등록된 파일까지 모두 삭제 ⚠️ |

### 💡 자주 쓰는 조합 패턴

```bash
# 삭제 전 미리 확인 (안전)
git clean -dn

# 파일 + 폴더 모두 삭제
git clean -fd

# 마지막 커밋 상태로 완전 초기화 (빌드 캐시 포함)
git clean -fdx
```

### ⚠️ 헷갈리는 포인트

- `-n` 없이 `-f` 바로 쓰면 **되돌릴 수 없음** → 항상 `-n`으로 먼저 확인하는 습관 들이기
- `-x` 는 `.gitignore` 파일까지 지우므로 **환경 설정 파일이 날아갈 수 있음** (신중하게 사용)
- 옵션 순서는 무관: `-fd` == `-df`

## 2️⃣ git restore — 변경사항 되돌리기

### 📌 언제 쓰는가?

- 실수로 파일을 수정했는데 저장 전 상태(마지막 커밋)로 되돌리고 싶을 때
- `git add`로 스테이징한 파일을 다시 워킹 디렉토리로 내리고 싶을 때
- 특정 커밋 시점의 파일 내용이 필요할 때

### 🔧 사용 패턴

```bash
# 워킹 디렉토리의 특정 파일 복구 (마지막 커밋 기준)
git restore 파일명

# 모든 파일 복구
git restore .

# 스테이지에서 워킹 디렉토리로 되돌리기 (add 취소)
git restore --staged 파일명

# 특정 커밋 시점으로 파일 복구
git restore --source=커밋해시 파일명

# HEAD 기준으로 복구
git restore --source=HEAD~2 파일명
```

### ⚠️ 헷갈리는 포인트

- `git restore 파일명` → 워킹 디렉토리만 변경 (스테이지 내용은 유지)
- `git restore --staged 파일명` → 스테이지에서만 내림 (파일 내용은 그대로)
- **둘 다 되돌리려면** 두 명령어를 순서대로 실행해야 함

## 3️⃣ git reflog — reset 이후 복구

### 📌 언제 쓰는가?

- `git reset`으로 커밋을 날렸는데 다시 돌아가고 싶을 때
- HEAD가 이동한 모든 기록을 보고 싶을 때

### 🔧 사용 패턴

```bash
# 이동 기록 전체 확인
git reflog

# 원하는 시점으로 reset
git reset --hard HEAD@{n}
# 또는
git reset --hard 커밋해시
```

### 💡 핵심 개념

> `reflog`는 로컬에서만 존재하는 안전망입니다.
> 원격 저장소에는 동기화되지 않으며, 일정 기간(기본 90일) 이후 자동 삭제됩니다.

## 4️⃣ git tag — 커밋에 버전 표시

### 📌 언제 쓰는가?

- 특정 커밋을 버전으로 기록하고 싶을 때 (v1.0.0, v2.0.0 등)
- 배포 시점을 명확히 표시하고 싶을 때

### 🔖 버전 표기 방식 비교

| 방식 | 형식 예시 | 주 사용 대상 |
| --- | --- | --- |
| 시맨틱 버저닝 (SemVer) | `v1.4.2` (Major.Minor.Patch) | 라이브러리, API |
| 캘린더 버저닝 (CalVer) | `v2024.1.5` | 앱, 운영체제 |

### 🏷 태그 종류

| 종류 | 설명 |
| --- | --- |
| lightweight | 커밋을 가리키는 단순 포인터 |
| annotated | 작성자 정보, 날짜, 메시지, GPG 서명 포함 가능 — 배포용 권장 |

### 🔧 사용 패턴

```bash
# 마지막 커밋에 태그 (lightweight)
git tag v2.0.0

# 마지막 커밋에 태그 (annotated + 메시지)
git tag v2.0.0 -m 'Gamma Version'

# 특정 커밋에 태그 달기
git tag v1.0.0 커밋해시 -m 'Alpha Version'

# 태그 목록 확인
git tag

# 특정 태그 내용 확인
git show v2.0.0

# 태그 필터링 (패턴 검색)
git tag -l 'v1.*'

# 태그 삭제
git tag -d v2.0.0

# 특정 태그로 체크아웃
git checkout v1.2.1
```

### ⚠️ 헷갈리는 포인트

- `-m` 옵션을 쓰면 `-a` (annotated)가 자동으로 적용됨
- 태그는 브랜치처럼 자동으로 원격에 push되지 않음 → 별도 push 필요

---

## 5️⃣ 원격 태그 & GitHub 릴리즈

### 🔧 원격 태그 관리

```bash
# 특정 태그 원격에 올리기
git push origin v2.0.0

# 로컬 태그 전부 원격에 올리기
git push origin --tags

# 원격 태그 삭제
git push --delete origin v2.0.0
```

### 🚀 GitHub Release 만들기

1. GitHub 저장소 → Tags 탭 이동
2. 원하는 태그에서 `Create release` 클릭
3. 제목 + 내용(마크다운) 작성
4. `Publish release` 클릭

> 릴리즈를 생성하면 소스코드 압축 파일(.zip, .tar.gz)이 자동으로 제공됩니다.

## ✅ 핵심 요약

| 명령어 | 핵심 역할 |
| --- | --- |
| `git clean -fd` | 추적 안 되는 파일/폴더 강제 삭제 |
| `git clean -n` | 삭제될 목록 미리 확인 (안전 확인용) |
| `git restore 파일명` | 워킹 디렉토리 파일을 마지막 커밋 상태로 복구 |
| `git restore --staged 파일명` | 스테이징 취소 (add 되돌리기) |
| `git reflog` | HEAD 이동 기록 확인, reset 이전으로 복구 가능 |
| `git tag v1.0.0 -m '메시지'` | annotated 태그 생성 |
| `git push origin --tags` | 로컬 태그 전부 원격에 동기화 |

## 📝 복습 퀴즈

### Q1. `git clean` 명령어에서 실제 삭제 없이 삭제될 파일 목록만 미리 확인하는 옵션은?

1. `-f`
2. `-d`
3. `-n`
4. `-x`
5. `-i`

정답: 3번 `-n`

해설: `-n`은 "dry run" 옵션으로, 실제로 파일을 삭제하지 않고 어떤 파일들이 삭제될지 목록만 출력합니다. 삭제 전에 반드시 `-n`으로 확인하는 습관을 갖는 것이 안전합니다.

---

### Q2. `git add`로 스테이징한 파일을 다시 워킹 디렉토리로 되돌리는(스테이징 취소) 명령어는?

1. `git restore 파일명`
2. `git restore --staged 파일명`
3. `git clean -f 파일명`
4. `git restore --source=HEAD 파일명`
5. `git reset 파일명`

정답: 2번 `git restore --staged 파일명`

해설: `--staged` 옵션은 스테이지(인덱스)에서만 파일을 내리는 역할입니다. 이때 파일의 실제 내용은 변경되지 않습니다. 1번은 워킹 디렉토리의 파일 내용을 되돌리는 것이고, 4번은 특정 커밋 기준으로 파일을 복구하는 것입니다.

---

### Q3. `git reset`으로 커밋을 날린 후 이전 상태로 복구하고 싶을 때 사용하는 명령어는?

1. `git log`
2. `git stash`
3. `git reflog`
4. `git restore --source=HEAD`
5. `git tag`

정답: 3번 `git reflog`

해설: `git reflog`는 HEAD가 이동한 모든 기록을 보여줍니다. `reset`으로 사라진 것처럼 보이는 커밋도 `reflog`에서 해시를 찾아 `git reset --hard 커밋해시`로 복구할 수 있습니다. 단, 로컬에만 존재하며 90일 후 자동 삭제됩니다.

---

### Q4. `git tag v2.0.0 -m 'Release'` 명령어로 생성되는 태그 종류는?

1. lightweight 태그
2. annotated 태그
3. 서명된(signed) 태그
4. 원격 태그
5. 임시 태그

정답: 2번 annotated 태그

해설: `-m` 옵션을 사용하면 `-a`(annotated) 옵션이 자동으로 적용됩니다. annotated 태그는 작성자 정보, 날짜, 메시지 등을 포함할 수 있어 배포 버전 관리에 권장됩니다. 단순히 `git tag v2.0.0`만 쓰면 lightweight 태그가 생성됩니다.

---

### Q5. 로컬의 모든 태그를 원격(origin)에 한 번에 올리는 명령어는?

1. `git push origin v1.0.0`
2. `git push origin --all`
3. `git push origin --tags`
4. `git tag --push origin`
5. `git push --tags`

정답: 3번 `git push origin --tags`

해설: 태그는 일반 커밋 push와 달리 자동으로 원격에 올라가지 않습니다. `--tags` 옵션을 사용해야 로컬의 모든 태그가 원격에 동기화됩니다. 1번은 특정 태그 하나만 올리는 방법입니다.
