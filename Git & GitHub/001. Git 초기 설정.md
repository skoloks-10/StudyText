# Git 초기 설정 완벽 가이드 (Windows)

## 🎯 이 문서를 언제 보나요?

- Git을 새 컴퓨터에 처음 설치할 때
- 새 프로젝트를 Git으로 관리 시작할 때
- `.gitignore` 문법이 헷갈릴 때
- SourceTree나 Cursor 설정이 기억 안 날 때

---

## 📦 1단계: 필수 도구 설치하기

### Git 설치

**다운로드**: https://git-scm.com/

**설치 시 주의사항**
- Git Bash 반드시 포함 (기본 체크되어 있음)
- C 드라이브에 설치 필수

**설치 후 확인**
```bash
git --version
```

**윈도우 전용 설정**
```bash
git config --global core.autocrlf true
```
이 명령어는 윈도우(CRLF)와 맥/리눅스(LF) 간 줄바꿈 차이로 발생하는 협업 문제를 방지합니다.

### SourceTree 설치

**다운로드**: https://www.sourcetreeapp.com/

**용도**: Git을 시각적으로 관리할 수 있는 GUI 도구

**팁**: BitBucket 계정 연동은 건너뛰어도 됩니다.

### Cursor 설치

**다운로드**: https://cursor.com/

**필수 설정**
1. 터미널의 Default Profile → Git Bash로 변경
2. 확장 프로그램: `Material Icon Theme` 설치 및 적용

## ⚙️ 2단계: Git 전역 설정

### 사용자 정보 등록

**왜 필요한가요?**
Git은 모든 커밋에 "누가 작업했는지" 기록을 남깁니다. 이 정보를 미리 설정해야 합니다.

```bash
git config --global user.name "홍길동"
git config --global user.email "hong@example.com"
```

**헷갈리는 포인트**
- GitHub 계정 정보와 다를 수 있습니다
- 나중에 변경 가능합니다

**설정 확인**
```bash
git config --global user.name
git config --global user.email
```

### 기본 브랜치명 변경

```bash
git config --global init.defaultBranch main
```

**왜 하나요?**
과거에는 `master`가 기본이었지만, 현재는 `main`을 주로 사용합니다. GitHub도 `main`을 기본으로 채택했습니다.

## 🚀 3단계: 프로젝트에 Git 적용하기

### Git 저장소 초기화

1. 프로젝트 폴더 생성 (원하는 위치)
2. 해당 폴더에서 터미널 열기
3. 초기화 명령어 실행

```bash
git init
```

**결과**: `.git` 폴더가 생성됩니다 (숨김 폴더)

**⚠️ 절대 삭제 금지**
- `.git` 폴더를 지우면 Git 관리 내역이 모두 사라집니다
- 파일 자체는 유지되지만 버전 관리 기록은 사라집니다

### 상태 확인

```bash
git status
```

**언제 쓰나요?**
- 어떤 파일이 변경되었는지 확인
- 어떤 파일이 Git에 추가되지 않았는지 확인
- 현재 브랜치 확인

## 🚫 4단계: .gitignore 설정하기

### .gitignore가 필요한 이유

**Git에 올리면 안 되는 파일들**
- 비밀번호, API 키 등 민감한 정보 (`secrets.json`)
- 설정 파일 (`config.py`)
- 빌드 결과물 (`dist/`, `build/`)
- 로그 파일 (`*.log`)
- 의존성 패키지 (`node_modules/`)

### 기본 사용법

`.gitignore` 파일을 프로젝트 루트에 생성하고 무시할 파일/폴더를 작성합니다.

```
config.py
dist/
secrets.*
```

## 📚 .gitignore 문법 완전정복

### 파일 단위 무시

```
config.json          # 정확히 이 파일명만 무시
README.txt
```

### 확장자별 무시

```
*.log               # 모든 .log 파일
*.tmp               # 모든 .tmp 파일
```

**실무 예시**
```
*.log
*.DS_Store          # 맥 시스템 파일
Thumbs.db           # 윈도우 썸네일 파일
```

### 폴더 전체 무시

```
node_modules/       # 끝에 / 붙이기
build/
dist/
```

### 특정 경로만 무시

```
src/config.json     # src 폴더 안의 것만
/root-only.txt      # 루트 디렉토리의 것만 (하위 제외)
```

### 패턴 매칭

```
temp*               # temp로 시작하는 모든 것
*temp*              # temp가 포함된 모든 것
config*.json        # config로 시작하는 .json 파일들
```

### 중첩 디렉토리 무시

```
**/logs/            # 모든 위치의 logs 폴더
logs/**             # logs 안의 모든 내용
src/**/temp/        # src 하위 어디든 temp 폴더
```

### 한 글자만 매칭

```
log?.txt            # log1.txt, logA.txt (한 글자)
temp?.log
```

### 문자 범위 지정

```
log[0-9].txt        # log0.txt ~ log9.txt
file[!0-9].txt      # 숫자가 아닌 한 글자
```

### 예외 처리 (중요!)

```
*.log               # 모든 .log 무시
!important.log      # 단, important.log는 추적

build/              # build 폴더 무시
!build/README.md    # 단, README.md는 추적
```

**자주 헷갈리는 포인트**
- `!`는 반드시 무시 규칙 다음에 와야 합니다
- 폴더를 무시한 후 그 안의 파일을 예외처리할 수 없습니다

## 📝 핵심 요약

### 설치 체크리스트
1. Git 설치 (Git Bash 포함, C 드라이브)
2. `git config --global core.autocrlf true` 실행
3. SourceTree 설치 (선택사항)
4. Cursor 설치 및 Git Bash 연동

### 필수 전역 설정
```bash
git config --global user.name "이름"
git config --global user.email "이메일"
git config --global init.defaultBranch main
```

### 프로젝트 시작
```bash
git init              # Git 저장소 초기화
git status            # 상태 확인
```

### .gitignore 핵심 문법
- `파일명`: 정확한 파일명
- `*.확장자`: 모든 해당 확장자
- `폴더명/`: 폴더 전체
- `!파일명`: 예외 처리
- `**/폴더명/`: 모든 위치의 해당 폴더

## 🧠 복습 퀴즈

### Q1. Git 설치 시 반드시 포함시켜야 하는 도구는?

A) Git GUI  
B) Git Bash  
C) Git Desktop  
D) Git Cola  
E) Git Extensions

**정답: B) Git Bash**

해설: Git Bash는 Windows에서 Git 명령어를 실행할 수 있는 터미널 환경입니다. 설치 시 기본으로 체크되어 있으며, 이후 모든 Git 작업에 필수적으로 사용됩니다.

---

### Q2. 다음 중 Git 전역 설정이 아닌 것은?

A) `git config --global user.name "이름"`  
B) `git config --global user.email "이메일"`  
C) `git config --global init.defaultBranch main`  
D) `git config --global core.autocrlf true`  
E) `git config --global repository.path "경로"`

**정답: E) `git config --global repository.path "경로"`**

해설: repository.path는 실제 존재하지 않는 설정입니다. Git 전역 설정은 주로 사용자 정보(name, email), 줄바꿈 처리(autocrlf), 기본 브랜치명(init.defaultBranch) 등을 설정합니다.

### Q3. `.git` 폴더에 대한 설명으로 올바른 것은?

A) 언제든지 삭제해도 프로젝트에 영향이 없다  
B) 삭제하면 파일과 버전 관리 기록이 모두 사라진다  
C) 삭제하면 버전 관리 기록만 사라지고 파일은 유지된다  
D) GitHub에 자동으로 업로드되므로 로컬에서 삭제해도 된다  
E) 프로젝트 설정 파일이므로 직접 수정해야 한다

**정답: C) 삭제하면 버전 관리 기록만 사라지고 파일은 유지된다**

해설: .git 폴더에는 모든 커밋 내역, 브랜치 정보, 설정 등 Git 관련 데이터만 저장됩니다. 삭제하면 현재 작업 중인 파일들은 그대로 남지만, Git이 추적하던 모든 버전 관리 내역은 영구적으로 사라집니다.

### Q4. 다음 `.gitignore` 설정 중 의미가 다른 하나는?

A) `*.log`  
B) `temp.log`  
C) `debug.log`  
D) `error.log`  
E) `logs/**`

**정답: A) `*.log`**

해설: `*.log`는 모든 .log 확장자 파일을 무시하는 와일드카드 패턴입니다. B, C, D는 특정 파일명을 지정한 것이고, E는 logs 폴더 안의 모든 내용을 무시하는 것으로, A만 패턴 매칭을 사용합니다.

### Q5. 다음 `.gitignore` 설정의 결과로 올바른 것은?

```
*.log
!important.log
```

A) 모든 .log 파일이 무시된다  
B) important.log만 무시된다  
C) important.log를 제외한 모든 .log 파일이 무시된다  
D) 아무 파일도 무시되지 않는다  
E) 문법 오류로 작동하지 않는다

**정답: C) important.log를 제외한 모든 .log 파일이 무시된다**

해설: `!`는 예외 처리 기호입니다. `*.log`로 모든 .log 파일을 무시하지만, `!important.log`로 important.log만 추적 대상에 포함시킵니다. 예외 처리는 반드시 무시 규칙 다음에 작성해야 합니다.
