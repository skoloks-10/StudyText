# Git 커밋과 되돌리기 완벽 가이드

## 🎯 이 문서를 언제 보나요?

- 작업 내용을 저장(커밋)하는 방법이 헷갈릴 때
- 잘못된 커밋을 되돌려야 할 때
- reset vs revert 차이가 기억 안 날 때
- Vi 에디터에서 빠져나오지 못할 때
- SourceTree에서 되돌리기 하는 법이 궁금할 때

---

## 💾 Git 커밋의 핵심 개념

### 커밋이란?

**현재 프로젝트 상태를 스냅샷으로 저장하는 것**

마치 게임 세이브 포인트처럼, 언제든 이 시점으로 돌아올 수 있습니다.

### 커밋의 2단계 과정

```
작업 디렉토리 → (add) → 스테이징 영역 → (commit) → 저장소
```

**왜 2단계인가요?**
- 변경된 파일 중 일부만 선택적으로 커밋할 수 있습니다
- 커밋 전에 한 번 더 검토할 수 있습니다

---

## 📦 1단계: 변경사항을 스테이징에 올리기 (add)

### 현재 상태 확인

```bash
git status
```

**언제 쓰나요?**
- 어떤 파일이 변경되었는지 확인
- 어떤 파일이 스테이징되었는지 확인
- 커밋 전 항상 확인하는 습관 들이기

**결과 예시**
```
Untracked files:        # 한 번도 Git에 추가 안 된 파일
  tigers.yaml

Changes not staged:     # 변경됐지만 add 안 된 파일
  modified: lions.yaml
```

### 특정 파일만 스테이징

```bash
git add tigers.yaml
```

**언제 쓰나요?**
- 특정 파일의 변경사항만 커밋하고 싶을 때
- 여러 기능을 작업했지만 하나씩 따로 커밋하고 싶을 때

### 모든 변경사항 스테이징

```bash
git add .
```

**언제 쓰나요?**
- 현재 디렉토리의 모든 변경사항을 한번에 스테이징
- 대부분의 경우 이 명령어 사용

**자주 헷갈리는 포인트**
- `git add .`는 현재 디렉토리 기준
- `git add -A`는 프로젝트 전체 기준 (더 안전)

### 변경 내용 자세히 보기

```bash
git diff
```

**언제 쓰나요?**
- 정확히 어떤 코드가 변경되었는지 확인
- 커밋 전 마지막 검토

**Vi 에디터 조작법**
- `k`: 위로 스크롤
- `j`: 아래로 스크롤
- `:q`: 종료

---

## 💌 2단계: 커밋하기 (commit)

### Vi 에디터로 커밋 메시지 작성

```bash
git commit
```

**Vi 에디터 필수 명령어**

| 명령어 | 기능 | 언제 사용 |
|--------|------|-----------|
| `i` | 입력 모드 시작 | 커밋 메시지 작성 시작 |
| `ESC` | 명령 모드로 전환 | 작성 완료 후 |
| `:wq` | 저장하고 종료 | 메시지 작성 완료 |
| `:q!` | 저장 안 하고 강제 종료 | 취소하고 싶을 때 |

**실무 팁**
- Vi 에디터는 처음에 어렵지만, 익숙해지면 편리합니다
- 하지만 대부분은 아래 방법을 선호합니다

### 커밋 메시지 한 줄로 작성 (추천)

```bash
git commit -m "FIRST COMMIT"
```

**언제 쓰나요?**
- 대부분의 경우 (가장 많이 사용)
- 간단한 커밋 메시지면 충분할 때

**좋은 커밋 메시지 작성법**
```bash
# 나쁜 예
git commit -m "수정"
git commit -m "ㅇㅇ"
git commit -m "완료"

# 좋은 예
git commit -m "Add login button component"
git commit -m "Fix navbar responsive issue"
git commit -m "Remove unused CSS files"
```

### add와 commit 동시에 하기

```bash
git commit -am "메시지"
```

**언제 쓰나요?**
- 이미 추적 중인 파일만 수정했을 때
- 빠르게 작업하고 싶을 때

**⚠️ 주의사항**
- 새로 생성한 파일(untracked)에는 적용 안 됨
- 새 파일이 있다면 반드시 `git add` 먼저 해야 함

### 커밋 내역 확인

```bash
git log
```

**언제 쓰나요?**
- 커밋 히스토리 확인
- 되돌아갈 커밋 해시 찾기
- 누가 언제 무엇을 했는지 확인

**Vi 조작법**
- `k`: 위로 스크롤
- `j`: 아래로 스크롤
- `:q`: 종료

**더 보기 좋게 확인하기**
```bash
git log --oneline              # 한 줄로 요약
git log --graph --oneline      # 그래프로 시각화
```

## ⏰ 과거로 돌아가는 3가지 방법

### 언제 어떤 방법을 쓰나요?

| 상황 | 사용 명령어 | 특징 |
|------|-------------|------|
| 잘못된 커밋을 **완전히 없애고** 싶을 때 | `reset` | 커밋 이력 삭제 |
| 잘못된 커밋을 **취소 기록을 남기며** 되돌릴 때 | `revert` | 새로운 커밋 생성 |
| 과거를 **구경만** 하고 싶을 때 | `checkout` | 읽기 전용 방문 |

---

## 🔄 방법 1: reset - 시간을 되감기

### 기본 사용법

```bash
git log                           # 되돌아갈 커밋 해시 확인
git reset --hard (커밋 해시)      # 해당 커밋으로 되돌아가기
```

**언제 쓰나요?**
- 아직 푸시하지 않은 로컬 커밋을 되돌릴 때
- 잘못된 커밋을 완전히 없애고 싶을 때
- "이 작업은 없었던 일로 하자"

**실무 예시**
```bash
# 시나리오: 실수로 패스워드를 커밋함
git log --oneline
# abc123 Add password (← 이걸 없애야 함)
# def456 Add login page
# ghi789 Initial commit

git reset --hard def456   # Add login page로 되돌아가기
```

### 마지막 커밋 상태로 되돌리기

```bash
git reset --hard
```

**언제 쓰나요?**
- 작업 중 엉망이 돼서 마지막 커밋 상태로 돌아가고 싶을 때
- "Ctrl+Z를 여러 번 누르는 것" 같은 효과

### reset 옵션 비교

```bash
git reset --soft (커밋 해시)    # 커밋만 되돌림, 변경사항은 스테이징 영역에
git reset --mixed (커밋 해시)   # 커밋 + 스테이징 되돌림, 파일은 유지
git reset --hard (커밋 해시)    # 모든 것 되돌림, 변경사항도 삭제
```

**자주 헷갈리는 포인트**
- `--hard`는 복구 불가능하므로 신중하게 사용
- 협업 중 푸시한 커밋은 reset 금지 (다른 사람에게 영향)

---

## ↩️ 방법 2: revert - 되돌림 기록 남기기

### 기본 사용법

```bash
git log                           # 되돌릴 커밋 해시 확인
git revert (커밋 해시)            # 해당 커밋을 취소하는 새 커밋 생성
```

**Vi 에디터가 열림**
- `:wq`로 커밋 메시지 저장

**언제 쓰나요?**
- 이미 푸시한 커밋을 되돌릴 때
- 팀 작업에서 안전하게 되돌려야 할 때
- "이 변경사항을 취소합니다"라는 기록을 남기고 싶을 때

**reset vs revert 핵심 차이**
```
reset:  A - B - C → A - B         (C가 사라짐)
revert: A - B - C → A - B - C - D (D는 C를 취소하는 커밋)
```

### 충돌 발생 시 해결법

```bash
git revert (커밋 해시)
# 충돌 발생!

git rm (충돌 파일)              # 파일 삭제로 해결 또는
# 수동으로 충돌 해결 후

git revert --continue           # revert 계속 진행
```

**언제 충돌이 나나요?**
- 되돌리려는 커밋 이후에 같은 파일을 수정했을 때
- 삭제된 파일을 다시 수정했을 때

### 커밋하지 않고 revert

```bash
git revert --no-commit (커밋 해시)
```

**언제 쓰나요?**
- 여러 커밋을 한번에 되돌리고 하나의 커밋으로 만들고 싶을 때
- 되돌린 후 추가 수정을 같이 커밋하고 싶을 때

**취소 방법**
```bash
git reset --hard    # 작업 취소
```

## 👀 방법 3: checkout - 과거 구경하기

### 기본 사용법

```bash
git checkout (커밋 해시)         # 해당 커밋 시점으로 이동
git switch main                  # 다시 최신으로 돌아오기
```

**언제 쓰나요?**
- 특정 시점의 코드를 보고 싶을 때
- 과거 버전을 테스트하고 싶을 때
- "어떻게 되어있었더라?" 확인할 때

**자주 헷갈리는 포인트**
- checkout은 읽기 전용 방문
- 이 상태에서 커밋하면 브랜치가 필요함 (나중에 배움)
- 반드시 `git switch main`으로 돌아와야 함

**실무 예시**
```bash
# 버그가 언제부터 있었는지 확인
git log --oneline
git checkout def456    # 과거 버전 확인
npm start              # 테스트
# 버그 없음! 다음 커밋 확인
git switch main
```

## 🖱️ SourceTree로 되돌리기 (GUI)

### revert 하기

1. SourceTree에서 되돌릴 커밋에 **마우스 우클릭**
2. **"커밋 되돌리기"** 선택
3. 자동으로 revert 커밋 생성

**언제 쓰나요?**
- 명령어가 기억 안 날 때
- 시각적으로 확인하며 작업하고 싶을 때

### reset 하기

1. 되돌아갈 커밋에 **마우스 우클릭**
2. **"이 커밋까지 현재 브랜치를 초기화"** 선택
3. 옵션에서 **Hard** 선택

**주의사항**
- Hard 옵션은 복구 불가능
- 반드시 확인하고 클릭

## 🚨 실무에서 자주 하는 실수와 해결법

### 실수 1: reset으로 푸시한 커밋 되돌림

```bash
# ❌ 잘못된 방법
git reset --hard (커밋 해시)
git push                        # 오류 발생!
```

**해결법**
```bash
# ✅ 올바른 방법
git revert (커밋 해시)          # revert 사용
git push
```

### 실수 2: Vi 에디터에서 못 빠져나옴

**증상**: 커밋 메시지 입력 중 막힘

**해결법**
```
1. ESC 누르기
2. :q! 입력
3. Enter
4. git commit -m "메시지"로 다시 시도
```

### 실수 3: 잘못된 파일을 커밋함

**방법 1: 아직 푸시 안 했다면**
```bash
git reset --soft HEAD~1         # 마지막 커밋만 취소 (파일은 유지)
git reset HEAD (파일명)         # 스테이징에서 제거
git commit -m "수정된 메시지"
```

**방법 2: 이미 푸시했다면**
```bash
git rm --cached (파일명)        # Git 추적만 제거 (파일은 유지)
git commit -m "Remove sensitive file"
git push
```

### 실수 4: 커밋 메시지를 잘못 작성함

```bash
# 마지막 커밋 메시지 수정
git commit --amend -m "수정된 메시지"
```

**주의사항**
- 이미 푸시한 커밋은 메시지 수정 금지

## 💡 실무 워크플로우 예시

### 일반적인 작업 흐름

```bash
# 1. 작업 전 현재 상태 확인
git status
```

```bash
# 1. 현재 상태 파악
git log --oneline

# 2. 로컬 작업이면 reset
git reset --hard (커밋 해시)

# 3. 푸시했으면 revert
git revert (커밋 해시)
```

## 📝 핵심 요약

### 커밋의 2단계
1. **add**: 스테이징 영역에 변경사항 올리기
2. **commit**: 스냅샷으로 저장

### 필수 명령어
```bash
git status              # 현재 상태 확인
git add .               # 모든 변경사항 스테이징
git commit -m "메시지"  # 커밋
git log                 # 커밋 내역 확인
```

### 되돌리기 3가지 방법

| 명령어 | 용도 | 기록 | 협업 시 |
|--------|------|------|---------|
| `reset` | 시간 되감기 | 삭제됨 | 푸시 전만 |
| `revert` | 취소 커밋 생성 | 남음 | 안전 |
| `checkout` | 과거 구경 | 변경 없음 | 안전 |

### Vi 에디터 탈출법
```
ESC → :q! → Enter
```

### 커밋 메시지 작성 원칙
- 영어로 작성 (관례)
- 동사 원형으로 시작 (Add, Fix, Remove, Update)
- 명확하고 간결하게
- 한글도 OK (팀 규칙에 따라)

### 자주 쓰는 패턴
```bash
# 빠른 커밋
git add . && git commit -m "메시지"

# 마지막 커밋으로 되돌리기
git reset --hard

# 커밋 이력 보기 좋게
git log --oneline --graph
```

## 🧠 복습 퀴즈

### Q1. 다음 중 스테이징과 커밋을 동시에 하는 명령어는?

A) `git add -m "메시지"`  
B) `git commit -am "메시지"`  
C) `git commit -all "메시지"`  
D) `git add . -commit "메시지"`  
E) `git stage -m "메시지"`

**정답: B) `git commit -am "메시지"`**

해설: `-a` 옵션은 이미 추적 중인 파일의 변경사항을 자동으로 스테이징하고, `-m` 옵션은 커밋 메시지를 지정합니다. 단, 새로 생성된 파일(untracked)에는 적용되지 않으므로 주의해야 합니다.

---

### Q2. Vi 에디터에서 입력 모드로 전환하는 명령어는?

A) `a`  
B) `i`  
C) `insert`  
D) `edit`  
E) `Enter`

**정답: B) `i`**

해설: Vi 에디터에서 `i` 키를 누르면 INSERT 모드로 전환되어 텍스트를 입력할 수 있습니다. 입력이 끝나면 `ESC`를 눌러 명령 모드로 돌아가고, `:wq`로 저장 후 종료할 수 있습니다.

---

### Q3. 다음 중 협업 중 푸시한 커밋을 되돌릴 때 사용해야 하는 명령어는?

A) `git reset --hard`  
B) `git revert`  
C) `git checkout`  
D) `git delete`  
E) `git undo`

**정답: B) `git revert`**

해설: 이미 푸시한 커밋은 다른 팀원들도 받아간 상태이므로, `reset`으로 커밋을 삭제하면 충돌이 발생합니다. `revert`는 기존 커밋을 취소하는 새로운 커밋을 만들어 안전하게 되돌릴 수 있습니다.

### Q4. `git reset --hard (커밋 해시)` 명령어의 효과는?

A) 해당 커밋만 삭제하고 나머지는 유지  
B) 해당 커밋 이후의 모든 커밋과 변경사항 삭제  
C) 해당 커밋으로 이동하지만 변경사항은 유지  
D) 해당 커밋을 취소하는 새 커밋 생성  
E) 해당 커밋의 변경사항만 스테이징에서 제거

**정답: B) 해당 커밋 이후의 모든 커밋과 변경사항 삭제**

해설: `reset --hard`는 지정한 커밋 이후의 모든 커밋 이력을 삭제하고, 작업 디렉토리의 변경사항도 모두 제거합니다. 복구가 불가능하므로 신중하게 사용해야 하며, 특히 이미 푸시한 커밋에는 절대 사용하면 안 됩니다.

### Q5. 다음 중 과거 커밋을 읽기 전용으로 확인할 때 사용하는 명령어는?

A) `git reset`  
B) `git revert`  
C) `git checkout`  
D) `git view`  
E) `git show`

**정답: C) `git checkout`**

해설: `git checkout (커밋 해시)`는 해당 커밋 시점으로 이동하여 코드를 확인할 수 있지만, 변경사항을 남기지 않는 읽기 전용 방문입니다. 확인 후에는 `git switch main`으로 최신 상태로 돌아와야 합니다. `git show`는 커밋 정보만 보여주는 명령어입니다.
