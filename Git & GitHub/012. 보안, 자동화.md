## 1. 🔑 SSH로 GitHub 접속하기

### SSH란?
비밀번호 없이 컴퓨터에 저장된 **키 파일**로 GitHub에 인증하는 방식.
`username + 토큰` 입력 없이 훨씬 편리하게 사용 가능.

### 핵심 흐름

```
① SSH 키가 이미 있는지 확인
        ↓ 없으면
② SSH 키 새로 생성
        ↓
③ GitHub에 공개키 등록
        ↓
④ 원격 주소를 SSH 형식으로 바꿔서 사용
```

### 명령어 정리

| 단계 | 명령어 | 설명 |
|------|--------|------|
| 이동 | `cd ~/.ssh` | ssh 키 폴더로 이동 |
| 확인 | `ls` | 키 파일 존재 여부 확인 |
| 생성 | `ssh-keygen -t ed25519 -C "이메일"` | 새 키 생성 |
| 복사 | `cat ~/.ssh/id_ed25519.pub` | 공개키 내용 출력 (복사용) |

### ⚠️ 헷갈리기 쉬운 포인트
- `id_ed25519` → 개인키 (절대 공유 ❌)
- `id_ed25519.pub` → 공개키 (GitHub에 등록하는 것 ✅)
- `~/.ssh` 폴더가 없으면 `mkdir -p ~/.ssh`로 먼저 생성

## 2. ✍️ GPG로 커밋에 사인하기

### GPG란?
커밋이 **진짜 내가 만든 것**임을 암호학적으로 증명하는 기능.
GitHub에서 커밋 옆에 `Verified` 뱃지가 붙음.

### 핵심 흐름

```
① GPG 툴 설치
        ↓
② GPG 키 생성
        ↓
③ GitHub에 GPG 공개키 등록
        ↓
④ 커밋/태그에 -S 또는 -s 옵션 추가
```

### 명령어 정리

```bash
# 커밋에 사인
git commit -S -m "메시지"

# 태그에 사인
git tag -s v1.0 abc1234 -m "태그 메시지"
```

### ⚠️ 헷갈리기 쉬운 포인트
- 커밋 사인: 대문자 `-S`
- 태그 사인: 소문자 `-s`
- macOS는 설치 후 **환경 변수 추가 설정** 필요 (공식 문서 참고)

## 3. ⚙️ GitHub Actions

### GitHub Actions란?
코드를 push하거나 특정 이벤트가 발생했을 때 **자동으로 작업을 실행**해주는 CI/CD 도구.
`.github/workflows/` 폴더 안에 YAML 파일로 설정.

### YAML 구조 이해하기

```yaml
name: 워크플로우 이름          # Actions 탭에 표시되는 이름

on:                            # 언제 실행할지
  push:
    branches: ["main"]         # main 브랜치에 push될 때
  workflow_dispatch:           # 수동 실행 버튼도 활성화

jobs:                          # 실제로 할 작업들
  job이름:
    runs-on: ubuntu-latest     # 어떤 환경에서 실행할지

    permissions:               # 필요한 권한 명시
      issues: write

    steps:                     # 순서대로 실행되는 단계들
      - name: 단계 이름
        uses: actions/checkout@v4   # 남이 만든 액션 사용

      - name: 명령어 실행
        run: |
          echo "명령어 실행"
```

### 예시 흐름 (calc.py → 이슈 등록)

```
push 발생
  → Python 코드 실행 (calc.py)
  → 결과를 output.md에 저장
  → output.md 내용을 GitHub 이슈로 자동 등록
```

### ⚠️ 헷갈리기 쉬운 포인트
- `uses` → 이미 만들어진 액션 가져와 쓰기
- `run` → 직접 셸 명령어 입력
- 이슈 생성 등 쓰기 작업은 `permissions: issues: write` 필수

## 4. 💻 GitHub CLI (`gh`)

### GitHub CLI란?
터미널에서 GitHub 웹사이트를 열지 않고도 **PR, 이슈, 저장소** 등을 관리할 수 있는 공식 도구.

공식 사이트: https://cli.github.com/

### 자주 쓰는 명령어

**인증**
```bash
gh auth login      # 로그인
gh auth status     # 로그인 상태 확인
gh auth logout     # 로그아웃
```

**저장소**
```bash
gh repo create     # 새 저장소 만들기
gh repo clone      # 저장소 클론
gh repo fork       # 포크하기
gh repo view       # 저장소 정보 보기
```

**PR (풀 리퀘스트)**
```bash
gh pr create       # PR 생성
gh pr list         # PR 목록 확인
gh pr checkout 3   # PR #3 체크아웃
gh pr merge        # PR 병합
gh pr status       # 내 PR 상태 확인
```

**이슈**
```bash
gh issue create    # 이슈 만들기
gh issue list      # 이슈 목록 보기
gh issue view 5    # 이슈 #5 상세 보기
gh issue close 5   # 이슈 닫기
```

## 📌 핵심 요약

| 기능 | 한 줄 정리 |
|------|-----------|
| SSH | 키 파일로 비밀번호 없이 GitHub 인증 |
| GPG | 커밋이 내 것임을 암호로 서명 → `Verified` 뱃지 |
| GitHub Actions | push 등 이벤트 발생 시 자동으로 코드/스크립트 실행 |
| GitHub CLI | 터미널에서 GitHub 기능을 명령어로 사용 |

**SSH 핵심:** 공개키(`.pub`)만 GitHub에 등록, 개인키는 절대 공유 금지

**GPG 핵심:** 커밋 `-S` (대문자), 태그 `-s` (소문자)

**Actions 핵심:** `.github/workflows/*.yaml` → `on` (언제) + `jobs` (무엇을)

**CLI 핵심:** `gh auth login` 먼저, 이후 `gh pr` / `gh issue` / `gh repo` 자유롭게

## 🧠 복습 퀴즈

### Q1. SSH 키 파일에 대한 설명으로 올바른 것은?

1. `id_ed25519`는 공개키이므로 GitHub에 등록한다.
2. `id_ed25519.pub`는 개인키이므로 절대 공유하면 안 된다.
3. `id_ed25519.pub`가 공개키이고, 이것을 GitHub에 등록한다.
4. SSH 키를 생성하면 파일이 하나만 만들어진다.
5. SSH 방식을 쓰면 매번 username과 비밀번호를 입력해야 한다.

정답: 3

해설: SSH 키 생성 시 개인키(`id_ed25519`)와 공개키(`id_ed25519.pub`) 두 파일이 생성됩니다. GitHub에는 공개키(.pub)를 등록하고, 개인키는 내 컴퓨터에만 보관합니다. SSH의 장점은 username과 토큰 없이 인증이 가능하다는 점입니다.

### Q2. GPG로 커밋과 태그에 사인하는 명령어가 올바르게 짝지어진 것은?

1. 커밋: `git commit -s -m "msg"` / 태그: `git tag -S v1.0`
2. 커밋: `git commit -S -m "msg"` / 태그: `git tag -s v1.0`
3. 커밋: `git commit --sign -m "msg"` / 태그: `git tag --sign v1.0`
4. 커밋: `git commit -S -m "msg"` / 태그: `git tag -S v1.0`
5. 커밋: `git commit -g -m "msg"` / 태그: `git tag -g v1.0`

정답: 2

해설: 커밋 사인은 대문자 `-S`, 태그 사인은 소문자 `-s` 를 사용합니다. 대소문자를 헷갈리기 쉬운 대표적인 포인트입니다.

### Q3. GitHub Actions의 YAML 파일에서 `on` 키워드의 역할은?

1. 워크플로우의 이름을 정의한다.
2. 실행 환경(운영체제)을 지정한다.
3. 워크플로우가 실행되는 조건(트리거)을 정의한다.
4. 각 단계에서 실행할 명령어를 작성한다.
5. 필요한 권한을 명시한다.

정답: 3

해설: `on`은 워크플로우의 트리거를 정의합니다. `push`, `pull_request`, `workflow_dispatch`(수동 실행) 등이 올 수 있습니다. 실행 환경은 `runs-on`, 명령어는 `run`, 권한은 `permissions` 키워드로 설정합니다.

### Q4. GitHub CLI에서 새 이슈를 만드는 명령어는?

1. `gh issue new`
2. `gh issue add`
3. `gh issue open`
4. `gh issue create`
5. `gh issue make`

정답: 4

해설: GitHub CLI에서 이슈 생성은 `gh issue create`입니다. 비슷하게 PR 생성은 `gh pr create`, 저장소 생성은 `gh repo create` 로 모두 `create`를 사용합니다.

### Q5. GitHub Actions에서 이슈를 자동으로 등록하는 작업을 하려면 반드시 추가해야 하는 설정은?

1. `runs-on: ubuntu-latest`
2. `workflow_dispatch` 트리거 설정
3. `permissions: issues: write`
4. `uses: actions/checkout@v4`
5. `python-version: '3.10'` 설정

정답: 3

해설: GitHub Actions에서 이슈 생성과 같은 쓰기(write) 작업을 수행하려면 job 레벨에서 `permissions: issues: write` 권한을 명시적으로 부여해야 합니다. 이 설정이 없으면 권한 오류가 발생합니다.
