# 🚀 Git & GitHub 완전 정복 - 복습 자료

> 💡 **이 문서의 목적**: 원격 저장소(GitHub)를 사용한 Git 협업의 핵심 개념과 명령어를 빠르게 복습하기 위한 요약본

---

## 📌 1. GitHub 시작하기

### 🔐 인증 설정 (GCM + PAT)

**언제 필요한가?**
- GitHub와 로컬 Git 간 인증이 필요할 때
- 비밀번호 대신 토큰 기반 인증으로 보안 강화

**설정 순서**
```bash
# 1. GCM 설치 확인
git credential-manager --version

# 2. 없으면 설치 (Mac)
brew install --cask git-credential-manager

# 3. Git에 GCM 연결
git config --global credential.helper manager
```

**PAT(Personal Access Token) 발급**
1. GitHub → Settings → Developer Settings
2. Personal access tokens → Generate new token
3. `repo` 권한 체크 + 기간 설정
4. 생성된 토큰을 **안전한 곳에 보관** (다시 볼 수 없음!)

**자주 헷갈리는 포인트** ⚠️
- PAT는 비밀번호가 아닌 토큰! 한 번 생성 후 다시 볼 수 없으므로 반드시 저장
- GCM이 없으면 매번 인증 정보를 입력해야 함

---

### 📦 레포지토리 생성 및 협업자 추가

**Public vs Private**
- **Public**: 전 세계 공개 (오픈소스 프로젝트)
- **Private**: 초대한 사람만 접근 가능 (회사 프로젝트, 개인 프로젝트)

**협업자 추가하는 법**
- 레포지토리 → Settings → Collaborators
- 팀원 이메일/아이디로 초대

## 🌐 2. 원격 저장소 연결하기

### 🔗 로컬 ↔ 원격 연결 설정

**기본 연결 명령어**
```bash
# 원격 저장소 추가 (origin이라는 이름으로)
git remote add origin https://github.com/username/repo.git

# 연결된 원격 저장소 확인
git remote -v

# 원격 저장소 연결 해제 (로컬 파일은 유지됨)
git remote remove origin
```

**첫 푸시**
```bash
# -u 옵션: 현재 브랜치를 origin/main과 연결 (다음부터는 git push만 입력)
git push -u origin main
```

**언제 쓰는가?**
- 로컬에서 작업한 프로젝트를 GitHub에 처음 올릴 때
- `origin`은 관례적 이름이지만 `backup`, `company` 등 다른 이름도 가능

**실무 팁** 💼
- 한 로컬 저장소에 여러 원격 저장소 연결 가능 (origin, origin2 등)

---

### 📥 GitHub에서 프로젝트 받아오기

**Clone vs Download ZIP**
| 방식 | Git 내역 포함 | 추천 상황 |
|------|-------------|----------|
| `git clone` | ✅ | 개발 참여, 커밋 히스토리 필요 |
| Download ZIP | ❌ | 단순 파일만 필요 |

```bash
# 클론하기
git clone https://github.com/username/repo.git

# 특정 브랜치만 클론
git clone -b branch-name https://github.com/username/repo.git
```

**자주 발생하는 실수** ⚠️
- ZIP 다운로드 후 `git push` 시도 → 불가능 (Git 관리 정보 없음)

## ⬆️⬇️ 3. Push & Pull - 협업의 기본

### 📤 Push: 로컬 → 원격

```bash
# 기본 푸시 (-u로 연결 설정 후에는 이것만 입력)
git push

# 강제 푸시 (위험! 원격 내역 덮어씀)
git push --force
```

**언제 쓰는가?**
- 로컬 작업 완료 후 팀원들과 공유할 때
- 커밋 후 push를 해야 다른 사람이 볼 수 있음

---

### 📥 Pull: 원격 → 로컬

```bash
# 기본 풀 (merge 방식)
git pull

# rebase 방식으로 풀
git pull --rebase
```

**언제 쓰는가?**
- 팀원이 올린 최신 코드를 받아올 때
- 하루 작업 시작 전 최신 상태 동기화

**Merge vs Rebase 방식**
| 방식 | 특징 | 히스토리 |
|------|------|---------|
| `--no-rebase` (기본) | 병합 커밋 생성 | 모든 내역 보존 |
| `--rebase` | 커밋을 재배치 | 깔끔한 일직선 히스토리 |

---

### ⚠️ Push 전에 Pull 해야 하는 상황

**시나리오**
1. 내가 로컬에서 작업 중
2. 팀원이 먼저 원격에 push
3. 내가 push 시도 → **거부됨!**

**해결 방법**
```bash
# 1. 원격 변경사항 가져오기
git pull

# 2. 충돌 해결 (있다면)

# 3. 푸시
git push
```

**실무 패턴** 💼
```bash
# 아침 출근하면
git pull

# 작업 후
git add .
git commit -m "작업 내용"
git pull  # 혹시 모를 동료의 push 확인
git push
```

---

### 💥 충돌(Conflict) 해결하기

**충돌이 발생하는 경우**
- 같은 파일의 같은 줄을 나와 동료가 동시에 수정

**해결 순서**
1. `git pull` 실행
2. 충돌 파일 열기 (`<<<<<<<`, `=======`, `>>>>>>>` 표시 확인)
3. 원하는 내용으로 수정
4. `git add` → `git commit` → `git push`

**자주 헷갈리는 포인트** ⚠️
- 충돌 해결 후 반드시 `add` + `commit` 필요!
- `--force` push는 협업에서 매우 위험 → 팀원 작업 날아감

## 🌿 4. 원격 브랜치 다루기

### 📤 로컬 브랜치 → 원격 푸시

```bash
# 새 브랜치 생성
git branch from-local

# 브랜치로 이동
git switch from-local

# 원격에 푸시 (최초 1회 -u 필요)
git push -u origin from-local
```

---

### 📥 원격 브랜치 → 로컬 받기

```bash
# 원격 브랜치 목록 확인
git branch -a

# 원격 브랜치를 로컬로 가져와 자동 연결
git switch -t origin/from-remote
```

**언제 쓰는가?**
- 동료가 만든 기능 브랜치를 내 로컬에서 작업하고 싶을 때

---

### 🗑️ 원격 브랜치 삭제

```bash
git push origin --delete branch-name
```

**실무 팁** 💼
- 브랜치 작업 완료 후 merge 되었다면 삭제하는 것이 관리에 좋음
- GitHub에서도 PR 머지 후 "Delete branch" 버튼 제공

---

## 🎯 실무 시나리오별 명령어

### 📋 시나리오 1: 새 프로젝트 GitHub에 올리기
```bash
# 로컬에서
git init
git add .
git commit -m "Initial commit"

# GitHub에서 레포 생성 후
git remote add origin https://github.com/username/repo.git
git push -u origin main
```

---

### 📋 시나리오 2: 기존 프로젝트 참여하기
```bash
git clone https://github.com/username/repo.git
cd repo

# 작업 후
git add .
git commit -m "작업 내용"
git push
```

---

### 📋 시나리오 3: 동료와 충돌 해결
```bash
# 내 작업 커밋
git commit -m "내 작업"

# push 전 최신 내용 가져오기
git pull

# 충돌 발생 시 → 파일 수정 후
git add .
git commit -m "Merge conflicts resolved"
git push
```

---

### 📋 시나리오 4: 기능 브랜치로 작업하기
```bash
# 새 기능 브랜치 생성
git switch -c feature/login

# 작업 후 푸시
git push -u origin feature/login

# GitHub에서 Pull Request 생성
# 리뷰 후 Merge
# 브랜치 삭제
git push origin --delete feature/login
```

## 🎓 핵심 요약

### ✅ 필수 명령어 치트시트

| 명령어 | 설명 | 언제 쓰나 |
|--------|------|----------|
| `git remote add origin URL` | 원격 저장소 연결 | 최초 1회 |
| `git push -u origin main` | 첫 푸시 + 브랜치 연결 | 최초 푸시 |
| `git push` | 로컬 → 원격 업로드 | 작업 공유 |
| `git pull` | 원격 → 로컬 다운로드 | 최신 상태 동기화 |
| `git clone URL` | 저장소 복제 | 프로젝트 참여 |
| `git branch -a` | 모든 브랜치 확인 | 원격 브랜치 확인 |
| `git switch -t origin/branch` | 원격 브랜치 가져오기 | 동료 작업 가져오기 |

---

### 🚨 주의사항

1. **Push 전 항상 Pull 먼저!**
    - 동료가 먼저 push 했다면 내 push는 거부됨

2. **force push는 최후의 수단**
    - 협업 중에는 거의 쓰지 않음 (다른 사람 작업 날아감)

3. **충돌은 자연스러운 현상**
    - 같은 파일을 동시 수정하면 발생
    - 침착하게 필요한 내용만 남기고 해결

4. **브랜치로 작업하는 습관**
    - main은 항상 안정적인 상태 유지
    - 기능 개발은 별도 브랜치에서

## 📝 복습 퀴즈

### Q1. Git에서 원격 저장소를 로컬에 연결하는 명령어는?
1. `git connect origin URL`
2. `git remote add origin URL`
3. `git link origin URL`
4. `git push origin URL`

**정답: 2번**
`git remote add origin URL`이 원격 저장소를 로컬에 연결하는 표준 명령어입니다. `origin`은 원격 저장소의 별칭으로, 다른 이름으로 변경할 수도 있습니다.

---

### Q2. 다음 중 원격 저장소의 최신 내용을 로컬로 가져오는 명령어는?
1. `git fetch`
2. `git push`
3. `git pull`
4. `git clone`

**정답: 3번**
`git pull`은 원격의 변경사항을 로컬로 가져와 자동으로 병합합니다. `git fetch`는 가져오기만 하고 병합은 하지 않으며, `git clone`은 저장소 전체를 처음 복제할 때 사용합니다.

---

### Q3. 로컬에서 커밋 후 push를 시도했으나 거부되었습니다. 가장 적절한 해결 방법은?
1. `git push --force`로 강제 푸시
2. `git pull`로 원격 변경사항을 먼저 가져온 후 다시 push
3. 로컬 커밋을 삭제하고 처음부터 다시 작업
4. 원격 저장소를 삭제하고 새로 생성

**정답: 2번**
원격에 먼저 적용된 변경사항이 있을 때는 `git pull`로 먼저 가져와 병합한 후 push해야 합니다. `--force`는 협업 시 다른 사람의 작업을 덮어쓸 수 있어 위험합니다.

---

### Q4. GitHub에서 생성한 `feature/new-ui` 브랜치를 로컬로 가져와 작업하려고 합니다. 올바른 명령어는?
1. `git branch feature/new-ui`
2. `git pull origin feature/new-ui`
3. `git switch -t origin/feature/new-ui`
4. `git clone feature/new-ui`

**정답: 3번**
`git switch -t origin/브랜치명`은 원격 브랜치를 추적(track)하면서 로컬에 같은 이름의 브랜치를 생성하고 자동으로 이동합니다. `-t` 옵션은 `--track`의 약자입니다.

---

### Q5. 협업 중 충돌(conflict)이 발생했습니다. 해결 순서로 올바른 것은?
1. `git pull` → 충돌 파일 수정 → `git commit` → `git push`
2. `git pull` → 충돌 파일 수정 → `git add` → `git commit` → `git push`
3. 충돌 파일 수정 → `git pull` → `git push`
4. `git push --force` → 충돌 무시

**정답: 2번**
충돌 해결 후에는 반드시 `git add`로 변경사항을 스테이징하고, `git commit`으로 병합 커밋을 생성한 후 push해야 합니다. `git add` 없이 바로 commit할 수 없습니다.

---

### Q6. `git push -u origin main` 명령어에서 `-u` 옵션의 역할은?
1. 원격 저장소를 업데이트한다
2. 현재 브랜치와 원격 브랜치를 연결하여 이후 `git push`만으로 푸시 가능하게 한다
3. 업로드 속도를 빠르게 한다
4. 원격 브랜치를 삭제한다

**정답: 2번**
`-u` (또는 `--set-upstream`)는 현재 로컬 브랜치를 원격 브랜치와 연결(upstream 설정)합니다. 한 번 설정하면 이후에는 `git push`만 입력해도 자동으로 연결된 원격 브랜치로 푸시됩니다.
