# 🪝 Git Hook & 🌳 Worktree 복습 자료

---

## 1. Git Hook

### 개념

> Git에서 특정 이벤트(커밋, 푸시 등)가 발생할 때 **자동으로 실행되는 스크립트**

- 위치: `.git/hooks/` 폴더 안
- `.sample` 확장자가 붙어 있으면 비활성화 상태 → **확장자 제거 시 활성화**
- 쉘 스크립트(`.sh`)로 작성, `exit 1` 반환 시 해당 동작 중단

---

### 언제 쓰는가?

| 상황 | 활용 예 |
|------|---------|
| 커밋 전 코드 품질 검사 | 특정 키워드 포함 여부 확인 |
| 커밋 후 알림 | 성공 메시지, 브랜치 출력 |
| 푸시 전 확인 | 의도치 않은 푸시 방지용 인터랙션 |

---

### Hook 종류별 설명

#### 🔴 `pre-commit` — 커밋 직전 실행

코드에 특정 문자열이 있으면 커밋을 막는 예시:

```bash
#!/bin/sh

if grep -r "error" . --exclude-dir=".git"; then
    echo "❌ 코드에 'error' 문구가 있어 커밋을 중단합니다!"
    exit 1
fi

echo "✅ 검사 완료: 커밋을 진행합니다."
exit 0
```

- `grep -r` : 재귀적으로 파일 탐색
- `--exclude-dir=".git"` : `.git` 폴더는 검색에서 제외
- `exit 1` : 커밋 중단 / `exit 0` : 커밋 허용

---

#### 🟢 `post-commit` — 커밋 완료 후 실행

```bash
#!/bin/sh

echo "🎉 새로운 커밋이 기록되었습니다."
echo "📦 현재 브랜치: $(git rev-parse --abbrev-ref HEAD)"
```

- 커밋을 막을 수 없음 (이미 완료 후 실행)
- 주로 알림, 로그 출력 등에 사용

---

#### 🟡 `pre-push` — 푸시 직전 실행

```bash
#!/bin/sh

echo "⚠️  정말로 푸시하시겠습니까? (y/n)"

exec < /dev/tty
read -r CONFIRM

if [ "$CONFIRM" != "y" ]; then
    echo "🛑 푸시가 취소되었습니다."
    exit 1
fi
```

- `exec < /dev/tty` : 터미널에서 직접 사용자 입력 받기 위한 처리
- `read -r CONFIRM` : 입력값을 `CONFIRM` 변수에 저장

---

### ⚠️ 자주 헷갈리는 포인트

- `exit 0` = 성공 / `exit 1` = 실패(중단) — 반드시 구분할 것
- `.sample` 파일은 예시일 뿐, 실제로 동작하지 않음. 반드시 확장자 제거 후 사용
- `post-commit`은 `exit 1`을 해도 커밋을 취소할 수 없음

## 2. Git Worktree

### 개념

> **하나의 저장소에서 여러 브랜치를 동시에 다른 폴더에서 작업**할 수 있게 해주는 기능

기존 방식은 브랜치 전환 시 현재 작업 중인 코드가 영향을 받지만,  
`worktree`를 쓰면 브랜치별로 폴더를 분리해 **동시에 독립적으로 작업** 가능

---

### 언제 쓰는가?

- 기능 개발 중 갑자기 핫픽스(hotfix) 작업이 필요할 때
- 두 브랜치의 코드를 **나란히 비교**하며 작업할 때
- 브랜치 전환 없이 다른 브랜치 내용을 확인할 때

---

### 주요 명령어

#### 1단계: 브랜치 생성

```bash
git branch hotfix
```

#### 2단계: 워크트리 생성 (기존 브랜치 연결)

```bash
git worktree add ../hotfix hotfix
```

- `../hotfix` : 생성될 폴더 경로 (현재 폴더 밖에 생성)
- `hotfix` : 연결할 브랜치 이름

#### 브랜치와 함께 동시에 생성

```bash
git worktree add ../hotfix2 -b hotfix2
```

- `-b hotfix2` : 브랜치 생성 + 워크트리 생성을 한 번에

#### 워크트리 목록 확인

```bash
git worktree list
```

#### 워크트리 삭제

```bash
git worktree remove ../hotfix
```

---

### 실무 패턴

```
프로젝트/
├── my-project/        ← 기존 작업 중인 폴더 (main 브랜치)
└── hotfix/            ← 새로 생성된 워크트리 (hotfix 브랜치)
```

- 에디터(VS Code 등)에서 `hotfix` 폴더를 **새 창으로 열어** 작업
- 두 창에서 각자의 브랜치를 독립적으로 수정 가능

---

### ⚠️ 자주 헷갈리는 포인트

- 같은 브랜치를 두 워크트리에서 동시에 체크아웃할 수 없음
- 워크트리 폴더를 그냥 삭제해도 되지만, `git worktree remove`로 정리하는 게 올바른 방법
- 워크트리는 `.git` 폴더를 공유하므로 실제 브랜치와 연동됨

---

## 📌 핵심 요약

| 기능 | 한 줄 정리 |
|------|------------|
| Git Hook | 특정 Git 이벤트에 자동 실행되는 스크립트 |
| pre-commit | 커밋 전 실행, `exit 1`로 커밋 차단 가능 |
| post-commit | 커밋 후 실행, 중단 불가 |
| pre-push | 푸시 전 실행, `exit 1`로 푸시 차단 가능 |
| Hook 활성화 | `.sample` 확장자 제거 |
| Worktree | 여러 브랜치를 별도 폴더에서 동시에 작업 |
| worktree add | 새 폴더 생성 + 브랜치 연결 |
| worktree remove | 워크트리 폴더 정리 |

## 🧠 복습 퀴즈

### Q1. Git Hook을 활성화하려면 어떻게 해야 하는가?

1. `.git/hooks/` 폴더 안의 파일을 복사한다
2. `.sample` 확장자를 제거한다
3. `git hook enable` 명령어를 실행한다
4. 파일에 실행 권한을 부여한다
5. Git 설정 파일에 hook 경로를 직접 등록한다

정답: 2

해설: `.git/hooks/` 폴더에 있는 파일들은 기본적으로 `.sample` 확장자가 붙어 있어 비활성화 상태다. `.sample`을 제거하면 해당 Hook이 활성화된다. 실행 권한도 필요할 수 있지만, 가장 핵심 조건은 `.sample` 확장자 제거다.

---

### Q2. `pre-commit` Hook에서 커밋을 중단시키려면 어떻게 해야 하는가?

1. 스크립트 안에 `git reset` 명령어를 실행한다
2. `exit 0`으로 종료한다
3. `exit 1`으로 종료한다
4. 스크립트 파일을 삭제한다
5. 아무 값도 반환하지 않는다

정답: 3

해설: 쉘 스크립트에서 `exit 1`은 "비정상 종료"를 의미하며, Git은 이를 감지해 커밋 동작을 중단한다. 반대로 `exit 0`은 "정상 종료"로, 커밋이 계속 진행된다.

---

### Q3. `post-commit` Hook의 특징으로 올바른 것은?

1. 커밋 전에 실행되어 커밋을 막을 수 있다
2. 커밋 완료 후 실행되며, `exit 1`을 써도 커밋은 이미 완료된 상태다
3. 푸시가 완료된 이후 실행된다
4. 브랜치 생성 시 자동으로 실행된다
5. 커밋 메시지를 수정하는 데 사용된다

정답: 2

해설: `post-commit`은 커밋이 완료된 이후에 실행되는 Hook이다. 이 시점에서는 이미 커밋이 기록되었기 때문에 `exit 1`을 써도 커밋을 되돌릴 수 없다. 주로 알림 출력이나 로그 기록 용도로 활용된다.

---

### Q4. 다음 중 `git worktree add ../hotfix2 -b hotfix2` 명령어의 설명으로 올바른 것은?

1. `hotfix2` 브랜치를 삭제하고 새 워크트리를 만든다
2. 기존 `hotfix2` 브랜치를 `../hotfix2` 폴더에 연결한다
3. `hotfix2`라는 새 브랜치를 생성하면서 `../hotfix2` 폴더에 워크트리를 만든다
4. 현재 브랜치를 `hotfix2`로 전환한다
5. `../hotfix2` 폴더를 Git 저장소로 초기화한다

정답: 3

해설: `-b hotfix2`는 새 브랜치를 생성하는 옵션이다. 즉, 브랜치 생성과 워크트리 생성을 한 번에 처리한다. 기존 브랜치에 연결하려면 `-b` 없이 `git worktree add ../hotfix hotfix`처럼 사용한다.

---

### Q5. `git worktree`를 사용하는 가장 적합한 상황은?

1. 커밋 메시지를 수정해야 할 때
2. 기능 개발 중 긴급 핫픽스를 별도 브랜치에서 동시에 작업해야 할 때
3. 원격 저장소에서 코드를 처음 받아올 때
4. 오래된 커밋으로 되돌아가야 할 때
5. `.gitignore` 파일을 설정해야 할 때

정답: 2

해설: Worktree는 현재 브랜치의 작업을 중단하지 않고 다른 브랜치에서 동시에 독립적으로 작업해야 할 때 유용하다. 대표적인 케이스가 기능 개발 도중 핫픽스가 필요한 상황이다.
