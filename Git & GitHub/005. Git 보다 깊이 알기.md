## 1. Git의 3가지 공간 이해하기 🗂️

### 📍 개념 정리

Git은 파일의 상태를 **3단계로 관리**합니다. 이를 이해하면 `add`, `commit`, `reset` 등의 명령어가 왜 필요한지 알 수 있습니다.

```
Working Directory → Staging Area → Repository
     (작업 공간)      (준비 공간)     (저장소)
```

### 🔹 Working Directory (작업 공간)

**언제 이 상태인가?**
- 파일을 새로 만들거나 수정했을 때
- 아직 `git add`를 하지 않은 상태

**파일의 2가지 타입**
- `untracked`: 한 번도 Git에 추가된 적 없는 새 파일
- `tracked`: 이전에 커밋된 적 있고, 지금 수정된 파일

**실무 포인트**
- 이 상태에서는 변경사항이 Git에 기록되지 않음
- `git status`로 확인 가능
- 실수로 수정한 내용을 되돌리려면: `git restore (파일명)`

---

### 🔹 Staging Area (준비 공간)

**언제 이 상태인가?**
- `git add (파일명)` 실행 후
- 커밋할 준비가 된 상태

**왜 이 단계가 필요한가?**
```
예시: 5개 파일을 수정했는데, 그 중 2개만 먼저 커밋하고 싶을 때
→ 원하는 파일만 선택적으로 add하여 커밋 가능
```

**실무 포인트**
- 작업 단위를 논리적으로 나눠서 커밋할 수 있음
- Staging Area에서 다시 빼려면: `git restore --staged (파일명)`

---

### 🔹 Repository (저장소)

**언제 이 상태인가?**
- `git commit` 실행 후
- `.git` 폴더에 영구적으로 저장된 상태

**실무 포인트**
- 커밋 = 프로젝트의 "스냅샷" 저장
- 언제든 이 시점으로 돌아갈 수 있음

## 2. 파일 삭제/이동 시 주의사항 ⚠️

### 일반 삭제 vs Git 삭제

| 방법 | 상태 | 복원 방법 |
|------|------|-----------|
| `파일 직접 삭제` | Working Directory에 삭제 기록 | `git restore (파일명)` |
| `git rm (파일명)` | Staging Area에 삭제 기록 | `git reset --hard` |

### 파일 이름 변경

```bash
# ❌ 이렇게 하면 복잡함
파일명 직접 변경 → git add로 추가

# ✅ 이렇게 하면 간단함
git mv old_name.js new_name.js
```

**실무 포인트**
- `git mv`를 쓰면 이동/이름변경이 자동으로 Staging Area에 추가됨

## 3. reset의 3가지 옵션 🔄

### 헷갈리는 포인트: 어디까지 되돌릴까?

```bash
# --soft: 커밋만 취소 (파일은 Staging Area에 남음)
git reset --soft HEAD~1
→ 사용 시나리오: 커밋 메시지를 수정하고 싶을 때

# --mixed (기본값): 커밋 + add 취소 (파일은 Working Directory에 남음)
git reset --mixed HEAD~1
→ 사용 시나리오: 커밋을 취소하고 파일을 다시 선택해서 add하고 싶을 때

# --hard: 모든 변경사항 삭제
git reset --hard HEAD~1
→ 사용 시나리오: 변경사항을 완전히 버리고 이전 상태로 돌아가고 싶을 때
```

**실무에서 자주 쓰는 패턴**
```bash
# 마지막 커밋 메시지만 수정
git reset --soft HEAD~1
git commit -m "새로운 커밋 메시지"

# 실수로 add한 파일 빼기
git restore --staged (파일명)

# 로컬의 모든 변경사항 버리고 원격과 똑같이 맞추기
git reset --hard origin/main
```

## 4. HEAD의 정체 🎯

### HEAD란?

**현재 체크아웃된 브랜치의 가장 최신 커밋을 가리키는 포인터**

```
main 브랜치에 있을 때:
HEAD → main 브랜치의 최신 커밋

feature 브랜치로 이동하면:
HEAD → feature 브랜치의 최신 커밋
```

### HEAD로 이전 커밋 탐색하기

```bash
# 1단계 이전으로
git checkout HEAD^
git checkout HEAD~1

# 3단계 이전으로
git checkout HEAD^^^
git checkout HEAD~3

# 특정 커밋으로 직접 이동
git checkout a1b2c3d
```

**실무 포인트**
- 과거 커밋을 확인하고 싶을 때 유용
- 다시 최신으로 돌아오려면: `git switch (브랜치명)`
- 과거 시점에서 새 브랜치를 만들 수도 있음

### HEAD를 활용한 reset

```bash
# 3개 커밋 되돌리기
git reset HEAD~3

# 특정 커밋까지 되돌리기
git reset HEAD~5 --hard
```

## 5. fetch vs pull 차이점 🔽

### 핵심 차이

| 명령어 | 동작 | 언제 쓰나? |
|--------|------|-----------|
| `git fetch` | 원격 변경사항을 **가져오기만** 함 | 일단 뭐가 바뀌었는지 확인하고 싶을 때 |
| `git pull` | 가져오기 + **자동 병합** | 바로 로컬에 적용해도 될 때 |

### 실무 워크플로우

```bash
# 1. 원격 저장소 확인
git fetch

# 2. 뭐가 바뀌었는지 확인
git checkout origin/main
git log

# 3. 문제없으면 병합
git switch main
git merge origin/main

# 또는 한 번에
git pull origin main
```

**언제 fetch를 먼저 쓸까?**
- 팀원이 작업한 내용을 확인하고 싶을 때
- 로컬 작업이 많아서 충돌 가능성이 있을 때
- 신중하게 검토 후 병합하고 싶을 때

### 원격의 새 브랜치 가져오기

```bash
# 원격 브랜치 확인만
git checkout origin/feature-login

# 로컬에 브랜치 생성하며 추적
git switch -t origin/feature-login
```

## 6. Git 설정 실무 팁 ⚙️

### 전역 vs 로컬 설정

```bash
# 전역 설정 (모든 프로젝트)
git config --global user.name "홍길동"

# 로컬 설정 (현재 프로젝트만)
git config --local user.name "회사용"
```

**실무 시나리오**
- 개인 프로젝트: 개인 이메일 사용
- 회사 프로젝트: 회사 이메일 사용
  → 각 저장소마다 `--local` 설정으로 분리

### 단축어 설정

```bash
# 자주 쓰는 명령어를 짧게
git config --global alias.st status
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.cm "commit -m"
git config --global alias.cam "commit -am"

# 사용 예시
git st          # git status
git co main     # git checkout main
git cam "수정"  # git commit -am "수정"
```

### 에디터 설정

```bash
# VS Code 사용
git config --global core.editor "code --wait"

# Cursor 사용
git config --global core.editor "cursor --wait"
```

**왜 --wait를 붙일까?**
- 에디터가 닫힐 때까지 Git이 기다림
- 커밋 메시지를 에디터에서 작성할 때 필요

### 설정 확인

```bash
# 모든 설정 보기
git config --list

# 전역 설정만
git config --global --list

# 특정 설정 확인
git config user.name
```

# 📌 핵심 요약본

### 3가지 공간
- **Working Directory**: 수정한 파일 (`git add` 전)
- **Staging Area**: 커밋 준비된 파일 (`git add` 후)
- **Repository**: 커밋된 파일 (`.git`에 저장)

### 자주 쓰는 명령어
```bash
# 상태 확인
git status

# Staging Area로 이동
git add (파일명)

# Working Directory로 되돌리기
git restore --staged (파일명)

# 파일 수정 취소
git restore (파일명)

# 커밋 되돌리기
git reset --soft HEAD~1    # 커밋만 취소
git reset --mixed HEAD~1   # add도 취소
git reset --hard HEAD~1    # 변경사항 완전 삭제
```

### fetch vs pull
- `git fetch`: 가져오기만 (안전)
- `git pull`: 가져오기 + 병합 (빠름)

### HEAD
- 현재 브랜치의 최신 커밋을 가리킴
- `HEAD~3`: 3개 이전 커밋
- `git checkout HEAD^`: 이전 커밋으로 이동

# 🎓 복습 퀴즈

### Q1. Working Directory에 있는 변경사항을 완전히 버리려면?
1. `git add .`
2. `git restore (파일명)`
3. `git reset --soft HEAD~1`
4. `git commit --amend`

**정답: 2번**

해설: `git restore (파일명)`은 Working Directory의 변경사항을 버리고 마지막 커밋 상태로 되돌립니다. 1번은 Staging Area로 추가, 3번은 커밋 취소, 4번은 마지막 커밋 수정입니다.

---

### Q2. 다음 중 `git reset --soft HEAD~1`의 결과는?
1. 변경사항이 완전히 사라진다
2. 변경사항이 Working Directory에 남는다
3. 변경사항이 Staging Area에 남는다
4. 아무 일도 일어나지 않는다

**정답: 3번**

해설: `--soft` 옵션은 커밋만 취소하고 변경사항은 Staging Area에 남깁니다. 이는 커밋 메시지를 수정하거나 여러 커밋을 하나로 합칠 때 유용합니다.

---

### Q3. Staging Area에 추가된 파일을 다시 Working Directory로 되돌리려면?
1. `git restore (파일명)`
2. `git restore --staged (파일명)`
3. `git reset --hard`
4. `git checkout HEAD`

**정답: 2번**

해설: `git restore --staged (파일명)`은 Staging Area에서 Working Directory로 파일을 되돌립니다. 1번은 Working Directory의 변경사항을 버림, 3번은 모든 변경사항 삭제, 4번은 HEAD로 체크아웃입니다.

---

### Q4. `git fetch`와 `git pull`의 차이점은?
1. fetch는 push도 함께 수행한다
2. pull은 원격 변경사항을 가져오기만 한다
3. fetch는 가져오기만 하고, pull은 가져오기+병합을 수행한다
4. 둘은 완전히 같은 기능이다

**정답: 3번**

해설: `git fetch`는 원격 저장소의 변경사항을 로컬로 가져오기만 합니다. `git pull`은 가져오기 + 병합(merge 또는 rebase)까지 자동으로 수행합니다. 신중한 작업이 필요할 때는 fetch를 먼저 사용합니다.

---

### Q5. HEAD~3이 의미하는 것은?
1. 현재 커밋
2. 3번째 커밋
3. 현재로부터 3개 이전 커밋
4. 3번 브랜치의 최신 커밋

**정답: 3번**

해설: `HEAD~3`은 현재 커밋으로부터 3개 이전 커밋을 의미합니다. `~` 또는 `^`는 이전 커밋으로 이동하는 표기법입니다. `HEAD~1`은 바로 이전 커밋, `HEAD~5`는 5개 이전 커밋을 가리킵니다.

---

### Q6. 파일을 삭제하면서 동시에 Staging Area에 추가하려면?
1. 파일 직접 삭제 후 `git add`
2. `git rm (파일명)`
3. `git delete (파일명)`
4. `git remove --staged (파일명)`

**정답: 2번**

해설: `git rm (파일명)`은 파일을 삭제하면서 동시에 그 삭제 내역을 Staging Area에 추가합니다. 일반적으로 파일을 직접 삭제하면 Working Directory에만 변경사항이 생기므로, 별도로 `git add`를 해야 합니다.

### Q7. 전역 설정이 아닌 현재 프로젝트에만 사용자 이름을 설정하려면?
1. `git config user.name "이름"`
2. `git config --global user.name "이름"`
3. `git config --local user.name "이름"`
4. `git config --system user.name "이름"`

**정답: 3번**

해설: `--local` 옵션은 현재 프로젝트(저장소)에만 설정을 적용합니다. `--global`은 모든 프로젝트, `--system`은 시스템 전체에 적용됩니다. 옵션을 생략하면 `--local`이 기본값입니다.
