# 04장. 변수

## 4.1 컴퓨터가 데이터를 처리하는 방식

컴퓨터는 **CPU(연산)** 와 **메모리(기억)** 가 역할을 나눠서 일한다.

```
10 + 20 을 계산한다면?
 → CPU가 10, 20을 메모리에서 읽어서 연산
 → 결과값 30도 메모리 어딘가에 저장됨
```

🚨 **문제**: 연산 결과가 저장된 메모리 주소(예: `0x0669F913`)는 코드 실행 때마다 달라진다.
개발자가 그 주소를 직접 알 방법이 없다.

→ 그래서 **변수**가 필요하다!

---

## 4.2 변수란?

> **변수(variable)**: 하나의 값을 저장하기 위해 확보한 메모리 공간, 또는 그 공간에 붙인 **상징적인 이름**
>

```jsx
var result = 10 + 20;
// "result"라는 이름으로 30이 저장된 메모리 공간에 안전하게 접근 가능
```

| 용어 | 설명 |
| --- | --- |
| 변수 이름 (변수명) | 메모리 공간에 붙인 이름. 예: `result` |
| 변수 값 | 변수에 저장된 값. 예: `30` |
| 할당 (assignment) | 변수에 값을 저장하는 행위 |
| 참조 (reference) | 변수에 저장된 값을 읽어 들이는 행위 |

---

## 4.3 식별자 (Identifier)

> **식별자**: 어떤 값을 구별해서 식별할 수 있는 **고유한 이름**
>

🔑 **핵심 포인트**: 식별자는 값 자체가 아니라 **메모리 주소를 기억**한다.

```
result  →  0x0669F913  →  30
(식별자)   (메모리 주소)  (메모리에 저장된 값)
```

식별자라는 용어는 변수 이름에만 한정되지 않는다.
변수, 함수, 클래스의 이름은 **모두 식별자**다.

---

## 4.4 변수 선언 (Variable Declaration)

> **변수 선언**: 값을 저장할 메모리 공간을 확보하고, 변수 이름과 주소를 연결해서 준비하는 것
>

```jsx
var score;   // 변수 선언
```

### 선언 시 2단계로 실행된다

| 단계 | 설명 |
| --- | --- |
| ① 선언 단계 | 변수 이름을 자바스크립트 엔진에 등록. 스코프에 변수 존재를 알림 |
| ② 초기화 단계 | 메모리 공간 확보 후, 암묵적으로 `undefined` 할당 |

> 💡 `var` 키워드는 선언 단계와 초기화 단계가 **동시에** 진행된다.
>

### 선언 없이 쓰면?

```jsx
console.log(average);
// ❌ ReferenceError: average is not defined
```

선언하지 않은 식별자에 접근하면 `ReferenceError`가 발생한다.

---

## 4.5 변수 선언의 실행 시점 & 변수 호이스팅

🚨 **가장 많이 헷갈리는 포인트**

```jsx
console.log(score);  // undefined (에러 아님!)
var score;
```

왜 `ReferenceError`가 아니라 `undefined`가 출력될까?

### 이유: 변수 호이스팅 (Variable Hoisting)

자바스크립트 엔진은 코드를 한 줄씩 실행하기 전에 **소스코드 평가 과정**을 먼저 거친다.

```
[소스코드 평가]          [소스코드 실행 (런타임)]
    ↓                           ↓
모든 선언문을            나머지 코드를
먼저 실행               순차적으로 실행
(변수 선언 포함)
```

이 때문에 변수 선언이 코드 어디에 있든 소스코드의 어디서든 참조가 가능해진다.
마치 선언문이 코드의 맨 위로 끌어올려진 것처럼 동작하는 이 특징을 **호이스팅**이라 한다.

> 📌 `var`, `let`, `const`, `function`, `class` 등 모든 선언문은 호이스팅된다.
>

---

## 4.6 값의 할당 (Assignment)

```jsx
var score;      // ① 변수 선언 → 런타임 이전에 실행
score = 80;     // ② 값의 할당 → 런타임에 실행

// 단축 표현 (내부 동작은 동일)
var score = 80;
```

🚨 **핵심**: 변수 선언과 값의 할당은 **실행 시점이 다르다!**

```jsx
// 실행 결과 예측하기
console.log(score);  // ① undefined  ← 호이스팅으로 선언만 된 상태
var score = 80;      // ② 런타임에 할당 실행
console.log(score);  // ③ 80
```

> 💡 값을 할당할 때: 기존 메모리 공간(`undefined`가 있던 곳)을 지우는 게 아니라,
**새로운 메모리 공간을 확보**하고 그곳에 할당값을 저장한다.
>

---

## 4.7 값의 재할당

```jsx
var score = 80;   // 선언 + 첫 번째 할당
score = 90;       // 재할당 (이전 값 80은 버려짐)
```

- 재할당도 마찬가지로 **새 메모리 공간**을 확보하고 새 값을 저장한다.
- 이전 값(`80`, `undefined`)들은 아무도 참조하지 않으므로 **가비지 컬렉터**가 자동으로 메모리 해제.

### const — 재할당이 불가능한 변수 (상수)

```jsx
const foo = 10;
foo = 100;  // ❌ TypeError: Assignment to constant variable.
```

> ⚠️ `const`는 선언과 동시에 반드시 값을 할당해야 하고, 이후 재할당이 불가하다.
>

---

## 4.8 식별자 네이밍 규칙

### 사용 가능한 것

- 문자, 숫자, `_`, `$` 사용 가능
- 한글, 일본어 등 유니코드도 허용 (권장하지 않음)

### 사용 불가능한 것

- 숫자로 시작 → `var 1st;` ❌
- 특수문자( 등) 사용 → `var first-name;` ❌
- **예약어** 사용 → `var this;` ❌

**주요 예약어:**`await`, `break`, `case`, `catch`, `class`, `const`, `continue`, `default`, `delete`, `do`, `else`, `enum`, `export`, `extends`, `false`, `finally`, `for`, `function`, `if`, `import`, `in`, `instanceof`, `let`, `new`, `null`, `return`, `static`, `super`, `switch`, `this`, `throw`, `true`, `try`, `typeof`, `var`, `void`, `while`, `with`, `yield`

### 대소문자 구별

```jsx
var score;
var Score;    // 다른 변수!
var SCORE;    // 또 다른 변수!
```

### 네이밍 컨벤션 (좋은 이름 짓기)

| 컨벤션 | 예시 | 언제 쓰나 |
| --- | --- | --- |
| 카멜 케이스 | `firstName` | 변수, 함수 이름 ← JS 표준 |
| 파스칼 케이스 | `FirstName` | 생성자 함수, 클래스 이름 ← JS 표준 |
| 스네이크 케이스 | `first_name` | JS에선 잘 안 씀 |
| 헝가리언 케이스 | `strFirstName` | 일부 특수 상황 |

```jsx
// 의미 있는 이름 쓰기
var x = 3;          // NG: x가 뭘 의미하는지 모름
var itemCount = 3;  // OK: 명확함
```

# 05장. 표현식과 문

## 5.1 값 (Value)

> **값**: 식(표현식)이 평가(evaluate)되어 생성된 결과
>

```jsx
10 + 20  // 평가되면 → 숫자 값 30 생성
```

- 모든 값은 데이터 타입을 가진다.
- 메모리에는 2진수(비트)로 저장되지만, 해석 방법(데이터 타입)에 따라 의미가 달라진다.

---

## 5.2 리터럴 (Literal)

> **리터럴**: 사람이 이해할 수 있는 문자/약속된 기호를 사용해 값을 생성하는 **표기법**
>

```jsx
3                     // 정수 리터럴
10.5                  // 부동소수점 리터럴
0b01000001            // 2진수 리터럴 (ES6~)
0o101                 // 8진수 리터럴 (ES6~)
0x41                  // 16진수 리터럴 (ES6~)
'Hello'               // 문자열 리터럴
true / false          // 불리언 리터럴
null                  // null 리터럴
undefined             // undefined 리터럴
{ name: 'Lee' }       // 객체 리터럴
[1, 2, 3]             // 배열 리터럴
function() {}         // 함수 리터럴
/[A-Z]+/g             // 정규 표현식 리터럴
```

> 리터럴은 런타임(코드가 실행되는 시점)에 평가되어 값을 생성한다.
>

---

## 5.3 표현식 (Expression)

> **표현식**: **값으로 평가될 수 있는 문(statement)**
표현식이 평가되면 새로운 값을 생성하거나 기존 값을 참조한다.
>

```jsx
// 리터럴 표현식
10
'Hello'

// 식별자 표현식
sum           // 변수 참조
person.name   // 프로퍼티 접근
arr[1]        // 배열 요소 접근

// 연산자 표현식
10 + 20
sum = 10
sum !== 10

// 함수 호출 표현식
square()
person.getName()
```

🔑 **핵심**: 표현식은 값과 **동치**다.
→ 값이 위치할 수 있는 자리라면 **표현식도 위치할 수 있다**.

```jsx
var x = 1 + 2;  // 우변 자리에 리터럴 대신 표현식 사용
x + 3;          // x는 3으로 평가됨 → 결과: 6
```

---

## 5.4 문 (Statement)

> **문**: 프로그램을 구성하는 **기본 단위이자 최소 실행 단위**
문의 집합 = 프로그램. 문을 순서에 맞게 나열하는 것 = 프로그래밍
>

문은 여러 **토큰(token)**으로 구성된다.
토큰이란 문법적으로 더 이상 나눌 수 없는 코드의 기본 요소.

```
var sum = 1 + 2;
 ↑   ↑  ↑ ↑ ↑ ↑
모두 토큰
```

### 문의 종류

```jsx
// 변수 선언문
var x;

// 할당문
x = 5;

// 함수 선언문
function foo() {}

// 조건문
if (x > 1) { console.log(x); }

// 반복문
for (var i = 0; i < 2; i++) { console.log(i); }
```

---

## 5.5 세미콜론과 ASI

세미콜론(`;`)은 문의 **종료를 나타낸다**.

- `{ ... }` 코드 블록 뒤에는 세미콜론 안 붙인다 (블록이 자체 종결성을 가짐)
- 세미콜론은 **옵션**이다 → **ASI(Automatic Semicolon Insertion)** 덕분

### ASI — 세미콜론 자동 삽입 기능

자바스크립트 엔진이 소스코드를 해석할 때 문의 끝이라 예측되는 지점에 **자동으로 세미콜론을 삽입**해준다.

🚨 **주의**: ASI의 동작이 개발자 예측과 다를 때가 있다.

```jsx
// ASI 오동작 예시
function foo() {
  return
  {}    // ASI가 return 뒤에 자동으로 ; 삽입
        // return; 이 되어버림 → undefined 반환!
}
// 개발자 의도: return {}
// 실제 동작: return undefined
```

→ TC39(ECMAScript 기술 위원회)는 **세미콜론을 명시적으로 붙이는 것을 권장**한다.

---

## 5.6 표현식인 문 vs 표현식이 아닌 문

> 표현식인 문: 값으로 평가될 수 있는 문
표현식이 아닌 문: 값으로 평가될 수 없는 문
>

### 구별하는 방법: 변수에 할당해보기

```jsx
// 표현식이 아닌 문 → 할당 불가
var foo = var x;  // ❌ SyntaxError

// 표현식인 문 → 할당 가능
var foo = x = 100;   // x = 100은 표현식 → foo에 100이 들어감
console.log(foo);    // 100
```

| 구분 | 값으로 평가 | 예시 |
| --- | --- | --- |
| 표현식인 문 | 가능 | 할당문: `x = 100` |
| 표현식이 아닌 문 | 불가 | 변수 선언문: `var x;` |

### 완료 값 (Completion Value)

크롬 개발자 도구에서 코드를 실행하면:

```
> var foo = 10;
<- undefined      ← 표현식이 아닌 문의 완료 값 (항상 undefined)

> 100 + 10;
<- 110            ← 표현식인 문은 평가된 값을 반환
```

완료 값은 변수에 할당하거나 참조할 수 없다.

# ⚡ 핵심 요약

| 개념 | 한 줄 정리 |
| --- | --- |
| 변수 | 값이 저장된 메모리 공간에 붙인 이름. 메모리 주소를 직접 다룰 필요 없게 해줌 |
| 식별자 | 변수·함수·클래스 등의 이름. 값이 아닌 메모리 주소를 기억함 |
| 변수 선언 | `var score;` → 선언(이름 등록) + 초기화(`undefined` 할당) 동시 실행 |
| 호이스팅 | 런타임 이전 평가 과정에서 모든 선언문이 먼저 실행 → 선언 전 접근해도 에러 없이 `undefined` 반환 |
| 할당 | 런타임에 실행됨. 새 메모리 공간에 값 저장 (기존 공간 덮어쓰기 아님) |
| 재할당 | 또 새 메모리 공간에 새 값 저장. 이전 값은 가비지 컬렉터가 해제 |
| const | 재할당 불가 = 상수. 선언과 동시에 할당 필수 |
| 리터럴 | 값을 만드는 표기법 (숫자, 문자열, 배열, 객체 등) |
| 표현식 | 값으로 평가될 수 있는 문. 값이 있어야 할 자리에 쓸 수 있음 |
| 문 | 프로그램 최소 실행 단위. 선언문/할당문/조건문/반복문 등 |
| ASI | 자동 세미콜론 삽입. 가끔 예측 못한 동작 유발 → 세미콜론 직접 쓰는 게 안전 |
| 표현식인 문 | 값으로 평가 가능 → 변수에 할당 가능 (예: 할당문) |
| 표현식 아닌 문 | 값으로 평가 불가 → 변수에 할당 불가 (예: 변수 선언문) |

# 🧪 복습 퀴즈

### Q1. 다음 코드의 출력 결과로 올바른 것은?

```jsx
console.log(name);
var name = 'Lee';
console.log(name);
```

1. `ReferenceError` 발생, 실행 중단
2. `null`, `'Lee'`
3. `undefined`, `'Lee'`
4. `'Lee'`, `'Lee'`
5. `undefined`, `undefined`

정답: 3번 — `undefined`, `'Lee'`

해설: `var name` 선언은 런타임 이전 호이스팅으로 먼저 실행되며 `undefined`로 초기화된다. 첫 번째 `console.log`는 이 시점에서 실행되므로 `undefined`를 출력한다. 이후 런타임에 `name = 'Lee'` 할당이 실행되므로 두 번째 출력에서는 `'Lee'`가 나온다.

### Q2. 다음 중 식별자(identifier)가 아닌 것은?

1. 변수 이름 (`result`)
2. 함수 이름 (`square`)
3. 클래스 이름 (`Person`)
4. 메모리 주소 (`0x0669F913`)
5. 배열 이름 (`users`)

정답: 4번 — 메모리 주소 (`0x0669F913`)

해설: 식별자는 어떤 값을 구별해서 식별할 수 있는 고유한 이름이다. 변수·함수·클래스·배열의 이름은 모두 식별자다. 메모리 주소 자체는 식별자가 아니라 물리적 위치값이다. 오히려 식별자가 이 메모리 주소를 내부적으로 기억하는 역할을 한다.

### Q3. `var score = 80;` 한 줄의 실행에 대한 설명으로 옳은 것은?

1. 선언과 할당이 동시에 하나의 단계에서 실행된다.
2. 선언이 런타임에 실행되고, 할당이 런타임 이전에 실행된다.
3. 선언이 런타임 이전에 먼저 실행되고 `undefined`로 초기화된 뒤, 할당이 런타임에 실행된다.
4. 할당 후에 선언이 이뤄진다.
5. 선언과 동시에 80이 즉시 메모리에 저장된다.

정답: 3번

해설: 자바스크립트 엔진은 변수 선언을 런타임 이전 평가 단계에서 먼저 실행하고 `undefined`로 초기화한다. 이후 런타임에 코드가 순차 실행될 때 할당문이 실행되어 새로운 메모리 공간에 `80`이 저장된다. 이 둘의 실행 시점이 다르기 때문에 선언 전에 변수를 참조하면 `undefined`가 출력된다.

### Q4. 다음 중 표현식이 아닌 문(statement)만 모아놓은 것은?

1. `x = 10;` / `1 + 2` / `square()`
2. `var x;` / `if (true) {}` / `for (...) {}`
3. `var x = 5;` / `x = 10;` / `1 + 2`
4. `square()` / `arr[1]` / `person.name`
5. `null` / `true` / `'Hello'`

정답: 2번 — `var x;` / `if (true) {}` / `for (...) {}`

해설: 표현식이 아닌 문은 값으로 평가될 수 없는 문이다. 변수 선언문(`var x`), 조건문(`if`), 반복문(`for`)은 모두 값으로 평가되지 않으므로 변수에 할당할 수 없다. 반면 1번, 4번, 5번은 모두 값으로 평가될 수 있는 표현식들이다.

### Q5. 다음 코드에서 `console.log(foo)`의 출력 결과와 그 이유로 옳은 것은?

```jsx
var foo = x = 100;
console.log(foo);
```

1. `undefined` — `x`가 선언되지 않아서
2. `x` — 식별자 이름이 문자열로 출력된다
3. `ReferenceError` — `x`가 선언되지 않았기 때문
4. `100` — `x = 100`은 표현식인 문으로 값 100으로 평가되어 `foo`에 할당된다
5. `null` — `x`에 값이 없어서

정답: 4번 — `100`

해설: `x = 100`은 할당문이자 표현식인 문이다. 표현식으로서 평가되면 할당된 값인 100을 반환한다. 따라서 `var foo = x = 100`은 먼저 `x`에 100을 할당하고, 그 결과값 100이 `foo`에 할당된다. 이처럼 표현식인 문은 값처럼 사용될 수 있다. (참고: 여기서 `x`는 선언 없이 할당됐으므로 암묵적 전역 변수가 되는데, 이는 좋지 않은 코드다.)
