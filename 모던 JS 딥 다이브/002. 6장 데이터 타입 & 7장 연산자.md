# 6장. 데이터 타입 🗂️

## 6.0 데이터 타입 전체 분류

자바스크립트(ES6)는 7가지 데이터 타입을 제공하며, 크게 **원시 타입**과 **객체 타입**으로 나뉜다.

| 구분 | 타입 | 설명 |
|------|------|------|
| 원시 타입 | number | 정수/실수 구분 없는 하나의 숫자 타입 |
| 원시 타입 | string | 문자열 |
| 원시 타입 | boolean | true / false |
| 원시 타입 | undefined | var로 선언 시 암묵적으로 할당되는 초기값 |
| 원시 타입 | null | 값이 없음을 의도적으로 명시할 때 |
| 원시 타입 | symbol | ES6에서 추가된 7번째 타입 |
| 객체 타입 | object | 객체, 함수, 배열 등 |

---

## 6.1 숫자 타입 🔢

### 언제 쓰는가?
수학적 계산, 숫자 비교, 반복 횟수 등 모든 숫자 데이터에 사용

### 핵심 특징
- JS는 **정수 전용 타입이 없다** → 모든 수를 64비트 부동소수점 실수로 처리
- 정수끼리 나눠도 실수가 나올 수 있다

```javascript
console.log(4 / 2);  // 2
console.log(3 / 2);  // 1.5  ← 실수!
```

### ⚠️ 특별한 세 가지 값

| 값 | 의미 |
|----|------|
| Infinity | 양의 무한대 (예: 10 / 0) |
| -Infinity | 음의 무한대 (예: 10 / -0) |
| NaN | 산술 연산 불가 (예: 1 * 'String') |

### ⚠️ 자주 헷갈리는 포인트
- `NaN`은 대소문자 구별 → `nan`, `NAN`은 에러 발생
- 2진수(`0b`), 8진수(`0o`), 16진수(`0x`)로 써도 내부적으로는 모두 10진수로 해석

```javascript
var binary = 0b01000001;  // 65
var octal   = 0o101;       // 65
var hex     = 0x41;        // 65
console.log(binary === hex); // true
```

## 6.2 문자열 타입 📝

### 언제 쓰는가?
텍스트 데이터를 표현할 때. 화면 출력, 사용자 입력 처리 등

### 표기법
```javascript
var str = '작은따옴표';   // 가장 일반적
var str = "큰따옴표";
var str = `백틱(ES6)`;
```

### 이스케이프 시퀀스 (자주 쓰는 것만)

| 시퀀스 | 의미 |
|--------|------|
| `\n` | 개행 (줄바꿈) |
| `\t` | 탭 |
| `\'` | 작은따옴표 |
| `\"` | 큰따옴표 |
| `\\` | 백슬래시 |

## 6.3 템플릿 리터럴 (ES6) 💬

### 언제 쓰는가?
- 줄바꿈이 있는 긴 문자열
- 변수나 표현식을 문자열 안에 삽입할 때 → `+` 연산 없이 가능!

### 6.3.1 멀티라인 문자열
```javascript
// 일반 문자열은 줄바꿈 불가 → 이스케이프 필요
var str = '<ul>\n\t<li>Home</li>\n</ul>';

// 템플릿 리터럴은 그냥 줄바꿈 가능
var template = `<ul>
  <li>Home</li>
</ul>`;
```

### 6.3.2 표현식 삽입 (핵심!)
```javascript
var first = 'Ung-mo';
var last  = 'Lee';

// ES5 방식 (+ 연산)
console.log('My name is ' + first + ' ' + last + '.');

// ES6 템플릿 리터럴 방식
console.log(`My name is ${first} ${last}.`);
// → My name is Ung-mo Lee.

// 수식도 삽입 가능
console.log(`1 + 2 = ${1 + 2}`);  // 1 + 2 = 3
```

### ⚠️ 주의
- `${}` 표현식 삽입은 반드시 백틱(`) 안에서만 동작
- 일반 따옴표 안에서는 문자 그대로 출력됨

## 6.5 undefined 타입 ❓

```javascript
var foo;
console.log(foo);  // undefined
```

### 언제 등장하나?
- `var`로 선언 후 값을 할당하지 않은 변수
- JS 엔진이 자동으로 초기화하는 값

### ⚠️ 자주 헷갈리는 포인트
- 개발자가 의도적으로 undefined를 할당하는 건 권장하지 않음
- "값이 없다"는 것을 명시하고 싶다면 → **null을 사용**

---

## 6.6 null 타입 🚫

```javascript
var foo = 'Lee';
foo = null;  // 이전 참조를 제거, 더 이상 'Lee'를 참조하지 않음
```

### 언제 쓰는가?
- 변수가 더 이상 값을 참조하지 않음을 명시할 때
- `document.querySelector()`처럼 요소를 못 찾은 경우 null 반환

### ⚠️ undefined vs null 비교

| | undefined | null |
|-|-----------|------|
| 누가 할당? | JS 엔진이 자동으로 | 개발자가 의도적으로 |
| 의미 | 아직 값이 없음 | 값이 없음을 명시적으로 표현 |

## 6.7 심벌 타입 🔑

```javascript
var key = Symbol('key');
console.log(typeof key);  // symbol

var obj = {};
obj[key] = 'value';
console.log(obj[key]);    // value
```

- ES6에서 추가, 변경 불가능한 원시 타입
- 이름 충돌 없는 유일한 프로퍼티 키를 만들 때 사용
- `Symbol()` 함수로 생성 → 절대 중복되지 않음

- 6가지 원시 타입 외의 모든 값 (객체, 함수, 배열 등)

1. 메모리 공간 크기 결정 → 숫자는 8바이트 확보
2. 값을 참조할 때 한 번에 읽어야 할 메모리 셀 수 결정
3. 메모리에 저장된 2진수를 어떻게 해석할지 결정

## 6.10 동적 타이핑 🔄

### 정적 타입 vs 동적 타입

| 구분 | 정적 타입 언어 | 동적 타입 언어 |
|------|--------------|--------------|
| 예 | C, C++, Java | JavaScript, Python, PHP |
| 타입 결정 시점 | 변수 선언 시 (컴파일) | 값 할당 시 (런타임) |
| 타입 변경 | 불가 | 언제든지 가능 |

### JS의 동적 타이핑
```javascript
var foo;
console.log(typeof foo);  // undefined

foo = 3;
console.log(typeof foo);  // number

foo = 'Hello';
console.log(typeof foo);  // string

foo = true;
console.log(typeof foo);  // boolean

foo = null;
console.log(typeof foo);  // object ← 주의! null이지만 object 반환

foo = Symbol();
console.log(typeof foo);  // symbol

foo = {};
console.log(typeof foo);  // object

foo = [];
console.log(typeof foo);  // object

foo = function(){};
console.log(typeof foo);  // function
```

### ⚠️ 동적 타입의 단점
- 타입이 언제든 바뀔 수 있어 추적이 어려움
- JS 엔진이 암묵적 타입 변환을 할 수 있어 예상치 못한 결과 발생 가능

# 7장. 연산자 ⚙️

## 7.1 산술 연산자

### 7.1.1 이항 산술 연산자

| 연산자 | 의미 |
|--------|------|
| + | 덧셈 |
| - | 뺄셈 |
| * | 곱셈 |
| / | 나눗셈 |
| % | 나머지 |

- 피연산자의 값을 변경하지 않는다 (부수 효과 없음)

### 7.1.2 단항 산술 연산자

| 연산자 | 의미 | 부수 효과 |
|--------|------|----------|
| ++ | 증가 | 있음 ✅ |
| -- | 감소 | 있음 ✅ |
| + | 숫자 타입 변환 (효과 없음) | 없음 |
| - | 부호 반전 | 없음 |

### ⚠️ 전위 vs 후위 증가/감소

```javascript
var x = 5, result;

// 후위 증가: 현재 값을 먼저 반환 후 증가
result = x++;
console.log(result, x);  // 5 6

// 전위 증가: 먼저 증가 후 반환
result = ++x;
console.log(result, x);  // 7 7

// 후위 감소
result = x--;
console.log(result, x);  // 7 6

// 전위 감소
result = --x;
console.log(result, x);  // 5 5
```

### + 단항 연산자의 타입 변환
```javascript
var x = '1';
console.log(+x);    // 1  (문자열 → 숫자)
console.log(x);     // "1" (원본 변경 없음)

x = true;
console.log(+x);    // 1  (true → 1)
x = false;
console.log(+x);    // 0  (false → 0)

x = 'Hello';
console.log(+x);    // NaN (변환 불가)
```

### 7.1.3 문자열 연결 연산자
```javascript
// 피연산자 중 하나라도 문자열이면 문자열 연결
'1' + 2;        // '12'
1 + '2';        // '12'

// 그 외는 산술 연산
1 + 2;          // 3

// 암묵적 타입 변환 예시
1 + true;       // 2  (true → 1)
1 + false;      // 1  (false → 0)
1 + null;       // 1  (null → 0)
1 + undefined;  // NaN
```

## 7.2 할당 연산자

할당 연산자는 변수 값을 변경하는 **부수 효과가 있다**.

| 연산자 | 예 | 동일 표현 |
|--------|-----|---------|
| = | x = 5 | x = 5 |
| += | x += 5 | x = x + 5 |
| -= | x -= 5 | x = x - 5 |
| *= | x *= 5 | x = x * 5 |
| /= | x /= 5 | x = x / 5 |
| %= | x %= 5 | x = x % 5 |

### 실무 패턴: 연쇄 할당
```javascript
var a, b, c;
a = b = c = 0;
console.log(a, b, c);  // 0 0 0
```

---

## 7.3 비교 연산자

### 7.3.1 동등/일치 비교 연산자

| 연산자 | 의미 | 타입 변환 |
|--------|------|----------|
| == | 동등 비교 | 있음 (느슨한 비교) |
| === | 일치 비교 | 없음 (엄격한 비교) |
| != | 부동등 비교 | 있음 |
| !== | 불일치 비교 | 없음 |

### ⚠️ 가장 중요한 포인트: == 쓰지 마라!

```javascript
// == 는 타입을 변환해서 비교 → 예측 불가
5 == '5';       // true  ← 위험!
0 == '';        // true  ← 위험!
false == '0';   // true  ← 위험!
false == null;  // false

// === 는 값과 타입 모두 같아야 true
5 === '5';      // false ← 예측 가능
5 === 5;        // true
```

### ⚠️ NaN 비교 주의
```javascript
NaN === NaN;          // false ← NaN은 자신과도 일치하지 않음!
Number.isNaN(NaN);    // true  ← NaN 판별엔 이걸 써야 함
```

### 7.3.2 대소 관계 비교 연산자

| 연산자 | 의미 |
|--------|------|
| > | x가 y보다 크다 |
| < | x가 y보다 작다 |
| >= | x가 y보다 크거나 같다 |
| <= | x가 y보다 작거나 같다 |

## 7.4 삼항 조건 연산자 🔀

```
조건식 ? 조건이 true일 때 값 : 조건이 false일 때 값
```

```javascript
var x = 2;
var result = x % 2 ? '홀수' : '짝수';
console.log(result);  // 짝수
```

### if...else 와 차이점

| | 삼항 연산자 | if...else |
|-|------------|-----------|
| 값으로 사용 | 가능 ✅ | 불가 ❌ |
| 가독성 | 단순할 때 좋음 | 복잡한 로직에 좋음 |

```javascript
// 삼항 연산자는 값이므로 변수에 할당 가능
var result = x % 2 ? '홀수' : '짝수';

// if...else는 값이 아닌 문(statement) → 변수에 직접 할당 불가
// var result = if (x % 2) {...}  ← SyntaxError
```

## 7.5 논리 연산자

| 연산자 | 의미 |
|--------|------|
| \|\| | 논리합(OR) |
| && | 논리곱(AND) |
| ! | 부정(NOT) |

```javascript
true || false;   // true
true && false;   // false
!true;           // false
!false;          // true
```

### ⚠️ 단락 평가 (Short-circuit evaluation)
```javascript
'Cat' && 'Dog';  // 'Dog'  ← 두 값 모두 truthy이면 마지막 값 반환
'Cat' || 'Dog';  // 'Cat'  ← 첫 truthy 값 반환
```

### ⚠️ ! 연산자의 타입 변환
```javascript
!0;        // true  (0은 falsy)
!'Hello';  // false (문자열은 truthy)
```

## 7.6 쉼표 연산자

```javascript
var x, y, z;
x = 1, y = 2, z = 3;  // 마지막 값(3) 반환
```

## 7.7 그룹 연산자 ()

- 소괄호로 묶어 우선순위를 높임
- 연산자 중 우선순위가 가장 높다

```javascript
10 * 2 + 3;      // 23  (곱셈 먼저)
10 * (2 + 3);    // 50  (괄호 먼저)
```

## 7.8 typeof 연산자

피연산자의 데이터 타입을 문자열로 반환.
반환값: `"string"`, `"number"`, `"boolean"`, `"undefined"`, `"symbol"`, `"object"`, `"function"`

```javascript
typeof ''          // "string"
typeof 1           // "number"
typeof true        // "boolean"
typeof undefined   // "undefined"
typeof Symbol()    // "symbol"
typeof null        // "object"  ← 버그! null인데 object 반환
typeof []          // "object"
typeof {}          // "object"
typeof function(){}// "function"
```

### ⚠️ 자주 헷갈리는 포인트
- `typeof null === 'object'` → JS 초기 버그, 아직 수정 안 됨
- null 타입 체크는 typeof 대신 `=== null` 사용

```javascript
var foo = null;
typeof foo === null;  // false ← 틀린 방법
foo === null;         // true  ← 올바른 방법
```

## 7.9 지수 연산자 (ES7)

```javascript
2 ** 2;   // 4    (2의 2승)
2 ** 2.5; // 5.65...
2 ** 0;   // 1
2 ** -2;  // 0.25
```

- ES7 이전에는 `Math.pow(2, 2)` 사용
- 음수를 밑으로 쓸 때는 괄호 필수: `(-5) ** 2`

## 7.12 연산자 우선순위 (중요한 것만)

| 순위 | 연산자 |
|------|--------|
| 1 (높음) | () 그룹 |

| 6 | ** (지수) |

| 8 | +, - |

| 10 | ==, !=, ===, !== |

| 13 | \|\| |

> 💡 외우기보다는 `()`로 우선순위를 명시적으로 조절하는 습관이 더 좋다!

## ✅ 핵심 요약 한눈에 보기

| 항목 | 핵심 포인트 |
|------|------------|
| JS 숫자 | 정수/실수 구분 없음. 모두 실수. NaN은 자신과도 !== |
| 문자열 | 변경 불가(immutable). 백틱으로 `${}` 표현식 삽입 가능 |
| undefined | JS 엔진 자동 초기화. 직접 할당 비권장 |
| null | 개발자가 의도적으로 "없음" 표현. typeof null은 "object" (버그) |
| == vs === | == 쓰지 마라. 항상 === 사용 |
| ++ 위치 | 전위(`++x`)는 먼저 증가 후 반환, 후위(`x++`)는 반환 후 증가 |
| 삼항 연산자 | 값으로 사용 가능. if...else는 문이라 값으로 사용 불가 |
| typeof null | "object" 반환 → JS 버그. null 확인은 `=== null` 사용 |
| 동적 타이핑 | 변수에 어떤 타입이든 할당 가능. 타입은 할당 시점에 결정 |

### Q1. 다음 코드의 출력값은?

```javascript
console.log(typeof null);
```

1. "null"
2. "undefined"
3. "object" ✓
4. "string"
5. ReferenceError 발생

정답: 3번 ("object")
해설: typeof null은 JS의 초기 버그로 인해 "object"를 반환합니다. null인지 확인하려면 `foo === null`을 사용해야 합니다.

### Q2. 다음 중 == 연산자를 쓰면 안 되는 주된 이유는?

1. 값만 비교하고 타입은 무시하기 때문
2. 암묵적 타입 변환이 발생해 예측하기 어려운 결과가 나오기 때문 ✓
3. 모든 비교에서 false를 반환하기 때문
4. 배열과 객체를 비교할 수 없기 때문
5. ES6에서 삭제된 연산자이기 때문

정답: 2번
해설: == 연산자는 피연산자의 타입이 다를 경우 암묵적 타입 변환을 수행합니다. 예를 들어 `0 == ''`은 true, `false == '0'`은 true처럼 예측하기 어려운 결과가 나옵니다. 따라서 항상 === (일치 비교)를 사용하는 것이 권장됩니다.

### Q3. 다음 코드의 result 값은?

```javascript
var x = 5, result;

console.log(result);
```

### Q5. 다음 코드의 출력 결과는?

```javascript
var foo;
console.log(typeof foo);
foo = 'hello';
console.log(typeof foo);
foo = 3;
console.log(typeof foo);
```

1. "undefined", "string", "number" ✓
2. "null", "string", "number"
3. "undefined", "undefined", "number"
4. ReferenceError, "string", "number"
5. "object", "string", "number"

정답: 1번
해설: JS는 동적 타이핑 언어입니다. 변수 선언만 하고 값을 할당하지 않으면 undefined, 문자열을 할당하면 string, 숫자를 할당하면 number로 타입이 바뀝니다. 이처럼 변수의 타입은 할당 시점에 동적으로 결정됩니다.

### Q6. 다음 중 NaN인지 올바르게 판별하는 방법은?

```javascript
var x = NaN;
```

1. `x == NaN`
2. `x === NaN`
3. `typeof x === 'NaN'`
4. `Number.isNaN(x)` ✓
5. `x !== x`

정답: 4번 (Number.isNaN(x))
해설: NaN은 자신과 일치하지 않는 유일한 값이라 `x === NaN`은 항상 false입니다. NaN 여부를 판별하려면 반드시 `Number.isNaN()` 함수를 사용해야 합니다. (참고: 5번 `x !== x`도 NaN일 때만 true가 되는 방법이나 가독성이 나빠 비권장)
