# 🗄️ SQL 복습자료 — 키 · 뷰 · 인덱스 · 트랜잭션 · 권한

## 1️⃣ 기본키 (Primary Key)

### 개념
테이블에서 각 행(Row)을 유일하게 식별하는 컬럼.

### 핵심 규칙
- 중복 불가 (고유값만 허용)
- NULL 불가
- 테이블당 딱 하나만 설정 가능

### 사용법

```sql
-- 방법 1: 컬럼 옆에 바로 선언
CREATE TABLE people (
  first_name CHAR(2) PRIMARY KEY,
  last_name  CHAR(3)
);

-- 방법 2: 하단에 따로 선언 (다중 기본키 설정 가능)
CREATE TABLE people (
  first_name CHAR(2),
  last_name  CHAR(3),
  PRIMARY KEY (first_name, last_name)  -- 두 컬럼 조합이 기본키
);
```

### 기본키 변경

```sql
ALTER TABLE people DROP PRIMARY KEY;
ALTER TABLE people ADD PRIMARY KEY (last_name);
```

### ⚠️ 자주 헷갈리는 포인트
> 다중 기본키(Composite PK)는 컬럼 하나하나가 고유한 게 아니라,
> **조합 전체**가 고유하면 된다.
> 예: ('홍', '길동') / ('홍', '우치') → 둘 다 허용됨

## 2️⃣ 고유키 (Unique Key)

### 개념
기본키처럼 중복을 막지만, **NULL은 허용**된다.

### 차이 정리

| 구분 | 기본키 | 고유키 |
|------|--------|--------|
| 중복 허용 | ❌ | ❌ |
| NULL 허용 | ❌ | ✅ |
| 테이블당 개수 | 1개 | 여러 개 가능 |

### 사용법

```sql
-- 단일 고유키
CREATE TABLE people (
  person_id  INT AUTO_INCREMENT PRIMARY KEY,
  first_name CHAR(2) UNIQUE
);

-- 다중 고유키 (조합)
CREATE TABLE people (
  person_id  INT AUTO_INCREMENT PRIMARY KEY,
  first_name CHAR(2),
  last_name  CHAR(3),
  UNIQUE (first_name, last_name)
);
```

## 3️⃣ 외래키 (Foreign Key)

### 개념
다른 테이블의 기본키를 참조하는 컬럼. 테이블 간 관계를 맺어준다.

- 참조 받는 테이블 → **부모 테이블**
- 참조 하는 테이블 → **자식 테이블**

### 외래키 추가 / 삭제

```sql
-- 추가
ALTER TABLE 자식테이블
  ADD CONSTRAINT 제약이름
  FOREIGN KEY (자식컬럼)
  REFERENCES 부모테이블(부모기본키)
  ON DELETE CASCADE
  ON UPDATE RESTRICT;

-- 삭제
ALTER TABLE 자식테이블 DROP FOREIGN KEY 제약이름;
```

### 외래키 제약 종류

| 제약 | 설명 |
|------|------|
| RESTRICT / NO ACTION | 자식이 참조 중이면 부모 수정/삭제 불가 |
| CASCADE | 부모 수정/삭제 시 자식도 함께 수정/삭제 |
| SET NULL | 부모 수정/삭제 시 자식 외래키를 NULL로 (NOT NULL이면 사용 불가) |
| SET DEFAULT | 자식 외래키를 기본값으로 (InnoDB에서 사용 불가) |

### ⚠️ 자주 헷갈리는 포인트
> 외래키 값은 **NULL이거나** 부모 테이블의 기본키와 **일치해야** 한다.
> 부모에 없는 값을 INSERT하면 오류 발생.

## 4️⃣ 뷰 (VIEW)

### 개념
실제 데이터를 저장하지 않는 **가상의 테이블**. 복잡한 쿼리를 마치 테이블처럼 사용할 수 있게 해준다.

### 생성 / 조회 / 삭제

```sql
CREATE VIEW section_view AS
SELECT section_id, section_name
FROM sections;

SELECT * FROM section_view;

DROP VIEW section_view;
```

### 뷰를 사용하는 이유

1. **보안** — 민감한 컬럼(예: 가격, 이름)을 숨기고, 가공된 형태만 노출
2. **편의** — 복잡한 JOIN / 서브쿼리를 미리 저장해 반복 작성 방지

### 뷰 내용 수정이 가능한 조건

수정 가능하려면 아래 조건을 **모두** 만족해야 한다.

- 집계 함수(MAX, MIN, AVG 등) 없음
- GROUP BY 없음
- UNION / DISTINCT 없음
- SELECT 절에 서브쿼리 없음
- WHERE 절의 서브쿼리가 FROM 테이블 참조 안 함
- JOIN은 INNER JOIN만 허용

### ⚠️ 자주 헷갈리는 포인트
> 뷰는 데이터를 직접 저장하지 않기 때문에,
> 위 조건을 위반하면 수정 불가 (읽기 전용 뷰가 됨).

## 5️⃣ 인덱스 (INDEX)

### 개념
특정 컬럼에 대해 **목차**를 만들어 검색 속도를 높이는 기능.
단, 데이터 추가/수정/삭제 시 인덱스도 갱신되므로 **쓰기 성능은 저하**될 수 있다.

### 인덱스 생성 / 조회 / 삭제

```sql
-- 단일 컬럼 인덱스
ALTER TABLE businesses
  ADD INDEX index_biz_name (business_name);

-- 다중 컬럼 인덱스
ALTER TABLE menus
  ADD INDEX index_name_cal (menu_name, kilocalories);

-- 인덱스 목록 확인
SHOW INDEX FROM businesses;

-- 삭제
ALTER TABLE businesses
  DROP INDEX index_biz_name;
```

### 인덱스가 적합한 컬럼

- 데이터 변경이 **적은** 테이블
- WHERE, ORDER BY에 자주 쓰이는 컬럼
- JOIN에 쓰이는 컬럼
- **Cardinality(중복도)가 낮은 컬럼** — 예: 이름 ✅ / 성별 ❌

### 인덱스 종류

| 종류 | 설명 | 적합한 상황 |
|------|------|-------------|
| B-Tree (기본) | 범위 검색, 정렬 지원 | 일반적인 경우 |
| Full-Text | 단어/구문 검색 | 긴 텍스트 컬럼 (CHAR, VARCHAR, TEXT) |
| Hash | 완전 일치(=)만 지원, 매우 빠름 | MEMORY/NDB 엔진 전용 |
| Bitmap | Cardinality 낮은 컬럼에 적합 | MySQL 미지원 |

#### Full-Text 인덱스 예시

```sql
ALTER TABLE ratings
  ADD FULLTEXT INDEX index_full_text (comment);

SELECT * FROM ratings
  WHERE MATCH(comment) AGAINST ('괜찮은데');
```

## 6️⃣ 트랜잭션 (Transaction)

### 개념
여러 SQL 구문을 묶어서 **모두 성공하거나, 모두 실패**하게 만드는 기능.
대표 원칙: **원자성 (Atomicity)**

### 기본 흐름

```sql
START TRANSACTION;  -- 트랜잭션 시작

-- SQL 작업들...
INSERT INTO sections (section_name, floor) VALUES ('동남아', 2);

COMMIT;    -- 변경사항 영구 저장
-- 또는
ROLLBACK;  -- 변경사항 전체 취소
```

### SAVEPOINT — 중간 저장점

```sql
START TRANSACTION;

INSERT INTO sections (section_name, floor) VALUES ('인도식', 2);
SAVEPOINT indian;  -- 여기까지는 되돌아올 수 있는 지점 저장

INSERT INTO sections (section_name, floor) VALUES ('남미식', 3);

ROLLBACK TO indian;  -- '남미식'만 취소, '인도식'은 유지

COMMIT;
```

### ⚠️ 자주 헷갈리는 포인트
> COMMIT 이후에는 ROLLBACK이 불가능하다.
> SAVEPOINT는 트랜잭션 안에서만 동작하며, COMMIT하면 사라진다.

## 7️⃣ 사용자와 권한

### 사용자 생성 / 삭제

```sql
-- 생성 (어디서든 접속 가능: % = 모든 IP)
CREATE USER 'user_1'@'%' IDENTIFIED BY 'abcdefg';

-- 삭제
DROP USER 'user_1'@'%';
```

### 권한 부여 / 조회 / 박탈

```sql
-- 권한 부여
GRANT SELECT ON mydatabase.businesses TO 'user_1'@'%';
GRANT UPDATE, DELETE ON mydatabase.businesses TO 'user_1'@'%';

-- 모든 권한 부여
GRANT ALL PRIVILEGES ON mydatabase.* TO 'user_1'@'%';

-- 권한 조회
SHOW GRANTS FOR 'user_1'@'%';

-- 권한 박탈
REVOKE DELETE ON mydatabase.businesses FROM 'user_1'@'%';
```

### ⚠️ 자주 헷갈리는 포인트
> `@'%'`는 모든 IP에서 접속을 허용.
> `@'localhost'`는 해당 서버 내부에서만 접속 가능.

## 📌 핵심 요약

| 개념 | 한 줄 요약 |
|------|-----------|
| 기본키 | NULL 불가, 중복 불가, 테이블당 1개 |
| 고유키 | NULL 가능, 중복 불가, 여러 개 설정 가능 |
| 외래키 | 부모 테이블 기본키를 참조, 관계 무결성 유지 |
| 뷰 | 가상 테이블, 보안·편의 목적 |
| 인덱스 | 검색 가속, Cardinality 높은 컬럼에 적합 |
| 트랜잭션 | 전부 성공 or 전부 실패, COMMIT/ROLLBACK으로 제어 |
| 사용자/권한 | GRANT로 부여, REVOKE로 박탈 |

## 📝 복습 퀴즈

### Q1. 기본키(Primary Key)에 대한 설명으로 올바른 것은?

1. NULL 값을 허용한다
2. 테이블에 여러 개 설정할 수 있다
3. 중복된 값을 허용한다
4. 테이블당 하나만 설정 가능하고 NULL과 중복 모두 허용되지 않는다
5. 고유키와 완전히 동일한 기능이다

정답: 4번

해설: 기본키는 NULL과 중복을 모두 허용하지 않으며, 테이블당 하나만 지정할 수 있다. 고유키(Unique)는 NULL을 허용한다는 점에서 다르다.

---

### Q2. 외래키 제약 중 부모 테이블의 행이 삭제될 때 자식 테이블의 관련 행도 함께 삭제되는 제약은?

1. RESTRICT
2. SET NULL
3. CASCADE
4. NO ACTION
5. SET DEFAULT

정답: 3번

해설: CASCADE는 부모 행이 수정/삭제될 때 자식 행도 함께 수정/삭제된다. RESTRICT/NO ACTION은 자식이 참조 중이면 부모 수정/삭제 자체를 막는다.

---

### Q3. 뷰(VIEW)에 대한 설명으로 틀린 것은?

1. 복잡한 쿼리를 미리 저장해 편의성을 높일 수 있다
2. 테이블의 특정 컬럼을 숨겨 보안에 활용할 수 있다
3. 실제 데이터를 별도로 저장하는 물리적 테이블이다
4. 조건에 따라 UPDATE가 가능한 뷰도 있다
5. DROP VIEW로 삭제할 수 있다

정답: 3번

해설: 뷰는 실제 데이터를 저장하지 않는 가상의 테이블이다. SELECT 쿼리의 결과를 마치 테이블처럼 사용할 수 있게 해줄 뿐이다.

### Q4. 인덱스(Index)를 생성하기에 가장 적합한 컬럼은?

1. 성별 (남/여)
2. 사용 여부 (Y/N)
3. 고객 이름
4. 활성 상태 (활성/비활성)
5. 국적 (한국/미국/기타 3종류)

정답: 3번

해설: B-Tree 인덱스는 Cardinality(중복도)가 낮은 컬럼, 즉 값의 종류가 많은 컬럼에 적합하다. 성별/상태/활성여부처럼 값의 종류가 2~3개인 컬럼은 인덱스 효과가 미미하다.

### Q5. 트랜잭션의 SAVEPOINT에 대한 설명으로 올바른 것은?

1. SAVEPOINT는 트랜잭션 없이도 단독으로 사용할 수 있다
2. ROLLBACK TO [세이브포인트명]을 실행하면 해당 지점 이후의 변경만 취소된다
3. COMMIT 이후에도 ROLLBACK TO로 SAVEPOINT 지점으로 돌아갈 수 있다
4. SAVEPOINT는 테이블에 영구 저장된다
5. 하나의 트랜잭션에 SAVEPOINT는 하나만 설정할 수 있다

정답: 2번

해설: ROLLBACK TO [세이브포인트명]은 해당 지점 이후에 실행된 쿼리만 취소하고, 그 이전 내용은 유지한다. COMMIT 이후에는 ROLLBACK이 불가능하며, SAVEPOINT는 트랜잭션 안에서만 유효하다.
