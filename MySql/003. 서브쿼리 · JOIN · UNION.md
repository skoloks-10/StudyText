## 1. 서브쿼리

> 쿼리 안에 또 다른 쿼리를 넣는 방식. "언제 쓰는가"가 중요하다.

### 🔹 비상관 서브쿼리 (Non-Correlated Subquery)

- 메인 쿼리와 독립적으로 실행됨 → **서브쿼리가 딱 한 번만 실행**된다
- 주로 `WHERE`, `SELECT`, `FROM` 절에서 사용

**언제 쓰는가?**
- 특정 조건에 맞는 값을 동적으로 비교할 때
- 평균값, 최대값 등 집계 결과와 비교할 때

```sql
-- 평균 가격보다 낮은 상품만 조회
SELECT * FROM Products
WHERE Price < (SELECT AVG(Price) FROM Products);

-- CategoryID가 특정 상품의 CategoryID와 같은 카테고리 조회
SELECT CategoryID, CategoryName
FROM Categories
WHERE CategoryID = (SELECT CategoryID FROM Products WHERE ProductName = 'Chais');
```

**자주 헷갈리는 포인트**

| 연산자 | 의미 | 예시 |
|---|---|---|
| `= (서브쿼리)` | 결과가 반드시 단일 값이어야 함 | 두 개 이상이면 에러 발생 |
| `IN (서브쿼리)` | 결과가 여러 값이어도 됨 | 가장 많이 씀 |
| `> ALL (서브쿼리)` | 서브쿼리의 모든 결과보다 커야 함 | 최댓값보다 큰 것 |
| `> ANY (서브쿼리)` | 서브쿼리의 결과 중 하나라도 작으면 됨 | 최솟값보다 큰 것 |

```sql
-- CategoryID = 2 인 모든 상품보다 비싼 상품
SELECT * FROM Products
WHERE Price > ALL (SELECT Price FROM Products WHERE CategoryID = 2);
```

---

### 🔸 상관 서브쿼리 (Correlated Subquery)

- 메인 쿼리의 각 행(row)을 참조해서 실행됨 → **행마다 서브쿼리가 반복 실행**
- 메인 쿼리의 테이블 별칭(alias)을 서브쿼리 안에서 사용

**언제 쓰는가?**
- 같은 테이블에서 행별로 다른 집계값이 필요할 때
- 외래 키 관계 없이 연관된 데이터를 SELECT 절에 추가할 때

```sql
-- 각 상품의 카테고리 이름을 SELECT 절에 추가
SELECT ProductID, ProductName,
  (SELECT CategoryName FROM Categories C WHERE C.CategoryID = P.CategoryID) AS CategoryName
FROM Products P;

-- 카테고리별 자신의 평균보다 가격이 낮은 상품
SELECT ProductID, ProductName, CategoryID, Price
FROM Products P1
WHERE Price < (
  SELECT AVG(Price) FROM Products P2
  WHERE P2.CategoryID = P1.CategoryID
);
```

**자주 헷갈리는 포인트**
- 비상관 서브쿼리는 **독립 실행**, 상관 서브쿼리는 **행마다 재실행** → 데이터가 많으면 성능 저하 주의
- 별칭(alias)을 반드시 다르게 써야 함 (`P1`, `P2` 등)

---

### 🔹 EXISTS / NOT EXISTS

- 서브쿼리 결과가 **존재하는지 여부만** 확인 (결과 값 자체는 쓰지 않음)
- `IN`보다 대량 데이터에서 빠른 경우가 많음

```sql
-- 가격이 80 이상인 상품이 있는 카테고리만 조회
SELECT CategoryID, CategoryName
FROM Categories C
WHERE EXISTS (
  SELECT * FROM Products P
  WHERE P.CategoryID = C.CategoryID AND P.Price > 80
);
```

## 2. JOIN — 테이블 조립하기

> 두 테이블을 공통 컬럼 기준으로 연결해 합친 결과를 만든다.

### 🔹 INNER JOIN (기본 JOIN)

- 양쪽 테이블 모두에 매칭 데이터가 있는 행만 반환
- `INNER` 키워드는 생략 가능

**언제 쓰는가?** → 교집합이 필요할 때. NULL 없는 확실한 연결 관계에서 사용.

```sql
SELECT C.CategoryName, P.ProductName, P.Price
FROM Categories C
JOIN Products P ON C.CategoryID = P.CategoryID;
```

**자주 헷갈리는 포인트**
- 두 테이블에 같은 컬럼명이 있으면 `테이블명.컬럼명`으로 반드시 구분 → **Ambiguous 에러 방지**
- 여러 테이블을 연달아 JOIN 가능

```sql
-- 4개 테이블 JOIN 예시
SELECT C.CategoryName, P.ProductName, O.OrderDate, D.Quantity
FROM Categories C
JOIN Products P    ON C.CategoryID = P.CategoryID
JOIN OrderDetails D ON P.ProductID = D.ProductID
JOIN Orders O      ON O.OrderID = D.OrderID;
```

---

### 🔸 LEFT / RIGHT OUTER JOIN

- 기준 테이블(LEFT: 왼쪽, RIGHT: 오른쪽)의 모든 행을 유지
- 반대쪽 테이블에 매칭 데이터가 없으면 **NULL** 로 채워짐

**언제 쓰는가?** → "없는 데이터도 포함해서 보고 싶을 때"

```sql
-- 모든 직원 + 다음 ID 직원 연결 (마지막 직원도 포함)
SELECT E1.EmployeeID, CONCAT_WS(' ', E1.FirstName, E1.LastName) AS Employee,
       E2.EmployeeID, CONCAT_WS(' ', E2.FirstName, E2.LastName) AS NextEmployee
FROM Employees E1
LEFT JOIN Employees E2 ON E1.EmployeeID + 1 = E2.EmployeeID
ORDER BY E1.EmployeeID;
```

NULL 처리 시 `IFNULL()` 활용:
```sql
IFNULL(C.CustomerName, '-- NO CUSTOMER --')
```

---

### 🔹 SELF JOIN

- 같은 테이블을 두 번 사용해 서로 조인
- **반드시 별칭(alias)을 다르게** 사용해야 함

**언제 쓰는가?** → 계층 구조, 순서 비교, 같은 테이블 내 관계 분석

```sql
FROM Employees E1 JOIN Employees E2
ON E1.EmployeeID + 1 = E2.EmployeeID;
```

---

### 🔸 CROSS JOIN

- 조건 없이 두 테이블의 모든 조합을 반환 (A행 × B행)
- 결과 행 수 = 테이블A 행 수 × 테이블B 행 수 → **데이터 폭발 주의**

```sql
SELECT E1.LastName, E2.FirstName
FROM Employees E1
CROSS JOIN Employees E2
ORDER BY E1.EmployeeID;
```

---

### 📊 JOIN 비교 한눈에 보기

| 종류 | 특징 | NULL 포함 |
|---|---|---|
| INNER JOIN | 매칭된 행만 반환 | ❌ |
| LEFT JOIN | 왼쪽 테이블 전체 반환 | ✅ (오른쪽) |
| RIGHT JOIN | 오른쪽 테이블 전체 반환 | ✅ (왼쪽) |
| CROSS JOIN | 모든 조합 반환 | ❌ |
| SELF JOIN | 같은 테이블끼리 | 상황따라 |

## 3. UNION — 집합 연산

> 두 SELECT 결과를 세로로 합친다. 컬럼 수와 데이터 타입이 같아야 함.

| 연산자 | 설명 |
|---|---|
| `UNION` | 중복 제거 후 합침 |
| `UNION ALL` | 중복 포함해서 합침 (더 빠름) |

```sql
-- 고객과 공급사를 하나의 목록으로
SELECT CustomerName AS Name, City, Country, 'CUSTOMER'
FROM Customers
UNION
SELECT SupplierName AS Name, City, Country, 'SUPPLIER'
FROM Suppliers
ORDER BY Name;
```

**자주 헷갈리는 포인트**
- `ORDER BY`는 UNION 전체의 맨 마지막에 한 번만 작성
- 중복 제거가 필요 없으면 `UNION ALL`이 성능상 유리

---

### 집합 연산 패턴 4가지

**합집합 (A ∪ B)**
```sql
SELECT CategoryID AS ID FROM Categories WHERE CategoryID > 4
UNION
SELECT EmployeeID AS ID FROM Employees WHERE EmployeeID % 2 = 0;
```

**교집합 (A ∩ B)**
```sql
SELECT CategoryID AS ID
FROM Categories C, Employees E
WHERE C.CategoryID > 4
  AND E.EmployeeID % 2 = 0
  AND C.CategoryID = E.EmployeeID;
```

**차집합 (A - B)**
```sql
SELECT CategoryID AS ID FROM Categories
WHERE CategoryID > 4
  AND CategoryID NOT IN (
    SELECT EmployeeID FROM Employees WHERE EmployeeID % 2 = 0
  );
```

**대칭차집합 (A △ B — 한쪽에만 있는 것)**
```sql
SELECT ID FROM (
  SELECT CategoryID AS ID FROM Categories WHERE CategoryID > 4
  UNION ALL
  SELECT EmployeeID AS ID FROM Employees WHERE EmployeeID % 2 = 0
) AS Temp
GROUP BY ID HAVING COUNT(*) = 1;
```

## 복습 퀴즈

### Q1. 다음 중 서브쿼리 결과가 여러 행일 때 사용할 수 없는 연산자는?

A. `IN`
B. `= (등호)`
C. `ANY`
D. `ALL`
E. `EXISTS`

정답: B

해설: `=` 연산자는 서브쿼리 결과가 반드시 단일 값(1개 행)이어야 한다. 결과가 여러 행이면 에러가 발생한다. 반면 `IN`, `ANY`, `ALL`, `EXISTS`는 다중 행 결과를 처리할 수 있다.

---

### Q2. 비상관 서브쿼리와 상관 서브쿼리의 차이점으로 올바른 것은?

A. 비상관 서브쿼리는 항상 SELECT 절에서만 쓸 수 있다
B. 상관 서브쿼리는 메인 쿼리의 각 행을 참조해서 실행된다
C. 비상관 서브쿼리는 메인 쿼리의 별칭을 반드시 사용해야 한다
D. 상관 서브쿼리는 항상 비상관 서브쿼리보다 빠르다
E. 두 방식 모두 서브쿼리가 한 번만 실행된다

정답: B

해설: 상관 서브쿼리는 메인 쿼리의 행 하나하나를 참조(`P.CategoryID` 같이)하며 반복 실행된다. 비상관 서브쿼리는 독립적으로 단 한 번만 실행된다. 따라서 대량 데이터에서는 상관 서브쿼리가 느릴 수 있다.

---

### Q3. LEFT JOIN에 대한 설명으로 틀린 것은?

A. 왼쪽 테이블의 모든 행을 반환한다
B. 오른쪽 테이블에 매칭 데이터가 없으면 NULL로 채워진다
C. INNER JOIN과 달리 매칭되지 않아도 행이 유지된다
D. 두 테이블 모두 매칭된 행이 없으면 결과에서 제외된다
E. OUTER 키워드는 생략 가능하다

정답: D

해설: LEFT JOIN은 왼쪽 테이블을 기준으로 모든 행을 보여준다. 오른쪽 테이블에 매칭이 없어도 왼쪽 행은 결과에 포함되며, 오른쪽 값만 NULL로 표시된다. 매칭 없는 행이 제외되는 것은 INNER JOIN의 특성이다.

---

### Q4. UNION과 UNION ALL의 차이로 올바른 것은?

A. UNION ALL은 두 테이블을 가로로 합친다
B. UNION은 중복 행을 제거하고, UNION ALL은 중복 행을 포함한다
C. UNION ALL은 컬럼 수가 달라도 된다
D. UNION은 중복을 포함하고 UNION ALL은 제거한다
E. UNION은 성능이 항상 더 빠르다

정답: B

해설: UNION은 중복 행을 제거(DISTINCT 처리)하고, UNION ALL은 중복을 제거하지 않고 모두 포함한다. 중복 제거 과정이 없는 UNION ALL이 일반적으로 성능이 더 빠르다.

---

### Q5. SELF JOIN이 필요한 상황으로 가장 적합한 것은?

A. 두 테이블을 공통 컬럼으로 연결할 때
B. 같은 테이블에서 행 간의 관계(예: 직원과 그 다음 직원)를 비교할 때
C. 결과에서 중복을 제거할 때
D. 서브쿼리 결과가 존재하는지 확인할 때
E. 두 테이블의 모든 조합을 구할 때

정답: B

해설: SELF JOIN은 같은 테이블을 두 번 사용해서 행 간의 관계를 분석할 때 사용한다. 예를 들어 직원 테이블에서 `EmployeeID + 1`인 다음 직원을 나란히 보거나, 계층 구조(상사-부하)를 표현할 때 활용된다. 이때 반드시 테이블 별칭(E1, E2)을 다르게 지정해야 한다.
