## 📌 1. 테이블 생성 / 수정 / 삭제

### ✅ CREATE TABLE — 테이블 만들기

테이블의 이름과 각 컬럼(열)의 이름·자료형을 정의해서 새 테이블을 만든다.

```sql
CREATE TABLE people (
  person_id   INT,
  person_name VARCHAR(10),
  age         TINYINT,
  birthday    DATE
);
```

> 💡 테이블을 만들 때는 반드시 각 컬럼의 자료형을 함께 지정해야 한다.

---

### ✅ ALTER TABLE — 테이블 구조 변경

이미 만들어진 테이블의 이름이나 컬럼을 변경·추가·삭제할 때 사용한다.

```sql
ALTER TABLE people
  RENAME TO friends,                                  -- 테이블명 변경
  CHANGE COLUMN person_id   person_id   TINYINT,      -- 자료형 변경
  CHANGE COLUMN person_name person_nickname VARCHAR(10), -- 컬럼명 변경
  DROP COLUMN birthday,                               -- 컬럼 삭제
  ADD COLUMN  is_married TINYINT AFTER age;           -- 컬럼 추가 (age 뒤에)
```

> ⚠️ 헷갈리는 포인트
> - `CHANGE COLUMN`은 컬럼명 변경 + 자료형 변경을 동시에 처리한다.
> - `ADD COLUMN ... AFTER 컬럼명` 으로 원하는 위치에 삽입 가능하다.

---

### ✅ DROP TABLE — 테이블 삭제

```sql
DROP TABLE friends;
```

> ⚠️ 복구 불가! 신중하게 사용할 것.

## 📌 2. INSERT INTO — 데이터 삽입

테이블에 새로운 행(row)을 추가할 때 사용한다.

### 기본 패턴

```sql
-- 컬럼명 명시 (권장)
INSERT INTO people (person_id, person_name, age, birthday)
VALUES (1, '홍길동', 21, '2000-01-31');

-- 모든 컬럼 순서대로 입력할 때는 컬럼명 생략 가능
INSERT INTO people
VALUES (2, '전우치', 18, '2003-05-12');

-- 일부 컬럼만 입력 (NOT NULL 컬럼은 반드시 포함해야 함)
INSERT INTO people (person_id, person_name, birthday)
VALUES (3, '임꺽정', '1995-11-04');

-- 여러 행을 한 번에 삽입
INSERT INTO people (person_id, person_name, age, birthday)
VALUES
  (4, '존 스미스',     30, '1991-03-01'),
  (5, '루피 D. 몽키', 15, '2006-12-07'),
  (6, '황비홍',        24, '1997-10-30');
```

> 💡 여러 행 한 번에 삽입하는 패턴은 실무에서 자주 사용된다. VALUES 뒤에 `,`로 구분해서 나열하면 된다.

> ⚠️ 자료형에 맞지 않는 값(예: age에 '스물여섯' 입력)은 오류 발생

## 📌 3. 테이블 제약 조건 (Constraints)

테이블 생성 시 컬럼에 규칙을 걸어 잘못된 데이터 입력을 방지한다.

```sql
CREATE TABLE people (
  person_id   INT          AUTO_INCREMENT PRIMARY KEY,
  person_name VARCHAR(10)  NOT NULL,
  nickname    VARCHAR(10)  UNIQUE NOT NULL,
  age         TINYINT      UNSIGNED,
  is_married  TINYINT      DEFAULT 0
);
```

| 제약 조건 | 설명 |
|---|---|
| `AUTO_INCREMENT` | 새 행 삽입 시 자동으로 1씩 증가 |
| `PRIMARY KEY` | 중복 불가 + NULL 불가 → 각 행의 고유 식별자 |
| `UNIQUE` | 중복 입력 불가 (NULL은 허용) |
| `NOT NULL` | NULL(빈 값) 입력 불가 |
| `UNSIGNED` | 양수만 허용 (숫자 자료형에서 사용) |
| `DEFAULT 값` | 값이 없을 때 자동으로 지정된 기본값 사용 |

> ⭐ PRIMARY KEY 핵심 포인트
> - 테이블당 하나만 설정 가능
> - 보통 `AUTO_INCREMENT`와 함께 사용해서 자동으로 고유 번호 부여
> - 기본적으로 인덱스가 생성되어 검색 속도가 빠르다

## 📌 4. 자료형 (Data Types)

### 🔢 숫자 자료형

| 자료형 | 바이트 | SIGNED 범위 | UNSIGNED 범위 |
|---|---|---|---|
| TINYINT | 1 | -128 ~ 127 | 0 ~ 255 |
| SMALLINT | 2 | -32,768 ~ 32,767 | 0 ~ 65,535 |
| INT | 4 | 약 -21억 ~ 21억 | 0 ~ 약 42억 |
| BIGINT | 8 | 매우 큰 정수 범위 | - |

| 자료형 | 특징 |
|---|---|
| `DECIMAL(s, d)` | 정확한 소수 (예: 금액) — s: 전체 자릿수, d: 소수점 자릿수 |
| `FLOAT` | 부동 소수점, 넓은 범위, 약간의 오차 가능 |
| `DOUBLE` | FLOAT보다 더 넓은 범위의 부동 소수점 |

> 💡 금액·정밀한 수치는 `DECIMAL`, 일반 계산은 `FLOAT`/`DOUBLE` 사용

---

### 🔤 문자 자료형

| 자료형 | 특징 | 최대 크기 |
|---|---|---|
| `CHAR(s)` | 고정 길이 (남는 공간은 공백으로 채움), 검색 빠름 | 255 bytes |
| `VARCHAR(s)` | 가변 길이, 실제 글자 수만큼만 저장 | 65,535 bytes |
| `TEXT` | 긴 문자열 저장 | 65,535 bytes |
| `LONGTEXT` | 매우 긴 글 (게시글 본문 등) | 약 4GB |

> 💡 짧고 길이가 일정한 값(예: 성별 코드 'M'/'F')은 CHAR, 그 외는 VARCHAR를 쓰는 게 일반적

---

### 📅 시간 자료형

| 자료형 | 형식 | 특징 |
|---|---|---|
| `DATE` | YYYY-MM-DD | 날짜만 |
| `TIME` | HH:MI:SS | 시간만 |
| `DATETIME` | YYYY-MM-DD HH:MI:SS | 입력값 그대로 저장 |
| `TIMESTAMP` | YYYY-MM-DD HH:MI:SS | 서버 시간대 기준으로 저장, 국제 서비스에 적합 |

> 💡 단순 기록 → `DATETIME` / 국제 서비스·자동 기록 → `TIMESTAMP`

## 📌 5. DELETE / TRUNCATE — 데이터 삭제

### DELETE — 조건에 맞는 행 삭제

```sql
DELETE FROM businesses
WHERE status = 'CLS';
```

### 전체 삭제

```sql
DELETE FROM businesses;     -- 행만 삭제, AUTO_INCREMENT 번호 유지
TRUNCATE businesses;        -- 테이블 초기화, AUTO_INCREMENT도 리셋
```

> ⚠️ WHERE 조건이 없으면 테이블의 모든 데이터가 삭제된다!
> MySQL Workbench에서 실습할 경우 Safe Updates 옵션을 꺼야 실행 가능

## 📌 6. UPDATE — 데이터 수정

조건에 맞는 행의 특정 컬럼 값을 바꿀 때 사용한다.

```sql
-- 단일 컬럼 수정
UPDATE menus
SET menu_name = '삼선짜장'
WHERE menu_id = 12;

-- 여러 컬럼 동시 수정
UPDATE menus
SET
  menu_name    = '열정떡볶이',
  kilocalories = 492.78,
  price        = 5000
WHERE fk_business_id = 4 AND menu_name = '국물떡볶이';

-- 기존 값을 활용한 수정
UPDATE menus
SET price = price + 1000       -- 현재 가격에서 1000 증가
WHERE fk_business_id = 8;
```

> ⚠️ 가장 중요한 주의사항: WHERE 절이 없으면 테이블의 모든 행이 수정된다!

## 📝 복습 퀴즈

### Q1. 다음 중 테이블의 기존 컬럼명을 변경하는 SQL 문법으로 올바른 것은?

- A. `ALTER TABLE t DROP COLUMN old_name`
- B. `ALTER TABLE t ADD COLUMN new_name VARCHAR(10)`
- C. `ALTER TABLE t CHANGE COLUMN old_name new_name VARCHAR(10)`
- D. `ALTER TABLE t RENAME TO new_name`
- E. `UPDATE TABLE t SET column = new_name`

정답: C

해설: CHANGE COLUMN은 "기존 컬럼명 → 새 컬럼명 + 자료형" 순서로 작성한다. A는 컬럼 삭제, B는 컬럼 추가, D는 테이블명 변경, E는 존재하지 않는 문법이다.

---

### Q2. PRIMARY KEY에 대한 설명 중 틀린 것은?

- A. 하나의 테이블에 하나만 설정할 수 있다
- B. NULL 값을 허용한다
- C. 중복 값을 허용하지 않는다
- D. 보통 AUTO_INCREMENT와 함께 사용한다
- E. 기본적으로 인덱스가 생성된다

정답: B

해설: PRIMARY KEY는 NULL 불가 + 중복 불가 두 가지 규칙을 동시에 가진다. 각 행을 고유하게 식별해야 하기 때문에 NULL이 허용되면 식별 자체가 불가능해진다.

---

### Q3. 다음 INSERT 문 중 오류가 발생하는 경우는?

- A. 모든 컬럼에 맞는 값을 넣을 때 컬럼명을 생략한 경우
- B. 여러 행을 VALUES 뒤에 콤마로 구분해서 한 번에 삽입하는 경우
- C. NOT NULL 컬럼을 생략하고 일부 컬럼만 입력하는 경우
- D. TINYINT 컬럼에 정수 값을 넣는 경우
- E. DEFAULT가 설정된 컬럼을 생략하는 경우

정답: C

해설: NOT NULL 제약이 걸린 컬럼은 반드시 값을 입력해야 한다. 생략하면 NULL이 들어가려고 시도하지만 제약 위반으로 오류가 발생한다. DEFAULT가 설정된 컬럼(E)은 생략해도 기본값이 자동 입력되므로 오류가 없다.

---

### Q4. DELETE와 TRUNCATE의 차이로 옳은 것은?

- A. DELETE는 테이블 자체를 삭제하고, TRUNCATE는 데이터만 삭제한다
- B. TRUNCATE는 WHERE 조건을 사용해서 특정 행만 삭제할 수 있다
- C. DELETE는 WHERE 없이 사용하면 모든 데이터가 삭제되고, AUTO_INCREMENT 번호가 유지된다
- D. TRUNCATE는 데이터를 삭제해도 AUTO_INCREMENT 번호가 유지된다
- E. DELETE는 테이블 초기화에 최적화된 명령어이다

정답: C

해설: DELETE는 행 단위 삭제이며 AUTO_INCREMENT 카운터는 그대로 유지된다. TRUNCATE는 테이블을 완전히 초기화하며 AUTO_INCREMENT도 1로 리셋된다. WHERE 조건을 쓸 수 있는 것은 DELETE뿐이다.

### Q5. 금액처럼 정확한 소수 계산이 필요할 때 가장 적합한 자료형은?

- A. FLOAT
- B. DOUBLE
- C. DECIMAL
- D. INT
- E. VARCHAR

정답: C

해설: FLOAT와 DOUBLE은 부동 소수점 방식으로 넓은 범위를 표현하지만 미세한 오차가 발생할 수 있다. DECIMAL은 고정 소수점 방식으로 정확한 값을 보장하기 때문에 금융·회계 데이터에 적합하다.
